# 按章节持久保存手动双页调整

日期：2026-09-27。状态：实施中；CP-01 已完成，CP-02 实施中，CP-03 正式产物验收待执行。本文的 SOURCE 表以最初规划时的 `167840dc96` 为核对基线，不表示当前代码仍保持该旧状态。

配套 [Roadmap](roadmap/2026-09-27-chapter-pairing-persistence-roadmap.md)。延续 [双页与继续阅读契约](2026-09-24-reader-dual-page-and-continue-design.md)，不改写章节选择、已读判定或同步位置优先级。

## 1. 问题与目标

用户将某章双页调整正确后，退出阅读器或重启应用，再打开同章，应恢复该章的手动配对，随后定位到包含续读页的显示单元。章节之间互不影响。

示例使用用户可见的 1 基页码，假设都是竖页且无自动匹配：默认为 `[1] [2,3] [4,5] [6,7]`；调整后为 `[1] [2] [3,4] [5,6] [7,8]`。读到 `[5,6]` 保存第 6 页，重开应仍显示 `[5,6]`，不能恢复为 `[6,7]`。本文其余数据字段使用 0 基页序。

## 2. 范围与复用决策

- 覆盖 Android 现有 RTL 双页，以及 Desktop RTL/LTR 双页和自动布局进入双页的情况。共享规则一致，平台 adapter 负责 View/Compose 生命周期与反馈。不新增 Android LTR 双页模式。
- 覆盖具有真实数据库章节 ID 的在线、已下载和本地源章节。Desktop 直接打开、不属于数据库章节的临时本地文件不在首版范围；不得用 `chapterId=0` 为多个文件共用记录。此入口保留会话内调整，并明确提示“此文件的双页调整仅本次有效”。
- 本机数据库持久保存，不扩展跨设备同步、备份导出/导入、漫画迁移或章节重新抓取后的身份匹配。仅同步阅读进度到另一台设备不会携带配对；备份恢复不承诺恢复配对。不得借章节 memo 隐式进入现有同步/备份格式。
- 复用 `adjustReaderPairing`、`ReaderPagePairing`、现有宽图/自动匹配算法和当前恢复定位函数；不保存最终左右槽位，不复制算法。
- 复用 SQLDelight 数据库、事务、Repository/Use Case 分层和 Injekt 注册；现有会话缓存继续作为呈现状态，不能充当持久事实来源。新增存储的原因是现有全局/漫画阅读模式偏好无法表达章级多个边界；进度表述的是阅读位置，也不能承载排版状态。
- 不新增设置页、重置对话框或独立管理工具。沿用已有调整操作的可逆语义；所有手动边界撤销后恢复默认策略。自动识别结果不写入本存储。

## 3. 用户行为与固定界面契约

遵循 [Desktop UI 规范](design/mihon-desktop-ui/README.md)；已核对事实表与页面契约，阅读器采用以下专用契约，不套用书架样本业务。

| ID | 入口/状态 | 行为、反馈与副作用 |
| --- | --- | --- |
| CP1 | 双页阅读器 → 现有调整按钮 | 有效调整成功后改变配对并自动保存到当前章；不增加确认步骤。沿用平台组件与国际化字符串，保留按钮可访问名称 |
| CP2 | 调整正在保存 | 本章调整操作暂时不可重复提交；按钮提供进行中语义。成功以配对变化反馈，不反复弹成功提示。事务失败保持上一次已保存配对，提示“未能保存双页调整，请重试”并恢复按钮 |
| CP3 | 退出、重启、继续阅读、历史或显式开章 | 所有入口进入同一章级恢复链；加载已保存边界后才展示双页和报告首个稳定视口，避免先显示默认组合再跳动。章节/页码仍由原入口规则决定 |
| CP4 | 保存期间返回或切章 | 返回与切章不被长期阻塞；已接受写入由受控持久任务完成，绑定原章。完成回调不得改变新章配对、焦点或显示过期通知；新章独立加载。正常关闭应用必须等待已接受事务收尾或明确失败 |
| CP5 | 单页/条漫/方向或窗口变化 | 不清除记录；双页再次启用时恢复。方向只影响物理左右，不能使记录反转。切章及再返回恢复各自配对 |
| CP6 | 恢复失败 | 阅读器保留加载/错误容器，提供“重试”与“本次使用默认配对”。后者不删除旧记录，不允许本次未经恢复的调整覆盖未知旧记录；要保存新调整须先成功重试读取 |
| CP7 | 返回与焦点 | 沿用阅读器 Escape/系统返回与设置面板关闭层级；不新增导航层。保存成功不跳页到其他章、不抢焦点，读写错误反馈不因重绘重复弹出 |

只重新配对或恢复边界不得制造阅读进度、完成章节或触发删除下载；真实停稳阅读与后续翻页继续使用既有可见页进度门禁。保留无变化调整的 no-op 行为，不为单页不可调整场景伪造写入。

## 4. 存储与生命周期设计

### 4.1 权威与数据结构

新增共享章级配对 Repository，SQLDelight schema 与 migration 只放在 `data/src/commonMain/sqldelight/`。建议以章节主键为唯一键的状态表（`chapter_id` 外键关联章节、删除级联），保存 `format_version`、调整时 `page_count`；配套边界表保存 `(chapter_id, page_ordinal)` 唯一对。名称可沿用实施时仓库命名，以下约束不可变：

- 一章全部边界以单个事务替换；集合排序去重、索引合法性由共享层验证。清空集合时在同一事务删除状态与边界，不遗留空壳记录。
- 不更新章节阅读字段，不触发同步日志、阅读事件、track 或下载删除。没有记录等价于现有默认行为。
- 保留多个局部边界，不简化为全章奇偶偏移。只保存用户手动边界，图片尺寸和边缘匹配仍从当前内容计算。
- Repository 以稳定章节 ID 操作，调用方必须验证属于当前漫画；不按标题、章号或章节列表排序位置关联。
- 迁移只新增表，旧数据库无需回填；原有进度、书签和下载引用保持不变。章节真正从数据库删除时级联清理；只删下载、标已读/未读或切换模式不清理。
- 备份覆盖、换源或刷新导致章节 ID 删除重建时旧记录不自动转移；不得按相似标题套用。

### 4.2 恢复顺序与竞态

1. 入口确定章节和原有续读页；同时加载该章持久记录及页面列表。
2. 页面列表稳定后验证保存版本、页数及全部边界。合法时一次注入平台配对状态；然后复用现有算法组页，再按续读页定位包含它的组合。
3. 首次呈现只使用已经完成恢复的状态；不得依靠图片解码回调先上报错误默认组合。图片尺寸陆续到达仍沿用现有 layout-only 规则，保留手动边界和逻辑 anchor。
4. 异步读写携带章 ID、会话 generation 与操作序号；旧结果不得覆盖新会话。共享持久服务按章串行受理读写，重开读取须排在已接受的本章保存之后；跨章互不阻塞。缓存不是取消写入的理由。
5. 用户调整通过共享算法计算候选；保存成功才提交呈现变化。保存失败保持旧配对。UI 可串行禁用调整，服务仍需防护多会话访问：同章修改从最新持久状态计算或拒绝过期版本并重新读取，不能静默丢掉另一会话的边界。

### 4.3 页面内容变动与损坏

首版记录使用章内页序，校验页数；不使用会过期的图片 URL，也不额外下载全章计算内容摘要。页数变化、边界越界、损坏数据或未知格式版本时，整份记录暂不应用，不只过滤部分边界后猜测配对；显示一次“章节页面已变化或调整记录不可用，本次使用默认配对”。保留旧记录，允许用户在当前已知页面列表上重新调整，成功事务替换旧记录。

读取 I/O 失败与已读到的无效记录不同：前者遵循 CP6，禁止盲写；后者有明确数据与当前列表，允许重新调整。相同页数但内容重排无法可靠检测是首版限制，用户可用现有调整按钮纠正；若要求自动识别，须单独定义稳定页面身份，不在实现中临时扩大范围。

### 4.4 保存承诺

事务提交后才表现为成功；正常返回、Activity 重建、正常进程退出与再次启动均应恢复。强杀或断电发生在提交前时只保证上次成功状态，不承诺未提交调整。失败不静默降级成“本次有效”的成功状态；唯一会话限定例外是前述无数据库身份文件，并有明确提示。

## 5. 固定验收矩阵

| ID | 操作/自动化场景 | 必须结果 |
| --- | --- | --- |
| A1 | 8 张竖页，实际点击调整，读到 1 基 `[5,6]`；返回并重新打开，再重启进程打开 | 三次都显示 `[5,6]`，数据库进度仍按第 6 页，不退回默认 `[6,7]` |
| A2 | A 章两处局部调整，B 章不调整；A→B→A，并打开另一漫画同名章节 | A 两个边界都保留，其余章无记录且无错用 |
| A3 | 同章连续调整直到边界集合为空，重启 | 记录原子清除，默认配对恢复；未删除其他章配置 |
| A4 | 调整后单页/条漫/双页切换、Desktop RTL/LTR 与自动宽窄窗口切换、Android Activity 重建 | 配对记录保留，无伪造进度；Android 不新增 LTR 入口 |
| A5 | 在线章节调整后切下载阅读；含宽图及 Desktop 自动匹配的章节 | 同一章节身份沿用手动边界；自动匹配优先级沿用现状，解码回调不抹掉调整 |
| A6 | 真文件数据库关闭重开、旧版数据库迁移、事务中途注入失败 | 保存恢复、迁移保留旧业务数据；失败无半份集合、无错误成功反馈 |
| A7 | 延迟读写，保存后立即退出重开、A 切 B、旧会话晚返回、同章并发修改 | 新读见已接受成功写入；旧回调不污染 UI，无丢边界或跨章写入 |
| A8 | 页数变动/非法索引/未知版本，以及 I/O 失败后重试/本次默认 | 各走第 4 节对应分支，反馈准确；不盲覆盖、无半有效集合 |
| A9 | 已读/未读、末页双页、布局调整本身、删除下载与删除章节 | 保护现有进度和已读语义；下载删除保留配对，章节删除清理配对 |
| A10 | 两端真实调整按钮、真实 DI、共享仓库、应用重建；临时文件入口 | 任一接线断开测试失败；临时文件不写章 0，显示会话限定提示 |

Android/Desktop 相同行为用共享契约覆盖，并分别通过真实平台接线执行；文件库恢复和 UI 事件测试不可被内存 fake 或源码字符串扫描代替。手工复核走 A1–A5；其余以故障注入和集成测试证明。测试名称、运行命令、平台环境、结果及产物由 Roadmap 对应任务在实施时记录；正式运行证据仍待 CP-03。
