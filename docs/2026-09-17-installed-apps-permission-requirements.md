# Android 获取已安装应用列表权限：启动检查与图源页引导

- 日期：2026-09-17
- 状态：需求细化与 HTML 交互原型；等待用户审阅。Android 生产功能尚未实现。
- 审阅入口：[双端 HTML DEMO](prototypes/installed-apps-permission/index.html)，[演示说明](prototypes/installed-apps-permission/README.md)。
- 范围：Android 的启动权限检查、浏览 → 图源提示、用户主动授权、返回刷新及失败反馈。Windows/macOS 无此权限要求。

## 1. 已确认的问题与目标

真机上的 `0.19.4-aex.4` 使用系统软件包安装器。用户确认三个不同插件均可在安装后使用，但杀进程后重启会从图源列表消失；两个插件同时安装也能复现。书架和设置保留。

本次读取真机状态时，系统中仍存在相关扩展 APK；fork 的 `QUERY_ALL_PACKAGES` 已授予，但设备提供的 `com.android.permission.GET_INSTALLED_APPS` 为拒绝且标记 `USER_FIXED`。原版 Mihon 的后一权限已授予。用户随后在系统中开启权限，并确认重启后正常。这是已验证的设备权限问题，不代表已修改或修复 Android 产品代码。

目标：避免将“无权读取系统插件列表”表现为“插件消失”，让用户在真实受影响的页面知道原因、取得权限并恢复图源，整个过程无需重装插件或重启应用。

不包含：自动授予权限、绕过系统拒绝、重装插件、清空数据、修改源 ID、同步权限、改变插件信任策略、替代安装未知应用权限，或修复所有插件兼容性错误。

## 2. 用户需求与验收映射

| 编号 | 需求 | 验收结果 |
|---|---|---|
| PERM-01 | Android 启动后检查应用列表读取权限 | 启动时执行一次真实检查，不自动弹出系统授权框，不阻塞书架和本地阅读 |
| PERM-02 | 未开放时在浏览 → 图源提示 | 页签下、图源列表上方展示持续提示；不只显示短暂 Toast，不需列表为空才出现 |
| PERM-03 | 提供获取权限按钮 | 用户点击后进入系统支持的授权界面；固定拒绝时引导应用权限设置 |
| PERM-04 | 授权返回后恢复已安装插件 | 再次检查实际授权状态，成功后重新扫描并更新 ExtensionManager → SourceManager → 图源页 |
| PERM-05 | 取消或拒绝时仍可使用其他能力 | 提示保留；本地和已可用私有图源继续可用，不循环请求 |
| PERM-06 | 兼容无需额外权限的设备 | 系统未提供此额外权限时按正常发现流程运行，不显示虚假的未授权提示 |
| PERM-07 | 运行期间撤销权限及错误可恢复 | 返回前台重新检查；权限未知、权限拒绝和插件读取失败使用不同反馈 |

## 3. 检查时机与平台边界

1. 在 Android 应用依赖初始化完成后检查，作为系统插件发现结果是否可信的依据；不阻塞主线程。进入图源页时订阅同一状态，必要时刷新；不得由多个页面重复建立检测器。
2. 授权界面返回、应用重新进入前台时重新检查，覆盖用户在系统中撤销或开启权限的情况。页面重组不重复请求；合并短时间内的重复刷新。
3. 本次观察到的权限名是 `com.android.permission.GET_INSTALLED_APPS`。它是该设备实际提供的额外权限，不能假设所有 Android 版本或厂商都支持，也不能仅依据品牌硬编码“已授权/未授权”。
4. Android adapter 应查询系统是否提供相关权限、该应用是否受其控制及当前授权状态。未提供该额外权限时返回“不适用”；查询异常返回“未知”，不得当作拒绝。
5. `android.permission.QUERY_ALL_PACKAGES` 与该设备额外的应用列表权限分别检查，不得以标准权限已授予替代额外权限检查。安装未知应用的 `REQUEST_INSTALL_PACKAGES` 也不能代替读取权限。
6. 不根据扩展数量为零、网络失败、仓库加载失败或某个扩展无法加载推断权限拒绝。权限允许也不保证每个扩展均兼容或可信。
7. 权限决定由操作系统保存。应用只保存必要的瞬时检查/加载状态；不得缓存一次允许结果并永久跳过检查，也不将权限状态同步至其他设备。
8. 私有插件和本地图源不依赖系统安装列表。权限提示不应屏蔽它们，也不能清除书架、插件文件、信任记录或用户筛选设置。

## 4. 页面文案与布局

入口：**浏览 → 图源**。沿用现有 Android 浏览页的图源 / 作者 / 插件 / 迁移页签与五项主导航，不新建页面或主导航。

在页签下方、语言/置顶分组之前插入完整宽度的提示卡。与图源列表一起滚动，进入页面即可看见；保留其余图源操作，不用全屏遮挡。切换其他页面不显示此卡，返回图源页仍可见。无关闭按钮，不将拒绝状态藏入一次性通知。

- 标题：**无法读取已安装插件**
- 主提示（按用户要求保留）：**需要允许“获取已安装应用列表”权限，否则无法读取已安装的插件列表**
- 补充说明：**已安装的插件无需重新安装。本地和私有图源仍可使用。**
- 主按钮：**获取权限**

主提示中的“插件列表”指受系统权限限制的共享 APK 列表；补充说明明确私有插件例外。即使部分图源已在本次会话中通过安装事件加载，也必须显示提示，不能把该瞬时成功当作下次冷启动能发现全部插件的证据。

按钮使用现有 Material 样式，最小触控区域 48dp，支持读屏。提示信息随状态变化以适当 live region 宣告；不每次重组重复朗读。窄屏下文案换行、按钮完整显示，深浅主题保持对比度。

## 5. 授权与返回流程

```text
启动 / 返回前台 → 检查权限
  ├─ 系统无需额外权限或已允许 → 扫描插件 → 更新图源列表
  ├─ 未允许 → 图源页提示 → 用户点击“获取权限”
  │                         ↓
  │                系统授权界面 / 本应用权限设置
  │                         ↓ 返回 Mihon 后真实复查
  │                ├─ 已允许 → 撤下权限提示 → 读取中 → 图源恢复
  │                └─ 仍拒绝 → 提示保留，不自动再次弹窗
  └─ 检查异常 → 检查失败提示与“重新检查”
```

- 用户点击才请求权限；初始启动和仅进入页面不弹框。系统支持且允许再次请求时可使用系统权限请求；固定拒绝、无法请求或厂商专门管理时转入该应用的权限设置，不能循环调用请求 API。
- 必须确认跳转目标存在并捕获跳转失败。优先进入本应用的可用权限设置，必要时回退应用详情；不得打开无关权限或其他应用设置。
- 不能用按钮点击、Activity result 为成功或“打开过设置”作为授权成功判据；返回时重新读取系统授权状态。
- 授权成功后隐藏权限卡，显示“正在读取已安装插件…”。执行现有扫描、信任/兼容性检查与注册链路，图源结果就绪后结束读取状态。不得要求手动重装、重启，或新建旁路插件加载器。
- 返回后仍未允许：保留提示及按钮，可补充“尚未开放权限。你仍可使用本地和私有图源。”不自动重开授权界面。下一次用户主动点击才再次尝试。
- 用户在其他页面授权返回时后台刷新，不强制跳转图源页、不抢焦点；随后进入图源页看到最新结果。
- 正在检查或跳转期间防止重复点击；在途扫描使用同一生命周期/刷新代次，较早结果不得覆盖较新的撤权或授权状态。

## 6. 状态与失败反馈

| 状态 | 图源页表现 | 用户动作及后续 |
|---|---|---|
| 检查中 | 正在检查插件列表权限…；保留不依赖此权限的图源 | 等待结果，不先闪现“无插件”或请求授权 |
| 未允许 | 第 4 节提示卡 | 获取权限；本地/私有图源继续可用 |
| 已允许 / 不适用 | 正常扫描、展示图源 | 不显示权限卡 |
| 正在读取 | 正在读取已安装插件… | 合并重复刷新，不重复要求授权 |
| 未授权返回 | 提示卡仍在，说明尚未开放 | 用户可继续其他操作或主动再次授权 |
| 设置跳转失败 | 无法打开权限设置；提供手动路径说明 | 系统设置 → 应用 → Mihon → 权限；说明不同设备入口可能不同，提供重新检查 |
| 检查异常 | 暂时无法确认权限状态；这不表示插件已卸载 | 重新检查；不得冒称拒绝 |
| 已授权但扫描失败 | 插件读取失败；无需再次授权或重新安装 | 重试读取，保留有效结果；具体扩展信任/兼容问题进入原有错误链路 |
| 前台复查发现权限被撤销 | 恢复权限提示；系统列表状态不再标为完整可信 | 不清空持久数据、不诱导重装；既有可用实例与系统列表完整性分开管理 |

与[建议安装需求](2026-09-16-extension-install-suggestions-requirements.md)的关系：权限检查中、未知或明确拒绝时，系统安装清单不完整，不能据此推导“已卸载”并批量推荐重新安装。该约束属于后续生产接入；本次不扩展建议安装 DEMO 的模型。

## 7. 复用方案与实现边界

| 当前代码 / 资产 | 后续生产或原型复用方式 |
|---|---|
| `app/src/main/java/eu/kanade/tachiyomi/extension/util/ExtensionLoader.kt` | 保留系统/私有发现、签名、兼容性与类加载逻辑；在其生产入口接入权限状态，不另建扫描器 |
| `app/src/main/java/eu/kanade/tachiyomi/extension/ExtensionManager.kt` | 在现有初始化/刷新链路发布权限与读取状态；授权返回触发同一管理器重新发现 |
| `app/src/main/java/eu/kanade/tachiyomi/source/AndroidSourceManager.kt` | 沿用已安装扩展流更新图源注册，不能只修改 UI 列表让图源看起来恢复 |
| `app/src/main/java/eu/kanade/tachiyomi/ui/browse/source/SourcesScreenModel.kt` | 用现有状态管理承接检测状态与用户授权/重试事件 |
| `app/src/main/java/eu/kanade/presentation/browse/SourcesScreen.kt` | 在真实图源列表插入提示卡，保留列表布局与现有操作 |
| Android Injekt / Activity 生命周期与权限 API | 权限检测及设置跳转限制在 Android adapter；通过既有依赖注入与生命周期接入 |
| `docs/prototypes/multi-device-sync/` 的外壳、导航、主题、图标 | 同级原型直接加载现有资产，仅以可选 renderer 在 Android 图源页展示权限场景 |

可以直接复用现有发现、注册、导航及列表能力，无理由另起一套插件管理实现。新增权限 adapter 是因为厂商权限与 Activity 跳转属于 Android 平台行为；Desktop 不需要同名设置或无意义的授权按钮。本次文档与 HTML 原型不定义共享数据库字段，不迁移数据，不改变下载/同步协议。
