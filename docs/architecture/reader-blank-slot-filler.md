# 双页阅读器章节内空槽填充

## 目的与边界

双页阅读中，章节内部的半槽单页在另一侧显示白纸和淡灰色应用 LOGO，以保持纸页视觉连续性。此层是装饰，不是漫画页；不分配 ReaderPageId，不产生加载请求、曝光确认、已读进度、保存图片或同步数据。

仅已有排页结果确定为 LEFT/RIGHT 的单页可填充。按真实源页索引排除章节首页及尾页，两页以内章节不填充。FULL、双真实页、章节过渡、单页和条漫模式保持既有显示。已经安排的图片即使尚未绘出、正在加载或失败，也不能作为装饰空槽。共享规则不改变配对决策。

### 2026-11-15 资格修正

半槽外观不是填充资格。共享呈现 owner 在既有发布/绑定更新阶段输出可空的物理空槽；平台绘制只消费此结果。要求当前有效帧与完整单页布局匹配、自身已知竖页、真实源页位于章节内部；从已承诺双页裁剪的残留半槽不填充。普通独页必须具有当前仍有效、与帧布局一致的认证；DEFAULT 仅允许当前已生效、确实覆盖本页的显式强制单页。不能仅凭 reason、certain、帧编号或历史 ticket.source 放行。横跨页前余页也可能因前缀相位改变而配回双页，因此不能默认豁免。

资格计算不新增认证扫描、I/O、计时器或绘制许可；事实不足时不画装饰，真实漫画不等待。资格变化不进入页/帧/图片缓存身份，仅重绘，不能重建 native 图片、重新读取或复位相机。

本轮修复基于平板原 157 的完整提交 `e6245f22ca776e159d7df7bf7891f4a7748a2f6c`，移入填充功能并修正上述资格，保留其预准备队列、原生图片复用、正反翻及加载层收尾。158 的旧分支基线不作为新候选来源。两基线 SQLDelight schema/migration 无差异；升级仍通过既有签名及更高 versionCode 校验，不清除数据。

## 展示与生命周期

- 采用当前 Desktop 应用 LOGO 的圆环和漫字轮廓，去除方形底色，颜色为 #BDBDBD。
- 左侧空槽图案顺时针旋转 25 度，右侧逆时针旋转 25 度；不反写字形。
- 图案直径为纸页宽度与纸页高度 62% 的较小值；圆心位于纸页宽度 28%（左）或 72%（右）、高度 84%，图案裁在纸页内。
- 纸页与真实页使用同一整组缩放、平移和复位状态。纸页几何独立于 LOGO 加载结果，图案迟到不得重置变换或重新定位真实页。
- Desktop 的平移边界包含白纸矩形，使用户放大后可以正常移动查看填充页；圆章自身的出血范围不扩大边界。未启用填充的空槽继续沿用原有边界规则。
- 进入阅读器时异步加载本地单色资源，白纸绘制无需等待 LOGO。失败时保留白纸，不阻塞漫画加载，不发起网络重试。
- 不在翻页时生成整页 Bitmap，不将装饰内容交给图片配对、采样或真实页绘制确认链。

纸页基准几何由平台现有布局和图片尺寸计算；不能把像素尺寸加入 domain 会话。使用已有尺寸时不额外打开漫画编码流。暂无尺寸时使用布局默认竖页框，真实内容不等待装饰。

## 验证约束

共享契约覆盖内部左右空槽与首页/尾页排除。平台测试执行真实渲染与接线，检查白纸及图案像素、加载/失败槽位排除、整组缩放和平移以及 LOGO 异步到达后变换不变。装饰不能导致额外阅读进度。

性能目标是消除翻页路径上生成装饰图片的异步等待；应用绘制开销及到屏延迟必须通过对应平台实际测量，不使用离线 Pillow 预览数据代替产品性能证据。
