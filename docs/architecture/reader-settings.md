# 双端阅读模式设置

交互基线为已审批的 [双端原型](../prototypes/reader-mode-default/README.md)。原型只确认设计；原生实现的验证以 Android 与 Desktop 的 production/wiring 测试为准。

## 状态与持久化

`domain` 的 `ReaderSettings` 是双端共同的设置契约。阅读模式分为横向与纵向；横向包含自动/单页/双页及左右方向，纵向包含连续/逐页及连续页面间隙。隐藏的方向、布局、间隙和双页自动匹配值保留，不因切换界面分支而重置。

作品仍通过 `Manga.viewerFlags` 保存，不引入数据库列或另一个作品配置存储。`ReaderSettingsCodec` 负责有效值、单独设置快照和默认继承之间的转换；平台负责将它接入已有偏好、reader viewer 和保存链路。选择默认时 active mode 为零，完整自定义快照保留；恢复单独设置时由同一快照产生 active mode。默认摘要展示有效值，不能展示隐藏自定义值。

全局偏好保留旧模式和匹配键作为有效值权威，另外保存完整快照以保留隐藏选项。Android 的隐藏快照键为 `reader_default_settings_snapshot`，Desktop 为 `reader_settings_snapshot`；读取时将旧模式/匹配键叠加到快照，写入时同步更新。这些平台偏好适配不改变共享作品 flags 的格式；首次启用单独设置可用默认值初始化，之后全局默认的修改不会覆盖已保留的作品自定义快照。

快照占用 flags 的位 6–12，存在标记为位 18。原来的模式位 0–2、方向锁定位 3–5、Desktop 旧布局位 32/33、旧自动位 34 及无关位均按各自契约处理。新增自动从左向右使用位 29 加低位模式 1；双页从左向右继续使用位 30 加低位模式 1。新增配置均能通过 Android 现有 Int 备份格式保存。旧客户端不理解新增模式时仍能回退为单页 LTR。

快照布局编码固定为 AUTO=0、SINGLE=1、DOUBLE=2；不可通过重排枚举改变已有编码。后续新增字段或编码必须先用旧 flags 夹具验证兼容，不能占用已有模式、方向锁定或扩展标记位。

没有快照的旧数据按实际模式懒转换：1/2 为横向单页，3 为纵向逐页，4 为纵向连续无间隙，5 为纵向连续有间隙，6/8 为横向双页，7/9 为横向自动。旧 Desktop 布局覆盖继续保留；旧 mode 0 加布局覆盖沿用原来的默认阅读模式，默认纵向时布局只作为隐藏值保留，不强制转为横向。快照与 active mode 不一致时，以 active mode 的显式字段为准，保留其余隐藏字段，兼容快捷模式入口和旧版本的模式更新。

## 原生边界

Android 复用已有 pager、vertical pager、webtoon viewer 和共享自适应布局。Desktop 的纵向逐页必须使用真实竖向 pager，不能将 flags 3 降级为横向单页。双端的匹配与间隙来自有效设置，不能只改变控件选中态。

Desktop 的 `initialReaderSettings` 是启动投影与完整 `ReaderScreenModel` 的唯一设置解析入口。`ReaderFirstComposition` 接受晚到页表前，按完整有效设置重新校验，不能只比较旧全局单双页/匹配字段。提前请求设置沿主干既有链路解锁完整模型；页表到达后继续保留已选择的设置和作用域。纵向逐页不进入横向单页启动视图，保留原有 early 输入、当前页需求及图片交接机制。

横向没有从上到下选项。自动与双页显示匹配选项，单页隐藏；连续纵向显示页面间隙开关，逐页隐藏。开关不附加是/否文字，辅助技术仍读取 checked 状态。图标沿用原型的 24×24 细线图形与主题颜色。逐页图标改编自 Lucide `gallery-vertical`，双端分别打包 `res/raw/reader_icons_license.txt` 与 `resources/icons/reader/LICENSE` 中的 ISC 声明。

Android 与 Desktop 的原型视觉由 `presentation-theme/src/commonMain/kotlin/tachiyomi/presentation/reader/settings/` 的 `ReaderModeSettingsContent` / `ReaderModeChoices` 统一承担，作品弹层、快捷入口和全局设置复用同一套真实视图。现有 KMP 表示模块已具备 Compose、domain 与 i18n 依赖，因此不另建模块或视觉副本；平台 adapter 只提供本地化字符串、外层容器和既有偏好/作品保存回调。作用域、单双页、滚动方式采用完整底槽的等宽分段控件；模式采用图标、说明和单选标记卡片，方向采用箭头卡片，开关采用带说明的整行卡片；默认继承使用分行摘要，自动布局继续附带当前实际单/双页信息。选中填色从当前 MaterialTheme 的 surface 与 primaryContainer 混合，保留原型的柔和层次而不锁定深色或蓝色主题。装饰图标不重复朗读；整个选项承担 RadioButton/Switch 语义、焦点提示以及 Enter/空格操作，更新仍调用原有状态与保存入口。文本允许随窄窗口和字号换行；不以截断说明或固定整行高度维持卡片外观。Windows 体验包 `0.11.24.10.c95438e` 已经用户验收；Android 接入同一控件后的组件测试和原生绘图证据，不等同于用户对 APK 的体验验收。

模式切换不另建章节加载、图像解码或进度权威；继续使用现有阅读器的呈现变更、进度和配对失效链路。读取旧数据不批量写回；用户显式修改设置时才保存规范化 flags。偏好保存失败沿用平台原有失败处理，不以临时 UI 选中态证明持久化成功。

双端阅读器的「自动放大横向图片」「拆分双页」「旋转横向图片」及其反转方向，只在显式「横向阅读 → 单页」时显示并生效；自动布局即使当前实际采用单页，也不启用这些扩展。条件来自共享 `ReaderSettings.singlePageExtrasEnabled`，不按 viewer 的瞬时宽高比猜测。隐藏时保留偏好；拆页反转随单页拆分显示，旋转反转随单页旋转显示。Android 的 PagerConfig 与 WebtoonConfig 同时限制实际图像配置，不能仅隐藏 UI。

Desktop 阅读模式页的扩展顺序对齐 Android：点按区域、反转点按区域、分页缩放模式与缩放位置、裁边、单页图片选项及平移导航；连续纵向改用独立点按设置、0–25% 侧边留白滑杆、裁边、双击缩放与禁止缩小。默认导航在连续纵向采用 L 形，在分页采用左右区域；禁用点按时隐藏反转选择。背景色移到「常规」，弹层移除章节导航/跳过设置与条漫自动滚动入口；既有全局偏好和独有能力不删除。

Desktop 新扩展使用 `ReaderDisplayOptions` 组织现有偏好适配器的独立稳定键，仍由 ReaderScreenModel 保存和投影；翻页动画复用原 `page_turn_animation` 键，条漫留白百分比未保存时从旧枚举读取。此模型不增加作品 flags。实际输入、原生缩放、已有图像变换 lease、共享章节呈现策略及系统 adapter 消费这些值；旋转沿已有派生位图内存权威释放，旋转状态不叠加未旋转源坐标的区域 tile。非默认扩展设置通过原有完整阅读器入口呈现，轻量首开不使用不完整的偏好投影。

两端常规页将闪烁、水波纹及相关样式/时长/间隔放在 E-Ink 标题下。Desktop 补齐背景、页码、全屏、屏幕常亮、长按菜单、章节过渡和翻页动画；屏幕挖孔选项依赖 Android 的物理 cutout 能力，Desktop 不显示无对应窗口语义的项。Windows 常亮通过周期性系统执行状态请求，macOS 通过可取消的 caffeinate 子进程；退出或关闭设置停止保活，Linux 暂无此 adapter。长按菜单保留 Desktop 的右键入口；页码和 E-Ink 层不持有图片或导航权威。E-Ink 只随既有已选页/单元变化触发，初次挂载、重复通知及章节入口不闪烁，取消和快速连续翻页清除旧遮罩。

开启分页分割时关闭宽页旋转，开启旋转时关闭分页分割；隐藏时不改写已存偏好。Desktop 继续使用 `autoSplitPages`，Android 继续使用 `dualPageSplitPaged()`；不映射到条漫独立分割键，不改变分切算法或配对算法。Android 屏幕方向等平台能力继续保留。

## 维护与验证

设置 → 阅读中的全局模式控件由共享 `DefaultReaderModePreference` 收纳为「默认阅读模式设置」入口。标题下只显示一行当前值，窄屏以省略号显示，辅助技术仍可读取完整文本；点击后打开可滚动的完整模式设置弹窗。弹窗使用同一 `ReaderModeChoices`，不展示作品级默认/自定义作用域，每次选择继续即时保存，关闭/遮罩/返回只关闭窗口，不撤销已保存值。全局摘要中的自动布局仅表示自动规则，不在没有阅读区域时伪造当前单/双页结果。Desktop 搜索锚点与目录使用新入口标题，原模式关键字继续定位到该入口。此收纳不影响作品阅读器中的设置弹层或其余阅读偏好。

双端的「双页自动匹配」「页面有空隙」继续共用 `ReaderModeSwitch` 的右侧椭圆开关、说明卡片、焦点与键盘行为；「拆分双页」按用户要求使用无说明的勾选框。共享模式控件需要由平台 adapter 提供 `ReaderSettingsTextScope`；遗漏接线时明确失败，不回退为空字符串或错误语言。控件不附加是/否文字，状态由图形及辅助技术的 checked 状态表达。

共享契约测试为 `ReaderModeFlagsContractTest` 与 `ReaderSettingsContractTest`，覆盖旧模式、隐藏值、默认恢复及 Int 格式往返。平台回归必须覆盖真实设置入口点击、保存/重开、默认摘要以及实际 viewer 选择；共享模型测试不能替代平台接线。

日常只运行这些行为及受影响 reader 路径的 focused tests，不因本页或原型审批触发完整模块测试、正式构建或版本发布。原生功能仍需用户体验验收后才能更新公共功能承诺。
