## 1. 类别与模板的交互约定

- 用单选“问题类别”替代用户填写标题；默认“请选择问题类别”，不预选，提交前必须选择。
- 每次只报告一个主要问题；无法判断时选择“其他／不确定”。
- 服务端从稳定类别 ID 生成公开标题 `【问题反馈】<类别中文名称>`，不让客户端传任意类别标签。
  该标题满足既有 5–120 码点限制；用户仍在提交前看到将公开的类别与描述。
- 共用模板与类别 ID 放进共享模块，两端消费同一版本；英文 UI 提供对应翻译，不以翻译文本作为 ID。
- 普通类别使用通用模板；只有 `reader` 使用“通用模板 + 阅读器定位段”；`feature_request` 使用建议模板。
  **通用模板不得出现阅读器定位段**，不要求其他类别填写源、作品、章节或页码。
- 选中类别后预填，可直接修改。提示“不确定的内容可以写‘不清楚’，不适用的段落可以删除”。
  空白或尚未修改的模板可以随类别切换；有用户修改时先保留草稿，只有用户确认替换才换成新模板。
  切换取消不丢草稿。禁止每次重绘或重新打开验证页时重新填入模板覆盖输入。
- 原样模板和只有提示语的描述不能提交，须给出用户实际问题或建议；该校验需覆盖中英文，不靠固定字符长度冒充有效内容。
- 这些模板属于公开描述；设备信息默认勾选且可取消，按类别自动准备的日志仍只供维护者查看，详见第10节。
  截图只在用户主动选择后附加，私密说明可见；最终明确提交授权可见附件，不自动读取相册。

| 稳定 ID | 中文名称 | 模板 |
| --- | --- | --- |
| `startup_crash` | 崩溃或无法启动 | 通用 |
| `performance` | 卡顿、无响应或资源占用过高 | 通用 |
| `source_network` | 漫画源、扩展或网络连接 | 通用 |
| `browse_details` | 搜索、浏览或漫画详情 | 通用 |
| `reader` | 阅读器、图片或翻页 | 通用 + 阅读器定位段 |
| `library_progress` | 书架、分类或阅读进度 | 通用 |
| `download_local` | 下载、离线阅读或本地文件 | 通用 |
| `backup_sync` | 备份、恢复或多设备同步 | 通用 |
| `update_install` | 应用更新或安装 | 通用 |
| `interface` | 界面显示或操作异常 | 通用 |
| `feature_request` | 功能建议 | 建议 |
| `other` | 其他／不确定 | 通用 |

## 2. 通用问题模板（用户修改版）

以下正文保留用户将错误提示改为“原文或附上截屏”、删除末尾私人信息提醒的修改。
Markdown 富文本快照中的换行转义和下划线转义还原为普通文本，不是模板中的反斜杠。
“附上截屏”只有在本文件截图能力实际通过验收的候选中启用；仅更新模板的候选先显示“请填写原文”。

```text
【遇到了什么问题】
请把这句话改成你的情况：我在______页面，进行______操作时，出现了______。

【如何再次遇到】
1. 打开……
2. 点击／操作……
3. 出现……

【期望的结果】
我原本希望……

【实际的结果】
实际发生了……
如果有错误提示，请填写原文或附上截屏

【出现频率与影响范围】
出现频率：每次都会／偶尔出现／只出现过一次／不清楚
影响范围：所有内容／部分内容／不清楚
相关漫画、章节或漫画源（如适用）：

【补充信息（可选）】
大约从什么时候开始？之前是否正常？
已经尝试过哪些解决方法？结果如何？
```

## 3. 仅阅读器类别追加的定位段

仅 `reader` 的模板，在“遇到了什么问题”之后、“如何再次遇到”之前插入以下段落。
保留其余通用正文；定位信息不自动从当前漫画源、书库或阅读历史采集。
每项均引导填写；不清楚可写“不清楚”，长条模式用大致位置代替页码，不阻断无法定位的反馈。

```text
【问题发生位置】
漫画源：
作品名称：
章节名称或编号：
页码：第______页／不清楚
如果是长条阅读，请描述大致位置：
```

## 5. 截图的用户路径与权限

首期只在 Android/Desktop 应用内反馈添加截图；旧网页/旧客户端继续兼容，不扩大到网页附件编辑器。
沿用已实现的共享表单、控制器、验证会话及最终提交，平台差异限于选图/解码/编码 adapter。

1. 点击“添加截图”，通过系统选择器选择已经存在的 PNG/JPEG；可追加到两张。
   不自动截取屏幕、不读取剪贴板、不扫描相册/目录，不申请整库访问权限。
2. 本地校验、转码后显示最终待上传图片的缩略图、可放大预览、序号与实际大小；逐张可删除或更换。
   用户应先在系统图片工具中裁剪/遮挡私人内容；本期不新增内置涂抹、裁剪或 OCR 编辑器。
3. 明示“截图仅供项目维护者查看，不会公开到 GitHub；请检查画面中的私人信息”。
   截图选择不等于发送；沿用户指定原型不再增加截图授权checkbox，最终明确提交授权当前可见的私密附件。
   添加、更换、删除、重排或重新编码后重新固定待提交快照，不复用已经完成的验证。
4. 没有最终明确提交不得发送；用户可移除截图后只提交文字/日志，处理失败不得静默丢附件后继续提交。
5. 最终提交前的图片只留进程内存；正常关闭表单或离开复现保留本进程草稿，移除/成功后释放。应用退出后不恢复敏感草稿，不新增永久图片缓存。
   不修改原文件，不将图片/路径/文件名写入持久草稿、测试产物或普通日志。
6. 发送时固定类别、描述、日志与图片快照；等待验证码时不可改图。取消/失败/同编号重试与现有反馈语义一致。
   发送开始后取消不等于撤回；不自动在后台继续上传。

## 6. 图片与请求限制

KiB/MiB 均为二进制单位，MB 沿用托管方十进制标注。客户端与服务端使用同一组整数常量。

| 项目 | 首期规格 |
| --- | --- |
| 数量 | 每份报告 0–2 张 |
| 本地输入 | PNG、JPEG；拒绝 GIF/APNG、WebP、HEIC、SVG、PDF、压缩包及其他类型 |
| 输入资源上限 | 每张源文件 ≤10 MiB；解码前检查宽高与乘法溢出，≤16,000,000 像素，单边 ≤16,384 |
| 待上传格式 | 全部转为静态 JPEG，只上传解码后重新编码的副本，不直传原文件 |
| 尺寸 | 保持比例、方向校正、不放大，最终长边 ≤1920 像素 |
| 大小 | 每张最终编码 ≤524,288 字节（512 KiB）；两张合计 ≤1,048,576 字节（1 MiB） |
| 处理顺序 | 全部在本地转 JPEG，质量 85→75→65；仍超限则明确拒绝，建议裁剪后重新选择 |
| 元数据 | 转为 sRGB，清除 EXIF/GPS、注释、缩略图、文件路径等；只保留渲染所需的格式信息 |
| 清晰度 | 展示实际最终编码的预览；不静默截掉内容，不强行降到更低质量/尺寸以通过限制 |
| 传输 | 版本化 JSON 中每张标准 Base64（无 data URI）；完整请求流式上限 2,097,152 字节（2 MiB） |
| 其他字段 | 沿用原描述/摘要/日志限制，日志仍 ≤256 KiB；无截图旧协议仍使用640 KiB上限 |

本地输入上限用于防止内存/解码炸弹，不代表能上传10 MiB。两张图串行处理，不同时解码；
移动端预览采用采样解码，不把原尺寸图片长时间留在共享状态中。JPEG 透明区域以白色合成，预览须一致。
客户端使用既有平台图片能力，不引入完整浏览器、云转码或图像识别服务。
服务端独立验证 Base64、解码字节数、文件签名、完整容器结构、宽高、静态格式、无多余尾随载荷及禁止元数据，
重新计算 SHA-256；不能仅相信扩展名/MIME/客户端哈希。不声称这些结构校验等于完整像素解码或恶意文件扫描。
服务端只接受最终JPEG，对marker/segment长度、元数据与尾随载荷有恶意夹具覆盖；源PNG不作为上传格式。解析有界且不能执行文件内容。
实施前验证所选解析依赖在 Free Worker CPU/内存范围内；不可行时停止该实现分支、报告具体约束，不静默放宽校验或启用付费云解码。

## 7. 服务协议、私密存储与容量

### 7.1 兼容与内容绑定

- 新协议显式 `protocolVersion: 2`；类别 ID、截图列表和 `screenshotConsent` 为白名单字段。
  无图的新类别报告也使用v2；原v1及旧网页的title、四段native哈希、幂等哈希与限制保持原样。
- 配置接口增加可选截图/v2能力与限制。旧服务缺字段时新客户端禁用该入口并解释原因，不能把图片转贴公开描述或外部图床。
- 每图由客户端生成 UUIDv4，附 MIME、最终宽高、字节数、SHA-256、Base64；不传源文件名或路径。
  服务从图片字节重新算出所有可验证字段，未知字段/类别/重复图片ID/数量超限均拒绝。
- v2 内容绑定使用现有“ASCII字节长度 + 冒号 + UTF-8值”的分段编码并 SHA-256。
  固定顺序：`mihon-feedback-v2`、categoryId、服务端生成的title、规范化description/summary/crashLog、
  图片数量的十进制字符串，随后按列表顺序为每张追加 id、MIME、十进制width、height、byteLength、64位小写sha256。
  正文规范化沿用现有ECMAScript trim契约，日志不trim；服务端独立构造该向量。
  图片顺序、内容或类别改变必须生成新提交UUID/新验证会话，防止用已验证快照替换附件。
- 浏览器仍只处理随机会话ID与Turnstile，不接收图片、正文、日志或native bearer。
  报告+全部图片+配额记账+会话消费必须在同一D1事务成功才返回202；失败回滚、保留本地草稿。
  无分片上传、暂存匿名图片或不带验证码的单独上传接口，避免孤儿文件和滥用入口。
- 相同UUID及完整内容重试返回原回执，不重复计费配额/存储；相同UUID换图或类别返回409。

### 7.2 复用D1的首期方案

- 复用当前私有 `DB`，新增独立 `report_screenshots` 表，一图一行 BLOB，外键关联报告；
  字段包含 submission_id、attachment_id、ordinal、mime、width、height、byte_length、sha256、created_at、data。
  原报告新增默认false的截图独立授权标记；旧行与旧日志不得重写。序号/图片ID唯一，非空图必须有授权。
- 数据通过绑定参数写 BLOB，不把Base64/二进制拼接进SQL或长期存成Base64 TEXT。
  512 KiB 单行远低于D1的2,000,000字节单行限制，同时与报告分行，避免触碰行上限。
- 截图与报告/日志同为正常Cron下最多30天，清理不依赖GitHub token；删除报告同步删图。
  Cron故障会延长保留。D1 Time Travel/平台备份可能仍保留恢复窗口，不能宣称物理即时抹除。
- 首期截图池设**32 MiB在库编码字节硬上限**，由事务内计数维护，避免每次全表扫描BLOB；
  配额不足返回可识别的附件容量错误且不落任何报告、不消费会话。保留图片和草稿，让用户选择稍后重试或主动移除截图。
  无图反馈不受截图池上限约束，仍受原报告及托管平台总配额约束；绝不自动删除未到期图片腾空间。
- 该上限最多容纳32份满1 MiB截图的报告，也可容纳更多小图报告，**不保证50份/天均能带图**。
  原50份/天×30天×256 KiB日志已约375 MiB；截图池另占最多32 MiB，仍需为正文、索引、页开销保留空间。
  维护者监控实际数据库体积与读写用量，接近450,000,000字节时关闭新截图接收并排查；
  清理后SQLite可能复用空页而不立即缩小物理文件，不用“删图后文件大小一定下降”判定失败。
  Free总容量/读写耗尽时连文字也可能失败；保留草稿、提示稍后重试，不自动升级付费。
- 免费D1是小范围测试的有界方案，生产图片存储不应无限扩容到数据库。
  若32 MiB池经常耗尽，再单独评估R2；R2虽有免费额度但需启用订阅/结账流程，不能当作本次零配置、无计费设施。

### 7.3 可见性与提取

- 截图按用户既有“仅维护者可见”偏好处理，不在GitHub Issue、公共回执/错误、验证页或静态站点输出。
  Cron只读取“有私密截图”的布尔值，不读取BLOB、文件名、哈希或私密下载链接；公开描述只提示存在私密附件。
- 无匿名预览/下载URL，无公开图床，无客户端维护者token。维护者沿用Cloudflare OAuth提取到仓库外新文件。
  扩展既有导出工具的安全边界：严格UUID、按张读取、校验长度/hash/格式、只生成受控序号文件名、禁止覆写/目录链接绕行，
  不在命令输出中打印图片Base64。无需新建维护后台或给最终用户GitHub账号。
- 32 MiB池和30天限制不包含维护者导出的本地副本；副本仍由维护者按既有权限和删除规则管理。

## 8. 实施时的固定验收边界

本节用于以后实施，不表示本轮执行了产品测试。类别/模板可以独立交付，截图必须先完成服务协议与隐私审查，再接双端。

- 真实类别选择/切换/编辑事件：未选不能提交、原样模板不能提交、编辑不丢失、只有reader出现四项定位字段、建议使用专用模板。
- Android/Desktop共享行为契约，加平台选图adapter的取消、拒绝格式、读取失败、旋转/透明、字节/像素边界与不覆盖原文件。
- 最终预览、放大、移除/更换、快照重建、忙时锁定、错误保留草稿、无图路径、浅深主题/大字号/键盘与返回焦点。
- 真实HTTP/SQLite：两图+日志最大组合、伪造MIME/尺寸/hash、损坏/动画/超限图、重复ID、未授权、容量并发、回滚、幂等、v1兼容。
- 两端与Worker共享v2哈希固定向量，保留已有Unicode trim、secret隔离、403/429/500等契约。
- 免费Worker实际运行预算与真实D1 BLOB绑定/事务/安全导出校验；测试环境不能以SQL文本扫描代替行为。
- 用户亲自验证码 + 明确获准的虚构截图，正常接收/私密导出内容一致；公开GitHub及响应不含像素内容、路径或附件访问能力。
- 原生候选从入口完成实际选图与提交；服务脚本/浏览器测试不能冒充原生路径。公共能力说明在具体候选获用户验收后再更新。
- 设备信息与自动日志/临时调试模式以后述第10节验收为准，不能沿用旧“必须点击读取日志”的测试断言。

## 9. 官方约束核对

## 10. 设备信息、自动日志与临时调试模式（2026-10-17设计修订）

### 10.1 用户确认与现状

用户确认：**只有崩溃类别附加崩溃日志，其他类别只附加对应类别调试日志**，不把所有日志打包混传。
此修订是设计变更，不代表当前程序已经默认只记录崩溃或能够按类别采集/附加日志。
当前共享草稿的 `includeSummary=false`，日志仍需显式读取及单独勾选授权；实施时必须替换该交互。

已核对的实现缺口：

- Android `App.kt` 的普通发布运行仍安装INFO级别AndroidLogcatLogger，并有可选HTTP HEADERS/Coil DebugLogger。
  `CrashLogUtil.readFeedbackLogs()`目前读取本应用UID的ERROR级logcat；ERROR不等于崩溃，且不是分类持久诊断日志。
- Desktop `CrashHandler`已持久化崩溃日志及轮转；共享控制器/现有日志reader没有分类、日期目录、临时会话生命周期。
- 后续应复用异常捕获、HTTP生产链路、共享偏好/状态与反馈提交，不复制另一套网络客户端或读取全设备logcat。
  仅把现有logcat改成更详细级别，无法满足“默认只记录崩溃、按类别、持久日期、可自动停止”的目标。

### 10.2 设备信息默认附加

- 每次创建新的反馈草稿，“附加设备信息”默认勾选；用户可取消，预览和最终快照须同步，不在提交时重新勾回。
- 本批沿用已有安全摘要字段：Application、Version、OS、Architecture、Runtime，不因“设备信息”名称扩展采集。
  不添加Installation ID、设备唯一标识、用户名、书库、安装路径或账号；如以后增加型号等字段另行固定白名单。
- 设备信息仍属于公开问题内容，在预览中明确标注将随问题公开；打开表单不会上传任何信息。
  公开内容同意保持原有显式确认，不因默认勾选摘要而自动确认公开授权。

### 10.3 按类别自动准备日志

- 不再要求用户先点击“读取日志”；“附加日志”默认勾选且可取消。选定类别后后台读取该类别的本应用日志索引，自动准备相关附件，显示读取中/有日志/无日志/读取失败。
  切换类别取消旧读取或丢弃过期结果；不得把迟到的旧类别日志放进新类别。
- `startup_crash`按实际事件日期索引新的安全崩溃记录，默认准备今天的记录；历史日期须主动选择，不能拿文件修改时间冒充崩溃时间。
  该类别也可附当天启动诊断日志（若临时采集已产生）。其他类别不附崩溃记录，只准备本类别当天调试日志。
- 本地预览区列出将提交的日期/时间范围、日志类型、字节数与内容，允许查看、编辑精简或移除；
  移除后该份草稿不因重绘自动重新附上，只有主动重新选择/重新读取才恢复。切换类别重新建立该类别附件快照。
- 分类日志日期列表显示最近7天有实际事件的日期，最近在前；默认只附今天。
  历史日期可以由用户主动选择，不能静默把过时诊断日志当作今天的现场。存在昨天日志仍算“今天没有”。
- 所有日志依旧仅维护者可见，不进入公开描述、GitHub、验证码浏览器、公共回执或错误。
  日志区域明确说明自动附加及访问范围，最终“提交问题”这一明确动作同时授权发送可见的私密日志；
  不再额外要求第二次勾选日志授权；原型默认勾选的“附加日志”用于是否发送，可取消且保留当前可编辑内容。服务端仍要求非空日志的明确授权标记，由最终提交事件产生，不能在后台预先发送。
  用户可以移除日志后只提交描述；缺日志不禁止上报。
- 日志最终合计仍≤256 KiB（崩溃+调试也合并计数），本地读取/预览仍有4 MiB上限。
  超限提示用户精简/选择较短范围或移除，不静默截断。现有256 KiB协议只复用传输限制，不能把类别日志塞入公开摘要。

### 10.4 分类采集范围

首期接入下列最小结构化事件，不承诺完整追踪每个模块内部步骤；不能用任意全文日志按关键词猜分类。现有业务只发固定枚举和有界数字，sink只写用户当前明确开启的类别。
阅读器涉及图片网络请求时，其请求结果需带reader上下文标签，不能只记录到source_network而遗漏阅读现场。

| 类别 | 临时调试日志范围 |
| --- | --- |
| `startup_crash` | 初始化阶段、启动/退出阶段、异常类型；崩溃捕获始终保留 |
| `performance` | 真实HTTP耗时与阅读器现有I/O阶段/页码；不新增线程转储、堆转储、屏幕或输入采集 |
| `source_network` | HTTP开始、响应状态码、耗时、失败/取消；沿用现有代理/TLS运行机制，不将原始路由信息、正文或认证头写入分类文件 |
| `browse_details` | 搜索/列表/详情加载阶段、分页结果数量、错误类型；不记录搜索词及整份作品列表 |
| `reader` | 复用真实阅读I/O的打开、列表、解码、首屏与页码，以及图片HTTP结果；不记录图片像素或章节URL，不另建模式/输入追踪器 |
| `library_progress` | 分类/进度操作类型、持久化结果、数量与错误类型；不倾倒书库内容 |
| `download_local` | 队列状态、下载/本地读取阶段、结果码及耗时；不记录原始路径/文件正文 |
| `backup_sync` | 备份/恢复/同步阶段、计数、冲突/错误类型；不记录备份数据、远端凭据或同步载荷 |
| `update_install` | 索引检查、候选校验、安装交接阶段和结果；不改变实际更新/安装行为 |
| `interface` | 本反馈页面已接入的固定操作阶段；不承诺全应用焦点/布局追踪，不记录用户输入 |
| `feature_request` | 可无日志提交；主动临时开启后仅记录本反馈页已有固定操作，不记录不存在的功能 |
| `other` | 本反馈页最小固定操作；不以“不确定”为理由开启全部模块详细日志 |

生产阶段做结构化脱敏：禁止token、Cookie、Authorization、请求/响应body、完整带参数URL、本机私有路径等进入采集文件。
日志的私密可见性不能替代采集时最小化；表单提交本身及验证码链路始终不记录正文、附件或bearer。
书名/章节/漫画源等复现信息仍由用户按阅读器模板填写，不自动扫描阅读历史补全。

### 10.5 当天无对应日志时的引导

日志区示意文案（以实际运行的本地日期替换示例日期）：

```text
调试日志：阅读器、图片或翻页
已有记录日期：2026-10-16、2026-10-15
今天（2026-10-17）暂无该类别的调试日志。

【临时开启，直到下一次问题上报完成】
开启后请返回出现问题的位置，再操作一次。
复现后回到“报告问题”，当天对应日志会自动附加。
不方便复现也可以直接提交，不要求必须有日志。
```

- 今天没有本类别实际事件记录时提供上述入口；已开启但暂无事件则显示“临时记录已开启，等待复现”，不重复启动。
  当天已有日志仍显示日期/范围，允许继续临时记录新的复现，不把“有日志”当作“已捕获问题”。
- 无日志、读取失败、权限/存储不足、文件损坏分开反馈；“开启临时记录”不能伪装为已解决读取故障。
- 开启是显式用户动作，只启用所选类别；不要求安装调试包、重启应用或授予全设备日志权限。
  启动故障可在开启后由用户主动重启复现，但要说明无法运行到捕获器前的故障未必可记录。
- 开启后可离开表单去复现；保留类别与描述的当前草稿，不能为了复现要求用户重新写一遍。
  敏感草稿不新增永久落盘；正常导航往返保留，应用退出/被杀可能丢草稿，需要如实提示。
- 日期按记录事件的设备本地日期展示，同时保存UTC时间及当时offset；跨午夜重新判断“今天”。
  同时显示临时会话起止时间，时区变化或设备时间异常不得改写原时间或承诺日志时间绝对准确。

### 10.6 临时模式生命周期与默认记录策略

- 正常状态仅保留本项目可控的崩溃日志；普通调试、HTTP详细、Coil调试、分类诊断生产/落盘默认关闭。
  Android系统、第三方组件及OS自身可能输出系统日志，不能承诺整个设备logcat只有崩溃；不采集这些无关日志。
  实施时须核对并统一已有verboseLogging开关和logger安装路径，不能一边关闭分类sink一边留下详细全局logger。
- 使用一份共享临时模式状态（类别、会话UUID、开始时间、启停状态），两端持久化在已有偏好链路中；
  日志只写应用私有分类文件，不能把诊断body写进偏好。重启只恢复用户已主动开启且尚未结束的临时模式，不自动开启新模式。
- 首期一次只允许一个临时类别。请求开启另一类别时说明将停止原类别，并由用户明确切换；不删除已记录文件。
  单纯切换报告类别不自动切换采集类别、不读取另一类别日志；界面始终显示当前临时记录的类别。
- 持续显示“正在临时记录：<类别>，下次问题上报成功后关闭”，并提供“立即停止”；关闭表单、取消提交或验证码过期都不关闭记录。
- **“下一次问题上报完成”定义为本设备应用从服务收到已持久接收的202/原回执幂等成功**，不等待GitHub转交。
  下一份成功报告即关闭本设备当前临时模式，不要求同类别；若当前报告类别与采集类别不同，在提交区说明本次不会附上另一类别日志且成功后会停止临时记录。
  其他设备或旧网页提交不远程改变本机状态。失败/超时/未知接收结果保持开启；同UUID重试确认成功后关闭，避免误关。
- 成功后先持久化“已关闭”，再停sink/清理该会话调试文件；重启不能重新开启已完成模式。
  若关闭状态落盘失败，不把停止状态当作已经持久成功，界面明确提示并重试；数据处理不得影响已收到的反馈回执。
- 不另设偷偷延长或自动缩短的时间期限；用户未上报时仍可随时手动停止。
  分类文件最多保存最近7天、所有分类合计8 MiB，单个会话最多2 MiB；到容量上限暂停采集并明确提示，不假装完整捕获、不无声丢弃旧记录。
  到期清理只删除本应用的调试文件，不改用户导出文件或崩溃保留规则；关闭/成功不影响常驻崩溃捕获。
- 不把这里的local调试文件保留期与服务端“已提交私密日志正常30天”混淆；程序不得后台上传采集内容。
