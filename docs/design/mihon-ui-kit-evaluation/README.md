## 实验设计与预算

使用仓库现有原型流程，不引入建站、部署或 Android catalog 构建流程。两个代理：GPT-6 Luna xhigh 核对源码；GPT-6 Sol medium 实施三个代表页面。主代理规划、整合及一次独立验收；实现者先做 focused 红绿验证，主代理最后运行新原型整套浏览器测试一次。仅具体失败项触发定向修复和复验。

用户限定周额度 4%；运行环境没有提供周额度总量与 token 换算。以代理数量、范围和输出上限控制成本：Luna 目标不超过 10000 token，Sol 目标不超过 14000 token，主代理采用定向读取，预估总量约 30000–36000 token（预估，不是用量证明或额度保证）。预计 25–45 分钟。过程不创建 roadmap、逐任务快照或大型 diff 包。

实现者获得原包、现有原型和项目源码；审核发现不提前注入实现，保留原规范效果的观察机会。样本为：

1. 书架与筛选：根容器、搜索、无结果、筛选关闭。
2. 漫画详情与章节多选：普通/选择模式、批量范围、取消和确认。
3. 同步设置：Desktop 扩展能力、即时设置、内部返回和跨设备隔离。

原版 DEMO 为产品语义和外观比较入口，并非严格的“无规范对照组”。没有让同一模型以同样提示再做一次无规范版本，因此不能量化因果提升；能检验的是规则能否被实现、哪些决定仍需补充、有没有不符合规则的成品。

## 当前结论

**适合作为交互检查清单和源码导航，不足以单独承担 Desktop 的可执行设计规范。** “参考源码”与“本次补充的健壮性要求”在原包已有总体声明，并非作者把每条建议都冒充原版事实；问题在于逐条来源、平台映射和验收操作仍不够精确。

它能让实现者注意页面容器、取消语义、多选、即时设置和异步反馈，但复用效果依赖继续阅读当前源码/旧 DEMO。颜色、字体、形状、间距多数写为“沿用现有组件”，没有形成供 HTML/Desktop 使用的数值表及已审核视觉样本。32 类、128 条规则是覆盖面的证据，不代表 128 项都已经验证或颗粒度足够。

### 首轮实施与独立检查

实现者先通过 4 项自写浏览器测试；主代理随后检查真实 DOM、键盘和实际截图，仍发现以下问题。它们是实验的观察结果，不能被修复后的绿灯覆盖：

| 观察 | 规则/含义 | 首轮证据 | 处理 |
|---|---|---|---|
| 取消最后一个章节后仍显示“已选 0 项” | UI-09.02 明确要求零选择退出动作模式 | 进入多选、点选再取消同一行，读取顶栏得到 `已选 0 项` | 要求补行为测试并修复 |
| 打开同步弹层后 Tab 到达背景同步按钮 | UI-14.03 / UI-26.04 的返回/键盘要求需要具体焦点契约 | 实际 `activeElement` 为背景 `sync-open`，不在 dialog 内 | 要求入焦、圈定、背景隔离和关闭恢复测试 |
| 描边图标显示残缺/消失 | UI-22.02/.03：复用图标还必须保留原渲染约束 | SVG 计算样式 `stroke-width:0px`，独立截图可见返回/退出图形异常 | 要求保留 SVG 原属性并复查截图 |
| 不同漫画共享章节下载状态；混合下载确认数量不精确 | UI-08.04 / UI-09.03：稳定实体身份和适用子集 | 实施代码以全局 `c1/c2/c3` 为下载 ID，未按漫画隔离 | 要求跨漫画及混合选择行为测试 |

[首轮详情截图](evidence/first-pass-detail.png)保留零选择与图标问题；[旧版书架截图](evidence/original-library.png)仅作 HTML 外观参照。以上没有证明原版 Mihon 存在同类 bug。

这说明**读取规范有帮助，但没有自动生效的保证**。特别是已有清晰条文仍会被漏实现，必须要求实现前把条款转换为测试，而不能由实现者做完页面后只挑已实现的路径验证。

### 建议补充的最小内容（本轮不自动安装）

1. **逐规则标记来源与适用平台**：`UPSTREAM_OBSERVED / PROJECT_POLICY / DESKTOP_ADAPTATION`；给出固定提交、文件、函数/行号、当前 Desktop 对应组件和例外。全包级免责声明无法替代条目级判定。
2. **Desktop 组件与视觉表**：顶栏、导航、Preference、对话框/Sheet、网格、章节行的当前实现入口、默认参数、尺寸/状态 tokens；按深浅色与窗口宽度保存经审阅的参考截图。HTML 只能使用派生值，不宣称调用了 Compose 组件。
3. **可执行状态表**：每页列“前置状态 → 用户事件 → 新状态 → 副作用 → 焦点/返回目标”。例如：章节选择 `{c1}` → 再点 `c1` → 普通模式；关闭确认 → 下载集合不变、选择保留、焦点回移除按钮。不要只写“行为正确”。
4. **Desktop 键鼠契约**：Escape 分层、Tab/Shift+Tab 焦点循环、窗口变化、滚轮、右键/长按替代、快捷键冲突；选择/搜索/弹层并存时明确优先级。系统 IME 与浏览器 Escape 不能混为一谈。
5. **独有能力附录与证据门槛**：同步的面板会话、即时设置、设备隔离、后台结果及取消影响取自已批准产品设计；条款绑定至少一个真实界面行为断言。修坏事件 wiring 后测试须失败；未覆盖组合明确 `NOT_RUN`。

原包的页面契约模板已有这些字段的骨架；改进重点是为 Desktop 填好可复用实例、给出精确状态和组件默认值，并让任务路由实际要求验证，避免继续增加抽象口号或更多空模板。

### 最终验证与剩余偏差

主代理集中运行一次 `node --test docs/prototypes/ui-kit-trial/trial.test.cjs`，退出码 0：**6 PASS / 0 FAIL / 0 SKIP**，约 10.1 秒。运行环境：Windows，本机 Chrome `154.0.8037.57`，`PLAYWRIGHT_CORE_PATH=C:/Users/feeli/AppData/Local/npm-cache/_npx/aa1f6563a672b75d/node_modules/playwright-core`。`trial.js`、`preview.js` 的 `node --check` 均退出码 0；报告本地链接核对通过。新代码遵循先失败、最小修复、定向绿灯，再由主代理集中回归的顺序。

覆盖实际 DOM 的搜索/筛选、双端章节选择/取消/确认、设置返回和本机隔离、320px/桌面宽度、弹层焦点和跨漫画下载隔离、混合下载适用数量。主代理独立查看了旧版截图、首轮问题截图以及修复后的双端书架和窄屏确认框。首轮四类阻塞性实验问题已修复；实现者另修复了状态提示遮挡按钮的实测问题。

**测试通过并不等于规范全部生效。** 最终实验仍保留以下明确偏差，不将其伪装为合规页面：

- 筛选只做二态“仅未读”，原版/本仓库已有三态；反选、范围选择和继续阅读 FAB 未实现，因而 UI-09/UI-12/UI-27 不能整类通过。
- 封面使用 `aspect-ratio:3/4`（`trial.css`），而本机 Android [MangaCover.Book](../../../app/src/main/java/eu/kanade/presentation/manga/components/MangaCover.kt) 为 `2f/3f`。UI-23.01 虽要求沿用比例，但没有直接给出此常量，实施者未正确追溯；本轮作为视觉颗粒度和执行约束不足的负面观察保留，不继续把实验扩成全面复刻。
- 顶栏、行高、封面占位和按钮尺寸中仍有自主选值；复用了旧图标和部分主题值，并不代表完整复用了 Mihon 视觉系统。
- 未获得原生视觉基准，不做像素相似度评分；没有无规范的同模型重做对照，不声称量化因果提升。

最终成品是一份**可操作、可对照且边界清楚的实验**，不是获准替换生产页面的 UI kit 合规实现。后续若正式接入，先补 Desktop 映射与精确视觉/行为基准，再以相同页面和验收条件复测。
