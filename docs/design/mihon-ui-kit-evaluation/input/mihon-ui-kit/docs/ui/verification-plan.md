# 验证计划与覆盖边界

## 不能混用的验证层级

| 层级 | 本包提供 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 模型 | CatalogModel + ContractChecks | 假状态转换、作用范围、序列化、取消副作用等断言 | Compose 事件连接、Android 导航、界面视觉、真实服务 |
| 包结构 | validate_package.py | 规则/场景唯一性、资源完整性、源集布局、部分禁止调用扫描 | Kotlin 语义编译、跨进程隔离、生产包排除 |
| 编译 | 导入后 Gradle 构建 | 本机所用分支上的 API/依赖/资源/类型正确 | 运行时行为、视图可点击、可访问性 |
| Android 组件 | 10 个待执行 Compose/Espresso 测试 | 实际界面入口、标题返回、焦点提交、选择、恢复等指定断言 | 所有 128 个手工场景、像素一致、生产端到端 |
| 视觉/设备 | 手工矩阵与候选基准流程 | 指定环境下的布局、状态和手势效果 | 未测试设备、未运行的组合 |
| 生产端到端 | 专项清单 | 真实导航、任务、权限和数据流 | 其他来源/服务/API 等未经测试的组合 |

状态：AUTHORED（已写代码）、NOT_RUN（未执行）、BLOCKED（有具体阻塞）、PASS、FAIL、N/A（必须附理由）。证据精确到层级和 case ID。不要使用一个笼统完成百分比掩盖未执行的设备或集成测试。

## 初始覆盖库存

32 个类别，每类 4 个预置/声明场景，共 128 项。`catalog-manifest.json` 的 setup/steps/expected 是初始验收契约。本包模型测试中的 `snapshot.UI-xx-Cyy` 仅检查对应 fixture 保存恢复；其通过不把原生 case 状态改为 PASS。

每个页面至少增加：正常入口→退出；加载→成功/失败；空数据→创建；有数据→刷新失败→重试；选择与搜索叠加→连续返回；弹层内部层级→关闭；编辑→取消/确认；重复操作→单次副作用；数据变化→无失效 ID；重建→状态和一次性事件正确。只选择适用转移，N/A 需说明原因。

## 环境矩阵

| 编号 | 环境要求 | 必测重点 |
|---|---|---|
| E01 | 手机、竖屏、浅色、简体中文、默认字号、手势导航 | 全部类别初次遍历、标题/返回、主要操作 |
| E02 | 同设备深色；原项目其他主题单独抽样 | 语义颜色、禁用、错误、遮罩、图标 |
| E03 | 平板或宽窗口，按项目 isTabletUi 判定 | 底栏/侧栏、双栏、自适应弹层 |
| E04 | 手机横屏、分屏、窄窗口 | 长标题、更多菜单、底部控件、最后一项 |
| E05 | 200% 字号；必要时增加显示缩放 | 表单、顶栏、按钮换行和可点击性 |
| E06 | 英文与 RTL 语言/伪语言 | 镜像、start/end、文本方向、数字/实体标题 |
| E07 | 软键盘显示/隐藏，软键盘搜索/完成键，硬件 Enter | 焦点、提交校验、返回、底部避让 |
| E08 | 三键导航与刘海/边缘屏配置 | 系统栏、弹层、FAB 与内容间距 |
| E09 | TalkBack、键盘/方向键导航 | 标签、状态、焦点顺序、无需手势的替代操作 |
| E10 | Activity 重建与实际进程终止恢复分别执行 | 草稿、滚动、选择、查询；禁止事件重放 |
| E11 | 动画时长缩放关闭 | 控件最终可见/可点击，不能依赖动画完成才能正确 |
| E12 | 最低支持 API 与目标 API 附近的设备组合 | 权限、文件选择、外部 Activity、返回行为 |

E01 全部跑；UI-01/03/04/05/14/16/18/25/26 必须覆盖与其相关的关键环境。其余采用风险驱动的两两组合抽样，同时额外执行“多选+搜索+失败”“草稿+弹层+IME”“大字号+窄窗口+底栏”“部分数据+重试+重复点击”。两两组合不能代替已识别的高风险三因素组合。

场景切换只更改假数据，不会自动改设备大小、主题、字号、RTL、TalkBack、网络或 Android 权限。必须实际切换环境并记录。

## 原生与视觉核对流程

1. 从全新 debug 安装打开 UI Catalog；记录 commit、variant、设备和配置。不得带入真实账号或书库。
2. 按 UI-01→UI-32 选择每个场景执行 steps，先开面板查看 expected，再隐藏面板查看布局；测试探针按钮不能代替真正系统返回和 AppBar 按钮。
3. 对原版规则同时打开相应原版页面作参考；只比较结构可比的区域。Lab 中任务控制按钮、类别导航、日志和假实体展示不作为生产视觉基准。
4. 截图命名建议 `UI-03-C02__E05__<commit>__actual.png`；保留候选参考图、实际图和差异说明。首次基准必须经审查后标 approved。
5. 每个实际动作核对 UI变化、导航结果和副作用。仅截图无法证明取消、重试、去重或数据一致性。
6. 失败先修实现或明确设计变更，不直接更新黄金图掩盖回归。每轮记录未执行项；禁止将候选截图或说明文字当成已执行证据。

## 业务样例明确缺失的生产验证

| 类别 | 已提供的假数据交互 | 必须在真实应用另测 |
|---|---|---|
| UI-27 | 章节行、选择、读/未读、计算继续阅读目标 | 实际 MangaScreen 导航、真实章节排序/过滤、历史写入、继续阅读打开的章节、真实封面/标签 |
| UI-28 | 10页边界、工具栏显隐、方向选择、设置弹层 | 图片引擎、拖动/缩放/双击、点击区域、音量键、章节预取、横竖屏、状态恢复 |
| UI-29 | 假队列、开始/暂停/恢复/进度 | Downloader、WorkManager/通知、应用重启、断网、磁盘不足、顺序持久化 |
| UI-30 | 假权限、信任确认、安装状态 | 真实 APK 签名、包安装器、拒绝权限后的返回、源网络错误、WebView/外部浏览器 |
| UI-31 | 假绑定、评分支持/禁用、解绑 | OAuth/登录、远程查询、日期范围、服务能力差异、离线失败、同步与隐私 |
| UI-32 | 假目录选择、取消、恢复任务互斥 | SAF URI 持久授权、权限撤销、无效备份、真实数据库恢复、磁盘空间和中断恢复 |

UI-02 的根导航是 Lab 内部模型，不是生产 TabNavigator 的回栈；UI-06 的 snapshot/Activity 重建不证明进程恢复；UI-10 的滑动样例只验证动作触发，不写真实章节；UI-22 的 PreviewTheme 不覆盖全部用户主题；UI-23 的假封面不验证图片加载器；UI-24 的简单动效不覆盖生产所有转场。

## 构建与设备命令

在导入后的目标 Android 仓库中先确认任务名（分支若改变 flavor，使用实际生成的任务）：

```sh
./gradlew :app:tasks --all
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest
./gradlew :app:connectedDebugAndroidTest
```

仅运行本包仪器测试时可给 connectedDebugAndroidTest 增加：

```sh
-Pandroid.testInstrumentationRunnerArguments.class=eu.kanade.tachiyomi.uicatalog.UiCatalogInstrumentationTest
```

构建失败保存完整日志/退出码并归因，不跳过源代码错误。缺少 SDK、依赖下载、设备、驱动或账号时写 BLOCKED。Android 官方文档见 [Compose testing](https://developer.android.com/develop/ui/compose/testing) 和 [build variants](https://developer.android.com/build/build-variants)。当前样例使用自定义 Activity 的 createAndroidComposeRule，不依赖空测试 Activity 的 ui-test-manifest。

发布隔离要另外检查 release/foss/preview/benchmark 的实际 merged manifest 和最终包，搜索 UiCatalogActivity/uicatalog 代码及实验入口；本地目录检查不能替代该项。正式签名和发布不是本验证任务的必要步骤。
