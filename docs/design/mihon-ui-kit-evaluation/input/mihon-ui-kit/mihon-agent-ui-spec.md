# Mihon fork：Agent UI 与交互规范 v1.0

## 强制程度与例外

“必须/禁止”属于当前契约的强制项；“建议/默认”可因明确设计理由调整。适用范围之外写 N/A 和理由。不能将“不方便做”“已有一处没做到”当成例外。合理的旧实现缺陷不应扩散到新功能。

普通子页面：明确且有效的标题和返回；完整传递 contentPadding；数据状态不能绕过容器；局部模式退出规则完整。根页不强行添加上级返回，标签内容不重复添加父级顶栏，阅读器工具栏可按阅读模式隐藏。顶栏箭头和系统返回不是在所有入口都必然具有相同语义，按宿主导航实际定义。

## 组件与状态责任

颜色、字体、间距、图标优先来自项目主题与现有组件。标题、普通操作与错误文案优先复用 i18n 资源。新业务可定义实体模型，但不要复制一套外观相近的导航或设置控件。查看组件的调用点及其默认参数，不能仅检查组件名称。

页面状态必须有明确所有者；永久偏好和真实任务来自现有仓库/业务层，局部模式或草稿按实际生命周期保存。副作用在明确事件中执行；重组、恢复、重试不能无意重复执行。列表实体用稳定 ID；排序、过滤、分页之后选择仍指向原实体。

## 示例的地位

本包 `UiCatalogActivity` 提供 32 个类别入口，每个入口有 4 个场景预置、开发控制面板和上一/下一类别。Android 容器、顶栏、搜索、部分设置及弹层复用当前 fork 的原组件；业务状态采用本包 reducer 和内存假数据。

开发控制面板、事件日志、手动任务推进按钮、返回探针属于测试工具，不属于 Mihon 生产设计语言。验证控件可以通过顶栏信息按钮隐藏；进行视觉基准采集时关闭面板，记录仍保留的样例上下文。根导航示例在 Lab 子页内展示，顶部 Lab 返回是测试宿主入口，不是生产首页规范。

所有业务类样例都不能替代真实组件的生产集成验证。阅读器翻页模型不包含图片引擎，目录选择是假选择，追踪与扩展不联网。环境变化必须使用真实设备设置，场景切换本身不等于切换主题、字号或屏幕尺寸。

# 01-navigation — Mihon fork UI 规范 v1.0

本文件中的“必须/禁止”是本次制定的 fork 规范。来源标记对应 `source-outline.md` 的固定提交索引；规则中增加的健壮性要求不表示上游所有代码已经符合。

## UI-01 页面类型与容器职责

适用范围：所有页面与可复用内容。

例外与边界：阅读器允许工具栏隐藏；嵌入内容复用父级容器。

参考实现：S05、S20；读取当前工作分支对应文件后实现。

### 强制条款

- **UI-01.01** 每次新增界面必须声明 root、subpage、tab-content、settings、detail、modal 或 reader 类型，以及顶栏、底栏、消息和安全区的唯一提供方。
- **UI-01.02** 普通子页面必须提供非空标题和有效返回回调；内容组件禁止自行添加第二套页面导航；开发验证控件不能进入业务页面。
- **UI-01.03** 不得因加载、空数据、错误分支提前返回而绕过已规定的页面容器。
- **UI-01.04** 复用容器必须连同导航、滚动、间距和状态参数一并接入；不得仅复制视觉样式。

### 验收场景

| ID | 场景/前置 | 操作 | 预期 |
|---|---|---|---|
| UI-01-C01 | 普通子页：默认数据 | 打开子页并返回 | 只有一处页面顶栏；回到目录。 |
| UI-01-C02 | 标签内容：切换标签场景 | 切换子标签 | 父级顶栏保留；内容没有重复顶栏。 |
| UI-01-C03 | 加载：切换加载场景 | 检查标题和返回 | 内容加载不影响返回。 |
| UI-01-C04 | 失败：切换错误场景 | 重试后返回 | 错误有恢复动作；页面容器不变。 |

验证层级：本地模型断言只证明状态转换；Android 组件行为、视觉、设备环境和生产业务必须各自记录证据。

## UI-02 顶层导航与标签切换

适用范围：根导航及其子标签。

例外与边界：开发目录的退出动作属于工具入口；不复制进首页导航。

参考实现：S01、S03、S20；读取当前工作分支对应文件后实现。

### 强制条款

- **UI-02.01** 根标签使用项目既有导航容器与平板判断；禁止每个标签独立定义屏幕断点。
- **UI-02.02** 标签切换必须同步选中状态、标题、搜索能力及操作区；角标只表达对应计数，零值默认不展示。
- **UI-02.03** 重复选择当前标签必须调用该标签既有重选行为；新增标签在设计记录中声明无操作或具体动作。
- **UI-02.04** 根导航系统返回遵循宿主规则：先处理局部模式，再从非书库根标签回书库；不得创建重复目的地。

### 验收场景

| ID | 场景/前置 | 操作 | 预期 |
|---|---|---|---|
| UI-02-C01 | 普通标签：默认根标签 | 依次切换标签 | 选中项和内容一致。 |
| UI-02-C02 | 重复选择：当前标签已选中 | 再次点击当前项 | 记录重选事件；不压入重复页面。 |
| UI-02-C03 | 计数：启用样例计数 | 查看零值与非零值 | 只有非零计数显示。 |
| UI-02-C04 | 宽屏：切换设备到平板或宽窗口 | 切换根标签 | 使用侧栏；状态不随尺寸丢失。 |

验证层级：本地模型断言只证明状态转换；Android 组件行为、视觉、设备环境和生产业务必须各自记录证据。

## UI-04 返回关闭与取消

适用范围：页面、模式、弹层、键盘。

例外与边界：系统 IME 会自行消费返回；不得把业务优先级误当系统全局顺序。

参考实现：S01、S02、S03、S12；读取当前工作分支对应文件后实现。

### 强制条款

- **UI-04.01** 必须分别声明系统返回、顶栏返回、选择取消、遮罩和滑动关闭的结果。
- **UI-04.02** 有局部模式时先按当前参考实现退出模式；选择与搜索共存时遵循书库的先取消选择再退出搜索。
- **UI-04.03** 嵌套弹层先返回内部上一级；关闭弹层不应同时弹出底下的业务页面；弹层关闭的一个动作只执行一次。
- **UI-04.04** 未提交编辑默认取消无副作用；高成本草稿退出需确认或明确保存方案，禁止静默丢弃。

### 验收场景

| ID | 场景/前置 | 操作 | 预期 |
|---|---|---|---|
| UI-04-C01 | 子级返回：子级深度为1 | 触发返回两次 | 先回父内容，再退出示例。 |
| UI-04-C02 | 选择优先：选择与查询共存 | 连续返回 | 先清空选择，再关闭查询。 |
| UI-04-C03 | 搜索关闭：查询已打开 | 系统返回 | 关闭查询并保留本页。 |
| UI-04-C04 | 嵌套弹层：弹层打开后进入第二层 | 返回、再返回 | 先回弹层首页，再关闭弹层。 |

验证层级：本地模型断言只证明状态转换；Android 组件行为、视觉、设备环境和生产业务必须各自记录证据。

## UI-05 安全区与滚动容器

# 验证计划与覆盖边界

## 不能混用的验证层级

| 层级 | 本包提供 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 模型 | CatalogModel + ContractChecks | 假状态转换、作用范围、序列化、取消副作用等断言 | Compose 事件连接、Android 导航、界面视觉、真实服务 |
| 包结构 | validate_package.py | 规则/场景唯一性、资源完整性、源集布局、部分禁止调用扫描 | Kotlin 语义编译、跨进程隔离、生产包排除 |
| 编译 | 导入后 Gradle 构建 | 本机所用分支上的 API/依赖/资源/类型正确 | 运行时行为、视图可点击、可访问性 |
| Android 组件 | 10 个待执行 Compose/Espresso 测试 | 实际界面入口、标题返回、焦点提交、选择、恢复等指定断言 | 所有 128 个手工场景、像素一致、生产端到端 |
| 视觉/设备 | 手工矩阵与候选基准流程 | 指定环境下的布局、状态和手势效果 | 未测试设备、未运行的组合 |
| 生产端到端 | 专项清单 | 真实导航、任务、权限和数据流 | 其他来源/服务/API 等未经测试的组合 |

状态：AUTHORED（已写代码）、NOT_RUN（未执行）、BLOCKED（有具体阻塞）、PASS、FAIL、N/A（必须附理由）。证据精确到层级和 case ID。不要使用一个笼统完成百分比掩盖未执行的设备或集成测试。

## 初始覆盖库存

32 个类别，每类 4 个预置/声明场景，共 128 项。`catalog-manifest.json` 的 setup/steps/expected 是初始验收契约。本包模型测试中的 `snapshot.UI-xx-Cyy` 仅检查对应 fixture 保存恢复；其通过不把原生 case 状态改为 PASS。

每个页面至少增加：正常入口→退出；加载→成功/失败；空数据→创建；有数据→刷新失败→重试；选择与搜索叠加→连续返回；弹层内部层级→关闭；编辑→取消/确认；重复操作→单次副作用；数据变化→无失效 ID；重建→状态和一次性事件正确。只选择适用转移，N/A 需说明原因。

1. 从全新 debug 安装打开 UI Catalog；记录 commit、variant、设备和配置。不得带入真实账号或书库。

## Mihon UI / interaction contract

适用于新增或修改页面、导航、弹层、菜单、列表项及交互状态的任务。

1. 开始前读取 `docs/ui/README.md`、`docs/ui/component-baseline.md`，按目录读取适用章节，并检查当前分支对应的原版参考实现。所有新增页面都读取 UI-01、03、04、05、18；业务类型按专项章节扩展。
2. 使用 `docs/ui/page-contract-template.yaml` 定义页面类型、容器所有权、状态、返回行为、副作用和适用规则。模板中的 UNKNOWN 必须解决或作为阻塞公开记录，不能默认为通过。
3. 完整复用当前分支的 AppBar / SearchToolbar / Scaffold / Preference 系列等项目组件，核对 import、参数、内容边距及回调。旧版和新版 Mihon 的图标、集合、主题 API 不能混用。
4. 普通子页面标题和返回动作必填；加载、空数据、错误均保留其页面容器。根标签、嵌入内容、阅读器按声明的例外执行。禁止空回调冒充完成。
5. 选择、搜索、弹层、嵌套步骤、未提交草稿分别定义返回/取消结果；取消不能误提交、删除或启动后台任务。系统 IME 处理与业务返回分开验证。
6. 新功能按类别和 case ID 实现/验证，逐项更新证据，不跳过失败项。执行顺序见 `docs/ui/sequential-roadmap.md`。一项环境阻塞不妨碍执行独立检查；最终必须列出所有未完成项。
7. Lab 的假数据、调试入口和诊断工具仅留在开发源集，不调用真实账号、数据库、下载、安装或文件写入。移植到生产页面时移除 Lab 控件，接入真实状态与现有导航。
8. 模型断言、编译、Compose 测试、截图比对、实机交互和生产端到端必须分别报告。禁止用样例存在、自动生成截图、自我陈述或配置重建测试替代其他验证。
9. 不得为通过验收擅自删除规则、放宽断言或替换已批准截图。设计变更须记录理由、影响和批准；没有批准的参考图只能叫候选基准。
10. 交付至少列出：改动文件、适用规则、实际执行命令及退出码、失败/阻塞项、设备/构建标识与证据路径。不存在的结果写 NOT_RUN；不适用项写 N/A 及理由。不能仅报告“已符合 Mihon 风格”。
