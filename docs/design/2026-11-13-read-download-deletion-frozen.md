- 公开投票以两项独立能力说明：Desktop 已读删除设置对齐、双端延迟删除；共享本设计的实现边界。

## 1. 最终要求与边界

1. Desktop 补齐 Android 已有的已读删除设置、候选选择、保护规则及真实生产接线。
2. 双端在设置 → 下载 → 删除章节中，紧接“读完自动删除”新增开关“延迟删除”。
3. 注释原文：`下次启动时再删除，如果退出前将状态改回未读的话则不会删除`。
4. Android 冷启动进入前台时处理；进程持续驻留满 24 小时后，从后台返回桌面、再次点击桌面图标进入时也处理。
5. 手动标记未读必须直接修改持久待删除队列；删除执行不遍历章节表复核读态，不扫描全书架或下载目录。
6. 删除任务在执行时消费；无论文件删除成功或失败均不保留失败条目重试。
7. 用户手动删除已进入队列的下载时，同步移除相应队列条目。
8. 仅“读完自动删除”受延迟开关控制。“手动标记为已读后”仍使用其独立开关和即时删除时机；主动删除下载仍使用原确认及执行入口。
9. 延迟开关默认关闭。自动删除关闭时，新开关置灰但保留勾选偏好；关闭父项、关闭延迟模式或改变保留章节规则时取消旧规则未执行的延迟任务，不在切换时补删。
10. 不回溯扫描历史已读章节、不承诺定时后台删除、不新增远端删除同步；本机排队信息不进入备份或作品同步。

## 2. 已核对的当前事实（SOURCE）

| 部分 | 当前实现与差异 |
| --- | --- |
| Android 设置 | `SettingsDownloadScreen.getDeleteChaptersGroup()`：手动标记已读后、读完自动删除（关闭 / 刚读完 / 倒数第 2–5 个）、允许删除书签、排除分类。 |
| 共享偏好 | `DownloadPreferences`：`removeAfterMarkedAsRead()`、`removeAfterReadSlots()`、`removeBookmarkedChapters()`、`removeExcludeCategories()`。 |
| Android 阅读完成 | `ReaderViewModel.completionPlan()` 选择候选；`AndroidReaderProgressCoordinator` 顺序提交阅读进度；`AndroidReaderProgressEffects` 执行完成副作用。 |
| Android 待删 | `DownloadPendingDeleter` 用独立 SharedPreferences 保存有限定位信息；`getPendingChapters()` 先清空，再交给 `DownloadManager` 异步删文件。 |
| Android 关闭阅读器 | `AppModule` 把 coordinator 的关闭回调接到 `downloadManager.deletePendingChapters()`。 |
| Android 手动已读 | `eu.kanade.domain.chapter.interactor.SetReadStatus` 在读态写入后按独立设置删除下载。 |
| Desktop 设置 | `DownloadSettingsScreen` 目前只有 `DesktopDownloadPreferences.deleteAfterRead` 布尔开关，没有 Android 完整的删除章节设置组。 |
| Desktop 阅读完成 | `ReaderProgressTracker.track()` 保存进度后直接调用 `DesktopDownloadManager.deleteDownload()`。 |
| 文件删除 | Android `deleteChapters()` 自行异步启动；Desktop provider 有 Boolean 结果，但 manager 当前包装不返回该结果。 |

旧队列没有最新 read/bookmark；恢复出的缺省字段不能充当权威状态。本设计通过状态变更时维护队列解决读态问题，不采用启动时逐章查询的上一版做法。

## 3. Desktop 对齐范围（PROJECT_POLICY）

在现有下载设置页面增设“删除章节”组，顺序与 Android 一致：

| 顺序 | 设置 | 默认值与规则 |
| --- | --- | --- |
| 1 | 手动标记为已读后 | 关闭；复用既有独立手动读态删除语义。 |
| 2 | 读完自动删除 | 关闭、刚才读完、倒数第二 / 三 / 四 / 五个已读章节；使用共享候选策略。 |
| 3 | 延迟删除 | 默认关闭；标题和注释双端共用资源。 |
| 4 | 允许删除书签章节 | 默认关闭；书签保护适用于对应自动/手动读态删除链路，具体与 Android 生产实现对齐。 |
| 5 | 排除分类 | 默认空；默认分类 ID 0、重复分类及作品多分类按 Android 既有规则处理。 |

- 不能只补界面；详情、书架、更新等手动读态入口及阅读器完成路径均须消费同一共享设置。
- 候选按现有 Android 阅读顺序/章节过滤链路选择，不重新按标题或章号实现近似算法；保留其已读候选限制。
- 旧 Desktop `delete_after_read=true` 只在共享 `remove_after_read_slots` 从未显式配置时迁移为 0；false/未设置迁移为关闭。已有共享选择优先，一次迁移，后续只读共享权威。
- 对齐正常模式的删除语义与保护；平台差异仅保留 URI 与桌面文件系统 adapter，以及 Desktop 下载目录/别名/占用等既有能力。
- 复用原设置组件、导航、分类选择和设置搜索，不另建设置页或第二套偏好存储。

## 4. 持久队列与原子变更

### 4.1 有限本机数据

建议用共享 SQLDelight 本机待删除表替代 Android 私有偏好队列，并供两端共用。唯一 schema/migration 位置为 `data/src/commonMain/sqldelight/`。

每项保存：稳定任务 ID、作品/章节/源身份、下载 artifact 的有限定位与代次、普通/延迟时机、入队序号、规则版本；不保存 Activity、页面对象、远端凭据或整个章节列表。以章节+下载代次去重，章节 ID 和作品 ID 建索引。

- 阅读进度成功提交与待删意图同事务接受；只对已有下载建立候选，未下载章节不留下针对未来下载的任务。
- 普通 Android 模式复用关闭阅读器清理时机；延迟模式的条目不能被该回调消费。
- 旧 Android 条目仅导入其有限身份范围，不扫书架；导入、读态/保护资格核对仅属于一次迁移，不放进日常清理热路径。导入成功后才清空旧记录；无可靠身份的旧条目放弃删除。
- 本机任务不进入标准备份和同步 wire；恢复备份、恢复配置、切换数据 profile 时清理适用的本机任务，避免把旧身份应用到恢复后的数据。

### 4.2 在变更发生时维护队列

| 真实生产事件 | 队列变化与接线 |
| --- | --- |
| 手动标记未读 | 在读态更新的同一 SQL 事务中，以受影响 chapter IDs 批量删除候选；覆盖单章、多选、整本、详情、书架、更新等实际入口。读态写失败时队列变更一并回滚。 |
| 同步/备份/重复章节处理将最终读态改为未读 | 在实际数据写入/投影事务中精确撤销受影响候选；不能只修改手动 UI use case 后遗漏其他写入口。 |
| 新增书签且禁止删除书签 | 书签写入时取消对应候选；移除书签不自动恢复已取消任务。 |
| 新增排除分类或修改作品分类 | 在变更对应的有限作品范围内撤销不再适用候选；不在启动删除时重扫分类。 |
| 关闭自动删除/延迟、改变保留规则 | 按规则归属清理未执行的适用任务；正在执行项按章节串行顺序确定边界。 |
| 手动删除单章/多章/整本下载 | 沿确认后的共同删除边界移除相应候选；取消确认不动队列。手动删除失败也不保留原自动任务。 |
| 重新接受该章下载 | 在新任务可写文件之前撤销旧代次删除候选，避免旧任务删除新下载。 |
| 章节移除、作品删除、迁移、下载目录变更 | 按有限身份清除失效候选；不能按新标题重新定位并删除后来文件。 |

关键成本：标记未读只处理本次受影响的索引 ID 集合；清理只读取待删任务及有限文件定位。不得逐章查询最新 read、遍历全库或扫描下载树。实施前必须列全最终读态写入点，并用真实数据库/同步投影契约证明没有旁路。

### 4.3 并发次序

队列移除与物理删除以章节级串行协调：撤销先取得执行边界则后续删除不发生；删除先开始则撤销不能恢复已删文件。已弹确认但尚未确认的主动删除不抢占候选。重新下载、阅读文件占用和文件迁移复用已有有限占用边界，不能持数据库事务跨网络或长时间文件 IO。

## 5. 启动与 Android 24 小时边界

### 冷启动

- 新进程第一次前台进入时消费上一逻辑会话的延迟队列；仅后台服务/任务拉起进程不清理。
- Desktop 完全退出后重开触发；单实例程序第二次启动、窗口聚焦不重复触发。
- 清理开始冻结最大入队序号；清理过程中产生的新候选留给下一次触发。
- 首帧/首个窗口不等待全批文件 IO；每章占用和删除串行边界单独协调。

### Android 驻留满 24 小时

- 24h 从本进程首次前台逻辑启动或上次符合条件的清理触发时刻起算，使用单调时钟 `SystemClock.elapsedRealtime()`；包含设备休眠时间，不受用户调整墙钟影响。
- 到达 `>=24h` 后，仅在此前应用已退到后台且收到桌面图标的 `ACTION_MAIN` + `CATEGORY_LAUNCHER` 入口时触发一次；覆盖新建 Activity 与已有 Activity `onNewIntent`。
- 通知、深链、应用内部跳转、旋转、普通前后台切换和连续前台阅读不算桌面图标重入，不自动在阅读中删除。
- 此入口建立新的逻辑清理会话并冻结本次工作集；同一 Intent/生命周期重复投递须幂等；即使队列为空或文件删除失败，本次触发也重置 24h 基点。
- 进程被系统回收后走冷启动分支；设备重启后的单调时钟不与旧进程值相减。

## 6. 单次消费，不重试

处理固定工作集时逐项（或有限小批）原子取出并删除队列记录，再对取出的有限对象执行一次文件删除。不能一次清空整个工作集后慢慢处理，防止尚未轮到的任务随中断全部丢失。

- 成功、文件已不存在、权限失败、目录离线、源缺失、身份无法确认均结束这项任务；不重新入队、不保留失败重试状态。
- 消费后、文件删除前发生进程中断，文件可能保留且不再自动尝试；这是用户选择的单次消费语义，必须在技术边界与测试中保留，不宣称恰好一次物理删除。
- 未消费的后续任务仍在队列，下一次合法触发可以处理。
- 一项失败继续处理其他项；更新实际下载状态；失败仅作一次汇总反馈和现有诊断记录，不逐章弹窗、不制造重试入口。
- 若队列消费本身失败，不可继续删文件，避免文件副作用与待删权威脱节。

## 7. 用户可见契约

| 场景 | 预期 |
| --- | --- |
| 延迟关闭 | 双端使用对齐后的 Android 普通删除设置与时机。 |
| 延迟开启，读完并退出阅读器 | 文件保留，下载标记继续反映真实文件存在。 |
| 退出前标记未读 | 队列当场取消，下一次触发保留文件。 |
| 下一次冷启动 | 只处理尚在队列的原下载，不扫描历史已读。 |
| Android 23h59m 后点桌面图标 | 不处理延迟队列。 |
| Android 满 24h 后退到桌面再点图标 | 处理一次并重置基点。 |
| 已排队后手动删下载 | 按原确认执行，同时移除自动任务；后续启动无重复删除。 |
| 执行一次删除失败 | 文件可保留，任务已移除，后续启动不自动重试。 |

设置变更即时持久化；保留原返回/Escape、滚动、焦点及危险操作确认。设置搜索可检索新增项。中英文资源语义一致；新功能尚未实施时只能列在明确标记“规划”的公共页面，不能进入当前可用功能说明。

## 8. 分层职责与复用

| 层 | 拟承担内容 |
| --- | --- |
| domain | 共享删除候选/保护策略、队列契约、逻辑会话与触发判定；平台入口事实由 adapter 提供。 |
| data | 本机 SQL 队列、原子读态/书签/分类撤销与任务消费；读态取消覆盖同步投影和恢复路径。 |
| Android | 复用 reader coordinator、SetReadStatus、DownloadManager/provider、Launcher/Activity 入口；URI 文件删除 adapter。 |
| Desktop | 完整设置组与偏好兼容、真实手动读态和 reader wiring；复用下载身份、有限别名及 producer/reader 占用边界。 |
| presentation | 复用现有设置控件、分类选择、i18n、搜索与下载状态刷新。 |

不复制两套候选算法，不引入后台常驻计时服务，不以全库扫描弥补遗漏的事件接线。
