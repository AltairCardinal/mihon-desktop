# Windows 发布前失败用例修复记录

日期：2026-11-09。源码基线 `7ced2f1cb920f72cfdc91906a6aaf4772894a187`。

## 范围与真实缺陷

本次收口之前复跑的 50 项失败及 1 项停滞，不重跑完整 Desktop 模块或仓库全量。

- 完整下载恢复：完整持久化页表与已提交页文件都在时，下载器仍提前解析源。真实回归使用会抛错的源解析器，原代码超时失败；现在仅在实际缺页下载路径消费惰性源解析，完成章节不再要求源在线。缺页、缺 URL 和源错误的原流程仍由相关定向用例覆盖。
- 正常退出：真实 main 的隔离子进程已完成主线程，但残留非守护 OkHttp Dispatcher，30 秒进程退出断言失败。线程诊断确认该观察；增加实际 DI 客户端关闭断言后保持红测。现将同一个生产 network helper 注册到既有 runtime closeable 链，不增加另一套关闭机制。3 项真实 main 探针及关联关闭用例通过。
- 添加仓库反馈：生产界面提交后丢弃 Pending，检查期间只显示空列表。原双语 Compose 点击测试失败。现使用请求身份维护本页面正在检查的 URL，在反馈区域展示已有本地化检查文案；完成、失败和取消均在 finally 撤回。不同请求互不清除对方的提示；未增加新的后台任务机制。测试还验证终止后不残留 Pending。

上述产品变更只在 Desktop。没有 schema、Android、签名或发布身份变更。

## 测试准备和契约修正

- 扩展表现测试补齐连贯 runtime snapshot；浏览测试使用实现原接口默认投影的空运行时夹具，不依赖宽松模拟对象的随机 StateFlow。
- 作者搜索夹具显式提供宿主注册源身份，使用线程安全查询记录并释放离屏帧；全局搜索等待实际语义渲染，失败也关闭场景。
- 普通 403 继续保持 Forbidden/Retry；需要登录的夹具改用 401。登录重试的 MockWebServer 等待有明确上限。
- 库更新继续以页面反馈为唯一 owner，不再要求已撤销的重复系统通知。通知测试依旧断言持久化成功、失败和取消状态。
- 依赖通知验证真实内容、必需依赖和排序，不固定旧的总数，也不假定不同制品的展示名称唯一。
- 阅读器以现有 ReaderIoGate 的真实内容边界控制延迟，取代无法拦截 acquireHeader 每次独立 open port 的反射改写；保留原首绘、方向、原图采样和租约清理断言。
- 冷尾页夹具把阻塞 HTTP 和受控 UI 调度分开，显式检查每个等待是否成功；正确性等待为 10 秒，仍小于生产事实预算 15 秒。结果仍须走到原 canonical 前置跨页边界、保持页 16 及实际右槽，不把放宽结果当作修复。
- 延迟 UI 绑定测试先固定原 publisher 句柄再释放并发能力，并推进受控时钟；保留真实 core 更换后拒绝旧批次及显式恢复断言。
- 两条章节导航/预取场景合为两个布尔参数的真实 mounted 用例，便于治理清单直接绑定行为体，没有删除任一场景。
- 刷新当前源码证据行及已改名行为引用；固定上游证据、能力状态不变。源码字符串检查仅是治理定位，真实行为证据另由上述生产回归和集成用例提供。

涉及 28 个实现、测试及清单文件，较大部分是当前证据行号更新；共同目标是关闭同一份发布失败清单，无无关重构。
