# Git 150% 目标：批次描述重复处理预研

## 结论

**本轮证明描述复用有局部收益，未达到完整首次同步≤Git耗时150%的目标。** 同条件单配对中，事务内append循环从7.013秒降到4.677秒（33.3%），初导生成从19.538秒降到17.678秒（9.5%），完整同步从145.043秒降到142.249秒（1.93%）。完整成绩仍远高于21.887秒目标。

新增分段发现更重要的剩余区间：缓存后分页调用15.958秒中，事务工作体仅5.169秒，其余10.790秒发生在body之前/之后，占该分页调用累计约67.6%。不能继续把整段耗时解释为编解码，也不能直接把差值称为磁盘fsync耗时。

这是一次先旧后新的配对，未随机交替；投影等未修改阶段也有波动。不得将完整2.794秒差值全部归因于描述缓存，或将单样本比例承诺为所有设备上的稳定收益。研究源码已撤回，只交付报告与复现补丁。

## 范围

本轮在用户追加3%额度内，接续[本地热点定位](../git150-followup-2026-09-25/report.md)，聚焦初导过程反复解码、编码批次对象描述及计算UTF-8长度的问题。起点为 `72e659b056`，研究补丁复用此前分页读取、进度去重与分段诊断；不改变真实书架，不写真实GitHub，不发布产品功能。

沿用1600本书、8700条公开阅读状态、10300事件的样本，输入SHA-256为 `e2cbcb9dad186f22a15615b374588f8b694e37b2f660e515c160b10ceea17458`。网络模型仍为每响应首部50ms、上下行各10Mbit/s。原生Git冻结制品对照为14.591507秒，目标21.8872605秒；完整Runtime包含Git制品对照之外的本地导入工作。不能将本机受控结果外推到Android或公网。

## 原型约束

优化只允许复用单页事务内已经处理的对象描述。对象按完整SyncObjectKey去重，保留首次描述及出现顺序；必须使用现有序列化器生成JSON片段，保留准确UTF-8字节计数、256事件与512KiB明文边界。缓存不能替代持久制品、安全记录或远端确认。

空objects在协议中省略，非空描述字段额外贡献11字节的 `,"objects":`。任何增量计数都须与完整 `SyncBatchCodec` 序列化结果逐字节核对；Unicode、转义、空/非空转换、封批及中段失败均是验收边界。

仍会保存完整对象描述JSON到现有数据库列，增量拼接也会复制字符串。本研究不据此承诺所有本地处理已成为线性成本，更不会删去事件投影、父闭包或校验来制造性能收益。


## 实现与安全验证

`PageAccumulator`只在当前导入页事务内存活，以space/generation/actor/epoch、batchId、下一序号及数据库返回的JSON核验连续性；不匹配时从持久内容重新加载并按旧逻辑归一化。新增描述由现有Json序列化器编码，按数组片段追加；成功完成事件、队列、批次和索引写入后才推进缓存。封批时针对当前事件从空集合重新规划，整页失败后实例被丢弃。

独立审查检查了真实baseline wiring、候选与已提交缓存分离、封批重置、准确字节差值及测量口径。红测试在旧路径上因“真实append没有页内复用”正确失败。最终15项baseline存储契约及1项journal边界契约通过，包含：

- 中文、emoji、反斜杠、引号、换行及first-wins冻结描述；完整Codec编码长度等于数据库plaintext_bytes。
- 跨页读取有效但非规范JSON时，归一化行为及长度与旧路径一致。
- cached baseline真实触发257事件场景的256事件封批，以及100条长中文描述场景的512KiB明文封批。
- 第20条事件写入失败后，事件/序号/导入进度整页回滚；文件库关闭重开后，cached与uncached路径的objects_json和编码字节数完全一致。
- 已有私密阅读、冻结来源删除、后续用户取消、迁移及恢复契约继续通过。

本轮没有绕过自身事件投影，没有扩大每页50条事务，也没有降低持久性设置。共享逻辑在JVM真实数据库和Runtime链路上验证；未追加Android设备验收。

## 同条件1600条配对

两次均沿用此前进度去重和heads批读原型，关闭JFR，跳过第二遍冻结制品重播。仅临时改变`enableDescriptionPageCache`默认值false→true，独立核验了三个关键源码文件的SHA-256，唯一差异就是这一布尔默认值。计时从接受导入开始，书架预填、授权和空间发现不计入。

两次均为10300事件、41协议批次、794次HTTP、41次ref更新，上传19,338,640B、下载19,682,529B。各批`events/batchBytes/indexBytes/headBytes`列表以及phaseCalls完全一致。加密空间分别初始化，初始/最终tree OID不同，因此这里只证明结构与长度一致，**不声称密文字节相同**。局部契约另以实际objects_json逐字节对照验证描述语义。

原生Git14.592秒仍引用此前冻结制品实验，没有在本轮对新随机密文重跑Git，也没有整合上轮20.755秒分组发布原型。不能把这些独立结果拼接成组合Runtime实测。

## 对剩余优化空间的判断

1. **描述复用值得作为可选落地候选，但收益不足以支撑150%目标。** 它减少了事务内重复计算；仍有完整JSON数据库读写、字符串复制、其他SQL及事务外等待。
2. **优先拆分10.8秒的body外成本。** `JvmTransactionContext`涉及事务互斥、线程获取、数据库begin/commit、变更通知及返回调度。现有测量只定位到这一组合区间，未证明各因素占比；不能据此直接重写事务框架或归因于磁盘。
3. **比较现有合法范围内的事务页大小是一个具体候选。** `process`已有1–256条参数范围，本轮固定50。可比较50/128/256的总时间、最长事务/取消延迟及失败恢复；事务页与协议批次不是同一个边界。此候选本轮未试，不能直接宣布调大就会得到固定倍数收益。
4. **字段投影和可靠分组发布仍不可回避。** 缓存后导入process与投影累计约33.321秒，保持测得串行本地成本时，完全隐藏网络仍超过21.887秒。还需削减本地工作、补齐持久分组与恢复，再验证有界生成/上传重叠；尚未证明完整链路可达标。
