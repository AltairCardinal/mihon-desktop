## 1. 交付顺序与预算

实施预计 3–5 个工作日，主要成本是历史数据库谱系兼容、检查点故障注入和正式设备验证，不以时间估算代替验收。最多 2 个子代理：一个连续实施 F1–F4，主代理负责接口、集成与验证协调；另一个负责 1 轮分阶段独立审查，F1/F2 高风险接口稳定时先检查，后续补查平台/UI；最多 1 轮定向修复复审。串行依赖不并行写入相同文件；代理不可用时记录并暂停需要独立审查的交付门禁。

每批按红→绿→重构执行 focused tests，完成后相关集成与格式检查。阶段 A 最终 Android/Desktop 全量测试集中 1 次；Windows/macOS 发布构建与 Test Mode 各按仓库脚本完成，避免重复全量。Gradle 由主代理通过协调器串行调度。阶段 B 的合并验证需在届时任务中重新声明实际范围和成本，不计为本轮已执行。

交付物：修复代码/测试、可追溯正式 Windows 与 Android arm64 产物及所需 macOS 证据、用户验收清单。过程记录集中本 roadmap，复用原需求/原型，不另建状态系统或逐任务报告。新增范围/额外审查/显著成本先说明再决策。批次 checkbox 需实现、审查、验证、提交齐备；不为纯推进状态单独提交。

前置：核对 `a45b2f8342`、固定作者结构提交 `0e68f9c5e9`、现有正式包身份及目标设备实际 schema（可得时）。先保存两条历史迁移证据，不能在冲突中覆盖掉任一谱系。

范围：SQLDelight schema/迁移、共享 DatabaseMigration、Android/Desktop driver 接入、必要最小 adapter、App/error_handler 初始化与对应测试。只移植固定作者结构，不引入作者整套 UI；实际目标为 schema 33：30 号兼容桥、31 号运行计数、32 号每次运行业务基线。升级 bridge 在正常迁移前识别同步28/作者28，在同一事务中补齐，再执行后续迁移；不得 onOpen 后才纠错。

红绿：用历史迁移/正式历史结构建立真实文件 SQLite fixture，分别覆盖共同27、同步28、作者28/29/30、新装、修复包重开、未知同号/更高版本。放入书架/阅读/作者新字段/同步冻结制品与运行日志数据。验证真实 driver 打开、结构指纹、数据保留、无重复 ALTER/建表、事务中断回滚和再次升级。共享契约跑 Android/JVM；Android release 的 Requery factory 必须有集成证据。禁止仅把当前 schema 建好后修改 user_version 冒充历史库。

启动红绿：真实主进程数据库失败后进入 error_handler，能显示错误且不启动业务调度、不循环崩溃；不能只 mock 掉全部 App 依赖。未知数据库安全失败而不是自动清库。

### F2：运行核心、进度与 setup 收口

前置：F1 的兼容接口通过审查。范围：现有 runtime/coordinator/runstore、import/inbox/projector/outbox 的事实报告及共享契约；仅为这些修复增加必要持久字段与后续迁移，不改远端协议。

红绿场景：暂停→冷启动/周期/网络恢复仍暂停；耗尽→重开不重置；手动继续保持同一运行、显式重试结束旧活动记录；取消/空间切换与 owner 完成竞争。3 次系统中断后网络预算仍未消耗；4 次实际网络失败才耗尽，10/30/120 秒及 Retry-After 下限跨重建保存。

检查点场景：不同阶段数量大小相反、未知总量切换、分段新快照、重复收件、提交后计数未写、投影失败/跳过、上传已生效但响应丢失。每个 run 在同一事务记录上传/下载业务基线，恢复时从已发布批次及已确认收件批次对账，避免历史计数混入，并分别保留 run 累计值和本次 attempt 返回值；运行中各阶段直接展示累计值，processed=completed+skipped+failed。日志含真实标题/操作/结果、稳定去重键，500 条截断和 20 次终态保留不删除活动数据。

首次配置场景：绑定后尚未创建 run、导入途中、交换已成功但 complete 未写三个位置中断；重建 runtime 并由生产恢复入口完成标记，面板关闭也能收口，不重复建库或要求密码。

验证用真实文件 SQLite、MockWebServer/有状态远端 fixture 与 production parser/交换实现；不以 coordinator mock 返回成功代替闭环。退出：共享核心与高风险迁移/归属审查通过，F3/F4 依赖同一稳定接口。

### F3：到期重试与平台交接

前置：F2。范围：App 生命周期、scheduler、Worker、最小网络/通知适配、DI 和必要 manifest；Desktop 仅既有应用内调度，无电源监听/常驻服务。

红绿场景：启动补偿已结束后手动失败；周期关闭时失败；保持前台直到到期；到期前后切前台；断网/联网抖动；Worker 过早唤醒；KEEP 尾部竞争；意图提交后入队前杀进程；系统停止 owner 后前台接管；暂停/取消后旧通知动作。断言未来唤醒实际存在、业务请求按时间发生、健康 owner 不重复执行、跟随者取消不影响 owner。

通知场景：真实独立 channel/id、实际计数、绑定 runId 的暂停/取消；周期不无条件长期前台化；提升拒绝/权限拒绝/协程取消不吞错，恢复意图保留且 UI 原因可见。旧连接和阶段超时的 cancellation 必须到达生产 HTTP call，释放前不启动第二个发布。

Android 使用真实 App/DI/WorkManager 与 runtime 联测，Desktop 使用同一恢复资格契约；受控时钟验证，不靠长 sleep。退出：补偿不是只存在于启动函数，前台/后台闭环均可执行。

### F4：双端页面与日志回看

前置：F2/F3。范围：共享 presentation-sync、controller、i18n、相关 DEMO 与必要 README；不另建同步入口。
