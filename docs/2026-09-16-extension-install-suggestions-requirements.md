# 收藏漫画缺失插件的「建议安装」需求

- 日期：2026-09-16
- 状态：待用户审阅；本文件只定义需求，不代表已实现或获准开始实现。
- 适用范围：本仓库 Android 与 Desktop；共享匹配语义，平台安装与网页打开方式使用各自 adapter。
- 目标：用户进入「浏览 → 插件」即可发现收藏漫画所缺失且能够匹配到的插件，并单独或批量安装，无须逐一从迁移页查询。

## 1. 用户需求与范围

| 编号 | 需求 | 本文对应设计 |
|---|---|---|
| R1 | 利用迁移功能检测未安装插件的图源 | 复用收藏图源统计与源可用性，额外核对插件实际安装状态 |
| R2 | 在「已安装」上方新增「建议安装」 | 按插件聚合精确匹配结果，展示受影响的收藏数量 |
| R3 | 可收起，默认展开，记忆选择 | 设备本地持久化展开状态 |
| R4 | 提供忽略、WebView、安装 | 明确忽略身份、网页目标和安装反馈 |
| R5 | 一键全部安装，特别处理 Android | 同一安装链路、批次快照、系统交互串行、结果汇总 |
| R6 | 不纳入用户数据同步 | 建议派生计算；忽略、展开及批次状态均留在本机 |

不包含：自动安装、自动添加插件仓库、修改漫画 source ID、执行漫画迁移、安装所有可用插件、修复所有源加载故障，或同步插件安装状态。本轮不实现功能，不构建应用。

## 2. 已有能力与复用依据

以下为当前代码观察，不是新功能已完成的声明。

| 能力 | 当前入口 | 复用方式与限制 |
|---|---|---|
| 收藏图源及数量 | `app/src/main/java/eu/kanade/domain/source/interactor/GetSourcesWithFavoriteCount.kt`；`app-desktop/src/main/kotlin/mihon/desktop/ui/migration/MigrationSourceScreen.kt` | 两端沿用 `SourceRepository.getSourcesWithFavoriteCount()`。Android 对 stub 源有排序处理，并排除本地图源；stub 只说明没有可用源实例，不足以证明插件未安装 |

新增逻辑应为共享的「收藏缺失插件建议」计算与状态编排，由 Android/Desktop 注入各自安装清单、偏好存储和网页入口。不能让 Desktop 复制 Android 匹配规则。平台差异限于系统包发现、安装方式及网页容器。

## 3. 建议资格、匹配与去重

### 3.1 输入与资格

1. 只统计当前应用本机数据库中已收藏的漫画；排除历史记录、仅浏览记录、未收藏漫画及本地文件源。
2. 按 source ID 聚合收藏数量，并查询当前源运行状态与插件安装清单。
3. 图源已有可用实例时，不推荐其他能提供同一 ID 的替代插件。
4. 图源不可用且候选插件确实未安装时，才可能生成建议。Android 的系统共享 APK 和本应用私有安装均算已安装；其他应用私有目录中的插件不算本应用已安装。
5. 已安装但未信任、被禁用、版本不兼容或加载失败不属于「未安装」。已知提供该源的插件存在时，不通过建议列表诱导重复安装；继续使用既有信任、更新或错误处理入口。
6. 安装清单、收藏统计尚未初始化时显示检测中，不能短暂把全部源认作缺失。

### 3.2 匹配规则

- 精确匹配：收藏记录的 `sourceId` 等于已配置仓库目录中 `ExtensionArtifact.sources[].id`。ID 全程保留 64 位精度。
- 不按源名、漫画标题、域名相似度或语言模糊匹配；不为检测而下载、安装或执行插件。
- 默认仅把当前平台已知兼容且允许展示的候选列为可安装建议；沿用现有内容显示限制和来源校验。签名、哈希及运行时兼容仍在实际安装阶段验证，不能承诺安装后网站一定可访问。
- 没有 source ID 元数据、ID 已更换或仓库不含该源时，不猜测插件。显示简短说明「另有 N 个缺失图源未匹配到可安装插件」，提供既有迁移/仓库管理入口；不伪造可安装条目。
- 一个插件覆盖多个缺失图源只显示一行，收藏数为这些源的收藏漫画数之和；不重复计数。
- 同一仓库、同一包的多个版本沿用现有目录版本选择规则，只形成一个候选。
- 同一源命中不同插件，或同包来自不同仓库且现有来源策略不能唯一确定时，显示一行「需要选择插件来源」。用户在候选选择中查看插件、仓库及版本后才能安装；未选择者排除在「全部安装」之外。不能按返回顺序或最高版本擅自选择仓库。
- 唯一候选的身份使用现有规范化仓库身份（含签名指纹）加 packageName；不同版本不改变身份。同一 source ID 的互斥候选在批量快照中最多选择一个。

## 4. 页面与交互

### 4.1 位置与信息

Android 在现有插件列表中「已安装」分组前插入建议分组；若有「待更新」分组，保留其位置。Desktop 当前为「已安装 / 可用」页签：拟将建议作为两页签共用、位于页签栏上方的可折叠区域，不新增第三个页签、不重构既有导航。建议列表须有受限高度和可滚动区域，避免大量建议挤出原列表；Desktop 具体位置见第 10 节。

```text
浏览 → 插件
▼ 建议安装（3）                         [全部安装（3）]
  根据本机收藏漫画匹配；安装后仍可能需要登录图源网站
  插件 A · 中文 · 仓库名称
  涉及 2 个图源，12 部收藏漫画       [忽略] [WebView] [安装]
  插件 B · 多语言 · 仓库名称
  涉及 1 个图源，4 部收藏漫画        [忽略] [WebView] [安装]
已安装
  ……保留现有内容……
```

- 标题数量表示待处理插件建议数，不是漫画数；歧义组另外提示待选择数量。
- 条目展示插件图标、名称、语言、仓库、关联缺失图源名称与收藏数。多图源名称可展开查看，不能把每个源重复当成一个插件。
- 首次默认展开；点击标题/折叠箭头切换，立即本地持久化。离开页面、重启、刷新或新增建议均不覆盖用户选择。
- 收起时保留标题、数量和批次进度；「全部安装」仍可用，开始前展示将处理的插件清单。
- 检测完成且无建议、无未匹配说明、无运行中批次时隐藏该区域，但保留展开偏好。
- 搜索按插件名、关联图源名和包名过滤建议；标题显示匹配数/总数。语言筛选不隐藏由收藏触发的建议，并用说明明确这一区域按收藏匹配；内容安全显示限制仍生效。
- 有搜索条件时按钮标为「安装匹配项（N）」，仅安装当前搜索结果；无搜索时为「全部安装（N）」。折叠不改变范围。
- 普通「可用」列表保留原条目；两处共用安装状态，任何一处操作都不能重复排队。
- 支持键盘操作、读屏标签和展开状态语义；窄屏允许操作换行，按钮不得被裁切。

### 4.2 忽略

- 点击后立即从建议列表移除，并显示「已忽略此插件建议」及本次 Snackbar 的「撤销」。无须额外确认。
- 忽略身份为规范化仓库身份加包名；在本机持久化，不因更新、刷新、重启、移除后重新收藏或覆盖更多漫画而重新出现。
- 忽略不卸载插件、不移除漫画、不隐藏普通可用列表条目，也不禁止手动安装。
- 源的全部候选被忽略后，不再用“未匹配”提示反复提醒这个源。来源或包名变化视为新候选，可再次建议。
- 批次中已排队或正在安装的条目暂不可忽略，避免用户误以为忽略等于取消安装。
- 本期仅提供即时撤销，不新增永久的「忽略管理」页面；是否需要长期恢复入口列入审阅决策。

### 4.3 WebView

- 打开建议所对应的缺失图源网站，不是仓库网页、APK 下载地址或任意漫画链接；URL 来自目录中的 baseUrl。
- 一个关联图源时直接打开；多个时先选择关联图源，不能默认打开插件中第一个不相关网站。
- 仅接受合法 HTTP/HTTPS 地址；无有效地址时保留禁用状态并解释「仓库未提供图源网址」。
- Android 复用现有 WebViewScreen 和导航。无需先安装插件即可访问页面，但不保证未加载插件时具备插件专属请求、登录或反爬能力；浏览不会改变建议资格。
- Desktop 拟复用现有外部浏览器入口，实际按钮标为「打开网站」，不把外部浏览器误标为 WebView。若要求两端都内嵌 WebView，须在批准实施前另行确定容器及平台验收范围。

### 4.4 单项安装与状态反馈

- 复用现有安装动作。状态至少可区分待安装、排队、下载中、等待确认、安装中、安装失败。
- 安装期间保留原行和进度，禁止重复点击；成功以真实安装清单及加载结果核对为准，不能仅以下载结束认定成功。
- 插件安装并正常加载后，移出建议，刷新已安装与图源列表。插件安装成功但加载失败时也不再标作未安装，明确显示故障并交由既有诊断路径处理。
- 用户取消或安装失败时保留建议及错误反馈，可手动重试；不写入忽略记录。

## 5. 一键全部安装与 Android 特别规则

### 5.1 批次共同规则

1. 点击后展示本次插件清单、数量及安装方式，用户点击「开始安装」即一次性提交批次。此确认也解决折叠和搜索时的范围歧义。
2. 使用点击时的候选快照，剔除忽略、来源未定、已安装、已排队及已知不兼容项；后续新增建议不自动进入本次批次。
3. 入队前再次核对安装状态、仓库身份及候选有效性。其他入口已完成安装的条目跳过，不重复提交；仓库删除或来源变化需重新选择，不能静默替换来源。
4. 复用现有下载并发与安装事务限制；不新增无上限并发。同包在任何页面或批次中最多一个有效安装事务。
5. 汇总展示完成/总数以及成功、失败、取消、跳过数量；单项网络或安装错误不回滚已成功项，也不阻止无关联项目继续。
6. 提供「停止后续安装」：停止尚未进入不可取消提交阶段的项目；已交给系统的安装由原安装器控制。不能声称停止批次已撤回系统操作或卸载成功项。
7. 返回/离开插件页不重复启动批次；重新进入恢复当前进度。应用进程退出后不自动重放整个批次，先核对实际安装结果并重新计算建议；仅继承原安装器已有的事务恢复语义。

### 5.2 Android 安装器

| 当前安装器 | 「全部安装」行为 | 必须给用户的反馈 |
|---|---|---|
| 系统 PackageInstaller / Legacy | 沿用现有安装队列，系统交互一次只处理一个插件，不同时弹出多个安装界面 | 开始前提示「Android 可能要求逐个确认安装」；有待确认操作时显示当前插件 |
| 私有安装 | 使用当前应用的私有安装链路，保留校验与加载步骤 | 提示仅安装到当前应用，其他 Mihon 应用不能直接共用 |
| Shizuku | 仅在现有授权与服务可用时按既有链路执行 | 服务/授权失效时暂停未提交项目并提示处理，不擅自改为其他安装器 |

- 不自动切换安装器，不自动授予未知来源安装权限，不使用无障碍或模拟点击跳过系统确认。
- 开始前展示当前实际生效的安装器；批次运行中设置发生变化时暂停剩余项目，重新确认后继续，不能混用用户未确认的方式。
- 缺少系统安装权限时暂停批次并提供既有设置入口；返回后检查权限，用户确认继续。未授权不能高速失败整个队列或循环拉起设置。
- 用户在系统确认页取消当前安装时，当前项记为取消并暂停后续系统提示；页面提供「继续剩余」或「停止后续安装」，避免连续弹窗。
- 保留现有仓库来源、签名、哈希与信任校验；需要来源确认的项目停在对应交互阶段，不能因“全部安装”默认同意。
- 安装回调与事务一一对应；Activity 重建、返回应用和迟到回调不得错配插件、重复安装或误报成功。
- 系统已装插件必须先识别并跳过。功能不能把“原版已经共享安装”误判为“此应用还须安装一份”。

## 6. 更新时机、空状态与失败

- 首次进入插件页，在收藏、插件清单及目录快照可用后计算。复用现有目录刷新策略，不因每次折叠或搜索重新请求网络。
- 收藏增删、迁移导致 source ID 变化、插件安装/卸载、目录刷新、仓库变更、忽略与撤销时自动重算；短时间连续变化可合并处理。
- 同步或备份恢复引入漫画后，使用本机新收藏记录重算；这不表示建议状态参与同步。
- 未配置仓库：说明需要添加仓库才可匹配，链接既有仓库管理；不自动添加第三方仓库。
- 目录加载失败：沿用仓库错误与重试反馈。有旧快照可继续展示但注明可能不是最新；不得声称“无需安装”。安装仍需实时校验产物。
- 部分仓库失败：展示已成功匹配项，说明结果可能不完整。未匹配数量只能表示当前目录尚未匹配，不代表插件不存在。
- 已知不兼容候选不可进入批次，说明平台/协议限制；不以“安装全部”强行尝试。

## 7. 本地状态与同步边界

| 数据 | 保存方式 | 同步规则 |
|---|---|---|
| 建议、关联源及收藏数 | 从本机收藏与目录派生，不作为权威数据长期保存 | 不上传、不合并、不下发 |
| 展开/收起 | 独立本地 UI 偏好，默认展开 | 不参与用户数据同步 |
| 忽略候选身份 | 独立本地集合，版本更新不清除 | 不参与用户数据同步 |
| 批次快照与进度 | 复用本机安装事务；不新增跨设备恢复协议 | 不参与用户数据同步 |
| 漫画、仓库等既有数据 | 沿用各自既有策略 | 本需求不修改其同步语义 |

新增持久化键必须明确排除在通用偏好同步枚举外，不能仅通过命名约定保证。拟将新增展开/忽略记录也排除在应用备份导出/恢复外，避免迁移到新设备继承旧机建议偏好；该备份边界为设计建议，见第 10 节。系统级应用数据恢复的行为以平台能力为限，不在本功能承诺内。

## 8. 验收清单（未来实施验收，不表示当前通过）

- [ ] 本机收藏包含未安装插件提供的源 → 浏览 → 插件 → 已安装上方出现匹配插件及正确收藏数。
- [ ] 两个缺失源属于同一插件 → 只出现一条建议；同名不同 ID 不被错误匹配。
- [ ] 仅历史记录或未收藏漫画缺源、本地文件源 → 不产生建议。
- [ ] Android 已系统安装或已私有安装候选插件 → 不出现重复安装建议；未信任/加载失败也不误报未安装。
- [ ] 收起建议 → 离开、重启或刷新 → 仍收起；首次使用默认展开。
- [ ] 点击忽略 → 立即移除；重启和目录升级后仍忽略；即时撤销可恢复；普通可用列表仍可安装。
- [ ] 多仓库/多插件命中同一源 → 明确显示选择入口；未选择项不参与全部安装。
- [ ] 点击 WebView → 打开关联缺失源的网址；多个关联源先选择；无网址显示原因；Desktop 按最终批准的网页方案验收。
- [ ] 点击安装 → 展示真实安装进度；成功后移入已安装；失败/取消保留可重试状态。
- [ ] 搜索后点击安装匹配项 → 批次清单只包含搜索结果；收起时开始批次仍可核对清单。
- [ ] Android 系统模式批量安装 → 按序确认；取消一个后暂停，用户选择继续后才出现下一项；权限缺失时不会循环弹窗。
- [ ] Android 私有及 Shizuku 模式 → 使用选定链路；授权失效与安装器变化有明确暂停反馈。
- [ ] 重复点击、其他入口同时安装、Activity 重建或迟到回调 → 不重复排队、不误报别的插件成功。
- [ ] 仓库失败、断网、无仓库或缺失元数据 → 明确说明不完整/未匹配，并保留可执行重试或管理入口。
- [ ] A 设备收起/忽略后同步到 B → B 的本地设置不变；收藏同步完成可独立触发 B 重算；同步载荷不含新增本地键。

实现时必须先写正确失败的行为测试，再最小实现与重构：共享契约覆盖匹配、去重、忽略与批次筛选；两端集成测试经过真实 repository、DI、展示和安装 wiring；Android 覆盖安装队列、系统确认/取消/权限与回调，WebView 覆盖导航与无安装源场景。涉及目录 HTTP 链路时用 MockWebServer 覆盖成功、空/缺失、403/429/500 与畸形响应。同步边界用真实导出/导入路径验证，不以源码字符串检查代替。

实际实施的 focused tests、阶段测试、发布脚本及真实运行验收预算在用户批准本需求后制定。本轮只有文档对照核验，不产生产品测试通过或发布验收结论。

## 9. 实施边界与维护约束

- 复用收藏查询、目录缓存、源描述与安装事务；仅抽取必要的共享建议计算，不新建一套目录或安装基础设施。
- Android/Desktop 共享相同输入时应得到相同建议资格、去重和忽略结果；平台兼容过滤与安装/网页 adapter 的差异需显式测试。
- 不扫描文件系统寻找其他应用私有插件，不读取原版 Mihon 的私有数据，不为匹配联网抓取各漫画网站。
- 匹配数据缺失时保持“未知/未匹配”，不误标为已安装或建议错误插件。安装存在性不能只依赖成功加载的源列表。
- 本文不建立执行 roadmap、不推进现有 active-task、不修改 capability manifest；需求批准后再按可独立验收的功能批次安排实施。

## 10. 审阅决策项

六项原始需求均作为必须满足项；以下为本稿补充设计，尚未视为用户同意：

1. **Desktop 网页行为**：建议沿用外部浏览器，并显示「打开网站」；若必须为内嵌 WebView，则需扩展平台设计与验收范围。
2. **Desktop 分栏位置**：建议在「已安装 / 可用」页签栏上方放共用折叠区域；Android 直接在列表「已安装」前插入。
3. **忽略恢复**：建议本期只有即时撤销，不增加长期忽略管理页面；忽略按仓库身份和包名持久化。
4. **备份边界**：同步明确排除；建议同时不把新增展开与忽略偏好放入应用备份，避免跨设备恢复带入旧偏好。

未决项应在实现前确认或修订本文；本稿不授权自动安装或改变用户现有安装器。
