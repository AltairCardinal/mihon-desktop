## 1. 用户目标与范围

用户报告：未下载的长章节（约 200 页、一章一卷），打开后直接用进度条跳到第 126 页，可能整屏黑色。用户明确要求优先保证正常顺畅阅读：缺少自动跨页匹配信息时，先按指定页码和默认规则显示；迟到的正确配对在下一次主动翻页时应用，必要时重复一张已看过的边界页，不能让用户漏看一页。

优先级固定为：**目标页可读 → 已显示画面稳定与源页不被自动遗漏 → 自动配对准确**。最初请求仅编写设计和 roadmap；2026-11-01 用户已明确授权实施。共享与双端接线的选定回归、Android API36 原生路径及 Windows 候选路径已完成；本次 Windows 图片重试取得用户实际像素恢复确认。Android 不冒称真机或用户人工验收，详细证据与平台边界见 roadmap。

适用 Android 与 Desktop 的双页模式，包括 RTL／LTR、在线／缓存／已下载来源。重点复现是在线长章冷跳；共享行为须在两端一致。复用现有图片加载、原图分析、自动配对算法、手动调整及进度存储，不新增设置、数据库格式、整章下载任务或持久分析索引。单页、条漫和相邻章业务规则不重设计，仅覆盖受影响接线的回归。

全文对用户页码使用 **1-based**：第 126 页对应 `sourcePageIndex == 125`。物理左右槽位随阅读方向镜像，源页顺序不变。

## 4. 用户行为契约

### 4.1 打开、恢复和精确跳页

1. 打开章节、恢复阅读位置或进度条提交页码，保留原始源页锚点；后台事实更新不得改写该锚点。沿用现有进度条提交时机，不扩大为进度条交互重设计。
2. 已有当前内容与设置下的可靠分组时，直接使用；否则按共享默认布局建立包含目标页的临时帧：`[1] [2,3] [4,5] …`。例如跳 126 得到 `[126,127]`，跳 127 也落在该组，但请求锚点保持 127。
3. 默认从章首规则推导，不能把“本次跳到的页”当新的两两配对起点。已知手动布局和可信宽图按既有硬边界规则优先；没有可证明的前缀相位时使用上述默认规则，不等待未知前缀。
4. 目标图片本身尚未可用时显示既有加载／下载进度；加载失败显示该页重试。目标图片可用且自身实际几何已知，即可画出，不等待伙伴图片、边缘样本、配对恢复或整个章节分析。
5. 图片尺寸只要求正常解码可取得的本图真实几何，不要求额外原图分析成功。宽图按既有完整宽图显示。未知伙伴不阻挡已知目标；若伙伴迟到才发现是宽图，未绘槽位可撤销，但该源页必须保留在下一导航的待呈现集合，不能吞页。

### 4.2 当前屏稳定，纠正在下一次用户导航生效

- 在第一次有效曝光前，可以选用当时已有的更准确分组；不人为等待认证。
- 一旦当前或手势中邻屏真实准备曝光并取得像素锁，保护其已经承诺的内容、槽位和几何。后台事实只更新后续候选，不使已显示图片换边、缩放重置、闪烁、消失或自动翻页。
- 同一帧迟到的兼容伙伴可以独立加载、绘制；不会移动已绘图像。与锁定内容不兼容的新分组延后到用户导航。
- 用户明确手动调整、切换模式／方向或重新加载沿用现有显式操作语义；它们不是后台自动纠正。手动布局尚未恢复时临时显示不代表已确认空布局；恢复成功仅影响之后主动导航的帧，不能移动当前已绘画面。恢复失败保留未知／失败状态、已知手动约束及原存储记录，不自动保存默认布局或以空记录／READY 掩盖失败。恢复操作仅在用户主动进入已有双页调整／阅读设置界面时可见，不自动打开或抢焦点。
- 新章节、新内容版本和会话关闭撤销旧能力；旧结果不能填进新目标。仍挂载的旧帧只保留必要的释放责任，不能继续为新位置报告阅读。

### 4.3 连续翻页、边界重叠与未绘伙伴

“已读”在本节仅指本次有效帧真实绘出的页，不新增全章逐页已读数据库。导航必须保存源页锚点、当前帧的实际绘出集合，以及该帧尚未绘出但应交给用户的源页；不能只读取最新 canonical 的数组下标或被刷新裁掉后的槽位。

**前进规则：**

1. 当前锚点之后若存在本帧尚未绘出的伙伴，候选为其中最早一页；否则候选为 `max(当前锚点, 当前帧已绘页的最大页码) + 1`。无已绘页时只用当前锚点。反向对称：优先锚点之前尚未绘出的伙伴，否则取相应最小页码减一。
2. 从最新的可靠分组中选取包含候选的组；仍缺证据则使用默认组。允许新组带回一张已绘边界页，不通过跳到后一整组消除重复。
3. 候选仍属于当前锁定帧且未绘出时，**无论该帧来自临时默认还是已认证分组，都精确激活该伙伴一次**：保留当前已绘像素，把源页锚点／页码反馈移到该伙伴，显示它的加载／重试状态。再次主动前进时以更新后的锚点计算，可离开这一仍未就绪的页面；不无限返回同一组，不伪造其已读。这是用户主动离开已明确呈现的加载／错误页，与后台重排自动越过它不同。
4. 用户用进度条明确跳到更远页时尊重该目标，不强迫补读跳过区间；精确直跳与连续翻页分开处理。跨章仍走现有章节窗口和边界入口，只在没有本章待交付的候选页时进入原边界流程。

| 当前状态（用户页码） | 后台确认的分组／动作 | 必须得到的结果 |
| --- | --- | --- |
| 126／127 均已绘，锚点 126 | 新组为 125／126、127／128；前进 | 候选 128，显示 127／128；不跳到 129／130 |
| 只绘 126，127 加载中，锚点 126 | 同上；前进 | 候选 127，显示 127／128；127 不因旧占位被跳过 |
| 只绘 126，127 加载中 | 仍无认证，默认组仍为 126／127；前进两次 | 第一次精确激活 127、保留 126 并显示加载状态；第二次可进入默认 128／129，127 不产生绘制进度 |
| 126／127 已认证但只绘 126 | 认证分组不变；前进两次 | 同样先激活 127、更新页码并保留像素，第二次进入包含 128 的下一组，不因认证来源陷入同组循环 |
| 126／127 均已绘 | 新组为 125／126、127／128；后退 | 候选 125，显示 125／126；重复 126，不漏 125 |
| 直接跳 127，126 尚未绘出 | 前进 | 尊重 127 的明确入口，不自动把用户拉回 126 |
| 全部图片仍加载中或当前页永久错误 | 连续主动前进／后退 | 源页锚点有界推进、保持可见反馈，不因空绘出集合死循环 |

动画期间旧 `[126,127]` 与新 `[127,128]` 可同时存在，各自持有独立帧身份、票据及图片 lease。新帧里的 127 不能被全局 `claims/emitted` 去重删除；也不能因“第一个包含 127 的组”命中旧帧而回跳。旧帧在原生移除／动画结束后释放；取消手势时撤销未完成目标，保留旧帧和原锚点。重复页不变成永久重复分组或不断累积的历史占用。

### 4.4 进度、反馈与失败处理

- 临时帧与认证帧均可通过有效真实绘制回报进度，`Ready`、占位、预取、分析完成、仅有页面容器均不算已读。
- 继续使用现有最大已绘源页与 settled viewport 语义；不在本迭代引入“证明之前每一页都读过”的新存储规则。同一导航位置下的边界重复绘出不回退进度；只重绘旧帧或后台纠正不制造新用户导航／完成事件。`last_page_read` 沿用既有继续阅读位置语义：用户主动后退并实际绘出较早视口时保存该视口的最大已绘源页，允许页码减小，已完成章节的已读状态保留；它不是全章最大已读页。验证后台纠正时比较用户下一次输入前的保存位置与阅读事件数，不能把合法主动回访当作自动回退，也不从事件最大值虚构新的已读存储规则。
- 图片失败和自动配对失败分开：图片失败提供逐页重试；配对 `NeedFacts`、超时、预算耗尽、分析失败只降级为默认显示，不能遮住可用图片或抛出整章不可读错误。
- 不新增强制弹窗、设置开关或反复提示；已有图片加载／重试反馈足以表达当前可用性。测试可观察临时／认证来源及降级原因，但不为此建立新的诊断产品或状态服务。

### 4.5 配对恢复失败与图片重试分别验收（2026-11-02 纠偏）

正常打开、恢复、冷跳、翻页及后台配对／手动记录恢复失败，都必须自动保留可用画面并按临时规则继续。禁止自动中央浮层、模态弹窗或要求先选择“本次使用默认配对”；既有失败弹层同样受此限制，不能仅修测试夹具来掩盖 production 界面。保留真实未知／失败状态、已知手动约束和存储记录；不把失败当空记录或 READY，不自动写默认覆盖旧数据。晚到恢复成功只影响之后主动翻页，当前帧不动且不漏页。

恢复入口复用用户主动打开的双页调整／阅读设置界面，仅提供一个可选的“重新读取双页调整”操作。正常阅读与主动打开设置都不显示旧恢复错误标题及“重试／本次默认”二选一错误块；不能把原错误块搬入设置当作非阻塞修复。该操作沿当前章节的既有恢复读取链执行，不是继续阅读的前提，不自动打开设置、抢焦点、触发 useDefault 或新增提示体系。

Desktop 的入口位于既有阅读设置双页区域，Android 位于既有阅读设置阅读模式页。Android 当前双页章主动重读复用后台读取，保持共享请求的可见帧保护，不重新激活章节；失败／未知状态、已知约束和原 SQL／CAS 保护继续保留。实际 AUTO 双页也适用；原单页等未变路径所依赖的内部恢复／默认方法可保留，不向双页设置暴露默认选择。此前设置中的二选一实现已被用户拒绝，其旧 Android 原生证据只能按未受影响的数据／帧行为复用，不能证明本次单一入口通过。最新源码定向结果及双端原生路径已通过，Windows 独立图片重试用户验收已通过；详细证据与平台边界以 roadmap 为准。

Android 恢复还须处理阅读模式及章节身份在 I/O 期间变化的时序。是否前台等待读取可在请求开始决定，但失败后能否激活必须在 UI 激活阶段按实际 viewer 与有效内容 owner 判断，并在进度会话挂起返回后复核；AUTO 已切为双页时不能因旧的单页等待策略留下空章节。双页可读许可独立于恢复是否失败／重读中／已成功，未知记录的保存权限仍由真实 revision 和既有 CAS 规则控制。

设置内双页重读只取当前章节及其当前 pages 对应的有效 owner；不能依赖仅在部分失败回调赋值、切章时又清空的全局提示目标。普通邻章预读可在该章被激活后失败，激活及后续可用性发布均须由当前 owner 派生状态，保留可选重读入口。旧章迟到结果不改变当前目标、导航位置或内容；恢复成功沿既有 viewer 重绑、已绘帧保护及后续主动翻页规则。单页的旧对话框／默认选择恢复边界保留。此处是后续 Android 时序修复约束，未扩大公共功能验收范围。

图片 Retry 是独立闭环：配对恢复正常，同章、同 owner 的真实 ONLINE source → SourcePageFetcher → 完整 ReaderViewport → 准确失败页按钮 → 新 attempt／新读取 → 真实解码与目标像素恢复；错误消失，正常伙伴及当前帧保持。不得用另一种总能返回地址的成功源、replacePage、强设 Ready 或只读状态计数替代。配对恢复失败场景单独验证，不能把两种“重试”混在同一个人工验收页。

准备人工验收时，若出现 RESTORE_FAILED、错误按钮未实际确认、捕获失败或证据来自不同章节，均标记准备未完成，不要求用户猜测应测试哪个按钮。一次原生验证前完成离线准备；失败后记录准确链路停点和新信息，再决定下一步，禁止无新证据重复点击／重建。

## 5. 共享实现边界

以下是责任与不变量，具体类型名由实施者按现有模式最小调整，不要求照名建立平行引擎。

| 层 | 本次职责 | 继续保留 |
| --- | --- | --- |
| `ReaderPairingCertifier`／canonical scan／samples owner | 继续计算有真实证据的最终分组；临时默认结果不得作为 `Certified` 或分析事实回灌 | 算法、原图坐标、版本、依赖有效性、手动优先级 |
| `SharedDualPageSession` | 区分配对证明和呈现许可；统一精确源页意图、临时组选择、导航纠正及有效进度 | 一个共享业务 owner；旧身份及迟到结果拒收 |
| `ReaderDualPagePresentationOwner` | 管理临时／认证帧、像素锁、有限过渡重叠、未绘伙伴、绘制与释放 | canonical 不依赖显示历史；rebind 释放责任 |
| Desktop model／presentation／pager | 消费共享帧身份及准备能力，真实图片逐槽绘制，按准确目标帧定位 | 现有加载／解码／缩放／原生资源管理 |
| Android viewer／adapter／holder | 消费同一共享契约，移除平台侧“必须 Certified”的基本显示条件，维护手势及 holder 生命周期 | 不新增 Android 私有配对或跳页算法 |
| 现有事实准备与调度 | 可见图片优先，后台匹配可暂停／失败；停止匹配不撤销基本显示 | 当前资源上限、真实取消完成、缓存与内容校验 |

呈现许可至少绑定 chapter/session generation、page-list/content identity、location sequence、frame identity、布局语义及显示来源；临时不等于无校验。不得把所有 `captureCertifiedViewport` 调用机械换成无约束的 `captureViewport`。

过渡重叠的页身份仍只有一份内容，允许多份有界显示 lease；不能让同页两个帧互相释放仍使用的资产。沿用实际在屏帧和动画邻帧的有界容量，不保存无界全章显示历史。手势取消、快速新导航、内容 rebind、退出分别覆盖准确释放、旧回调拒收和帧选择。

正常图片数据获取不得反向依赖配对 ticket；否则即使放开绘制也仍形成加载循环。复用现有 current／nearby 和显式用户需求入口，不为消除黑屏扩大成整章下载，也不伪造导航来刷新分析预算。分析仍允许在既有预算中取得必要事实，不承诺所有章节在有限时间内一定自动认证成功。

Android HTTP 的同帧两张普通图片也须独立准入，不能让先提交的迟到伙伴阻止另一张正常图片启动。当前 viewer 的精确帧窗口可将普通显示／显式图片重试的逻辑并发从原 1 提升至 2；Single／Webtoon 默认路径、事实／optional／prefetch 准入和原 materialize 物理上限 2 均不扩展。租约、窗口代际和页面对象须在 production 接线核对；IO 准入不能替代 before-draw 像素许可。两个旧物理操作均未真实退出时仍须等待，不伪造释放来声称立即开始第三个操作。详见[共享架构](architecture/reader-shared-core.md)。

## 6. 固定验收

以下均为 **PROJECT_POLICY / 按 roadmap 逐项验收**。设计时源码已存在的机制见第 2 节；浏览器原型、源码字符串扫描或复制配对实现不作为行为证据。平台测试应控制真实 production 调用链的 I/O 响应时序，不依靠睡眠或更长超时制造通过。

| ID | 输入／动作 | 必须断言 | 最小证据层 |
| --- | --- | --- | --- |
| NB-A01 | 200 页在线未下载章，开篇后进度条提交 126；前缀与分析挂起，仅目标响应 | 锚点 126；正常默认 126／127；126 有真实像素，后台仍未认证 | shared + 两端 UI／真实内容链集成 |
| NB-A02 | 仅目标就绪、伙伴延迟／错误；两页到达顺序互换 | 单页可独立画；保留加载／重试；重试不移走已绘图片 | 两端原生呈现及图片重试 |
| NB-A03 | 已绘 126／127 后出现 125／126、127／128 证据 | 当前帧内容与几何不动；用户前进后为 127／128 | shared + 两端真实翻页 |
| NB-A04 | 只绘 126 或只绘 127；正确配对迟到；双向移动 | 遵守第 4.3 节；未绘伙伴不因占位或旧组 max 被吞掉 | shared 矩阵 + 两端代表用例 |
| NB-A05 | 当前／下一帧重复 127；动画提交、取消、快速反向 | 127 两处可见能力各自有效；不选回旧帧、不丢页、不泄漏 | 两端真实 pager／holder 生命周期 |
| NB-A06 | 匹配永不完成、超时、资源拒绝；图片成功 | 默认阅读持续可用；无后台自动续预算；前景不被增强任务阻塞 | shared budget + 两端 production wiring |
| NB-A07 | 所有页等待／错误；临时与已认证同组的伙伴未绘出；连续输入 | 一次停靠更新锚点和页码后允许主动离开，不制造未绘进度、不死循环；逐页反馈和重试仍可用 | shared + 两端输入接线 |
| NB-A08 | LTR／RTL、封面、奇数尾页、可信宽图及迟到宽伙伴 | 默认章首规则正确，宽图完整，尾页可达，方向只镜像槽位 | shared 契约 + 两端局部像素 |
| NB-A09 | 手动对／单页边界、慢恢复、恢复失败和显式调整 | 已知手动优先；恢复失败自动临时阅读，无自动遮图／模态／默认选择，保留失败及记录；主动调整入口可达，晚到成功不搬当前帧 | existing persistence integration + 两端接线 |
| NB-A10 | 新跳页、换章、rebind、旧分析／绘制回调迟到、退出 | 旧能力无效；新目标准确；挂载释放责任完整 | shared + 两端已有生命周期回归 |
| NB-A11 | 临时帧真实绘制、部分伙伴、边界重叠、未绘尾页 | 只有真实有效绘出参与既有进度；不伪造已读／章完成；后台或同一位置重绘不回退，主动回访沿用第 4.4 节的继续阅读语义 | shared progress + 两端 production progress |
| NB-A12 | 单页／条漫代表路径及原认证算法反例 | 未受策略改变的路径可用；真正认证仍不能由缺信息或临时猜测伪造 | 精确受影响回归，不跑完整模块 |

“立即显示”按因果验收：让匹配依赖保持挂起，等待正常图片链完成后仍能观察真实目标像素；不把分析耗时藏进图片 Ready 前，不以空容器、loading spinner 或延长 10 秒等待替代目标图显示。性能观察复用生产首绘／加载事件，记录冷跳首像素和下一步响应，不建立全新基准平台。

## 7. 交付与失败边界

实现顺序、具体测试入口、审查和预算见 roadmap。功能完成须有共享真实行为红绿、两端接线及受影响平台用户路径证据；仅共享 helper 或一个平台通过不算双端能力交付。

正常日常修复以 focused 验证收口；不自动运行全模块／全量、`finalParityAudit`、正式发布矩阵或分配版本。预览和原生验收按当前授权及项目入口执行；环境受阻记录平台、具体入口和缺失证据，不能勾选未通过项目。公共功能说明须等待用户验收本次具体候选；本设计不构成已发布能力承诺。
