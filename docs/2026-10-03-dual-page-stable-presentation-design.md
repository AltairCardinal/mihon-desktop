# 双页阅读：布局确定后呈现与提前准备设计

本文件承接[共享双页设计](2026-10-01-shared-dual-page-rules-and-repair-design.md)，解决真实 Windows 验收发现的“页面先居中，随后移到右侧并补出左页”。用户明确要求：漫画内容显示后，不得因图片继续加载、尺寸或匹配结果晚到而改变位置。本文是设计方案，尚未实施；当前正式版本 `0.11.19.70.84d98c7` 不具备该保证。

终态配对、RTL/LTR、自动跨页评分、宽图独占、手动边界和 B1/B2 规则继续共用。改变的是**哪些结果可以进入屏幕，以及何时准备这些结果**。旧设计第 4.2、6.2、7、9 节允许“暂定居中先显示，事实补齐后重排”的行为不再满足目标，不能以旧规范允许为由签收。

## 1 用户体验与不能同时承诺的条件

### 1.1 必须满足的约束（PROJECT_POLICY）

同一内容版本、用户设置及视口下，从一个显示组第一帧漫画内容出现，到用户离开该组：

1. 页的归属、左右槽位、内容矩形、裁边结果、初始缩放及书脊对齐不再因后台加载而改变。
2. 双页一次显示两张已准备好的内容；单页从第一帧就位于最终的右侧、左侧或居中位置。左侧仅沿用已确认的开篇语义，例如 B2 第 2 页，不能用未决左侧孤页填补正文中段。
3. 可细化同一固定矩形内的图片清晰度或更新动画帧，不能用后到尺寸重新 fit，也不能先出未裁边图再换成裁边图。
4. 目标已确定后，下一张图片不应使正在阅读的组变成另一组。回翻同一内容与设置下的已确定组也不能重新排版。
5. 两端共享准备状态和判定。平台不自行猜槽位、不各自决定等待多久以后按单页显示。

用户主动翻页的整组动画、缩放/平移、调整窗口、旋转设备、切换方向/阅读模式或明确调整配对仍保留；它们必须由对应用户/视口事件触发。后台尺寸与匹配回调不能伪装成这些事件。触摸拖动中已经露出的漫画同样受约束，不能等翻页停稳后才开始保护。

### 1.2 必须公开的取舍

在必要图片尚不可用时，无法同时保证“立即显示漫画、与完整匹配算法一致、以后绝不移动”。本方案选择正确布局和显示后稳定：正常顺读用预加载隐藏等待；冷跳页、慢网或失败时允许显示准备/错误反馈，但不先展示位置未定的漫画。

不会把临时居中永久锁住来消除移动，那会拆散原本应当形成的双页；也不会仅延迟几百毫秒、加位移动画、关闭自动匹配或假定固定多读 N 页就已正确。等待超时不是“匹配不存在”或“本页必须单独显示”的证据。

## 3 先证明本组结果不会再变

### 3.1 分开保存三种状态

在现有共享 presentation owner 内增加准备阶段；名称是职责描述，可合并入既有类型：

- **候选结果**：事实逐步到达时重算，允许变化；只能用于准备和诊断，不交给可见 pager。
- **已确定布局**：带有依赖证明的页集合、物理槽位及独占原因；尚不代表图片已可画出。
- **已显示帧**：已确定布局加平台完成的内容/几何准备，由共享 owner 核准后一次提交。它是显示和进度上报的唯一依据。

共享层保存页身份、内容版本、方向、自动匹配开关、手动记录 revision、证明覆盖的事实/评分；平台仅保存对应图像 lease、实际测量和渲染状态。bitmap 和像素坐标不进入 KMP 规则层。

### 3.2 判定完成的条件

允许显示的证明必须覆盖 **分组和槽位**，不能只证明“这两张目前可以配”。至少满足：

1. 页表及手动边界恢复完成；目标定位意图有效。
2. 相关图片真实尺寸及有效 EXIF 方向已确认，不能靠 UNKNOWN/FAILED 的默认值。
3. 影响目标的结构起点、奇偶传播及开篇/尾页/剩余页原因已经确定。知道附近有宽图，不等于已知此前是否进入过正常双页。
4. 自动匹配关闭时不等样本；开启时，影响目标的所有竞争关系已有终态。明确算得“不匹配”是终态，未读、失败、取消和超时均不是。
5. 对其余未取得事实的所有合法结果，目标组的页集合和槽位相同。拿不到这个保证时继续准备，不将经验猜测标为确定。

第 5 条是语义契约，生产实现不枚举指数级组合。第一版采用保守的依赖范围与摘要：在已经确定的结构边界之间求解，需要时向前恢复配对相位和开篇状态；边界摘要本身也必须确定。完整数据时仍调用当前唯一规则与候选选择算法，不另写一套“快速排版”。

### 3.3 自动匹配必须处理连续竞争

示例：连续纵页 A、B、C、D，有候选 AB=10、BC=5，距离越小越强。只知道这两条边时选 BC；随后 CD=1 到达，原算法会先选 CD，再选 AB，A 的分组也随之变化。等待 A/B 下载完成或只确认它们直接相邻的评分都不足以封闭这个影响。

安全的准备范围为影响目标的**完整潜在竞争连通部分**：未知相邻边继续视为可能竞争，不能作为结束位置；确定不匹配、真实宽图、已恢复手动边界及章界可截断自动匹配竞争。整个相关部分评分完成后，用原有强边优先算法求解；独立部分不必互相等待。

但“不匹配边”只能截断自动匹配竞争，不能自动重置默认顺序配对的奇偶或开篇状态。准备器仍须追溯结构依赖；共享证明同时包含两类依赖。不能用当前暂选的匹配边充当永久边界。

极端情况下，长串相互竞争的纵页可能要求准备整个相关纵向段，甚至整章。不存在既保持当前全局强边优先语义、又保证任意情况下只读相邻两三页的办法。常规章节按已确认边界逐段提前推进，不能为隐藏这项代价偷换为到达顺序优先。

### 3.4 合法居中与暂定居中的区别

- B2 第 20 页在完整有效事实下仍属于规定的歧义孤页：这是最终居中，可以显示并保持居中。
- 第 17 页因前方尺寸/匹配未完成而暂定居中：不能显示；先取得足够事实，第一次出现就位于右侧。
- 配对已确定、其中一张图像还未解码：继续准备该组，不能先把另一张放大居中。

已显示布局不能因后到事实重新分组或换边。若同一输入下后来结果推翻已签发证明，属于证明实现缺陷，应保持当前帧、记录诊断并使相关待显示候选失效，不能静默套用新排版；该情况必须让验收失败。

## 4 提前加载要提前完成“下一组”，不只下载文件

### 4.1 复用一条生产流水线

```mermaid
flowchart LR
    A[用户目标与阅读方向] --> B[共享准备器列出依赖]
    B --> C[现有 scheduler 与内容缓存]
    C --> D[头部事实与边缘评分]
    D --> E[分组及槽位确定]
    E --> F[原生解码 裁边 测量 首帧准备]
    F --> G[核对版本并一次显示整组]
    G --> H[继续准备后续组]
    H --> B
```

已缓存/已下载/局部下载/本地文件继续走原内容路由。头部、采样和呈现共用原 encoded 内容、去重和有界解码资源；不额外请求同一 URL，也不向图源假发 HEAD/Range。若图源必须下载完整图片才可取头部和样本，计入真实读取成本。

### 4.2 阅读窗口与优先级

正常阅读时以当前已显示组为中心：

| 范围 | 准备目标 | 资源与优先级 |
|---|---|---|
| 当前组 | 保持现有帧和 lease | 不因预取被挤出；重试沿原 P0 |
| 用户正在请求的下一组/跳页目标 | 依赖判定、内容、最终几何及可画首帧全部完成 | 在原调度器中取得交互目标优先级；等待中的依赖不能继续被当无关后台请求饿死 |
| 沿阅读方向后两组 | 尽量提前确定布局；最近一组在已有内存允许时预先解码/测量 | 原 P1/current+4 基础窗口及共享额外预算；“两组”是准备目标，不是保证追加任意下载 |
| 刚读过的一组 | 保留确定布局和已存在的可复用资源，方便回翻 | 不新增独立反向全图缓存；内存不足先回收未显示预解码内容 |
| 更远页和相邻章 | 继续原背景与邻章策略 | 不能抢占当前目标；跨章永不拼页 |

用户改方向时调整未来准备顺序；跳页时取消仅由旧目标拥有的准备工作，保留被可见组或其他真实消费者持有的工作。原请求从预取提升为当前目标应复用请求身份与已有结果，不能取消重下载。

预加载的交付单位是“可显示的下一组”，其中可能包含为其判定而读取的更早/更后图片。已确定组不需要因无关页面完成而重复验证整个章节。样本最多 16 页，已确认的正/负评分与必要结构摘要可继续保留；不保留整章 Bitmap。

### 4.3 首帧前必须允许必要事实工作

当前“先画当前页，再读取其他 ready 页头部”和“布局 viewport 上报后再补齐”是旧首帧性能策略。新要求优先，必须把相关工作触发改为**有效目标与准备需求**：

- page-list/手动记录就绪后即可准备必要依赖，与当前是否已经出过漫画首帧无关。
- 保持一份已显示状态及一份 pending 目标；请求调度不能依赖把 pending 冒充真正可见页。
- 依赖工作可以获得交互优先级，但仍按额外事实的页数/字节/并发额度记账；不能借“可见”标签绕过预算。
- HEADER_READ、采样、OPEN_PAGE、首次真实显示仍分别记实，不改事件名伪装首帧更快。
- Android adapter/holder 同样不能等可见 holder 创建后才产生判定所需事实。平台准备票据不是已读/可见票据。

### 4.4 流量、时间与内存仍然有界

首版沿用现有硬上限：额外 materialize 同时最多 2 页、每次显式定位最多新增 16 页、累计 32 MiB、主动准备窗口最多 15 秒，头部读取最多 512 KiB；原有平台总并发上限继续生效。数字是现有资源政策，不代表需要等待 15 秒或每次都请求 16 页。

当前目标和滚动预准备共享本次额度；下一次真实导航可以开启新的定位额度，但后台不得靠生成虚假导航或每次候选重算重置额度。连续点击同一未完成“下一组”不能刷新预算。与原 nearby 重叠的请求去重；超出原预取策略的新图片明确归入额外预算。

到上限后停止自动扩展，不自动降级为居中漫画。允许用户明确重试，复用已经获得的事实并继续缺失部分；不清空缓存从头再来，也不自动开启下一轮。预取关闭/流量限制仍约束非可见依赖，不能以本方案为名绕过。长期不可取得必要事实时，该组保持未显示并给出可取消/重试的结果。

缓存命中不计新增网络字节，但计算、解码、时间、句柄与内存仍受限。预解码保留最多当前之外的一个准备组，并且受既有字节预算约束，可能实际保留零组；需要回收时回收准备内容，再在显示前重新准备。缩略首帧/分块可继续使用，前提是最终几何已知且后续清晰度更新不改变矩形。

## 5 原子显示与生命周期

### 5.1 状态转换

| 状态 | 屏幕内容 | 进入下一状态的条件 |
|---|---|---|
| PREPARING | 进入章节时为中性加载面；翻页/跳页时保留上一组并显示准备反馈 | 目标依赖证明完成 |
| LAYOUT_READY | 仍不显示新组漫画 | 本组每张图内容、方向、裁边、实际 viewport 测量与首个可画内容均已准备 |
| FRAME_READY | 保留前帧；准备结果持有必要 lease | 同一 UI 事务核对有效目标、证明、内容和视口版本后提交 |
| PRESENTED | 一次显示整组；固定页、槽位及内容矩形 | 只由用户导航或明确设置/视口变化进入下一次准备 |
| WAITING_RETRY | 中性错误/准备失败反馈，或保留前组并反馈未翻页 | 显式重试/新跳页/返回；晚到结果可缓存，不能自行重排前组 |

下一组已经准备好时，正常点击/键盘/滚轮沿原翻页动画直接显示，不插入一帧 spinner。失败反馈和准备反馈使用覆盖层或固定工具栏区域，不挤压画布造成当前图重新 fit。

### 5.2 双页与几何

“两张 encoded Ready”不足以提交。要准备两张实际可画出的首帧，以及最终有效方向、裁边边界、比例和书脊对齐。Desktop 原有 image/transform owner、Android 原解码器/SSIV 继续执行这些操作，在暂不可见的准备阶段完成；共享层只接收符合票据的就绪结果。

整个双页组一次暴露，不让右图先显示、左侧暂时全黑，随后才补内容。等待期间不展示任何临时漫画缩放图。对既有大图分块路径仅要求首个足够覆盖当前视口的可画层准备完成，不要求整幅超大原图解码进内存。

已提交组持有真实资源至新帧接替，避免先释放旧图再等新图。READY/测量回调晚到时再次检查页身份、content/attempt、方向、用户配置、viewport 和 pending 序号；不符合即释放该准备资源，不能抢占更新的目标。

### 5.3 手势、列表与导航

- 当前显示列表不得直接消费 `owner.units` 的每次变化。可见项、正被拖出的相邻项及其身份在一次手势内保持；后台候选不改变这些项的数量、索引或宽度。
- 手势露出目标漫画前必须已取得整组 FRAME_READY。未准备好的目标只提供明确加载反馈/占位，不允许半次手势看见临时单页，再在手指下重新配对。
- 多次按“下一组”在目标未确定期间合并为同一待翻请求，不按不断变化的候选组数越跳越远。反向操作可取消待翻并保留当前已显示组；直接选源页码则替换为最新明确目标。
- 翻页时按确定显示组导航，页码条/恢复记录按源页身份定位。旧 `0`/End 的章界单元语义问题单独保留，不在本方案顺带改快捷键。
- 已确定组的证明可复用；回翻仅可能等待资源重新解码，不能重新猜组或换边。

### 5.4 内容变化与阅读进度

新的源图片、重排页表、手动调整、方向/模式及影响几何的设置改变会产生新输入版本。用户主动改变设置时按新版本重新准备一次，并明确属于用户动作；其他后台数据替换不能用旧尺寸搭配新像素。在当前帧仍能合法保留时继续持有旧版本，提示明确重新加载；不能悄悄把正在看的图替换成另一个位置。资源或应用被系统销毁后的恢复先重建已确认目标，再显示内容。

未显示的准备组、缓存读取、隐藏预解码、加载与错误面均不产生阅读进度。只有已提交组真正可见并停稳、实际成功页集合完整时，才经现有共享进度链提交一次。保留前帧等待期间仍报告前帧，不用 pending 页码伪记已读。

## 6 具体用户路径（PROJECT_POLICY）

阅读器沿用原页面、设置面板、返回和 retry，不新增 Screen/Tab。无 HTML 替代验收。

| 操作/场景 | 用户实际看到的结果 |
|---|---|
| 正常顺读，下一组已准备 | 按原动画翻到两张完整的双页，或最终槽位的单页；页面落定后不再自动移动 |
| 首次打开/冷跳第 17 页 | 短暂加载反馈；17 第一次出现就在右侧；足够事实前不显示居中的17 |
| 当前组停留时下一组仍在下载 | 后台准备；当前画面完全保持 |
| 用户翻向未准备好的下一组 | 保留当前组，反馈“下一页加载中”；菜单、返回、页码选择可用；准备完成后一次进入目标 |
| 点击页码条跳转 | 保留旧图时明确显示“正在跳转到第 N 页”；已读页码仍属于旧图，不把旧图标成新页 |
| 准备超出上限或关键图片失败 | 提示“暂时无法完成双页加载”，提供重试与返回/取消；保留已有已读位置。用户仍可自行使用现有单页模式入口，应用不自动切换 |
| 某组在完整事实下应当居中 | 从第一帧起居中，之后保持居中，例如满足现规则的B2第20页 |
| 关闭准备反馈/返回 | 只取消本次待翻/跳页；不会取消前帧的资源或其他消费者 |
| 关闭阅读器 | 释放本 reader 准备票据和 lease；迟到回调不产生布局或进度 |

准备反馈必须有及时、可访问的状态通知，复用既有本地化与焦点方式；不向用户暴露“依赖闭包”“layout revision”等实现术语，不反复播报每条边完成。反馈出现不能推动当前漫画的位置。

## 7 实施边界与复用

| 功能范围 | 主要修改位置 | 必须一起交付的验证 |
|---|---|---|
| 共享判定完成与显示状态 | SharedDualPageSession、SharedDualPageRules 输出说明、ReaderSpreadSamplesOwner 的评分状态、现有 presentation/ticket 类型 | 共享行为红测；尺寸及匹配晚到、连锁竞争、槽位证明、确定组不再改变 |
| 目标与预准备调度 | 原 ReaderRequestScheduler/Session、Desktop fact/sample publisher、Android loader/adapter | 真实内容入口去重、预算、优先级、取消及无首帧死锁；已缓存与冷请求分开计量 |
| 两端原生整组呈现 | Desktop model/pager/image/transform owner，Android adapter/holder 与 View 生命周期 | 第一帧、拖动预览、双图不同到达顺序、裁边/方向晚到、真实窗口几何稳定与进度接线 |

上述范围构成同一功能的依赖链，不能只修 Desktop 截图或另建平台配对逻辑。先以共享契约固定判定与生命周期接口，再让两个平台接入；正式实施时按仓库要求委派主要实施、独立核对高风险接口。当前轮仅完成方案，不运行这些测试或改动产品。

原有数据库格式、手动配对记录、图源解析、下载器、采样阈值、默认自动匹配开关、单页/条漫业务均复用。新增状态仅属于共享双页呈现和原调度器的需求表达；不新增网络客户端、全章 Bitmap 缓存或新的持久化格式。

| S13 | 原生内容已画出/尚未画出/失败/准备被取消 | 只有真实稳定显示产生一次正确进度，预取与加载不记已读 |

共享层用有界随机/枚举小样本测试不同到达顺序，并与完整事实输入的生产算法比较；反例包括长竞争链及已评分不匹配边，不能在测试中复制匹配实现。平台用可控制的真实内容/解码完成门闩和帧时钟，记录真实 View/Compose 的页身份、绘制内容矩形、变换及像素，不用 sleep 500ms 后只截一张终态图。

去掉共享显示门禁、恢复 `owner.units` 直接接线，或让某端只在 holder 出现后采样时，对应集成测试必须变红。原生 Android 正式ART与Desktop正式窗口仍须验收受影响链路；浏览器原型、纯state断言、源码字符串检查不能替代。
