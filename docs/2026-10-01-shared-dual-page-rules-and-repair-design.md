# 双端共享双页规则与阅读器修复设计

本文规定 Windows Desktop 与 Android 双页模式的唯一业务规则，同时修复直接跳尾页后的错误配对、正文尾页后有广告时的错误摆放。全部双页决策进入 KMP 共享层；平台提供图片事实、持久化和原生呈现，不再自行选择配对策略。Desktop 的 macOS 构建消费同一实现。

配套执行入口：[开发 roadmap](roadmap/2026-10-01-shared-dual-page-rules-and-repair-roadmap.md)。本文定义产品和接口契约，roadmap 定义实施批次、红绿测试、审查及交付。状态为**设计完成、尚未实施**；本文件不是运行通过报告。

## 1 目标和范围

用户已明确要求两端只维护一套双页规则，包括原 Desktop 独有的 `preserveParityAfterSpread`。相同页序、有效图片事实、阅读方向、用户设置和手动边界必须得到相同分组、槽位及定位结果；缓存和网络到达顺序不能形成另一套排版语义。

| 纳入范围 | 交付边界 |
|---|---|
| 页面分类、配对、单页摆放 | 包括正方图、宽图封面、首尾单页、中间孤页、未知尺寸和失败兜底 |
| 宽图后的配对及自动跨页匹配 | 修正奇偶推测优先级；将已有匹配能力提取到共享层并接入 Android，保留用户可用能力 |
| 双页状态、显式跳页和重排 | 共享定位意图、稳定身份、事件接纳和布局变化语义，保护阅读进度 |
| 手动调整及恢复 | 复用现有章级记录和 CAS；两端消费相同调整、保存反馈及恢复规则 |
| 真实平台接线 | Android View、Desktop Compose 均实际消费共享结果；包括自动匹配设置入口 |
| 验收 | 共享契约、两端 production wiring、Windows 与 Android 正式产物、同一 Desktop 代码的 macOS 回归 |

本轮不新增广告识别、OCR、漫画站专属页码补丁、同步协议或章级配对云同步；不改下载器、单页阅读和条漫的业务规则。双页对宽图的处理不反向改变单页模式的宽图切片偏好。

“双端规则一致”不要求复制原生控件、窗口尺寸或输入硬件。Android 当前公开双页模式为 RTL；本轮保留现有模式编码，**不新增 Android LTR 双页入口或重编码 viewer flags**。共享规则完整支持 RTL/LTR，Desktop 两个方向均实际验收，Android RTL 实际验收；未来 Android 增加 LTR 入口时直接消费同一契约。Android 自动横屏进入双页也必须走本实现。

## 3 唯一共享决策层

### 3.1 归属和复用

在现有 `domain/src/commonMain/kotlin/mihon/domain/reader/` 内演进 `ReaderPagePairing`、`ReaderPairingState`、`ReaderPortraitSingleSlot` 和 `adjustReaderPairing`，组织成共享双页 presentation 策略及状态。可以拆小型文件，但不能另建与现有 reader 平行的引擎。

| 能力 | 唯一 owner | 平台 adapter 可以做什么 |
|---|---|---|
| 宽高分类、旋转坐标、配对优先级、段边界、槽位、方向 | 共享 presentation 策略 | 提供实际尺寸/有效旋转；按共享输出建立 View/Compose 槽位 |
| 跨页采样计划、评分、冲突消解和匹配有效期 | 共享匹配策略 | 用 Android/Skia 解码器执行指定采样，返回标准像素数据 |
| 跳转意图、layout revision、旧回调拒绝、暂定与确定分组 | 共享双页状态 | 将原生操作转为事件，回报实际呈现成功/失败和停稳 |
| 需要哪些尺寸/采样、优先级、预算、取消条件 | 共享需求策略，复用 ReaderRequestScheduler | 经现有 source、encoded store、解码端口执行，遵守统一预算 |
| 手动配对调整及读写状态机 | 共享 use case + ChapterPairingRepository | 复用现有应用级 coordinator、数据库事务和生命周期调度 |
| 显示帧、测量、动画、触摸、焦点及辅助功能 | Android View / Desktop Compose | 处理像素与平台生命周期，不决定页序、槽位或替代配对 |
| 阅读进度、章节已读及副作用 | 既有共享 ReaderProgressPolicy/session | 报告真实稳定可见页集合，不自行取最大页或写数据库 |

复用现有 `ReaderPageId`、generation、encoded cache、materialize executor、取消机制、`ChapterPairingRepository`、Voyager/Injekt 和两端原生测试宿主。平台独立解码是图像 API 差异所必需；平台独立线程/停止协议可以保留，其结果接纳和失败语义由共享层决定。

AUTO是否进入双页继续消费既有共享 `AdaptiveReaderLayout`，稳定等待与方向映射不得在平台内重新定义。原生触摸/键盘转为既有共享导航命令；像素级缩放和平移动画由各端执行，但不能改变逻辑页序、配对、槽位或已读语义。通用主题、图像滤镜和单页/条漫交互不因本次迁移重写。

### 3.2 输入与输出契约

以下为职责模型，名称允许按现有类型合并，不要求逐个新建类。

- 输入：章节与有序页面身份、page-list revision、session generation、原始宽高及有效旋转、事实有效性、用户阅读方向、自动匹配偏好、已提交手动边界、当前定位意图、必要缓存/请求状态。
- 事实必须显式区分 `UNKNOWN / PORTRAIT / SPREAD / FAILED`；UNKNOWN和FAILED不能因为“不在宽图集合中”而被当作已知PORTRAIT。失败不改变图像身份，不是永久页面类型。
- 输出：有序显示单元、每个单元的逻辑页身份、绝对物理 `LEFT / RIGHT / CENTER_FULL` 槽位、独占原因、确定性、稳定ID、layout revision、目标显示单元、补充事实请求和用户反馈状态。
- 共享输出不得包含 Compose/View、Android Context、AWT、Skia、HTTP client 或数据库对象。可共享坐标/采样DTO，不共享原生 bitmap。
- 一个逻辑页在同章显示列表恰好出现一次；占位空槽不占页码。宽图在双页模式仍是一张源页。单元ID由逻辑身份及槽位/切片语义构成，不用URL、缓存对象地址或当前数字pager索引。
- 平台不能再传入 `preserveParityAfterSpread`、`forceFirstPageSingle` 等改变默认产品规则的常量；只传用户真实选择和图片事实。共享 primitive 若为单页/历史测试保留低层选项，production 双页入口也必须经唯一策略，不能自行组装这些选项。

### 3.3 一致性定义

同一事实集合与用户选择产生同一输出，事实到达顺序不影响最终结果。两端可以同时处于不同加载阶段，但每个中间状态也只能由共享状态机产生。布局未定时的单页只是呈现兜底，不能写入手动边界或被下一次计算当成真实宽图/段界。

不允许以“两个平台都调用了同一个 build 函数”作为一致性证据：若传入不同默认值、在平台内删除匹配、提前把UNKNOWN当PORTRAIT或重新计算左右槽位，仍判不合格。

## 4 页面分类与配对规则

本节为 `PROJECT_POLICY`，定义生产默认规则，没有平台分支。

### 4.1 分类和宽图

1. 使用经有效旋转后的原始尺寸分类：非正尺寸为UNKNOWN；宽≥高为SPREAD；宽<高为PORTRAIT。正方形沿用共享分类作为独占图，Desktop改为消费相同结果。
2. 裁边、滤镜、缩放、窗口形状和屏幕旋转引起的视口变化不改变源页分类；只有输入图像的有效旋转事实可以改变分类。
3. SPREAD独占居中完整呈现，包括源第1页的横向封面。取消 Desktop 横向封面左半屏特例；不拉伸、不裁切来填满视口。
4. 双页模式不把宽图拆成两次翻页，也不与邻页配对。单页模式的“拆分宽页”偏好仍保存，返回单页时恢复；双页模式下不产生切片。当前 Desktop production 双页请求未传入 splitPageIndices，不能把低层切片能力误写成现有双页用户入口。
5. 一张源页的章节始终居中完整显示；空章节沿现有空/错误反馈，不制造占位漫画页。

### 4.2 优先级和默认分组

从高到低应用以下约束：

| 优先级 | 规则 |
|---|---|
| 1 | 章节边界、真实宽图、显式无效/未知事实不得被自动匹配跨越；相邻章永不拼成一组 |
| 2 | 已提交手动边界及源第1页独占策略；手动边界只限制相关页面，不关闭整章无冲突自动匹配 |
| 3 | 自动匹配开启时，在已知相邻纵向页之间选出的有效、无冲突跨页关系 |
| 4 | 在可确定起点的连续纵向段内按源顺序相邻配对；不足两张的剩余页独占 |
| 5 | 仍不能确定组归属时显示目标页的暂定居中单页，并请求必要事实 |

源第1页总是独占；若为宽图按4.1呈现，若为纵页按第5节摆放。这是源列表的开篇策略，不等于识别出了正文封面。不得按作品名、图源或“第2页”硬编码第二个首页。

真实宽图、手动独占边界及已确认跨页可以为相邻纵向段提供配对起点；从已确认起点顺序处理，遇到强于默认配对的匹配关系时保留该关系，其前剩余一张独占。UNKNOWN是未决依赖，不能虚构一个会重置后续奇偶的永久边界。若当前组在未知页的所有合法分类下都相同，可确定该组；否则保持暂定。实现可用有限的配对相位状态传播，不需要枚举所有图片组合。

### 4.3 preserveParityAfterSpread 的统一决策

**移除 production 双页的分平台开关，并废止“宽图后整段数量为奇数就无条件拆出段首”的旧规则。**该规则依赖后方图片分类，还会抢在明确跨页之前执行，不能作为统一基线直接复制到 Android。

统一规则保留自动对齐的用户目标：真实宽图独占、已确认的跨页不被拆散、手动调整可改变边界。没有更强证据时使用4.2的顺序配对；有匹配关系时由共享层局部重排。旧规则曾正确处理的实例必须纳入对照夹具，由明确匹配或稳定边界继续得到正确结果，不能静默牺牲 Desktop 的合法跨页能力。若该结果只能依赖尚未描述的证据，应在实施门禁补足共享契约，不得恢复平台开关。

统一算法的固定样例，均为一基页码：

| 图片事实和选择 | 预期分组 |
|---|---|
| 4张纵页 | `[1] [2,3] [4]` |
| 5张纵页 | `[1] [2,3] [4,5]`；不能强制拆出末页 |
| 17页，仅14宽，其余纵向 | `[1] [2,3] … [12,13] [14] [15,16] [17]` |
| 上例另有匹配15/16 | 仍为 `[15,16] [17]`，匹配不会被奇偶推测覆盖 |
| 10页，仅4宽，后补8宽 | 前方 `[5,6]` 保持；`[7,8]` 因8实际为宽图变成 `[7] [8]`，后接 `[9,10]` |
| 纵向段开头A，已有匹配B/C | `[A] [B,C]`，不能先默认合并A/B |
| 末页本来已在正确双页中 | 保留双页；章节是否结束由实际可见逻辑页决定 |

## 5 单页物理位置

配对和摆放是同一共享 presentation 的两个步骤。摆放不能为满足某个左右位置而拆散一个已经确定的双页。

双页RTL中较早页在右、较后页在左；LTR相反。空半屏保持空，不复制页面。物理左右不受系统locale的RTL二次反转。

按以下顺序决定纵向独占页的位置，决策同时记录原因：

| 顺序与条件 | RTL | LTR |
|---|---|---|
| 整章只有一张页 | 居中完整 | 居中完整 |
| 源第1张纵页 | 左 | 右 |
| 已确定分组的章节最后一张独占纵页，且不是第1张 | 右 | 左 |
| 开篇连续独占区内的纵页，尚未进入第一组正常双页 | 左 | 右 |
| 前一组为确定双页，当前为剩余纵页，紧接确定宽图 | 右 | 左 |
| 当前是为紧随其后的有效匹配/手动边界保留的开篇单页，且没有相反的确定约束 | 左 | 右 |
| 中间单页同时受到相反约束、夹在宽图之间且不属开篇区、原因不足或分组尚未确定 | 居中完整 | 居中完整 |

“开篇连续独占区”从源第1页开始，只在有关前缀分组已确定、且其间没有普通双页时成立；未知前缀不能用这个规则猜首页。该规则是明确的开篇呈现约定，不声称识别出广告或正文。一页章节已由最高优先级处理；中间只有一张纵页的段不能仅因同时是段首/段尾就任意选边。

手动记录只表达配对边界，不包含左右选择；按相同摆放规则处理，不添加未经用户要求的逐页左右编辑器。居中沿用整图等比fit行为；不得横向拉伸、改变源页或把空槽计入进度。

B2的预期是：若真实结构为“确定双页 → 20独占 → 21宽图”，20进入右槽。证据不足时20居中。2若属于现有正确的开篇独占区，保持左侧；其真实结构必须以夹具确认。仅使用groupIndex/groupCount不再足以决定槽位。

## 6 图片事实和自动匹配

### 6.1 尺寸事实与缓存

尺寸识别接入现有图片 materialize/encoded cache 链路，不能只由可见 holder/Composable发布。HTTP、已下载、局部下载及本地文件都通过既有内容路由提供事实；成功预取的可用图片应能在未显示时贡献尺寸。读取图片头优先于完整bitmap解码，失败保留重试，不把失败当纵页。

图片事实是可重建的派生缓存，第一版不新增数据库schema或同步格式。身份至少绑定源页面身份、页列表版本、实际内容引用/内容版本和有效旋转；不得仅按章节ID和页数跨重新排序或替换图片复用。会话重建可从既有encoded缓存重读头部，避免为持久化尺寸另起一套存储。

所有回调携带generation、页身份、事实版本及需求标识；旧章、旧列表、旧图片或已取消需求的回调被共享门禁拒绝。重复尺寸是幂等更新，不无条件触发整章重排。

### 6.2 有界事实补齐

共享策略从显式目标页及最近确定边界计算所需范围，优先目标与相邻页，再定位缺失边界；已经确定的无关章节不补齐。第一版共享预算为PROJECT_POLICY：额外事实请求最多2个并发，每次显式定位最多新增16张页的materialize需求、累计32MiB新读取数据或15秒主动等待，任一达到即停止扩展。可见页自身正常加载不因补齐预算耗尽而停止；缓存命中不消耗网络字节额度。

这些是硬上限，不是一次跳页必须下载的数量。复用scheduler中的相同请求与encoded bytes，额外需求低于可见页，不取消其他真实消费者。预取开关/流量限制继续生效；不许可后台请求时只用可见与已有缓存事实。第一版不新增HEAD、Range探测协议或绕过production source鉴权的独立客户端。

网络中只有下载后才能取得头部的格式/图源仍会有真实流量。预算不足、离线或某页失败时，保留目标单页居中并结束主动等待，不用永久spinner阻塞阅读、不偷偷启动下一轮整章补齐。新的显式翻页/重试或已有正常请求完成可以提供新事实；读取不等于用户看过页面。

B1所需信息未齐时至少保证17不被猜测拼入16；信息足够后恢复 `[15,16] [17]`。补齐预算不能被用来宣称真实案例已完成：验收分别记录正常网络下的最终正确分组和人为限额/失败下的兜底行为。

### 6.3 自动跨页匹配

将现有边缘采样、连续性评分、白边/暗边/低方差排除、阈值及候选选择迁到共享实现。初始沿用50个纵向采样点、色差阈值30、暗色阈值50、最低方差100等现有有效参数，并以原有防误匹配用例锁定；不把相似白边重新当作匹配证据。

共享层规定采样位置、有效旋转、源坐标、颜色归一及透明像素合成；采用与主题无关的sRGB数据和固定白底透明合成。匹配基于原图，不基于裁边、滤镜、屏幕缩放或动画瞬时帧；动图仅在有稳定首帧事实且可有界采样时参与，否则保持无匹配证据。RTL比较较早页左边与较后页右边，LTR比较对应书脊边；切换方向使相应采样/候选重新求值。

平台解码器只执行共享采样计划，优先已有受控图像lease或encoded图片的小范围解码，释放临时资源。不能为了采样加载无界原图，不能在Composable/holder内建立第二个HTTP或解码队列。匹配本身不发网络请求；必要输入受现有解码预算和6.2事实需求约束。

候选以相邻页对身份保存评分与版本，按完整有效候选集合求解无重叠关系：先按匹配强度由高到低排序，完全同分时按较早源页序排序，再依次选择不与已选关系重叠的候选。不得在不同端自行选择另一种求解方式。禁止把多次局部贪心结果简单取并集，留下重叠匹配或依赖到达顺序。缓存淘汰不清除仍有效的事实；内容/方向/开关/手动边界改变时按依赖失效。手动边界只屏蔽冲突边，不屏蔽整章其他有效候选。

自动匹配两端默认关闭，保留 Desktop 已有用户值；Android新增同语义设置。关闭时只使用手动和结构配对，不继续以旧匹配影响布局。阈值与回退不是用户可分平台配置项。

## 7 定位和阅读进度

共享状态明确区分：用户逻辑定位目标、当前显示组首张、真正可见页集合、持久阅读进度。现有测试要求组首张作为UI anchor，不能为修复跳页把所有currentPage改成双页后张。

| 事件 | 共享处理 |
|---|---|
| 点击页码、拖动页码条、显式恢复某页 | 建立包含pageId、generation和序号的定位意图；跨后续layout revision保留同一目标 |
| 暂定 `[16,17]` 后重排 | 仍以用户目标17找新组；不能被旧组首张16覆盖。正式修复中未决时优先直接呈现17单页 |
| 图片/匹配/设置导致重排 | 更新布局，重定位同一目标；这是layout-only，不创造阅读动作 |
| 用户下一页/上一页 | 基于当前显示单元的故事顺序决定目标并更新定位意图；平台只映射手势/按键为逻辑命令 |
| 新跳转、切章、页列表替换、关闭阅读器 | 使旧意图和旧补齐需求失效；同章Activity重建按现有恢复链保留有效目标 |
| 目标不存在 | 沿用现有页码越界提示和恢复规则，显式反馈；不能默默改选另一章 |

定位意图不因一次暂定pager停稳自动退化为组首张；它保留到下一次真实导航或身份失效。模式切换、窗口调整、方向变化按共享重定位规则处理，不因宽屏/窄屏改变用户请求对象。

稳定可见上报必须同时核对当前generation/layout revision、已停稳、实际呈现成功的逻辑页集合和事件原因。双页需两张均成功，加载/错误占位不算已读。用户主动跳到17并真正看到了居中的17，可按现有政策记为真实阅读；后续尺寸补齐和槽位变化不能再制造进度。单页、双页、宽图均送入既有共享进度链，不让Android单页回调绕过同一门禁。

章界分类继续复用 `readerChapterBoundary`；末组包含最后逻辑页即可完成章节，不能只看右页或显示组序号。相邻章只在各自页列表/手动记录就绪后接入，绝不跨章拼页；快切章的迟到事实不能污染当前章。

## 8 手动调整和兼容

复用 `adjustReaderPairing` 的现有操作语义：对双页调整会建立/撤销相关独占边界并给出逻辑目标；单独自然尾页不凭空生成可切换记录。共享层执行相同规则，两端原按钮消费相同命令和反馈。

复用 `ChapterPairingRepository`、formatVersion=1、pageCount验证、漫画归属验证和CAS revision。保存成功后才改变持久边界及显示；失败维持上次成功状态并可重试。恢复失败继续提供“重试／本次使用默认”，本次默认不删除旧记录，也不能在尚未成功读取时覆盖保存。

平台应用级coordinator继续负责已受理写入的生命周期；共享层拥有保存中、冲突、失败、临时会话等业务状态。窗口/Activity重建不另造调整命令；临时文件阅读器仅会话内调整并明确反馈，不写错误章节ID。

不迁移、清空或同步旧手动记录；相同手动边界应在两端产生相同结果。已有Desktop自动匹配偏好沿用原值；Android新键默认false，经原preference/DI注册。规则版本属于代码和派生布局，不写进现有同步数据，也不为统一规则重置阅读进度。

## 9 用户界面和交互契约

适用页面是两端现有阅读器及其设置面板；复用导航、按钮、主题、错误/重试和保存反馈，不建立新阅读器页面或广告管理页。

| 入口或状态 | 用户行为与反馈 | 副作用和边界 |
|---|---|---|
| 现有双页模式／AUTO进入双页 | 立即进入共享策略输出；宽图封面居中，纵向首页/尾页按统一方向摆放 | 不改变作品/章节选择；Android模式编码保持 |
| 阅读器设置中的自动跨页匹配 | Desktop保留既有开关；Android在分页设置的双页区域增加同语义开关，仅双页可操作 | 默认false；关闭清除有效匹配影响，保留手动边界；退出面板后焦点/滚动按原实现恢复 |
| 双页底栏调整配对 | 两端沿用原入口，保存中禁用重复提交，成功呈现新组合，失败提示并可重试 | 不要求确认弹窗；这是可逆布局设置，不触碰漫画内容 |
| 跳页后布局待定 | 已加载目标页可先居中；菜单可显示一次性轻量“正在确认双页排列”状态，预算结束移除等待状态 | 不闪现未经确认的错误邻页，不阻塞翻页，不把内部术语暴露给用户 |
| 尺寸补齐失败/限额 | 正常显示目标页；可通过既有重试入口重新尝试，暂时反馈“暂按单页显示” | 不持续toast，不在关闭后回放通知，不自动无限重试 |
| 单页位置不确定 | 保持居中完整显示 | 不新增强制用户选左右的流程；2的开篇位置与20的尾侧/兜底各自有测试 |
| 返回/关闭/切设置 | 原导航层级、焦点恢复、按键和触摸继续有效；布局变化不抢焦点 | 平台控件和硬件事件可以不同，逻辑动作与结果相同 |

状态文本须本地化，深浅主题、窄屏、大字体均可操作。只新增必要的Android开关，不增加Screen/Tab；若实施确需新导航或DI绑定，必须加真实实例化、导航和解析测试。所谓“居中完整”是等比fit，空白由图片比例决定，不承诺两台不同视口上的像素尺寸完全一致。

## 10 两个BUG的修复闭环

### 10.1 B1 直接跳到第17页

固定真实17页清单及影响边界 → 页面事实不再仅依赖显示回调 → 共享策略拒绝未知事实的确定配对 → 修正宽图后规则和匹配优先级 → 显式17定位意图跨重排保留 → 两端实际渲染 `[17]`、前组 `[15,16]` → 真正停稳后按现有逻辑写进度。

不能只把17加入forcedSingle：那会改变用户记录，可能留下16单独显示；不能以预先访问整章、预热缓存或测试中直接注入最终分组冒充直接跳页修复。

### 10.2 B2 第20页及第2页

固定真实22页清单，记录20两侧分组和2的开篇来源 → 共享配对产出独占原因 → 尾部剩余纵页优先按确定结构放RTL右侧 → 无法可靠分类时20居中 → 2保留开篇左侧 → 第21页等宽图继续独占，其他双页组合不变。

算法不识别“广告”文本，不移除1/21/22，不按“文件最后页”冒充正文末页，不把所有宽图前单页改到右侧，也不把所有中间单页一律居中。若真实2并非本文开篇结构，实施者必须提供最小反例，在同一共享规则中补足可解释的条件后再编码；禁止特判作品或页码。

## 12 风险和实施约束

- 真实样例仍缺完整事实：第一任务先取最小可复核夹具，图片只在授权本地存放，不把漫画整章或账号/临时签名URL提交仓库；可提交非敏感尺寸、拓扑和合法合成图，真实运行证据单独脱敏。
- 统一规则会改变已登记的平台差异：宽图封面、正方图、landscape parity、手动边界屏蔽匹配等必须逐项由共享契约替代，并更新架构与相关parity证据；不能只删除测试或改manifest为通过。
- 事实越完整不等于可以保证识别正文语义：不引入内容识别模型；按固定排版策略和居中兜底处理信息不足。
- 自动匹配移植需真实采样输入和内存约束；无法直接复用native bitmap时只增加采样adapter，评分与选择不得复制两份。
- 共享输出接口、进度原因和保存协议属于高风险集成点，须独立审查后再向下游推进；TDD与测试预算见roadmap。
- 与历史续读、同步和其他reader任务存在共享文件：执行前复核HEAD及工作树，串行协调写入，保护本轮以外改动；不顺便实施其他roadmap。
- 本文与roadmap合计形成一次设计交付，不创建额外状态系统、生成器或逐任务报告。实现完成前，本文件状态及产品capability状态保持未完成。
