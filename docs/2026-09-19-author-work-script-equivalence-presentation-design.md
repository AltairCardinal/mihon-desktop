# 作者作品简繁与排版符号等价自动聚合 · 迭代需求设计

日期：2026-09-19；审核更新：2026-09-20。状态：USER_APPROVED / READY_FOR_IMPLEMENTATION。

- 本文是[作者页体验迭代设计](2026-09-18-author-experience-iteration-design.md)的后续需求，替代 AX-07 的“发现候选后手动合并”交互。
- 本次目标是自动把简繁及排版符号等价的来源版本作为一个作品呈现，不把标题推断直接写成永久 canonical 身份。
- Android 与 Desktop 使用同一归一化、分组、计数和纠错语义；平台差异只限控件布局与导航容器。

## 0. 审核冻结

用户已于2026-09-20审核通过需求与HTML交互，冻结原型提交为 `b1d4d73d89`。正式实现必须保持以下已确认决策：

1. 页面不显示“简体源”“繁体源”等脚本标签，继续使用作者详情既有的真实图源名称和来源筛选。
2. 标题分组在简繁转换后忽略 Unicode 空白与排版标点；`《詭譎屋：外傳》` 与 `诡谲屋 外传` 应呈现为一个作品。
3. 大小写、数字、卷次与副标题正文仍是硬边界，不增加编辑距离、翻译、封面或模糊相似匹配。
4. 自动结果只属于展示投影；来源原题、mangaId、canonical 事实、收藏、下载、更新与同步对象保持独立。
5. 来源窗口保留“分开显示/撤销”纠错，普通浏览流程不出现检测提示、确认弹窗或合并按钮。

此次审核确认交互与需求，可以进入production实施；不表示Android/Desktop正式功能已经完成。

## 1. 用户问题与目标

同一作者的同一作品可能由不同图源返回简体、繁体标题，例如 `詭譎屋` 与 `诡谲屋`。当前页面会把它们显示为两部待审作品，用户必须进入审阅并手动确认，增加了重复卡片和管理负担。

目标行为：

1. 作者页加载时自动识别简繁及排版符号等价的版本，只显示一个作品卡片。
2. 用户无需看到候选、确认弹窗或“按标题简繁体合并”按钮。
3. 点击聚合卡片后仍能看到所有来源版本及各自原始标题，并选择准确图源进入漫画详情。
4. 自动聚合只改变展示分组，不改写图源原题，不自动建立 canonical 决策，不删除或覆盖来源事实。
5. 严格规则误判时，用户可以把版本分开显示，并可立即撤销。

## 2. 术语与核心原则

### 2.1 展示组与作品身份

- **canonical 作品**：用户已确认或已有业务事实建立的持久作品身份，继续作为数据、同步和恢复的权威。
- **简繁展示组**：由同一作者归档内的标题归一化键临时或可重建地形成，仅用于作者页面呈现。
- **来源版本**：由 `sourceId + stableSourceUrl` 唯一标识，标题、封面、章节、收藏、日期和可用状态始终独立保留。

自动简繁聚合不能把展示推断升级为 canonical 事实。同步、备份、下载、更新、收藏和漫画详情导航仍以实际来源版本或已确认 canonical 为准。

### 2.2 分组优先级

按以下顺序构建作者页作品投影：

1. 已确认 canonical 组先形成，组内成员不得被自动拆散。
2. 显式 `REJECTED`、用户“分开显示”的版本不参与对应简繁展示组。
3. 未确认来源版本按简繁与排版符号归一化键聚合。
4. 未确认版本若只匹配一个 canonical 组的主标题或成员标题，可仅在展示层附着到该组。
5. 同一归一化键匹配两个或更多不同 canonical 组时视为歧义，保持分开显示，不自动选择目标。
6. 两个不同 canonical 组即使标题简繁等价，也不得自动合成一个组。

## 3. 简繁与排版符号等价规则

复用共享 `WorkTitleNormalizer` 的最长短语优先、字符回退转换。转换简繁脚本后，分组键移除 Unicode 空白与排版标点（包括书名号、引号、冒号、间隔号、连接号及全半角对应标点），不改变其余正文字符。

必须满足：

- 两个原始标题均非空，且原文不同。
- 转换并移除空白、排版标点后的完整字符串完全相同。
- 字母大小写、数字、卷次和副标题正文必须一致；这些语义字符不参与模糊匹配。
- 只在同一 active creator root 的归档内比较，不跨作者、全库或网络搜索。
- 上下文短语优先于单字映射，避免把 `乾坤` 等语义不同的字符错误转换。

示例：

| 标题 A | 标题 B | 结果 | 原因 |
|---|---|---|---|
| `詭譎屋` | `诡谲屋` | 自动聚合 | 只有简繁脚本差异 |
| `情有獨鍾` | `情有独钟` | 自动聚合 | 上下文短语等价 |
| `詭譎屋：外傳` | `诡谲屋：外传` | 自动聚合 | 简繁转换后相同 |
| `詭譎屋:外傳` | `诡谲屋 外传` | 自动聚合 | 冒号与空白属于排版差异 |
| `《詭譎屋：外傳》` | `诡谲屋 外传` | 自动聚合 | 书名号、冒号与空白被忽略 |
| `Series` | `series` | 保持分开 | 大小写不同 |
| `詭譎屋 外傳 1` | `诡谲屋 外传 2` | 保持分开 | 卷次数字不同 |
| `怪物` | `Monster` | 保持分开 | 翻译标题不属于简繁转换 |
| `乾坤` | `干坤` | 保持分开 | 上下文规则不等价 |

## 4. 展示标题与聚合字段

一个简繁展示组只显示一张作品卡片。2026-09-21 用户修订：展示标题跟随当前应用语言的简繁偏好，静默生效；不增加独立开关、标题选择器、确认框或标题切换通知。

1. 使用应用已经生效的 locale，而非图源语言筛选或系统语言的独立猜测；“跟随系统”先通过现有平台 locale adapter 解析。显式 `Hans/Hant` 优先，其次 `CN/SG` 对应简体、`TW/HK/MO` 对应繁体；非中文不强制脚本，未细分的中文沿用应用资源实际解析结果。
2. 已确认 canonical 主标题仍是身份事实。仅当组内原题与该主标题满足现有严格等价规则时，允许选取目标脚本原题作为显示别名；非等价 canonical 主标题不被其他成员覆盖。原始标题、canonical、漫画记录、分组键和备份均不改写。
3. 在同一有效语言下，从目标脚本候选中优先保留仍有效的已选标题，否则按稳定自然键选择。切换应用语言时，旧语言标题不得压过新脚本候选；来源语言标签只作辅助信息，不能把 `zh` 或错误标签当作标题脚本证据。
4. 无目标脚本成员时保留稳定原题，不倒置简繁归一化字符表生成有歧义的繁体，也不做翻译。新增首个目标脚本成员时允许静默升级；已有合格标题时新增较小 sourceId 不触发替换。非中文优先稳定 canonical/原题。
5. 两端遵循现有应用语言生效生命周期，在页面重建或 locale 更新后自动重投影；来源窗口始终显示各版本原题。标题选择缓存按组键和有效脚本隔离、仅设备本地可重建，不影响其他设备或作品身份。

实现边界：标题历史按作者根、脚本和展示组分别存于设备本地 app state；单来源卡不写标题历史。重新打开页面仍读取历史标题，但只在该原题仍属于当前组、符合目标脚本且与 canonical 主标题严格等价时使用。旧组键或旧作者根的缓存记录可能留在本机偏好中，不能作为作品身份或同步事实；若本机偏好读取或写入失败，页面仍按当前归档重算标题，当前页面会话保留已选标题。偏好容量增长需在未来设备状态清理工作中处理，不因此阻断作者页。

普通刷新和来源顺序变化不改变仍有效的同语言标题；语言切换、旧标题成员移除、首次出现目标脚本成员是明确的重新选择条件。具体修复与验收见[实现审查修复 Roadmap](roadmap/2026-09-21-branch-implementation-review-fixes-roadmap.md)。组内聚合字段遵守现有作品规则：

- 来源数为完整成员版本数；来源筛选不能把总来源数改小。
- 任一版本收藏，则作品卡显示收藏标记。
- 章节数和日期不跨来源相加；卡片沿用现有代表版本与可信日期选择规则。
- 任一成员有“新作 · 未查看”，组卡显示一次；用户成功进入任一版本后，当前展示组内对应来源发现一起标为已查看，但原始发现记录保留。
- 作者详情的未查看作品排在已查看作品前，未查看组按组内最早发现时间倒序排列；同时间按稳定组键定序，已查看组保持原有顺序。
- 代表作选择、作品计数、搜索结果和作者页新作计数以展示组去重。

## 5. 交互流程

### 5.1 首次进入作者详情

```text
进入作者详情
  → 读取 canonical 组、未确认来源版本和分开显示规则
  → 计算简繁/排版符号等价展示组
  → 每个展示组渲染一张作品卡
  → 卡片显示标题、来源数、收藏/新作/日期等既有信息
```

用户不会看到检测提示、确认弹窗、待审徽标或自动操作 Toast。自动聚合是默认展示行为。

### 5.2 打开聚合作品

```text
点击作品卡
  → 打开“选择漫画源”窗口
  → 标题说明“此作品的全部来源版本”
  → 每个版本显示原始标题、原有图源名称、章节、收藏、日期和可用状态
  → 点击具体版本
  → 进入该版本的漫画详情
  → 返回时恢复作者页筛选、滚动和焦点
```

单来源作品仍沿用现有“选择漫画源”规则；自动聚合不改变导航对象或 mangaId。
界面不引入“简体源”“繁体源”等脚本标签；图源筛选和来源窗口继续使用作品列表原有的真实来源名称。

### 5.3 新增等价来源

```text
后台发现或刷新得到新的来源版本
  → 保存原始来源事实
  → 新标题与现有组按简繁/排版符号规则等价
  → 下一次投影自动加入原展示组
  → 来源数更新，页面仍只显示一张卡
```

不弹出“已合并”提示，不创建新的 canonical，也不生成额外的新作卡片。若新增来源是组内唯一未查看成员，组卡显示一次新作状态。

### 5.4 搜索与来源筛选

- 输入简体或繁体标题都能命中同一展示组；搜索同时检查原始标题和严格归一化键。
- 选择某个来源筛选时，只要组内存在该来源版本，作品卡就可见。
- 从筛选结果打开作品后，来源窗口仍显示该展示组的全部版本，不把筛选后的子集当完整成员。
- 清空筛选后保持同一展示组和稳定标题，不产生重复卡片。

### 5.5 误判纠错：分开显示

```text
打开聚合作品的来源窗口
  → 更多菜单选择“分开显示”
  → 选择要移出的来源版本
  → 页面立即拆成独立作品卡
  → Snackbar 显示“已分开显示”与“撤销”
```

- “分开显示”只写入展示排除规则，不删除来源版本，不改写 canonical 或阅读数据。
- 分开显示成功后优先按被拆版本的自然键聚焦新卡；新卡因筛选或虚拟滚动暂不可聚焦时，聚焦详情页返回按钮，不向已移除的旧组卡还焦。
- 规则在刷新和重启后保持；撤销后立即恢复自动聚合。
- 已确认 canonical 组不提供此入口；需要改变确认身份时继续使用既有高级拆分能力。
- 多个版本需要移出时逐项选择，窗口明确显示原始标题和来源，避免只靠简繁文字区分。

## 6. 页面状态与文案

| 状态 | 页面行为 | 用户反馈 |
|---|---|---|
| 简繁/排版符号等价 | 自动显示为一个作品 | 卡片显示完整来源数，无额外提示 |
| 新等价来源加入 | 原卡片成员和来源数更新 | 保持位置和标题稳定 |
| 转换不等价 | 继续显示多个作品 | 无警告，不引导手工合并 |
| 多 canonical 歧义 | 保持各 canonical 与未确认项分开 | 不猜测目标，不显示错误状态 |
| 用户分开显示 | 立即拆成独立卡片 | `已分开显示` + `撤销` |
| 排除规则保存失败 | 保持原聚合状态 | `无法分开显示，请重试` |
| 来源缺失或离线 | 仍保留版本和本地信息 | 沿用缺源/不可用反馈 |

需要移除的旧交互：

- “检测到可能只是简繁标题差异，请确认后合并”说明；
- “按标题简繁体与……合并”按钮；
- 因简繁等价产生的确认/拒绝流程和写入中按钮锁定状态。

普通的高级作品校正、canonical 确认、拒绝和拆分能力继续存在，但不再是简繁同名展示的前置步骤。

## 7. 数据与实现边界

### 7.1 复用

- 直接复用 `WorkTitleNormalizer`，不引入第二套字符表或平台专用转换。
- 复用 `CreatorWorkArchive`、`SourceWorkArchiveVersion`、`CanonicalWorkArchiveGroup` 和既有来源选择窗口。
- 抽取共享 `WorkPresentationGroup`/分组服务，Android 与 Desktop 只消费结果，不各自实现归一化和成员选择。
- 搜索、计数、收藏、新作和代表作选择使用同一展示投影，避免各页面出现不同组数。

### 7.2 不允许的实现

- 不因简繁命中调用 `createCanonicalWorkWithUserWorkDecisions` 或 `appendUserWorkDecisionIfCurrent`。
- 不把归一化标题覆盖到 `SourceWorkArchiveVersion.title`、漫画表或备份数据。
- 不使用模糊相似度、编辑距离、翻译词典、作者别名或封面相似度扩大自动分组。
- 不跨作者自动聚合，不把来源 ID 当作品身份。
- 不让 UI 自己临时拼接成员而绕过共享投影。

### 7.3 分开显示规则

实现时优先使用最小的设备本地展示排除记录，键至少包含 active creator root 和来源作品自然键。规则只影响自动简繁展示层：

- canonical 关系变化后重新校验，无效规则可安全忽略；
- 作者合并时按来源自然键迁移到新 root；作者拆分时只保留仍属于对应作者的规则；
- 备份与同步是否携带排除规则不在本迭代扩张，默认设备本地；文档和 UI 不宣称跨设备同步。

若无需新增持久表即可复用现有设备本地偏好存储并满足有界查询，可沿用现有存储；不能把排除规则编码进 `REJECTED` canonical 决策。

## 8. 兼容与迁移

- AX-07 已由用户确认形成的 canonical 关系保留，不自动撤销或降级。
- 现有 `SUGGESTED` 简繁候选不再触发按钮；满足规则时直接进入展示组。
- 现有 `REJECTED` 决策继续作为不自动附着到对应 canonical 的边界。
- 升级后首次打开通过现有归档即时重建展示组，不需要批量重写来源作品。
- 降级到旧版本时，展示排除记录可被安全忽略，原始来源和 canonical 数据不受影响。

## 10. 测试与交付要求

1. 共享 domain 契约测试覆盖分组优先级、简繁/排版标点正例、大小写/数字/正文差异负例、canonical 冲突、`REJECTED` 与排除规则。
2. Android 真实 ScreenModel/SQLite 测试验证一张卡、两版本、搜索、来源导航、分开显示和重启恢复。
3. Desktop mounted 测试验证相同交互及键盘/320dp 布局，不再出现手动简繁合并按钮。
4. 新作、收藏、来源筛选、代表作和作品计数各至少有一个 production wiring 测试，证明都消费同一展示投影。
5. 修改产品行为时遵守红绿重构；实现完成后执行相关模块测试、格式检查与双端运行验收。

交付完成的判定是：用户在正常作者浏览流程中不需要理解简繁转换或维护作品身份，简繁同名版本稳定显示为一个作品，同时仍可查看准确来源、纠正误判且不损失任何原始事实。
