# Android 扩展专项：执行成本与经验

本文件记录 2026-09-15 接续执行的成本、失败与方法调整；产品进度及验收唯一入口是[roadmap](./2026-09-12-android-extension-v2-compatibility-roadmap.md)。由主模型直接推进，按收益委派独立子任务；不使用 Luna 技能。

## 计量与决策

- 用户要求以累计 token 消耗估算成本；先用主线程 goal 返回的 `tokensUsed` 在批次边界计算增量，统计口径不等于账单，也不默认包含子代理。统一插件如提供含子代理数据，另列其结果，不与 goal 计数相加。缺数据记不可得，不为计量反复启动任务。
- 每批记录：交付/提交、主模型与子代理角色、用量起止与增量、实际构建/测试、失败原因、可避免返工、下批方法。没有数据不声称节省比例，不把必要 RED 算失败浪费。
- 默认主模型连续实现、一个稳定边界后的独立审查者。仅有明确独立工作、无共享写入且节约大于交接成本时并行；执行中根据实际结果调整。

## 可复用经验

1. 交付批次围绕完整用户能力，测试循环围绕可观察差异；两者不要求一一对应。不为每次测试建目标或代理。
2. 继承的未提交实现按真实 diff 和报告恢复；保存历史流程缺陷，补有效回归。撤回后重放不能改变历史顺序，也不应成为重复实现的理由。
3. 同一协议的格式、跟随和身份决策集中到共享实现，平台保留生产 HTTP 错误映射及资源选择；可减少双端重复修复。
4. 网络错误分类必须沿真实异常包装链验证；本次目录安全异常被共享 `awaitSuccess` 包装为 `IOException`，只检查最外层类型会把不合法目录误报为网络故障。验证需要调用 production HTTP adapter，不能仅直接调用错误映射函数。
5. 读取上界需要同时覆盖声明长度与无长度的分块响应；解码前检查已读完的 `ByteArray.size` 不能证明网络读取有界。安全跟随同样应在发出下一跳请求前验证，而非只检查最终内容。
6. 首次并行选择存储/备份上下文：一名子代理负责真实数据库与恢复，主模型负责目录协议和平台 HTTP；Gradle 仍由主模型串行合并运行。子代理提交测试筛选及预期失败后冻结受测文件，避免重复构建或编译期间改动输入。是否降低 token 成本留待批次实测，当前仅记录采用原因。
7. 协议接口稳定后，将两端列表状态/操作/UI 作为一个完整包交给第二个窄上下文代理；原存储代理连续补仓库页→HTTP→数据库整链，复用其存储装配。主模型保留协议异常、跨包整合和独立验证。不是按每个测试类委派，也不为一项失败另开代理。
8. 测试装配故障单列：最初 MockResponse 字节正文误用 String 构造器；声明长度用例的便捷构造器覆盖了手写 Content-Length；KMP commonTest 资源目录未自动进入 Android unit 资源集。它们不算产品 RED。流式超限另有正确 RED；修正响应构造与 Android 资源落点后复验真实行为。后续优先复用本仓库已验证的 Builder 与 source-set 装配。
9. 启动合并构建前应收齐所有写入者的最终冻结回执；不要在请求一方收尾清理后，仅凭另一方的完成通知启动。此次收尾消息与构建启动交叉，后续明确以全部受测输入冻结为启动条件。

10. 批末确认共享接口稳定后，将串行构建权显式交给一个执行者，主模型不再逐次转发命令；协调权交接须先核对上一进程结束。主模型仍独立核验产物和证据。AEX-02 前半采用主模型转发每轮测试，长上下文反复加载的成本偏高；后续以整批执行包减少交接，不减少真实 RED 或验收。
11. 工具成功退出不能替代动作成功：Spotless 的 `spotlessIdeHook` 要求绝对路径，传相对路径只输出提示而可能成功退出。首次无效运行单列流程浪费；更正后实际发现超长测试数据行。复用已验证参数与检查实际输出，不能只看 exit code。

12. 会话恢复时区分状态文件与活进程：`aex02-final-format-fix3` 文件仍为 RUNNING，但对应 PID 已消失，协调器复查为 ORPHANED，不能推定格式通过。本次只恢复未完成的批末验证，保留全部实现和已审查结果；专用模拟器退出后按原授权重启同一 AVD，不重新安装环境。恢复包传递准确测试组与现有 diff，避免再次从 roadmap 历史全文探索。

13. 完整模块验证发现继承测试的跨域耦合：新增 schema 19 后，共用“最新版本”常量仍为 18；Desktop 合成旧库由 latest schema 创建却未删除新列；旧安装 wiring 测试缺少新增生产发现链的 metadata 响应。应修正历史装配并增加真实请求/迁移结果断言，不能放宽生产解析或跳过迁移。批末一次完整模块回归有价值，但不应每个行为循环重复全量。

14. 一个完整能力包由同一执行者持有实现与串行测试权，主模型按稳定边界验收，本批减少了逐 RED 往返。但验收矩阵必须在开工时明确到真实入口、存储和结果：固定 ID Proxy 只能证明导航参数，不是持久化；仅 Desktop 的按钮隐藏不能证明 Android 对照。最终通过复用真实 repository 和 production Composable 补齐，不扩展框架。后续在交接时明确这些证据层级，减少批末返工。

15. DI 集成测试不能假设重复 `addSingleton` 会替换此前注册。AEX-03B 的 Worker 装配保留了初始 mock，导致真实用例未执行；这种失败不是产品 RED。应使用隔离 registrar、每类型一次注册，并在触发业务前断言解析到预期实例。后补旧实现对照仍须如实记录时间顺序，不能改写先前无效的红灯记录。

16. 主模型等待完整执行者期间，可承担接口已稳定、独立文件且无需并行构建的窄测试补证。本批由主模型新增 Android ART 存储/迁移与 Source 输入测试，明确冻结后交还执行者统一格式化和设备运行；不重复实现 Worker/Reader 测试，不增加代理。是否节约成本须看批末计量，不能把并行写测试等同于允许并行 Gradle。

17. 新字段不能机械加入每个 `copyFrom`：同一 helper 在源更新与备份合并中的复制方向可能不同。AEX-03B 的现有章节恢复测试暴露了旧数据库空 memo 覆盖备份 memo；修复采用固定上游的边界，domain Chapter.copyFrom 不复制 memo，源同步显式复制。新增数据字段应同时测试“恢复到空库”和“恢复到已有记录”，只证明前者不足以排除合并丢失。

18. Android 数据库验收不能用 JDBC 结果替代。AEX-03B 的真实 ART 升级暴露 `BLOB DEFAULT '{}'` 被 Android Cursor 按文本转字节后带入尾部 NUL，严格 JSON 解码失败；改用 `DEFAULT (CAST('{}' AS BLOB))`，并检查 SQLite `typeof`/`hex`。两种十六进制字面量写法被当前 SQLDelight 拒绝后停止盲试，检查解析器并用内存 SQLite 确认替代语法，再回到真实设备。保留严格解码，不以清洗输入掩盖存储类型问题；最终复验结果见 roadmap。

19. 子代理额度耗尽时，先检查协调器的终态与活进程，不盲目重启或清理全部 Java。本次最后构建已 FAILED，现存 daemon 属于另一 worktree；主模型保留实现及既有测试结果，接手详情 UI 的最后失败和批末验证，没有重新委派整批。离屏 UI 等待应以实际渲染节点为准，模型状态变化不等于按钮闭包已经更新。

20. 包格式升级应沿同一声明检查目录兼容、APK inspection、loader admission、已安装版本及事务提交，不能只放开 UI 范围。AEX-04 focused RED 已分别暴露这些边界的差异；共享协议按离散版本判断，历史 1.5 保留。加载器接线测试使用真实 TrustExtension 和 AndroidPreferenceStore，仅模拟 PackageManager 边界；未实现字符串集合的 InMemoryPreferenceStore 不适合这条链。此类装配错误如实单列，不算产品红灯或真实 APK 验收。

21. 新接入真实手机后，将 APK 构建与设备安装分开，所有 adb 命令显式指定专用模拟器序列号，并在会修改配置的测试中检查 emulator 硬件身份。不能依赖“之前只有一台设备”的默认选择。测试源码在打包完成后变化时必须刷新测试 APK，不能用旧包当作当前 diff 的验收；本次因此多执行一次仅测试包增量构建，应在启动编译前冻结测试输入。`am instrument` 的 shell 退出码为 0 不代表测试通过，必须读取 `OK (N tests)`、失败数量和 instrumentation 状态；AEX-04 首次真实语言 RED 正是 shell exit0/test failure1。

22. 特殊权限的开启/撤销可能由系统主动杀 UID，不适合在被验收进程的 instrumentation finally 中恢复。先查 ApplicationExitInfo 区分系统终止与产品异常，再将正常 Settings 界面操作移到进程外，不用 shell 授权替代用户确认。系统适配器“消费 URI 文件”也是重要所有权边界：事务源文件、交付副本及回滚快照不能共用会被平台删除的同一文件。AEX-04 用真实系统确认发现此缺口；补文件行为契约时，把原先虚构不存在路径的 8 个生命周期 fixture 改为独立真实临时文件。另一次私有 helper 可见性编译错误属于主模型实现失误，记录而不归咎环境。

23. 进程恢复证据要与内存重载、数据库重新查询分开。单一测试入口可让默认模式自清理地验证普通数据库行为，再由显式 prepare/verify 参数进行两次 instrumentation，并断言 PID 不同；不能把默认模式的绿灯算作重启成功。仅保留受控数据 ID 和准备进程信息的小型测试交接记录，精确清理且复查级联删除，不建设通用状态框架。及时把跨进程 PID 证据写入测试日志，避免仅依赖可能轮转掉的 logcat。

24. 阅读/下载验收优先让同一个真实安装源贯穿数据库、ChapterLoader、DownloadManager 和离线重读，复用上下文而不是建立第二套源或 downloader。受控 Source-only 样本返回空页时，使用既有真实签名插件，不修改样本冒充成功。网络前置检查必须区分连接与系统验证；本次未提前检查 VALIDATED 导致一次 90 秒等待，后续在测试开始即检查，不修改产品限制。临时代理要恢复全部派生设置，不能只清理最初写入的键。

25. 清理查询要遵循 repository 的可空/必须存在契约；删除后调用必须存在查询会掩盖业务结果并中断清理。本次因此产生一次清理专用运行和测试 APK 重建，明确不算产品 RED 或验收。清理各步骤独立尝试、聚合异常，精确回收已拥有的数据。Windows Gradle 属性参数包含盘符时整体引用；ktlint 报告的行号可能对应格式化后内容，应检查嵌套展开后的所有长行，避免逐行盲重跑。本次格式参数错误一次、长行失败两次如实记录，不归因于产品。

26. 签名拒绝测试必须同时核验终态和旧文件字节，不能只断言 false。本次真实私有替换 helper 在旧证书列表为空时越过匹配检查并删除了测试旧包，最终返回 false 仍不能证明回滚/保全。矩阵应直接把文件缺失计为保全失败，避免读取异常掩盖对照结果。沿同一 loader/签名上下文连续处理比重新分派更省交接，但本轮两次格式拦截仍是可避免开销：必须按格式报告的实际 diff 修正，而不是凭行长猜测另一种写法。

27. 信任交互验收可复用已安装的固定 APK：精确移除测试自身的仓库/信任，再通过真实广播重新加载，随后点击生产 UI 验证关闭与确认的不同结果。这样复用安装、签名、源注册上下文，不另建安装模拟器或直接调用 trust 冒充用户操作。测试需要的返回键优先用已有 instrumentation；本轮误以为 Espresso 可用导致一次测试编译失败，改用现有能力后未新增依赖。首次安装和更新的候选签名检查应共用同一前置门槛，不能因没有旧包而跳过认证。

28. 认证回归不能只覆盖“整个包未签名”：保留真实签名后追加未签名类、服务资源及伪装签名后缀的嵌套资源，才能发现逐内容校验的豁免错误。本轮真实 RED 发现 META-INF 子目录 `.SF` 被跳过，修复后还从真实 Manager 验证具体 JAR 认证错误和无残留文件，防止以其他阶段的 Authentication 失败冒充目标保护。扩大相关回归时发现旧正向输入与已提交仓库身份规则不符；先用当前代码、断言和 blame 核对语义，再修正输入并新增反向断言。保留生产身份限制，记录原套件失败，不把83项局部回归当作完整 Desktop 验收。

29. 完整安装入口不能由人工构造目录项代替：本轮复用 APK 生命周期 helper，使用真实仓库存储、HTTP v2 索引、默认 DI ScreenModel 和生产安装按钮，再复用加载/查询/memo 断言。只增加一个独立 UI 用例，没有建立第二套安装框架。合并运行暴露同 ID 不同 Source 实例的异步观察问题；等待条件必须匹配本次实例，清理也应等待 SourceManager 移除，而不是仅等上游 Manager 状态。不能通过删除身份断言修复测试。网络前置失败单列，不用其他10项通过掩盖下载未复验。
