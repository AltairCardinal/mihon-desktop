## 目标与计量

完整目标仍为[双端性能基准](../evidence/reader-startup-performance-baseline-2026-11-02.md)：Android 真机与 Windows、下载章节单页与双页分别登记条件。阅读器实际显示响应≤100ms；无内容累计及最长连续间隔的采样上界≤60ms；正确目标漫画首次可见不慢于同条件官方参考；页码、方向、恢复位置和首次呈现后的稳定性必须正确。内部 FIRST_DRAW、图层首 TX 和实际可见端点分别报告，不能相互替代。未测的平台或模式保留未确认。

近期仍优先解决 Android 同平板史莱姆第04卷的首次打开。P4首次近黑上界均值132.5→99.5ms，改善33ms；内部初始化→首绘均值320.403→283.045ms，改善37.358ms。唯一暖态未证明改善。它们是下一轮的比较依据，不是整体达标结论。

每轮在候选前固定主指标和对照：本轮主收益为同条件新进程首次近黑**上界均值的减少量（ms）**，内部首绘为旁证；逐样本、区间和暖态同时公开，不用均值掩盖失败。若上下界变化不能分辨收益，标记未证实，先检查既有连续帧与同次内部指标，不无限补样本。没有确定收益时不把源码少做工作换算为假定毫秒。

成本按各模型每次响应的 uncached input、cached input 和 output 计算；cached 已包含在 input、reasoning 已包含在 output，均只计一次。包括主代理、子代理、调查、失败、审查、构建等待中的模型调用、分析和收尾。墙钟构建时间不冒充 token 成本。按官方当日 API 价格处理长上下文，不使用订阅额度价格。服务档位、缓存写入字段或历史归属缺失时报告标准化估算及边界，不能称真实账单。

定义 `ROI = 实测主收益 / 本轮 API 等价成本`，首轮以前一完整P4批次作基线，此后按完整优化轮比较，不把同一候选拆成有利的微轮次。若可比较的 ROI 严格低于前轮的1/4，结束自主性能优化，报告未完成目标；如果计量边界会改变裁决，保留不确定性并先做有限核账。达到完整性能目标后也结束，不为消耗预算继续优化。

## 分工与最小流程

Sol（`gpt-6.1-sol / medium`）独占生产/测试修改、Gradle协调器与ADB。Luna（`gpt-6-luna / medium`）负责限定代码读取、离线批量分析和用量核算，不碰设备。主代理固定范围、维护本计划/报告、做一次独立审查及必要修复复审、整合提交。最多两个子代理，不同时构建或操作平板。

初始调查/最小实现预算30–60分钟；其中R1代码红绿与定向验证15–25分钟。只在真实机制与focused结果支持时进入一次候选构建及六份交替对照；主要增量成本是构建、采集和离线分析。实际预算、失败和新增条件在结果中记录。全模块、全仓库、完整发布矩阵、正式发布和推送不在授权流程内。

保持P0非阻塞页表、P3首次事实快照与正常停稳重绘、P4同次位置复用。不改转场、画质、下载格式、共享配对协议或全局调度器，不增加持久缓存、整章预读或提前打开阅读器。设备无密码锁屏自行唤醒/解除，只有前台采集时亮屏，其余时段读回Asleep；官方及正式fork APK和数据保持不变。操作沿用[平板指南](../automation/ANDROID_TABLET_ACCEPTANCE.md)。

## 执行路线

### [x] R1：消除同值页状态通知造成的整章重复投影

已定位链路：`completePageListLoad → bindPages → bindSharedState → publishSharedState → dispatch`。187个Ready页逐次通知；reducer对同值返回同一snapshot，但adapter仍无条件转换整章legacy状态。候选仅在`ReaderChapter.dispatch`检测`next === current`后返回，真实新snapshot仍按原顺序发布。保留初始绑定通知，不依赖“绑定时状态永远不变”的假设，不顺势删除reducer的页查找。

1. 在真实187页生产绑定链确认原实现188次整章投影、目标仅1次的失败测试。观察真实投影调用，不复制实现；只为测试可见性将现有投影函数调整为internal，不添加生产计数器。
2. 最小实现，验证真实状态及encoded identity变化仍投影、同值不投影、descriptor建立后绑定前状态变化不丢失；运行相关generation/旧页回归及受影响格式。静态spy无法可靠执行时先报告，不伪造计数成功。
3. 主代理审查锁、可重入回调、flow发布顺序和无变化语义。只修本候选实际问题，不扩大到holder协程启动或共享reducer。
4. 若通过，保留原42点仪器构建一次隔离benchmark包。A为P4真实APK，B为候选；相同证书/R8/non-debuggable和数据，记录源码输入及包哈希。正常安装并实读OAT，不反复强制编译。
5. 固定原章节/page0、单页RTL、横图自动放大OFF、hint OFF、黑背景、原动画。A1首次/暖→B1首次/暖→B2首次→A2首次，共六份；原表Perfetto/视频和内部探针同次取得，不改采集时序，不筛慢样本。每次核设置，记录USB、电源和可取得的温度；原件保持可复核。
6. 用原生PTS的四边界及连续画面确认近黑，精确native输入/Activity/Reader TX端点，报告四阶段与页表发布间隙。若视频无绝对时钟映射，不伪称输入到漫画可见已测。关闭probe后正常1→2→1三次，保护P3往返黑屏修复；最后关闭隔离包/采集进程并熄屏。
7. 核本轮净收益和完整成本，决定采用/撤回候选及是否继续；失败测试、无收益结果和未覆盖边界都保留。验证后代码、必要维护说明和本计划/报告同批本地提交，不推送。
