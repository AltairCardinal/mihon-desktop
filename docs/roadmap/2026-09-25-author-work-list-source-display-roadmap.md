- 开始前核对 HEAD、相关 AGENTS、现有未提交改动和最新 UI 规范。规划时 `docs/2026-09-17-global-author-functional-design.md`、旧 roadmap/handoff 及 `testfile/` 为其他工作，不能覆盖或混入提交；若实施时状态变化，以当时状态为准。
- 不改作品身份、展示分组算法、数据库、备份、通知、日期质量、收藏或显示偏好。来源筛选只影响卡片可见性，卡片及选择窗口使用完整当前组。删除直接审阅按钮不删除待定数据和高级纠错能力。

## 批次 AWSD-01 · 双端作品卡与审阅入口收敛

- [x] AWSD-01：列表显示完整图源名称；两种网格隐藏图源；点击仍选准确版本；作者详情无直接 `Needs review` 按钮。

**用户结果**：作者详情选择「列表」即可看到作品对应的不同图源；切到任一网格时先看封面和标题，点击后再选图源。待定作品不再显示多余的 `Needs review` 直接按钮，既有高级纠错仍可从明确入口进入。

**实施步骤与边界**：

1. 锁定当前双端卡片和待定/拒绝条目的真实入口、来源名解析、比较页面可达路径、现有测试与原生视觉事实。核对同名不同 source ID、缺失插件、自动聚合和分开显示样本，记录实际可复用组件；Android 现有审阅对话框仅由待定条目直接按钮打开，按设计将该入口移入条目级「更多」菜单，不创建第二套管理页。
2. 先写 Android/Desktop 真实 mounted UI 红测：列表显示未被来源筛选裁剪的来源名且无逐版本按钮；两种网格无来源文案／数量／操作，点击卡片打开完整来源窗口；待定条目无直接 `Needs review` 按钮而高级路径可达。断言真实点击和导航，测试在旧实现上因对应行为失败，不用源码字符串扫描代替。
3. 从 `WorkPresentationGroup.members` 投影稳定的图源文字，按 source ID 去重并保留缺源表示；将作品卡的可选内容限制在列表，复用主题 `bodyMedium` 与现有次级颜色层级。日期、新作、收藏和整卡点击语义不变；来源名只是文字，不再执行 `openVersion`。
4. Android 移除列表/网格待定条目的直接审阅 TextButton，在对应独立条目的「更多」菜单提供「作品校正」并复用原对话框。Desktop 将普通作品卡的逐来源动作收进来源窗口，保留待定/拒绝独立条目的 MoreVert → WorkCompareScreen；状态分区标题与底层待定事实由既有设计保留，不以此任务清理历史状态或资源字符串。
5. 双端分别运行红绿重构的 focused 测试，再运行相关 mounted/wiring、显示偏好与来源窗口回归、格式检查。Android/Desktop 预期相同的来源集合与模式规则用共享投影契约测试；平台焦点、布局和导航用各自集成测试。独立审查核对按钮移除未使高级能力失联、来源筛选未裁掉版本，以及无身份/日期数据改动；问题由实施者限域修复并复验。

**固定验收矩阵**：

| 用例 | Android 与 Desktop 必须看到/做到 | 证据 |
|---|---|---|
| 单源、多源、同名图源、缺源 | 列表逐图源名显示且无空白间隔；按 source ID 去重；长名能换行 | 共享投影契约 + 双端 mounted UI |
| 来源筛选、自动聚合、分开显示 | 只影响卡片可见性或成员关系；列表卡列出当前组全部来源，窗口列出同一完整组 | 真实归档 fixture + 双端来源窗口点击测试 |
| 舒适/紧凑网格 | 卡片无图源名、数量和逐版本操作；点击进入来源窗口，准确版本进入漫画 | 双端 mounted 导航/wiring 测试 |
| 待定/拒绝与纠错 | 作者详情无直接 `Needs review` 按钮；既有高级纠错入口仍能完成原有动作 | 双端真实点击 + Desktop 比较页/Android 对应高级入口测试 |
| 既有行为 | 显示偏好、收藏、新作、日期、取消还焦及 320dp/深浅主题不退化 | 受影响回归 + 离屏视觉核验 |

**完成与风险**：本批默认一名实施子代理承担主要实现及 focused 验证，主代理负责接口、整合和验收；需要独立审查时使用另一名未实施者，按项目每批预算执行。双端 UI 与现有测试虽跨多文件，但共同完成单一作品浏览交互，不按文件拆成不可独立验收的微任务。重点风险是 Desktop 比较入口及 Android 待定审阅按钮的可达性；先确认替代路径再移除控件。每次运行重型 Gradle 由同一协调者串行调度，最终 Desktop 迭代按 `scripts/build-desktop.sh` 正式构建、Test Mode 与发布产物验收；需要阶段收口时按仓库规则完成全量 Android/Desktop、Windows/macOS 及实际设备验收，环境缺口如实记录。只提交本批生产、测试和必要文档改动，报告 hash。

## 实施与验收记录

- 共享 `WorkPresentationGroup.sourceNames` 按 source ID 保序去重；Android/Desktop 列表从完整当前组解析名称和缺源状态，网格仅保留封面、标题、既有标记和日期。整卡仍打开完整来源窗口，窗口中可选准确版本；Desktop 比较入口保留在窗口，待定独立卡另保留条目级 MoreVert；Android 待定独立卡用「更多 → 作品校正」进入原审阅对话框。归档和身份模型未改。
- 红绿证据：共享投影契约、Android 真实挂载页面和 Desktop 离屏挂载页面均先因目标行为缺失失败，再通过。Android 相关两个测试类通过；Desktop 正式构建中的完整 JVM 测试 3178 项、失败 0、跳过 2；`spotlessCheck` 与本批 `git diff --check` 通过。Desktop 320dp 深浅主题离屏图已核对换行和边界，待定卡菜单及比较页导航已由挂载测试验证。
- 独立审查发现 Desktop 实际待定版本会投影成单成员展示卡，首次实现遗漏该卡的条目级 MoreVert；原实施者限域补齐，红绿测试与三项相邻回归通过，唯一修复复审通过。首次完整 Desktop 测试还发现测试宿主在导航后继续挂载未配置的漫画详情页，造成异步异常泄漏；限域修复测试隔离后，经用户批准追加一次完整测试并通过。
- Windows 使用 `scripts/build-desktop.sh` 构建 `0.11.19.57.6282447`，Test Mode 发布运行时扩展安装验收通过；日志为 `.gradle-coordinator/awsd-desktop-build2.log`，交付地址以其中 `Final unpacked EXE:` 为准。本批跨 Android、Desktop、共享投影、i18n、测试、版本与状态文档，超过 8 文件／400 行审查提示，但均服务同一作品浏览交互；主要风险是待定纠错入口及筛选后完整来源窗口，已由独立审查和挂载测试覆盖。
