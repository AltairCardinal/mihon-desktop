# 同步初次配置简化与可选密码 Roadmap

日期：2026-09-18。状态：P1 前置核验已启动；用户已确认无需兼容旧格式，权限证据与发现范围待确认，P2–P6 尚未启动，不代表生产功能完成。

设计权威：[本次迭代交互设计](../2026-09-18-sync-onboarding-password-design.md)，其中 O1–O10 是本轮交互覆盖索引。原型：[双端 DEMO 及验证说明](../prototypes/multi-device-sync/README.md)。现有实现与历史验收：[已完成 S1–S5 计划](2026-09-13-multi-device-sync-implementation.md)。

## 1. 目标与范围冻结

用户从书架同步入口登录 GitHub，应用自动查找专用私有同步空间：不存在时仅询问可选密码并自动创建；已有无密码直接合并；已有密码输入正确密码后合并。正常流程移除选仓库、保存／导入恢复资料和额外合并确认。

本计划是现有生产同步的增量迭代，不重新实现 S1–S5。需要新增或修改：自动发现／创建、未加密与密码保护格式、配置状态机、原生配置页面及设置相关入口。日常单按钮交换、倒计时、取消确认、批量处理、记录、阅读归并和调度只做受影响回归；发现无关缺陷另行记录，不顺带重构。

明确排除：其他同步服务、组织账号支持、新同步字段、密码找回／改密、既有数据重加密迁移、仓库清理、公开仓库同步、全新冲突处理中心、原型模型修复、扩展功能开发。真实账号权限变更、远端建库或数据迁移不得仅凭本文规划执行。

进度由下面第一个未勾选任务推导。只有实现、必要独立审查、验证及提交都完成才勾选；不更改旧已完成计划的状态，不自动切换其他 roadmap 的执行状态。

### P1：冻结权限、空间识别与格式支持边界

**目标**：确认“登录后自动连接”的真实实现条件，为后续代码提供唯一接口与格式约定。此任务不实现新 UI，不进行完整技术预研重跑。

**范围与交付**：

1. 核对现有 GitHub App 类型、设备授权、安装范围及用户令牌权限，验证发现个人专用私库和创建私库所需权限，区分用户登录与安装授权。以官方接口与实际配置事实为依据；未经授权不修改线上 App 或创建用户仓库。
2. 固定专用仓库命名／有效空间标识／协议版本识别、分页查找、同名非同步库、多候选及权限不明的结果类型。只有确定不存在才允许创建；无权读取不能等同不存在。
3. 冻结明文／密码／旧恢复格式的识别和拒绝降级规则、密码字符与上限策略、派生算法和参数、元数据结构及双端性能验证方法。不在实施时临时加入密码强度步骤或第二次输入。
4. 按用户于 2026-09-18 确认的“无需兼容”执行：不提供旧恢复资料导入／导出、迁移或旧格式交换；旧绑定启动和旧空间发现均明确拒绝，保留本机数据与远端文件，不将旧队列转入新空间。对应设计第 10.2 节，兼容例外无需再次审核。

**验收与测试**：形成精确的请求／响应与空间格式 fixture 清单、格式支持矩阵、失败分类及接口签名说明，附来源与实际可验证范围。纯契约文档做一致性检查；如修改 production 授权代码，必须先有对应真实 HTTP 失败测试再实现。未解决权限或格式边界阻塞须显式标注，P2／P3 不得以假设通过进入依赖实现。

**收口边界**：只在本设计和本 roadmap 更新必要决策，不建立第二套治理文档；不引入服务端密钥服务或代理授权后台。如果验证发现需要这些新架构，提交差异与成本审核，不在 P1 自动扩项。

### P2：接入未加密／密码保护两种空间格式

**依赖**：P1 的版本、密码学及格式支持规则通过。覆盖设计第 3、4、7 节和 O4／O5／O8 的底层契约。

**实现范围**：复用既有 codec、AEAD、批次校验、安全存储；为新空间显式编码保护模式。明文模式仍执行完整格式、大小、身份及批次校验；密码模式使用派生密钥包装随机数据密钥，正确密码才可交换。拒绝未知模式、坏参数、篡改和隐式降级。原始密码不得写入普通偏好、日志、异常或仓库；解锁材料使用现有平台安全存储。不实现旧格式兼容；识别后明确拒绝且不重写旧数据。

**写入边界**：domain/data 的 sync crypto、空间元数据与 transport 编解码；仅在必要处扩展安全材料接口。依赖或迁移改动由单一实施者协调，不重写操作日志、归并或投影。

**红绿测试与完成标准**：

- 在共享契约测试中先复现不支持新格式，再覆盖无密码往返、正确／错误／空密码、Unicode 与前后空格原样处理、篡改包装、非法派生参数和未知版本。
- 真实 codec → crypto → transport 链路分别完成两种模式交换；旧格式 fixture 必须被拒绝且零写入，不能被当作明文或空空间。
- Android/JVM 执行同一格式契约；覆盖安全存储重开后的可用性和敏感内容不进入可观察输出。最低端性能证据在 P6 的真实运行补齐，不用桌面耗时替代。
- 批次运行受影响 crypto/transport 契约与格式检查；独立审查格式与安全边界通过后，P4 才可依赖该结果。

**不做**：密码找回、改密 UI、所有历史数据重加密、用户自选算法或安全等级。

### P3：实现自动发现与可恢复创建

**依赖**：P1 的权限与发现契约；与 P2 并行时只消费冻结的格式接口。覆盖 O2／O3／O7。

**实现范围**：在现有授权与 production HTTP 链路上自动发现个人专用私库。返回已有空间及其模式、确定不存在、需重新授权、多个候选或不可兼容等明确结果。不存在且用户确认密码选择后才创建 `private: true` 仓库。创建与初始化分步恢复：超时先查结果，能够识别自己创建但未初始化的库，不能占用未知空库。两端同时创建以远端事实为准，后加入端不能覆盖先创建端的模式。恢复授权后重新核对账号和可见范围。

**写入边界**：data sync/auth 与必要 HTTP/空间发现接口；不实现页面，不改既有 Git 非强制发布、操作归并和批量确认。

**红绿测试与完成标准**：真实 HTTP 客户端和解析器接入 MockWebServer，覆盖分页成功／空结果、已有两种模式、同名非同步仓库、多个有效空间、403／429／500、畸形响应、取消／过期授权；创建明确成功、结果未知、初始化中断、重试发现已存在及并发赢家。断言不发生覆盖、公开建库和重复空间写入；失败不能错误转为“未找到”。生产客户端与 DI 接线测试必须能捕获私自另建 HTTP 客户端的回归。受影响 HTTP/授权契约和格式检查通过，并完成独立数据完整性审查。

**不做**：支持任意组织、手工仓库／分支编辑器、搜索用户所有业务仓库内容、未经授权的线上账户操作。多候选仅按 P1 审核后的异常方案处理。

### P4：连接配置状态机与自动首次合并

**依赖**：P2、P3 均完成并审查。覆盖 O1–O7、O9／O10 的状态与生命周期。

**实现范围**：替换现有 `SIGN_IN → REPOSITORY → RECOVERY → MERGE` 正常配置链路，接入授权、查找、新密码选择／已有空间解锁、创建、自动合并、完成／失败状态。复用 `SyncRuntime`、`SyncPanelController`、基线导入和现有任务管理，不复制第二个同步控制器。

一次确认只启动一个任务。创建或解锁成功立即自动合并，无人工合并确认；暂停／继续复用既有实现。关闭只清未提交输入和临时提示，已开始任务继续；进程重启按持久事实恢复，不保存密码明文。任务回执必须绑定账号、空间及配置尝试，旧授权回调不能覆盖新账号。重新授权／更换账号不能把旧队列写入新空间，断开沿用现有本机数据保留语义。

**红绿测试与完成标准**：扩展实际 panel/runtime 与真实存储契约，覆盖新建有／无密码、加入有／无密码四条闭环；未验证密码不能导入或上传；空书架不产生取消；失败／重试／重复点击／关闭重开／后台完成／暂停继续／重启恢复；切账号时旧回调与旧队列隔离。验证完成状态只能在合并真正完成后出现；共享状态契约在 Android/JVM 运行，必要 SQL 变更验证事务回滚。只回归受影响初始基线、连接和队列，不重跑整个 S1–S5 规模验收。

**交付边界**：controller 与 runtime 可通过真实集成测试使用，UI 接入留给 P5；不得为给未接入页面演示而保留虚假“成功”状态。独立审查账号隔离和恢复边界后交付。

### P5：完成双端原生配置交互与相关设置入口

**依赖**：P4。覆盖 O1–O10 的真实用户入口和反馈；主实现集中于共享 `SyncPanelContent`，平台 adapter 只处理必要差异。

**实现范围**：按设计接入设备授权和自动查找／创建反馈，新增单个可选密码框及显隐、动态按钮、解锁错误和重试。移除新空间的仓库选择、恢复资料及合并确认页面。设置显示实际保护状态；连接检查、重新连接、密码问题恢复及更换空间连接新状态机。继续复用同面板导航及已有返回／关闭控件，不重做同步主面板、批量条、记录和倒计时。

**红绿测试与完成标准**：

- 先写共享 Compose 交互失败用例，再接真实 controller：输入／粘贴／清空更新按钮，显隐不丢焦点／光标；空密码新建允许跳过而已有空间禁用连接；错误可纠正。
- 四条配置分支均无正常选仓库、恢复资料和合并确认步骤；设置状态与真实空间一致，失败不显示开启。
- 面板关闭后密码清除、重开可继续，后台回执不抢页面、不补播旧通知；Android 返回和 Desktop Escape、窄屏与键盘输入可用。
- 新增或修改导航／DI 时补对应实例化、导航类型及 wiring 测试；复用既有平台测试入口，不只检查文字存在。
- 回归日常立即同步、取消待确认期间交换、定期状态和设置返回各一条关键路径，仅保护受影响接线，不改其设计。

**不做**：重排其他同步页面、全站图标或主题调整、批量系统重构、插件页新功能。DEMO 只作本轮交互参照，不为通过原型旧断言扩大任务。

### P6：迭代集成回归与发布运行验收

**依赖**：P5 完成；P1 的外部权限与格式支持边界全部有明确结果。此任务验证本次改变的配置能力，不重新规划已完成同步系统。

**自动化范围**：运行本次受影响共享模块完整测试、Android/Desktop 应用测试和必要 Test Mode；汇总已有 focused 红绿与独立审查证据，不逐任务反复全量。构建前查协调器状态，同一 worktree 串行执行重型 Gradle。Windows/macOS 使用规定 `scripts/build-desktop.sh`，仅满足等价全量证据条件时采用 `build-only`；Android 按既有发布链路验证 ART/R8 与系统安全存储。

**真实运行矩阵**：

1. 新账号无空间：登录 → 自动发现 → 不设置密码 → 自动创建私库 → 合并 → 重启仍连接。
2. 新空间设置密码：创建 → 另一隔离设备登录 → 错误密码留在原页 → 正确密码合并 → 重启无需重复输入。
3. 已有无密码：登录直接合并，无额外选择；验证来源端取消与接收端本地变动仍可独立处理。
4. 中断与隔离：创建响应丢失重试不重复建库；配置关闭／后台完成不抢页；更换账号无旧队列泄漏；旧绑定和旧空间按已确认策略拒绝交换，原有数据保留。
5. 双端输入及显示：Android 窄屏、系统返回和密码输入；Desktop 键盘、关闭、浏览器回执；最低支持 Android 上密码派生耗时与取消响应可接受，阈值使用 P1 冻结标准。

真实 GitHub 写入使用明确获准的隔离账号／私库和合成数据；无权限时记录该项未验收，不借用用户日常书架，不以 MockWebServer 替代真实授权证据，也不自动删除测试仓库。各平台运行项明确记录实际执行平台，Windows 现场通过不冒充 Android/macOS 现场通过。

**完成标准**：记录每项命令、结果、必要跳过原因和正式产物；Windows 交付地址来自构建日志 `Final unpacked EXE:` 且确认存在。更新本设计、必要 README 及本清单，提交仅含本迭代文件。存在权限、格式支持边界或数据安全阻塞不得勾选完成。与本迭代无因果关系的老测试失败独立说明，不能据此悄悄扩大产品范围。

## 6. P1 执行证据与待决门槛（2026-09-18）

本节是本计划内的前置核验记录，不另建执行计划或报告。P1 保持未勾选；设计文档中的候选契约不等于批准实施或性能通过。

### 已核实事实

- 当前 `SyncRuntime.CLIENT_ID` / `APP_SLUG` 使用既有 `mihon-desktop` GitHub App；`authorization`、`repositories` 和 `transport` 均接收现有 `productionClient`，后续必须沿用这一网络图。
- `GitHubPrivateRepositorySelector.select()` 遍历用户可见安装及安装仓库，仅返回可写私库；没有验证个人账号归属、安装的 Administration 权限、完整账号可见范围或专用空间标识。其空列表不能直接转换成新流程的“确定不存在”，默认 200 项截断也不能用作不存在的证明。
- 本轮重新读取官方 [个人建库接口](https://docs.github.com/en/rest/repos/repos#create-a-repository-for-the-authenticated-user)：GitHub App **用户访问令牌**可调用 `POST /user/repos`，要求 Administration 写权限，请求必须显式 `private: true`。[安装说明](https://docs.github.com/en/apps/using-github-apps/installing-a-github-app-from-a-third-party)说明 App 创建的仓库会自动授予该 App 访问权。这些是接口能力，不能代替当前 App 安装与令牌的实际证据。
- 经本机代理只读请求 `GET https://api.github.com/apps/mihon-desktop` 返回 HTTP 404；不能据此判定私有 App 不存在。现有 GitHub CLI 调用 `GET /user/installations` 返回 HTTP 403，服务端明确要求 GitHub App 用户访问令牌；这证明该 CLI 请求不能用于验证 App 安装，不证明 Mihon 的生产令牌缺权限。没有提取系统凭据、重新发起用户授权、修改 App 或创建远端仓库。
- 历史已完成同步交接记录有真实设备登录、安装及交换证据，但没有本轮自动建库所需 Administration 写权限证据；不把旧流程成功误记为新权限通过。检查时没有运行中的 `Mihon Desktop.exe` 可供现有生产会话只读验证。
- `SyncRecoveryCodec` 的旧材料包含 32 字节随机数据密钥，`SyncRuntime.connect()` 先导入该密钥再读取远端。旧格式没有密码包装，不能通过输入任意新密码加入，也不能安全地作为无密码空间读取。

### 授权与发现接口约束候选

继续复用 `GitHubAuthClient`、`SyncHttpClient` 与 Git Database transport。P1 通过后由 P3 新增有类型结果，不能继续使用“列表为空或抛通用异常”表达全部状态：

| 请求/结果 | 必须保留的判断 |
| --- | --- |
| `GET /user` | 稳定账号 ID 与 `type=User`；登录名仅用于路由，任务回执绑定账号身份 |
| 分页 `GET /user/installations` | 个人账号安装、暂停状态、Contents 读写、Administration 写权限及仓库选择范围；缺权限与查库失败分别反馈 |
| 分页 `GET /user/installations/{id}/repositories` | 穷尽已授权范围，不跨 origin 跟随分页；上限达到则返回不完整，不能返回不存在 |
| 仓库元数据与固定同步标识读取 | 私有、本人所有、可写及有效版本；仅检查候选同步标识，不搜索业务文件正文；未知版本与旧格式分别返回 |
| `Found` / `MultipleCandidates` | 有效空间及实际保护模式；多候选只选择一个，不合并多个空间 |
| `Absent` / `VisibilityUnknown` | 只有完整可见范围内的确定不存在才可建库；selected 安装下的空列表或隐藏私库的 404 不满足条件，须先补齐可见范围证据，不能要求所有私库授权作为静默补救 |
| `AuthorizationRequired` / `Incompatible` / `RetryableFailure` | 401/权限403、格式异常与429/5xx/超时分开；403还需区分权限与限流，不沿用一律 RATE_LIMITED |
| `POST /user/repos` | 仅在授权门、查找门与用户密码选择均通过后调用；显式私有，记录本地操作身份；201核对返回身份，超时/422先重新查找，不能再次盲建 |

上表是语义约束；**selected 安装如何在不扩大所有私库权限的条件下证明不存在尚未闭合**，不得将其标为已冻结的可实现承诺。具体命名、初始化所有权证明和并发发布必须与设计候选协议一起审核，再固定 Kotlin 签名及 HTTP fixtures。

### 解除门槛所需的最小决定

1. **已解决：用户确认“无需兼容”。** 按设计第 10.2 节移除旧格式导入／导出及交换兼容要求，旧连接不要求继续可用；发现旧格式明确拒绝，不自动迁移或覆盖。该决定无需再次确认。
2. 核对当前 App 设置与个人安装的 Administration/Contents 权限和仓库选择范围（只需状态，不提供令牌、私钥或恢复资料）。若要修改线上权限、以真实账号建库验证，须另有明确授权和隔离数据范围；本次实现指令不覆盖 roadmap 明确排除的线上操作。
3. 权限与发现范围门仍未关闭时，P2/P3 不进入假设性实现。此时只交付可审核契约与证据，不运行无代码变化的全量测试或发布构建，不勾选 P1–P6。
