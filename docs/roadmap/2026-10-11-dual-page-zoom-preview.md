# 双页完整视口缩放预研体验版

范围：在 `b7b3/mihon` 工作树，以 `027ca888d24ff94a327eaf61963cbb7d8b274aa9` 为基线，交付 Windows preview 和签名 Android candidate。承接[调查与方案](../evidence/dual-page-zoom-investigation-2026-10-11.md)，本计划不表示稳定发布里程碑。

## 固定契约

- PROJECT_POLICY：阅读器 → 既有双页模式 → 左右孤页/双页 → 既有缩放、拖动、复位入口；1 倍页侧不变，放大后可跨原槽位，裁剪使用完整阅读区域。反馈、退出和导航继续使用既有入口。
- SOURCE：复用共享配对/锁定、解码/缓存/租约、平台图片组件和高清瓦片；不拼接双图，不重建阅读器核心。半槽 Single 和 Double 共用 frame 变换，迟到伙伴不改变现有图片位置和倍率。
- 平台边界：Windows 使用 Compose 图层及现有 region 几何；Android 使用原生图片控件的完整视口与有效倍率，动画、EXIF、背景适配限制在图片 adapter。普通单页和 FULL 路径保持既有行为。
- 共享 CSV `domain/src/commonTest/resources/reader/dual-page-zoom.csv` 由双端真实组件消费。边界为变换后的未裁剪矩形，right/bottom 排他；像素检查再与阅读视口求交。

- [x] 两平台真实组件红测：左右孤页聚焦、跨中缝移动、复位与持续拖动，确认现状因目标原因失败。

- [x] Android 实现与 focused 验证：完整原生视口、单一手势所有者、倍率/瓦片入口、稳定资源、动画/镜像/双图遮盖边界。
- [x] 主代理关键路径独立审查与必要补验，格式检查；同步架构说明和调查报告中的本轮证据。

## 验证与预算

两个实施代理并行修改互不重叠的平台文件，主代理独家串行协调 Gradle；1 轮独立审查，必要时 1 轮修复复验。仅运行本行为与受影响的集成/资源所有权 focused tests、目标格式检查；不执行完整模块测试、全量测试或正式 Desktop 版本分配。过程计划及报告各 1 份，报告复用既有调查文档。

预计 60–120 分钟，主要成本为平台实现、定向编译测试和签名打包。遵守 TDD，红测通过主代理确认后实现。机器内存紧张时先核查资源并串行限载，不清理其他业务进程。外部依赖失败遵循代理规则最多追加一次网络尝试；有阻塞时保留真实证据，不使用旧产物冒充新包。

## 体验版边界与退出条件

固定验收覆盖：真实图片跨槽/复位；连续拖动及翻页所有权；伙伴迟到身份与位置稳定；图像/高清几何一致；双图、背景和动画不会因本变更互相遮盖或重启。窗口与 EXIF 适配列入相关 focused 路径。

用户此次选择预研体验交付，尚未完成的长期压力、设备性能分布及硬件专项验收必须在报告明示。它们不得被写成 PASS，不阻止已通过定向回归的预研产物供用户体验。Android 构建不隐式安装；不操作实体设备。Windows preview 的运行时检查不等同阅读器原生交互验收。
