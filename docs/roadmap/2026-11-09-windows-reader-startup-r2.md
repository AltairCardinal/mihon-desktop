# Windows 首开 R2：早期输入修复与单页需求实验

日期 2026-11-09。用户要求修复 V1 审查问题并继续一轮优化。起点 `539e297eec`，产品候选 `06287cf3c3`；已有隔离工作树承担实现、构建与数据，避免与主干的发布工作争用。仅本轮相关文件可提交，不推送或发布。

## 固定范围与依据

1. 修复早期 F11、Space、Ctrl 缩放等不依赖页表的操作被统一排到 Loaded 后执行。页表失败也须生效一次；导航仍等待有效页表，退出及换代不重放旧输入。复用原键鼠 handler，由真实 handler 的依赖决定排队，不另造动作语义。
2. 只试一个性能候选：已确认下载、固定 RTL/LTR 单页、无 AUTO/拆页、opening 身份不变的轻量入口，在页表可用时通过原 session/core/scheduler 发起无进度内容需求，解除需求对复杂视口 apply 的等待。正式选择以前置可行性核查为准，不提前解码、不创建隐藏 holder、不整章预热、不改请求并发/预取预算。

V1 两份原始内部记录：页表→轻量视口 apply 为 34.880/45.705 ms；准入→apply 为 31.442/32.556 ms；目标归档 copy 为 2.477/3.562 ms；页表→显示 OPEN_PAGE 为 77.566/86.192 ms。待检验假设是可提前当前页普通 encoded 需求，使部分准备与轻量 UI 组合重叠，不能把上述 wall 区间全算可回收收益。

D5 的全下载路由提前内容准备已撤回：单页反向未重现、双页 OFF 更慢。本次的新条件是 P1 稳定、确定单一目标的轻量视口以及首绘前不再创建完整 model/UI；仅在该入口试验，双页、在线、未知下载事实和不符合准入的模式保持原链。不能把 D5 负面结果抹去，也不能先决定采用再补证据。

## 实现与失败处理

注册只能绑定本次 runtime、章、generation 和 opening 目标，并沿已有 resolveInitialPage/恢复与下载准入。页表失败、非法恢复、退出、换代、转入完整入口时取消未完成的注册。实际 session 调度前再次核对身份；真实视口仍负责呈现和进度，目标 holder/encoded 内容由原链接用，不能重复读取或记已读。若原 API 会带有限预取，如实保留和观测，不伪称只读取一页；不为本实验新增共享调度协议。
