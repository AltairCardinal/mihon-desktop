## 1. 范围、复用与交付边界

- 修复 10 项已报告缺口；不重做作者身份、模糊匹配、源抓取、同步协议或通知中心，不扩大 HTML DEMO。
- 复用 WorkPresentationGroupService/WorkTitleNormalizer、CreatorArchiveRepository、CreatorRepresentativeWorkSelector、既有来源选择窗口、发现/read/outbox、SourceDateQualityPolicy、备份贡献者及 SyncOnboarding/SyncSetupStorage。抽取共享投影输入和用例供现有消费者使用，不新增独立作者仓库或平台算法。
- 用户可见结果：单源和多源都可选择来源；各处作品计数一致；查看后整组清除提示；分开显示成功/失败真实反馈并随作者合并保留；日期可信且稳定；更新列表可滚动；旧同步初始化可显式放弃后重新检查；标题静默跟随应用中文脚本。
- “展示同作”不成为 canonical 事实。标题变化不改变组键、mangaId、原题或源成员；排除、标题缓存、质量样本仍设备本地。已有作者日期/查看事实的备份与恢复契约不得降级。
- 现有偏好存储可复用 UI 读写，但不能与作者 SQL 合并/拆分构成原子事务：仅纠错规则拟迁入最小本地 SQL 表；不迁移其他设置。确需新增 schema 时现场核对最新编号，不预占迁移号。

## 3. 任务定义与逐批验收

### RF-01 · 统一展示投影与当前应用语言

- [x] RF-01：双端作者列表/详情使用一致分组、数量、代表作与标题；单来源也走来源选择窗口。

**入口/范围**：domain creator 的分组/代表作/模型，data 作者卡片批量查询与缓存，双端 AuthorsTab/ScreenModel，现有 locale adapter 及相关测试。不修改发现已查看事务、日期质量或同步。

**实施方案**：

1. 从现有分组服务抽取最小共享分组输入/结果契约，包含作者根、canonical/自然键、排除集合和完整成员。作者列表批量查询输出相同分组依据，不在 SQL 再写另一套简繁转换。先分组再计算作品数/未查看组数，再让既有 selector 选择最多 3 部代表作；保留 VERIFIED/POSSIBLE、REJECTED 与语言可见性资格，不扩大低可信内容曝光。
2. 分页仍最多 50 位作者，批量加载该页所需候选元数据，封面仅最终代表作需要；以查询计数测试防逐作者 N+1。缓存策略版本失效时可重建，canonical/source 旧键通过自然键重映射，禁止缓存错组导致重复封面。
3. 正常可见单成员组与多成员组都渲染标准三视图卡片，移除按成员数回退待审核行的分支；明确 REJECTED/高级校正入口仍按原规则保留。点卡片均打开完整成员来源窗口，过滤只决定卡片可见，不截断窗口成员；窗口选择准确版本走现有 opener。
4. 按简繁设计第4节接入当前有效应用 locale：Desktop复用 DesktopLocaleAdapter，Android复用实际资源配置/现有应用语言生命周期；仅平台提取 locale，共享层决定脚本/标题。`zh-Hans`与`zh-Hant`优先于区域，CN/SG与TW/HK/MO做区域回退；“跟随系统”不能把空偏好当无中文偏好。
5. 历史标题缓存按组键+有效脚本隔离；同语言保留仍合格标题，切语言重选。仅从已有严格等价原题选显示别名，不凭 sourceLanguage 的 `zh` 判断简繁，不反转单向归一化表。无对应脚本保留稳定原题；非等价 canonical 主标题保留。代表作和详情均消费结果，来源窗口原题不变。
6. 语言变化只改变展示，不写原始数据、不产生发现/通知；不新增设置、弹窗或Toast。保留既有语言设置本身的反馈，本修复不改它。切换生效遵循平台现有页面重建机制，不承诺改造全应用热切换。

**红绿验证**：先让生产测试证明双源列表计2而详情计1、单源绕过窗口、语言切换不换题。随后覆盖3种布局/单源/缺源/筛选完整成员、canonical冲突、分页/代表作缓存、重启、简→繁→非中文→跟随系统、脚本与区域冲突、无目标脚本、错误源标签、新增低sourceId不抢占、删除旧成员可重选。真实SQLite＋双端mounted/导航/DI测试；共享fixture断言组键、成员、数量一致；语言切换前后原始记录及通知数量不变。

**完成边界**：不要求强制转换只有一种脚本的作品，也不做翻译；无新增canonical。交付共享契约、双端接线、focused日志及同批提交；行数超过估算只记录内聚性，不按文件拆任务。

### RF-02 · 分开显示的原子提交、撤销与关系迁移

- [x] RF-02：成功保存后才拆卡/提示成功；失败可重试；作者合并/拆分后纠错按自然键保留。

**入口/范围**：CreatorWorkPresentationExclusions、CreatorIdentityGraphMerger/既有身份编辑事务、data schema、双端分开显示回调与测试。复用现有用例/入口，不新建身份系统。

**实施方案**：

1. 将纠错持久化改为可等待、带明确成功/失败结果的用例。操作期间锁定重复提交；成功后才更新分组、关闭窗口并显示“已分开显示 / 撤销”。失败保持原窗口、原组和可重试错误；取消协程不伪装成功。两个版本拆开后均为正常单源卡片。
2. 撤销捕获本次成功提交的确切自然键/版本状态，不覆盖后续纠错；撤销失败保留已拆状态并反馈。用稳定自然键定位拆分后焦点，禁止向已移除的组卡FocusRequester恢复焦点。
3. 最小设备本地SQL记录使用creator root＋来源自然键唯一约束，在作者merge/split事务内迁移/去重；拆分只向实际拥有成员的新根移动，仍共享该成员时保留各自有效规则。canonical变化后忽略不再适用的规则，不把排除映射为REJECTED。
4. 一次性幂等导入现有偏好：读取现存记录、解析/核对根与自然键，在同一数据库事务写入规则与导入完成标记；失败回滚且保留原偏好，未完成前不得允许新SQL纠错写入。成功后SQL唯一权威，原偏好不反复回灌，避免撤销记录在重启时复活；无法解析/归属未明的旧值保留且记录非敏感失败原因，不静默丢弃或判定完整迁移成功。
5. 本地表与导入标记不进入备份/同步；恢复作者事实后按有效关系重校验。沿用现有合并/拆分事务和查询，不做全库破坏性清理。具体迁移编号与兼容说明随实现提交补齐。

**红绿验证**：真实持久存储故障注入先红；覆盖写失败不关窗/无成功提示、重复点击、撤销失败、拆卡焦点、合并A→B后重启、拆分部分成员、多作者成员、旧偏好导入/重跑/中断/坏记录、撤销后重启不复活；SQLite事务失败时身份与纠错均不部分提交；备份/同步不携带设备规则。

**高风险关口**：迁移与身份事务必须由未实施者独立审查；本批不发布新的下游接口，保留RF-01公共用例契约。若实施发现必须引入未审查高风险新接口供后续消费，先暂停依赖项并申请调整审查安排。

### RF-03 · 展示组查看闭环与更新页

- [x] RF-03：成功进入任一版本清除当前整组提示；更新页大量新作与章节仍可滚动访问。

**入口/范围**：CreatorArchive.markWorkSeen与repository事务、既有发现插入/read/outbox路径、双端导航确认与更新页面/模型。依赖RF-01投影，不复制分组规则。

**实施方案**：

1. 导航请求携带作者根/选中自然键及组定位上下文；导航成功后用共享规则重新解析当前有效组，在同一事务更新全部成员发现记录。核对成员仍属于作者且未被纠错排除；canonical成员与自动附加成员都覆盖。保留原始发现，不把展示groupKey写为canonical或跨作者身份。
2. 开窗口、取消、打开失败都不标记；标记失败保留未查看并反馈，允许重试。UI各处使用group.unread而非仅代表版本unread，计数与列表观察同一提交。
3. 复用现有已查看发现事实抑制后续严格等价来源重复提醒：发现入库/通知资格判断调用同一有效分组政策；排除项、canonical冲突、不同作者不得继承。先以现有SEEN成员证明状态；若真实测试证明现有事实无法满足并发/恢复契约，停止该扩展并提出最小持久事实方案，不临时建立标题全局已读表。
4. 将Desktop新作提示放入现有LazyColumn同一滚动体系，优先按作者汇总未查看组数并提供既有“查看新作”入口；不在顶部铺不可滚动的200张卡片，不让同一发现重复占据提示及普通条目。保留既有显示/语言筛选语义、章节操作和滚动状态。

**红绿验证**：真实repository＋导航确认测试覆盖pending×2、canonical+pending、失败/取消、纠错后成员变化、并发到达来源、两作者同名、合并/拆分/恢复无重复事件；Android/Desktop使用同一fixture。mounted更新页注入200组及章节，滚动至末尾验证可点击，覆盖隐藏作者发现/筛选与空态；不能仅检查字符串或列表长度。

**边界**：不重做系统通知中心，不标记漫画章节已读，不为提醒增加远端请求。涉及查看事务/通知资格的独立审查纳入统一高风险审查。

### RF-04 · 有界采样与稳定日期投影

- [x] RF-04：完整长目录也能积累跨日稳定证据；卡片使用最早可信上架日期或冻结首次发现日期，降级不漂移。

**入口/范围**：SourceDateQualityPolicy、production目录/发现记录入口、author_archive日期查询/快照、备份贡献者、双端卡片/来源窗口。沿用既有字段质量key，不扩大图源支持。

**实施方案**：

1. 保留最近最多20部作品，每部先选最多20个稳定章节自然键，再为每键保留最多两条质量观测；禁止先按全目录观测时间截40行。稳定键优先复用，不因目录重排/新增章节把所有历史锚点挤掉。
2. 两条质量观测用于基准/最新：24小时内相同值刷新保留跨日锚点；新观测值变化保留可判漂移的前值/最新值。不要简单滚动最近两次导致高频更新永远UNKNOWN；异常摘要与质量证据分离，网络失败不挤掉有效观测。30日诊断清理不删冻结展示快照，过期证据不足不得继续虚报当前TRUSTED。
3. 使用已有来源日期与冻结firstSeen字段抽取共享卡片日期选择器：仅完整日精度、语义已确认且可信的作品上架值有资格，取有效成员最早值；否则读冻结首次发现日/时区，不从epoch在UI重新算日。章节日期不能充当作品上架日。
4. 展示日期快照保留所选日期、类别、依据自然键、质量失效原因；刷新只允许更早可信证据修正或同日升级，可信度下降保留日期并显示“日期依据待核实”。审阅现有表后只补确缺字段；快照及必要证据随既有备份兼容扩展，质量原始样本仍本地。关系拆分/显式纠错按实际成员重算。
5. 双端作者三种视图与来源窗口消费共享结果；真实源没有可靠上架字段时正常回退，不硬编码白名单或抓新端点。

**红绿验证**：注入时钟，3部×100章跨24小时、每小时刷新、目录重排/新增/删除、30日清理、今日漂移/未来日/闰日/部分精度/网络错误/插件升级；真实更新入口→SQL→投影→双端UI，验证样本上限及达标/降级。备份新旧fixture、迁移中断回滚、重启/跨时区/恢复后日期不后移、可信日期不是代表版本日期时仍取正确值。不实际等待24小时。

**高风险关口**：日期事实、迁移和备份独立审查通过后才能计入发布完成；无可靠时区不猜测来源日期，不为清理样本清除历史快照。

### RF-05 · 旧同步初始化恢复入口

- [x] RF-05：旧newSpace记录可明确放弃并重新检查；取消/失败/账号切换均保持安全。

**入口/范围**：SyncPanelController/State、SyncOnboarding.abandonLegacyPending、SyncSetupStorage现有CAS、共享presentation-sync与i18n。优先共享UI，两端只保留已有平台导航差异；不改Git发布协议或App权限。

**实施方案**：

1. 旧newSpace重查不能恢复时返回可操作的旧初始化状态，而非通用死循环错误。提供“重新检查”和“放弃旧初始化并重新检查”；后者复用确认框，说明仅清除本机未完成初始化记录，保留书架、队列和远端文件；若未完成空间仍依赖本机密钥材料，明确提示放弃后该材料不可恢复，不能宣称无损。
2. 确认后捕获账户和精确旧记录，调用现有abandonLegacyPending/CAS；成功才退出旧状态并执行只读discover。写失败或记录已被并发更新时保留原状态、提示重查，不清凭据/其他账户记录，不自动执行create/join。
3. 重查到完整v2按已有加入流程；固定空目标按已有确认/密码流程；非空不兼容目标继续安全拒绝，不能以放弃本机记录为由删除远端bootstrap或覆盖文件。已绑定记录走既有断开连接确认而非未完成初始化放弃路径。
4. 关闭/切换账号使用已有authVersion隔离陈旧回调，重复确认串行；旧join迁移仍沿用原校验，不被newSpace退出改动破坏。

**红绿验证**：扩展SyncPanelStorageContract及真实controller+Compose集成测试，旧记录→取消/确认/失败→重启，CAS竞争、账户切换、已绑定保护、已有v2/空库/非空库三类重查。MockWebServer断言放弃+重查阶段零远端写入、无POST建库、无凭据跨账户；双端返回/关闭/按钮入口测试。复用生产安全存储契约，不mock整套onboarding。

**边界**：不访问真实账号、不更改GitHub App权限、不删除/创建真实仓库。原M3真实Contents-only联调与设备验收仍单独未完成；本地fixture不能关闭M3。

### RF-06 · 集成、发布与完成证据

- [ ] RF-06：10项修复通过生产路径回归与独立审查，必要平台产物和运行证据齐全后收口。
