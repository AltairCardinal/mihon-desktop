# 三阶段同步进度与 ETA 实施计划

需求权威：[2026-09-26 同步三阶段进度与实时剩余时间需求](../2026-09-26-sync-progress-eta-requirements.md)。本计划只针对现有同步面板和共享 Runtime；不改变同步协议、批次上限、发布策略或其他进行中的性能优化计划。进度从首个未勾选功能批次推导；勾选仅表示实现、独立审查、验证及提交均完成。

## 批次与依赖

- [x] **E1：共享进度事实与真实事件通知。** 在现有 `SyncProgressReporter` / `SyncRunStore` 上增加本轮范围、方向、准备/传输/确认的条目与正文工作量事实。复用冻结导入清单、待上传批次和远端索引，未知总量保持未知；上传与接收按事件或批次身份去重，确认只在现有安全事务成功后增加。HTTP 生产客户端在正文读写时通知内存观测器，重试请求的网络流量与有效进度分开。进度不得改变交换结果。**红绿验证**：确定性模型测试；MockWebServer 限速请求，证明结束前多次通知；文件数据库与真实 `SyncDatabaseExchange` 的批次、恢复和确认契约。**退出条件**：真实链路事实可被同一运行实例订阅；字节回调不逐块落库，未知分母无假百分比。
- [x] **E2：共享面板与双端交互。** 用现有 `SyncPanelContent` 在主面板及首次合并页显示准备／传输／确认、当前动作、当前阶段条目数、正文百分比或不定进度、已用与可用 ETA、等待/重试及确认状态。字符串走 Moko 国际化；Android/Desktop 均继续调用同一共享组件，阶段不只靠颜色识别。**红绿验证**：离屏 Compose 测试覆盖两处入口、已知/未知/零条、方向切换、失败和暂停；Android/Desktop 容器 wiring 冒烟；小屏放大字体与语义检查。**退出条件**：数据来自 E1 的 production 订阅，关闭再开不重启计时。
- [x] **E3：运行与性能收口。** 文件数据库重开、Runtime 重建、同空间多轮追赶和空间切换按持久事实恢复；未确认字节不冒充成功。运行相关模块测试、格式检查，以及一次完整 Android/Desktop 测试；使用同一 10,300 条样本对照进度关闭/开启时的准备与传输开销，并保存分段中位数及测量条件。最后按项目脚本构建 Windows 与 macOS Desktop 和 Android 产物，执行 Test Mode 与可用平台运行验收；设备/真实仓库验证交给用户执行，不写用户真实仓库。**退出条件**：生产链路、性能和发布产物证据可追溯；独立审查关闭高风险问题。

## 实现边界

复用现有队列、数据库事务、`SyncRunSnapshot`、面板、HTTP 客户端和共享 Compose 组件。已知工作范围内分母冻结；远端追加开新轮次。每条事件算一条，batch、请求、文件不算数据条目。字节回调只进短期内存状态，最多每 250ms 推送 UI；计时器变化不落库。安全确认仍按现有事务及时持久化。估速用单调时钟，10 秒窗口、至少 3 秒及 3 次有效增量，10 秒无进展或暂停/等待时撤销 ETA；原子确认无实测时显示无法估算。没有阶段依据时只显示局部 ETA。

这一功能批次跨数据、HTTP、共享界面、Android 调度和国际化模块，预计超过 8 个文件与 400 行；这些改动共享同一条“真实正文／事务事实 → 运行状态 → 双端面板”链路，拆开提交会留下没有真实数据的界面或没有入口的内部事实。主要风险是确认时序、并发冻结、旧数据库迁移和高频回调性能，因此用真实文件数据库与 MockWebServer 集成、确定性计时、离屏界面、独立审查和同样本对照验收。

## 验证与成本控制

同一 worktree 的 Gradle 由协调器串行执行。每批只做影响范围的红绿与相关集成，末尾一次完整测试；独立审查 1 轮，阻塞修复复审最多 1 轮。计划过程产物仅本文件，正式交付是代码、测试、必要文档、性能报告和构建产物。外部设备或真实仓库不可用时记录待验项，不把自动化结果写作设备验收。
