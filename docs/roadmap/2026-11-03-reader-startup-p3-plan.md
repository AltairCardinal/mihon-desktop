Sol `gpt-6.1-sol / medium`负责实现、focused、构建和唯一真机操作；Luna `gpt-6-luna / medium`负责限定读取、上游对照及离线核算；主代理负责计划、一次独立审查及提交。共享工作区不回滚他人改动；Gradle和设备不并发。预计90–150分钟，主要成本为诊断/候选构建和真机采集。

## 执行roadmap

### [x] P3-0：复用已有trace与源码，形成可证伪的调用假设

优先检查已有54.7ms窗口的主线程任务、slice自耗时与调用关系，父子区间不得重复相加。沿`MainScope.launch → loadPageAndProcessStatus → statusFlow Ready → setImage`区分排队、开始执行与状态处理；查同窗口的attach、呈现准备、布局与Compose工作。用现有本机上游源码/历史ref对照，不新建研究平台，不重测官方。

交付具体候选调用、触发路径、证据及缺口；没有执行栈就不能把通用布局slice当作函数根因。Sol与Luna互通发现，不各自重复探索。

### [x] P3-1：只补识别具体执行者所需的诊断

已有证据足够则跳过诊断构建。否则最多一次归因诊断构建、一首一暖，记录少量必要调用的成对起止/调用次数，以及目标任务排队和执行边界；可复用已有可用的局部栈证据，不默认启用全局逐方法日志。定义请求、章节、页面、线程归属，避免重入和跨尝试拼接。探针只在测量打开时工作，保留P2事件和相同外部协议。

先用真实focused验证新记录行为，再格式、benchmark构建。不能用新旧仪器差值推算净探针成本；归因诊断只支持机制判断。若无法归属，报告究竟缺少哪个执行者/边界和原因，而不是泛称主线程忙。

### [x] P3-2：一个最小产品候选，真实红绿与独立审查

先固定具体冗余工作或不必要依赖、真实消费者、失效条件与收益假设，再写真实production失败测试、确认失败原因、最小实现并复验同一focused范围。若改变调度或初始化时序，必须覆盖重入、取消/销毁、已Ready与后续状态更新；若触及进度/身份/隐私，补相应必要保护。不能把整个保护流程删掉，也不能仅修改动画或先展示空背景取得成绩。

只运行直接覆盖变更和集成点的方法及受影响格式；不跑完整类、全模块或全量。主代理一次独立审查，必要修复只复验受影响项。没有安全候选则保留有价值的证据，明确说明原因，不制造优化提交。

### [x] P3-3：同条件真机对照、结果与收尾

候选沿用最终控制同一套仪器，原版签名链隔离包保留数据更新、R8/资源压缩/non-debuggable、同一speed请求并读回OAT状态。先核当前设备与包身份；只操作`app.mihon.desktop.fork.benchmark`，官方及正式fork数据不动。

执行中的条件调整：归因控制已取得cmdline/speed，但候选在熄屏数分钟后仍被`HwBackgroundDexOptServiceEx`杀掉编译进程，实际为install/verify；熄屏不是成功的充分条件。停止追加强制编译，采用两版均正常保留数据安装后的install/verify对照，前后读回OAT验证。本轮因此只补控制一首一暖，候选仍为原定三样本，无新增构建或第二候选，增加约10分钟且在总预算内。原speed控制仅用于机制归因单列，不与verify样本混池，不把此次条件调整称为编译问题已修复，也不与旧speed绝对耗时直接比较。

史莱姆第04卷原SAF、合成入口1/1、page0、第1/187页、单页RTL、横图自动放大OFF、hint OFF、黑背景和原动画固定。候选采集首①/同进程暖/新进程首②，同次MKV+Perfetto+probe，保留所有有效慢样本。控制一首一暖仅分别描述性对照，不能伪装成统计充分的性能结论。采样后正常1→2→1并确认正确漫画像素。

实测发现的正确性门槛：候选1→2→1在返回首页时持续黑屏；最小旧归因控制同条件对照也在第二页黑屏、返回首页恢复。两版均失败，不能归因候选guard，也不能因此放行。保留全部性能样本并标候选未通过正常阅读，追加仅针对共有呈现链的原因区分、真实生命周期回归及必要修复/复核（预计30–45分钟，仍在总预算内），不作为第二性能候选或扩大到全模块。原手工调用setImage/绘制的测试未覆盖该真实往返路径，不以其通过替代真机。先区分未绑定/解码与已加载但被身份或呈现守卫拒绘，禁止盲增invalidate或绕过保护。

报告内部四段、具体机制区间、输入→应用FIRST_DRAW、原表系统端点与近黑上下界；不得把首窗口TX当漫画可见，归零MKV不生成绝对输入→首漫画时间。近黑上界≤60ms才确认该样本通过；下界>60失败，跨60未确认。跨仪器/历史P0、P1、P2仅作参考，不扣固定探针开销。

## 范围与失败处理

最多一个产品候选；必要诊断和候选各一次正常构建，修复构建只针对真实失败，不重复开启并行Gradle。设备暂不可用时继续代码/离线工作。锁屏须区分showing与secure；本轮已读到secure=false，后续可先尝试系统正常唤醒/解除无密码锁屏并复核焦点，不因showing=true就一律要求用户操作。确需认证或正常解除失败时由主代理询问，不修改安全或超时设置、不绕过认证。需要第二候选、额外实验或超过预算，先说明新证据、成本和最小方案；不把每个已授权步骤变成确认点。

本轮不启动B较完整回归、Windows、模拟器或正式发布矩阵；当前改动直接影响的正确性和资源保护检查不得后置。历史配对算法研究继续暂缓，除非本轮形成明确新条件并记录证据。
