## 实施顺序

- [x] **T1　建立真实快翻失败回归。** 在 Android 双页现有测试夹具中使用真实 ViewPager 触摸和本地图片生产加载链。首先在 A 准备好 B，进入 B 后发起第二次滑动，控制两次选择间没有 IDLE。以可观测的开流、准备和原生绘制计数证明 C 在停稳前无法开始准备。反向再走一次，断言准确的左右内容和阅读位置。计时断言用事件先后关系，避免宿主速度影响结果。保留原资源淘汰策略作为对照。
- [x] **T2　让六张普通图片的准备随选页移动。** 从现有 `updateNormalPreparationWindow` 拆出普通图片准入，接在 `selectGesturePage` 确认有效源页意图后。当前两张先行，沿最近翻页方向依次准备近、远两张，再准备反方向近、远两张；首次按阅读方向。保留现有两路有界并发。仅凭已有可靠分组或已知源页安排读图，分组暂不确定时也允许准备已知图片。手势内不调用整窗重建来启动加载。把准备好的图片交给最终 holder 时核对章节、源页和内容版本；只有有效的呈现票据和正确物理槽位才可绘制或记进度。优先复用原 holder；若单页占位变为双页而必须换 holder，验证已完成工作实际得到复用。手势取消或中途反向时更新临时优先级，取消的意图不覆盖上一次成功翻页方向。收紧窗口时保护正在离场的可见像素和仍在运行的解码任务。
- [ ] **T3　同条件测量并决定是否增加保留区。** 同一平板、同卷同组、相同设置和暖态，旧包与候选分别采至少 5 个完整 A → B → C → B → A 循环，记录真实手势间隔与中途 IDLE，分列有效及不符合快翻条件的样本。优先保留用户手动输入路径；已有 142 原始日志可复算，补采须在更新前完成。逐步报告目标开流／解码次数、相对选页的启动时刻（允许为负）、两张各自首绘、中位数和范围。另核对过渡及停稳的实际左右画面并记录同阶段 PSS。能获取逐帧证据时记录每侧首次露出到正确像素出现的时间；低频截图只能核对停稳内容，回调间隔单列。通过条件为可提前准备的目标在中间 B 停稳前已开始准备或命中现有资源，第二步消除约 650 毫秒的停稳等待，人工快翻消除可见加载黑屏。无需规定两侧必须同一时刻进入视口。
- [ ] **T4　按证据处理回收。** 若 T3 体验达标，即以时机修复收口。若端点仍因离开六张范围而反复重新解码并出现可见等待，先加入同一内容第二轮回访应复用的失败测试，再试行窗口外最多保留最近实际看过的一组双页，最多两张。另设字节预算，根据样本的解码尺寸、瓦片占用和 PSS 确定；无法可靠限制的资源跳过保留。低内存、内容变化或关闭阅读器时释放；缓存不得授予绘制或阅读进度。复验同一循环，比较 T2 与 T4 的重读次数、耗时和内存；资源超预算或没有改善则舍弃额外保留。如果残余黑屏发生在目标已准备好后，转查其曝光与重画时序，不启动缓存扩容。
