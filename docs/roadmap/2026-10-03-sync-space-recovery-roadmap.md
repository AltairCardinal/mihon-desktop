# 同步空间不可用：恢复设计与实施计划

本轮交付为设计，尚未实施以下产品行为。进度从第一个未勾选任务推导，不声明 active-task；不改写已完成的历史 roadmap，也不将本计划注册为已激活实施任务。

## 目标与事实

让 Mihon Desktop 在远端仓库被删除、改名、同名重建、授权撤销或同步数据损坏后，能够说明问题、保护本机数据，并提供可完成的恢复路径。共享行为同时适用于 Android，平台差异限于浏览器、导航和后台调度 adapter。

SOURCE，基线 `d85f3600cd`：

- 用户确认此前连接的仓库已经删除，没有建立新仓库；实体 Android 发布运行记录为 `RESUME_VERIFY_REPOSITORY / HTTP 404 / newSpace=true / CONNECTED`。Desktop 尚未进行该场景的真实发布验收，不能以 Android 证据宣称 Desktop 已通过。
- `SyncPanelController` 的 SWITCH_SPACE 确认调用 beginSetup，discover 优先取 pending Current，再 resume 旧记录，因此更换入口也会重复失败。
- `SyncOnboarding` 使用保存的名称核验仓库；当前 CONNECTED pending 可能保护尚未结算的首次导入，不能按“已经连接”直接删除。
- `SyncRuntime.bindSetup`、`SyncSetupStorage`、`SyncBaselineStore` 已有绑定、CAS 与按空间建立本机基线的机制；disconnect 会清除凭据，不适合作为“更换空间”的直接实现。
- `GitHubSyncSpaceClient` 已有安装授权、分页扫描、仓库固定 ID、空仓库检查和空间发现。createOrResume 不创建 GitHub 仓库，只初始化已有且已授权的空仓库。
- Desktop 书架的 `DesktopLibrarySyncAction` 使用共享 panel 和 `SyncPanelContent`；不得另写 Desktop 恢复状态机。

GitHub 对无权读取的私有资源也可能返回 404，因此应用不能仅凭 404 宣称仓库已删除。参考 [GitHub REST 故障说明](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api)。改名还可能返回重定向，而旧名称被复用后原重定向会失效，参见 [仓库改名](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository)。

## 用户交互契约（PROJECT_POLICY）

入口沿用“书架 → 同步”，在原面板内部显示恢复页面，标题“同步空间暂时无法访问”。不出现无说明的重试页，也不把 GitHub 对象不可访问归为“等待网络恢复”。主说明为“本机书架、阅读进度和待同步内容已保留。空间可能已删除，或当前授权无法访问。”

| 检查结果 | 用户看到的反馈与操作 |
|---|---|
| 账户授权失效 | “GitHub 连接已失效”；主操作“重新连接 GitHub”；取消后保留旧空间与恢复入口 |
| 仓库不可见，原因不确定 | 主操作“选择恢复方式”；次操作“重新检查”；恢复页提供“检查 GitHub 授权”“连接其他空间”“创建新空间” |
| 固定仓库 ID 相同，只改了名称 | 核对所有者、权限、空间标识与加密验证后更新地址，反馈“空间地址已更新”；不更换空间，不重新首次导入 |
| 原名称对应不同仓库 ID | “发现新的同步空间”；必须显式选择与确认，不能静默沿用旧密钥或上传旧批次 |
| 仓库存在但同步数据缺失/不兼容 | “空间数据需要处理”；提供连接其他空间、创建新空间及查看详情，不自动初始化或覆盖已有远端数据 |
| 网络超时、5xx、限流 | 沿用有界网络重试或服务器指定等待；不启动更换空间向导 |

默认页面只呈现一张问题卡、一段数据保留说明和一个主操作；其他路径放在恢复方式页。技术诊断放在展开详情中。活动同步仍遵守简洁进度界面：同步中、完成数/总数、已用/估时和确定进度条；恢复动作不与暂停按钮混在一起。

没有可访问的新空间时，“创建新空间”执行以下向导：

1. 说明“建立新的同步空间，本机现有书架与阅读进度会用于首次同步；已删除远端中仅其他设备拥有的数据无法凭空恢复”。用户确认后进入准备页面，尚不替换旧绑定。
2. 提供“在 GitHub 创建私有仓库”入口，打开 GitHub 仓库创建页；明确名称 mihon-sync、私有、空仓库。应用当前授权边界不能直接创建仓库，不能伪装成一键已创建，也不为此要求全仓库权限。
3. 返回应用后提供“仓库已创建，继续”。复用现有安装授权管理，为新仓库授予所需权限；取消、拒绝和浏览器启动失败都有原地反馈，草稿与旧连接保留。手动返回必须可继续，不依赖浏览器自动回跳。
4. 应用重新发现并验证目标：账户、固定仓库 ID、私有、可写、非归档、确为空。无权限只提供授权路径；非空且非有效同步空间拒绝初始化，不覆盖。
5. 用户设置空间密码，应用沿用现有初始化与首次导入。在新绑定可安全激活后显示同步进度；完成后显示下一次自动同步预计时间。失败显示发生在哪一步及有效继续入口。

连接已存在的其他空间：重新发现可访问的合法候选 → 用户选择 → 输入密码并验证 → 明确显示将切换到哪个空间 → 确认 → 生成该空间的本机导入基线。候选列表必须只读，不因选中一项启动上传。多候选不擅自选择；没有候选显示创建与授权入口。

返回/关闭/Escape：先取消确认框；向导页面返回上一步；关闭面板取消本次未提交选择与敏感输入，不删除持久恢复意图或旧数据，不自动开始同步。Desktop 关闭后焦点返回书架同步按钮。密码不写普通日志或恢复草稿。窗口尺寸、主题变化不重置向导；旧请求晚到不能覆盖新的账户、选择或面板会话。

## 恢复判断与后台行为（PROJECT_POLICY）

- 404 必须携带发生的业务阶段。初始化允许的空仓库/未建目标探测、可选对象缺失，继续沿用原语义；只有必需仓库或已连接空间资源不可访问才进入恢复判断。
- 使用同一 production 客户端核对账户和现有安装授权范围，复用分页清单按已绑定 repositoryId 查找；不以名称作为身份，不引入未经验证的私有 API 或独立网络客户端。
- 改名恢复必须验证相同仓库 ID、账户、空间标识/generation、解密与完整性，并对绑定地址更新使用 CAS。重定向处理仅允许经过审查的 HTTPS GitHub API 同源地址、有界跳数，拒绝跨域、降级和循环，不开启无约束自动转发凭据。
- 需要用户恢复时，以持久连接恢复状态阻止该空间再次自动上传/下载。不能将一次瞬时 HTTP 错误直接永久停用连接；恢复判断成功后才写状态。
- 重启、冷启动恢复和周期调度均读取此状态；后台可以保持本机记录，不反复创建失败运行或弹窗。自动同步偏好保留，主界面显示“自动同步等待恢复空间”，不展示实际上不会执行的下一次时间。
- 用户“重新检查”每次只启动一个受账户请求门控保护的检查。授权成功、网络恢复、用户明确重查后才重新判断；可访问且身份相同才能解除阻塞，不因重新登录成功就恢复上传。
- 状态变化期间等待旧 coordinator 与请求结束，使用账户/绑定版本和所有权检查拒绝旧回调；旧空间任务不能借新空间恢复继续运行。

## 数据保留与切换边界（PROJECT_POLICY）

复用现有绑定、日记、导入与初始化结构，新增的只有必要恢复状态及更换意图。实施前须核对其可复用粒度，不按 UI 方便直接清除 pending。

1. **旧空间记录保留**：书架与阅读数据、旧密钥和连接材料、待上传批次、待导入/待决定项、运行历史均按旧空间保存。它们不能因仓库删除自动清除。
2. **新空间身份独立**：同名重建仓库视为新目标，使用新空间标识、密钥、actor 与运行身份。旧批次不能换一个目标地址后原样发送。
3. **新空间从当前本机状态建立基线**：通过现有 baseline/import 链路重新冻结并记录当前可同步数据。旧空间待上传中已体现在本机的修改由新基线覆盖；旧操作历史不直接移植。尚未应用的远端待决定内容仍留在旧空间，切换前告知数量，不声称已经迁入新空间。进入新空间后的本机修改仍需由正常 journal 捕获。
4. **旧 pending 不成为永久拦截器**：显式更换必须使用独立的持久切换意图，把旧 pending 保留为可追溯的旧空间恢复信息；普通重试仍恢复原 pending。不得让旧 CONNECTED pending 抢占新向导，也不得丢弃正在初始化但未完成的远端写入证据。
5. **准备与激活分开**：新目标验证、密码校验和必要初始化完成前保持旧绑定；激活时串行停止旧运行，再更新新连接和导入基线。SecureStore 与数据库无法假装处于一个事务，必须持久记录激活阶段，重启后幂等完成或回到明确恢复页面，不允许两空间同时被标为可执行。
6. **失败可继续**：密码错误、授权拒绝、空间被再次删除、初始化响应丢失、断电均不删除旧状态；重试沿同一已确认意图，不创建重复远端对象。首次同步未成功时显示新空间未完成状态，不能提前宣称旧空间已恢复。
7. **恢复能力有边界**：如果远端已永久删除，只能把本机可用数据建立到新空间；无法保证恢复仅存在于其他设备/已删除远端的数据。其他设备必须通过各自应用明确连接新空间，不静默跨设备改绑。

无需独立 Desktop 服务：HTTP 与恢复判断追加在现有 auth/transport/onboarding/runtime 链路，UI 追加在共享 panel，后台平台 adapter 消费共享阻塞状态。只有现有按账户单槽 pending 不足以保存双目标时，才增加有版本的恢复意图存储；不得借机重写完整同步引擎。

## 实施批次与固定验收

每批严格红→绿→重构；checkbox 仅在实施、独立审查、验证和提交全部完成后勾选。以下设计不构成已完成产品能力，也不授权自动创建或删除用户远端资源。

- [ ] **R1：故障分类与持久恢复门控。** 先以真实 MockWebServer 覆盖必需仓库 404、授权不可见、401、403/429/500、网络异常、合法初始化 404、已连接目标缺失；写红测确认原通用失败和后台重试。最小实现共享检查与恢复状态，保留限流、取消和正常初始化语义；测试从生产 HTTP 到 controller/runtime，并断言重启与 PERIODIC 不创建新失败运行、不会错误显示网络等待。检查恢复状态存储版本兼容与旧数据不变。
- [ ] **R2：恢复页面及只读重新发现。** 依赖 R1；通过真实 Compose 点击覆盖主问题卡、重新检查、重新授权、恢复方式、无候选和多候选、改名相同 ID、同名不同 ID、远端格式缺失。点击更换必须进入重新发现而非旧 resume；退出/关闭无远端写入，旧账户请求晚到不更新新页面。改名更新需覆盖同源/跨域重定向、身份及加密验证；不能只用静态文案测试。
- [ ] **R3：保留旧状态的切换意图与创建向导。** 依赖 R2，属于数据完整性高风险批次。先测试旧 CONNECTED pending 与未完成初始化、旧未上传/未决定内容、新空仓库/有效空间/非空无关仓库、密码错误及相同名称新 ID；红测覆盖被旧记录抢占。实现独立持久意图与 CAS，复用原授权、初始化与 baseline。自动化模拟 SecureStore/DB 每个激活阶段崩溃、重启和响应丢失，断言旧材料/批次/历史不变、新基线正确、新旧上传目标严格隔离、幂等恢复无重复写。跨存储顺序通过独立审查后才进入发布验收。
- [ ] **R4：共享契约与发布验收。** 依赖 R1–R3 完整闭环。运行受影响模块完整测试、Android/Desktop 共享 HTTP/controller 契约、Desktop production DI 与面板真实点击测试；验证窗口/字体/主题、返回和焦点。最终仅一次全量 Android/Desktop 测试与适用 Test Mode，并用官方脚本构建 Windows、Android，完成真实发布客户端恢复验收；macOS 依项目最终收口要求执行，环境不足须如实记录影响。真实服务优先使用隔离测试账户/空间；远端删除或改权限的破坏性复现须另获明确授权，可用 MockWebServer 覆盖自动化失败矩阵，不为测试破坏用户真实空间。HTML 如用于审阅，只模拟 UI 且不得替代原生与持久化验收。

实现工作默认复用一个实施代理承担首批主要实现与验证，主代理规划整合、独立核对数据安全与发布验收；相互依赖的 R1–R3 串行，不同时写共享控制器。预算：独立审查一轮，必要修复复审一轮，focused 随红绿最小执行，全量最终一次；正式构建在全部实现稳定后执行，不为每个 UI 状态重复构建。实施前按选择的批次重新给出墙钟预算与新增存储范围，不能把本次 5–10 分钟设计预算当作全量实施授权。

## 用户可执行验收（未来实现目标）

- [ ] 已连接空间不可访问 → 书架 → 同步：明确说明不可访问和本机数据保留，有可执行恢复入口；重开/重启后仍可恢复，不持续网络重试。
- [ ] GitHub 只是撤销授权 → 检查授权 → 授权原仓库 → 重新检查：仍连接原空间，不新建密钥/首次导入。
- [ ] 旧仓库删除、没有新仓库 → 创建新空间 → 建立私有空仓库并授权 → 返回继续：通过校验与密码设置后首次同步成功，本机书架和阅读进度保留。
- [ ] 存在新空间 → 连接其他空间 → 选择并确认：旧批次保留在旧空间，新空间使用独立基线；取消不切换、不上传。
- [ ] 改名或同名重建：相同固定 ID 安全更新地址；不同 ID 必须确认新空间，不复用旧数据密钥和批次。
- [ ] 向导任一步关闭/退出或在激活阶段重启：旧本机内容不变，恢复入口有效，不留下双活动连接或只能重试的死路。
- [ ] 恢复后正常同步：确定进度、暂停计时、完成状态与下一次自动同步时间符合现有已审核契约。

本文件不附构建产物：本轮只完成设计与只读核验，未实施上述验收项。
