# 阅读器双页与继续阅读迭代方案

日期：2026-09-24。状态：**已实施**；三项主需求及单页章节例外已按配套 Roadmap 实现。Android 仍只提供现有 RTL 双页入口；横向宽图沿用既有呈现，Android LTR 双页入口不在本轮范围。

- 配套执行计划：[开发 Roadmap](roadmap/2026-09-24-reader-dual-page-and-continue-iteration-roadmap.md)。本文定义行为、入口和边界；Roadmap 定义任务、依赖、红绿测试、审查与发布。两者冲突时先修正文档，再实施，不以任务描述反向改写产品行为。
- 架构边界：[阅读器共享核心](architecture/reader-shared-core.md)；固定原版来源与 Fork 增强分类：[reader-authority](architecture/reader-authority.md)。既有[Android 双页布局记录](roadmap/2026-09-16-android-dual-page-layout-parity.md)是当时版本的完成证据，不能替代本轮新反馈。

## 1. 目标与三个相互独立的问题

用户从书库或漫画详情点“继续阅读”时，进入故事顺序最早的未读章节，并从该章节已有进度继续。用户用双页阅读时，实际看到的最后一张逻辑页决定章节完成；独占的首尾纵向页按阅读方向占据相反的物理半屏。

| 问题 | 触发实例 | 错误表现 | 目标 |
| --- | --- | --- | --- |
| P1 已读判定 | Android RTL 双页；**奇数页章节**，例 5 张纵向页按 `[0] [1,2] [3,4]` 分组 | 最后一组右侧第 3 页是进度 anchor，左侧第 4 页是真正末页；只报告 anchor 时不能自动标已读 | 最后一组稳定呈现后记录第 4 页、章节已读 |
| P2 继续阅读 | 漫画仍有较早未读章节 A，最近同步/打开位置指向其他章节 B | 点继续按钮进入 B，甚至 B 已读；A 的章内进度被忽略 | 选 A，再在 A 内恢复页码 |
| P3 物理位置 | Android RTL 双页；**偶数页章节**，例 4 张纵向页按 `[0] [1,2] [3]` 分组 | 独占末页第 3 页铺满视口而居中 | RTL 独占末页在右半屏；LTR 对称，在左半屏 |

P1 与 P3 **不是同一个章节、也不是同一种末页分组**。上述奇偶只描述无宽图和手动调整的实例。真实排版以当前逻辑页分组和图片类型决定，不能按页数奇偶硬编码进度或槽位。

## 2. 用户入口、选择和反馈

| 入口 | 本轮行为 | 反馈/无目标 |
| --- | --- | --- |
| Android 书库卡片继续按钮、漫画详情“继续阅读” | 在该入口原有可读章节筛选范围内，按故事顺序选择最早未读章节；打开后恢复所选章进度 | 有目标时打开阅读器；无目标时不打开旧的已读章节，沿用现有按钮隐藏或“没有下一章”反馈。同步位置本身不得使已读完漫画重新出现继续按钮 |
| Desktop 书库卡片继续按钮、漫画详情主阅读按钮 | 与 Android 相同的章节选择结果；保留平台既有导航和外部链接处理 | 同上；界面显示的“下一章”名称必须与实际打开目标一致 |
| 章节列表显式点击某章 | 精确打开被点章节；已读章按现有重读规则从头进入 | 不受“最早未读”选择器改写 |
| 历史记录的显式续读、同步恢复的显式入口 | 保持其针对指定阅读历史/同步位置的既有语义 | 不作为普通“继续阅读”按钮的章节优先级 |

“最早”指**故事顺序**，不等于屏幕列表顶部或最近访问时间；升序与降序显示应选择同一章节。先沿用各入口现有扫描组、章节过滤、下载限制和不可在内置阅读器打开的外部章节约束，再用共享 `resolveReaderEntry` 选未读章。不得因同步记录存在而放宽这些候选边界，也不得把用户手动标为未读的章节跳过。

### 章内页码与同步位置的优先级

1. 先确定未读目标章 `targetChapter`。若无目标，普通继续入口停止，不回退到同步位置、最近历史或已读章。
2. 默认从 `targetChapter.lastPageRead` 所表示的零基页码恢复；无进度从第 0 页开始。页数加载后沿用现有越界处理与反馈，不能因保存页码无效改选另一章。
3. 若同步恢复位置的 `chapterId == targetChapter.id`，允许沿用现有同步恢复页码和与**该章**关联的 `resumeSnapshot`；这是同章进度来源，不改变目标章。若两者不同，同步位置只保留在同步/历史功能里，普通继续入口不传它的 snapshot。
4. Android Reader 初始化必须保留入口选定的目标章：普通继续入口不得被 `resume=true` 对漫画级旧位置二次覆盖。若调用方有显式恢复意图，应使用与普通继续入口区分的参数/调用路径，避免两种意图共用一个布尔值而再次混淆。

| 候选与进度例子 | 普通继续入口的预期 |
| --- | --- |
| A 未读且已读到第 4 页；B 已读、同步位置在 B 第 9 页 | 打开 A 第 4 页，不附 B 的 snapshot |
| A 未读且已读到第 4 页；同步位置也在 A 第 5 页 | 打开 A；采用现有同章同步恢复页码第 5 页并携带 A 的 snapshot |
| A 被手动标为未读、仍保留旧页码；B 较新且未读 | 先选故事更早的 A；章内页码按 A 的现有进度规则处理 |
| 全部候选章已读，只有 B 的同步位置 | 不打开 B；继续入口隐藏或给现有无目标反馈 |
| 章节排序切为降序 | 选中章节不变，只有列表显示位置变化 |

同步数据的合并、冲突解决、写入格式和历史入口不在本轮修改。若实施发现同章同步页码与 `Chapter.lastPageRead` 的优先级在两端不一致，应先用现有同步契约和生产数据链证实预期，再调整本节和测试；不能用“取较大页码”等新规则猜测用户真实进度。

## 3. 双页进度契约

平台阅读器只负责把**稳定显示单元内实际可见的逻辑页身份集合**送到 KMP。双页 `[3,4]` 上报 `{3,4}`，单页 `[3]` 上报 `{3}`；同一张宽图拆为两半仍只对应一个源逻辑页。KMP `ReaderProgressPolicy` 按当前章节有序页列表取可见集合中的最末逻辑页，生成 `lastPageRead`、`isRead` 和幂等 effect，数据库/同步/track 后效沿用现有提交链。

区分三种概念：

| 概念 | 用途 | 双页 `[3,4]` RTL 示例 |
| --- | --- | --- |
| UI/预加载 anchor | 当前显示单元的定位、翻页和附近请求 | 可为右侧第 3 页 |
| visible page IDs | 用户真正看到的逻辑页集合 | `{3,4}` |
| 持久进度页 | KMP 从集合选出的故事最末页 | 第 4 页 |

打开章节、图片预下载/解码、布局尺寸改变、RTL/LTR 切换、宽图识别或手动重新配对本身不代表新的阅读动作；保留现有 `layoutOnly`/generation/active-chapter 门禁。真正停稳在最后一组时，即使最后逻辑页处于左侧，也应完成章节。已经标已读的章节不会因为稍后报告较早视口而变未读。读到倒数第二组不提前完成。

## 4. 双页排版与方向

此表只描述**纵向源页作为独占显示单元**时的绝对物理位置，左右不受系统 locale 布局方向二次翻转。中间双页继续保持 RTL 右页先读、LTR 左页先读。改变物理槽不改变源页顺序、配对边界、页码、当前章或下载请求。

| 阅读方向 | 独占首页 | 中间一组两张纵向页 | 独占末页（不是首页） |
| --- | --- | --- | --- |
| RTL | 左半屏，右半屏空 | 较早页在右，较后页在左 | 右半屏，左半屏空 |
| LTR | 右半屏，左半屏空 | 较早页在左，较后页在右 | 左半屏，右半屏空 |

- 4 张纵向页 `[0] [1,2] [3]`：Android RTL 首页左、末页右；Desktop RTL 同样，Desktop LTR 首页右、末页左。末页仍独占一个显示单元，**不要**为了把它移动到右/左而拆散 `[1,2]`。
- 5 张纵向页 `[0] [1,2] [3,4]`：末页已与前一页配对；按该方向的中间双页规则渲染，并由可见页集合完成进度。**不要**为强行让每章最后一张都在末端半屏而拆散 `[3,4]`。
- **用户已确认：一页章节居中显示整屏。**它既是首页也是末页，因此不应用左右半屏规则；测试必须覆盖 Android 与 Desktop 的真实双页呈现，不能沿用封面左槽的旧断言。
- 横向封面/宽图可能被识别为跨页、切片或平台现有的完整图。其页面尺寸与图像呈现保持既有行为；本方案暂不强制横图进入半屏。Android 与 Desktop 当前横向封面呈现存在差别，不能在本轮暗中声称已统一；RD-02 实施前须确认本例外，若选择强制半屏需另行评估裁切、缩放和跨端视觉验收。
- 强制单页、手动调整配对、edge matching、宽图识别会改变哪些页成为“独占末页”。槽位决策依据最终分组中的位置和页类型，不依据章节奇偶；重排保持同一逻辑阅读锚点，不产生虚假进度。

## 5. 平台边界与复用方式

| 能力 | Android 当前状态 | Desktop 当前状态 | 本轮作用 |
| --- | --- | --- | --- |
| RTL 双页 | 有 `DUAL_PAGE_R2L` 操作入口；Android holder 对非封面单页全屏居中 | 支持 | 修复 Android 可见页上报与末尾独占页物理槽；Desktop 做回归 |
| LTR 双页 | **没有**可选的 LTR 双页模式；LTR 是单页 pager | 有独立阅读方向和双页选项 | 在 Desktop 落实首页右、末尾左；共享纯槽位契约包含 LTR，不把规则测试冒充 Android 用户入口 |
| 章节选择 | 已使用共享 `resolveReaderEntry`，但入口先看漫画级同步位置 | 同样 | 复用共享选择器；平台只提供原有可读候选与导航 |
| 进度完成 | 已调用共享 `ReaderProgressPolicy`，但双页只给一张页 | 已报告全部可见页 | 修 Android presentation→共享 core 接线，不复制第二套已读规则 |

Android `ReadingMode` 的低三位 0–7 已分配给现有模式（7 为 AUTO）。新增 Android LTR 双页需要新的模式编码、旧数据读取/降级、设置与阅读器入口、导航方向和持久化测试，是**另一项用户可见能力**。当前迭代不默认新增它；若用户明确要求双端都能选择 LTR 双页，先把该能力作为独立功能批次加入 Roadmap 并重新估算，不能偷用 AUTO 值或仅改 holder 条件。

KMP 继续拥有页配对纯算法、章节选择和进度判定；Android View/Desktop Compose 只把显示单元转成稳定页集合及物理槽。可将方向/首尾独占页的纯槽位决策提到共享 presentation 规则，但不要让 `ReaderSessionCore` 认识“左/右半屏”，也不要让图像 holder 直接更改章节已读状态。实现后同步修正当前[共享核心说明](architecture/reader-shared-core.md)中“Desktop 封面无论方向都在左槽”的旧描述，并以真实 Android holder/ Desktop renderer 测试证明新契约。

## 6. 可执行验收矩阵与失败处理

| 场景 | 入口与动作 | 可见/持久结果 |
| --- | --- | --- |
| P1 前一组 | Android RTL 双页打开 5 张纵向页章节，停在 `[1,2]` | 章节仍未读；进度不越过第 2 页 |
| P1 最后一组 | 同章翻至 `[3,4]` 并停稳，返回章节列表 | 第 3、4 页均曾显示；持久进度为第 4 页，章节已读；返回重开不倒退 |
| P3 Android | Android RTL 双页打开 4 张纵向页章节，从首页翻至 `[3]` | 首页图像在左半屏；末页图像在右半屏而非居中，空半屏不残留上一页 |
| P3 Desktop | Desktop RTL/LTR 双页分别打开同样章节 | RTL 左首/右尾；LTR 右首/左尾；中间双页顺序各自正确 |
| 一页章节 | Android RTL、Desktop RTL/LTR 双页分别打开只有一张纵向页的章节 | 图片居中显示整屏；没有空半屏，也不重复展示该页 |
| P2 旧同步章 | Android/Desktop 都准备较早未读 A（有页进度）和已读 B（旧同步 resume），从书库与详情各点继续 | 两个入口都进入 A 的有效进度页；B 仅能由显式入口打开 |
| P2 同章同步 | 同步位置与最早未读 A 相同，页码与本地值不同 | 目标仍为 A，章内页码按第 2 节既有同步规则；snapshot 只属于 A |
| 保护路径 | 手动改配对、旋转/窗口缩放、失败重试、快速切章、显示模式切换 | 排版和定位稳定；无伪造已读、旧章进度覆盖或错误章跳转 |

生产路径失败时保持可见加载/错误/重试反馈，不把失败页当作已完整阅读。无法获取章节或有效页码时沿用现有错误/越界处理，不静默退到另一章；进度事务失败不得用 UI 临时页码假装已经持久已读。验收使用真实 View/Compose、ScreenModel/Activity 和共享持久化调用链，源码文本扫描不能替代行为测试。正式产物与测试次数、审查门槛见 Roadmap。

## 7. 待确认而不得默许的例外

1. 横向封面/跨页图是否也强制占方向半屏，本方案推荐保留现有宽图呈现；若要求统一，应增加跨平台宽图尺寸/切片视觉范围与预算。

这一项只影响 RD-02 的边缘实例，不阻止 RD-01 和 RD-03 的独立修复。Android LTR 双页是否作为新能力纳入，由范围决策单独处理；未获明确答复时不扩大已存在模式的产品入口。
