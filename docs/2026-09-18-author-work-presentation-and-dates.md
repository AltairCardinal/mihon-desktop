# 作者作品：收藏标记、书架显示与日期可信度

日期：2026-09-18。范围：HTML交互迭代与实施契约；本轮未修改正式应用、数据库或插件。取代上一轮作者详情中“来源按钮直接进入漫画”的设计，作者B布局、关注/全部、顶部栏与名字规则保持。

## 1. 收藏标记

- 作者列表B布局的每张作品封面，以及详情的列表/网格封面，在左上角显示小型「已收藏」标记。使用实色底与高对比文字，不用仅颜色表达状态；不能盖住书名或把“关注作者”误认为“收藏作品”。
- 同一规范作品的任一版本已在书架，就在聚合作品封面标记已收藏；来源筛选隐藏该收藏版本时，作品级收藏状态仍不改变。
- 来源选择窗口逐版本标记：只有该具体漫画版本已收藏才显示已收藏，其他版本显示未收藏。同一作品A源已收藏不代表B源也已收藏。
- 本轮展示状态，不新增跨图源自动收藏/取消收藏；正式实现订阅已有favorite变更，原型使用可辨认的固定收藏样本。

## 2. 作者作品复用书架视图

作品区提供「显示方式」入口，窗口选择列表、舒适网格、紧凑网格；布局语义参考既有书架组件。列表左封面右标题；舒适网格封面下标题；紧凑网格标题位于封面渐变遮罩上。日期作为独立次级信息保留，三种视图均显示收藏标记。

选择即时应用到当前设备的作者作品列表，切换作者或来源仍保留，不影响书架自身的显示偏好或另一个设备。原型只在页面内存保存，刷新重置；正式实现为独立“作者作品显示方式”偏好，复用书架渲染/主题，不复制其选择、下载或筛选业务。不要直接复用书架全局视图偏好导致两页相互修改。

保留横向来源chip、作品搜索和紧随作品标题的计数。计数仍是筛选后规范作品数。整部作品是一个点击目标；在三种视图中都先打开「选择漫画源」，单源也展示该窗口以便查看日期/章节/收藏信息。取消/Escape/蒙层关闭不导航，回焦点到原作品。

## 3. 来源选择窗口

每个条目包含本版本封面、图源名称、图源中的作品名、总章节数、收藏状态、最新章节日期；点击条目进入准确的漫画版本。作品级日期在作品列表显示，来源窗口展示版本自己的最新章节日期，不能拿A源日期冒充B源日期。

- 选择窗口展示当前作者同一规范作品的全部已收录来源，来源筛选只决定外层作品列表，不丢掉窗口中的其他版本。窗口用简短说明解释这一点。
- 没有完整章节数据时显示「章节数未知」，不得将未抓取误画为0章；总章节数是该版本当前完整目录条目数，不能把多图源章节相加。正式实现若仅取得分页子集，显示“已获取N章”而不宣称总数。
- 可信最新章节日期显示完整年月日；没有字段显示「日期未提供」，存在不可信/异常值显示「日期待核实」，不把它回退为本机首次发现来冒充章节更新时间。
- 缺插件、失效图源仍可查看已有本地漫画详情；其可用状态明确展示，不为打开选择窗口发起多源抓取。打开具体版本之后才走既有漫画加载链路。
- 320px窗口内部滚动，封面/数值/来源文字不挤出屏幕，长作品名可换行；键盘焦点限制在当前窗口。

## 4. 日期字段与显示语义

| 信息 | 含义 | 显示策略 |
|---|---|---|
| 作品上架日期 | 某来源明确记录该作品首次上架 | 仅字段语义明确且该来源作品日期可信时使用，显示「上架 YYYY-MM-DD」，可查看来源依据；不是作者创作日期或全网首发日期 |
| 最新章节日期 | 该版本最新目录对应的有效更新时间 | 按章节日期可信记录使用；与作品上架日期分离 |
| 本机首次发现日期 | 本地第一次记录该规范作品/来源版本 | 上架证据缺失/不可信时显示「首次发现 YYYY-MM-DD」，永久保留原始首次时间 |

所有完整日期包含年份，不只显示“今天/昨日”。源只提供年份或月份时保存精度，不凭空补1月1日；不能满足完整上架日期的样本仍以首次发现作为主日期，并可在详情保留原始部分日期。本轮原型只使用完整日精度。

**最早章节日期不能等同上架日期。** 它最多证明该源某个章节的时间，搬运、补档和目录缺失都会造成差异。可信章节记录可以帮助评价该图源的章节日期质量，但不能自动授予作品上架字段同样的可信资格。

规范作品多来源有明确上架证据时取最早可信日期，标明来源；这些日期只是已知来源中的最早上架，不宣称全网首发。原始首次发现记录始终保留。主展示日期采用“只允许更早的可信校正，不随普通刷新向后移动”：新可信上架时间早于旧值时可校正标签及日期；更晚值不替换旧值。资格降级后保留历史展示日期及失效证据，不静默把它推迟成今天，正式UI可提示“日期依据待核实”。

作品对应关系合并时取最早firstSeenAt、保留所有来源证据；作者别名合并或主名切换不得重置日期。作品拆分按剩余来源证据重算，不复制不属于该作品的早日期；这一纠错属于显式关系操作，不是日常刷新。恢复/迁移保留原firstSeenAt，普通网络响应不准传入并覆盖本机首次发现时间。

## 5. 本地可信来源记录与判断

现有数据依据：`source-api/.../SChapter.kt` 提供date_upload，但没有保证其真实有效；`data/src/commonMain/sqldelight/tachiyomi/data/author_archive.sq` 已有first_seen_at，并以min更新。优先复用它及现有作品自然键/检查点；本轮不建第二套人物身份规则。

正式本地记录建议按“扩展包/版本＋sourceId＋字段类型”保存，而非图源显示名称。字段类型至少区分作品上架和章节更新。记录UNKNOWN/TRUSTED/SUSPECT、证据样本键、两次观察时间、日期精度/时区、判断原因和策略版本；这是内部维护数据，不在普通作者页面展开代码状态。

**默认未知，不预置未经验证的真实图源白名单。** 可从已有正常更新流程积累证据，不因作者列表首次显示批量爬取全站。用户提出的“其他已更新数章的作品”用作交叉样本，而不是只看当前新作。

章节字段建议的初始保守门槛（待真实图源回放校准）：

1. 同一source至少3部不同作品，每部至少3个有稳定章节ID的历史章节；两次观察间隔至少24小时。按章节ID比较，不按列表序号比较，以免新章节插入造成误判。
2. 至少3个不同历史日期、无未来/非法日期；旧章节日期跨日稳定，新章可以自然追加。章节重排不能影响判断。通过后可登记“样本支持可信”，并保留证据而非永久无条件信任。
3. 若同一批旧章节从不同历史日期整体跳成新的抓取日，立即将该字段降为可疑。所有章节恰好同一天的单次记录只算证据不足：可能是合法集中上架，不能直接定为造假。
4. 图源扩展版本、解析逻辑或日期格式改变后重新取证；已有日期不因升级而重写成当天。日期记录不足/疑似回填时宁可首次发现，不猜上架日。
5. 作品上架字段另行核对明确标签、稳定值和跨作品历史分布；章节可信不自动传递到作品字段。对“默认当前时间”的解析兜底也应在adapter层标记不可作为事实日期。

这些规则是启发式质量控制，不是证明真实出版日期的算法；高仿但错误的稳定时间仍可能逃过检测。无需依赖远端作者ID或第三方作品数据库来决定身份。

## 6. 防止日期漂移的保存契约

- 版本firstSeenAt仅首次入库赋值，重复观察只取已有值；规范作品firstSeenAt是已确认版本的最小值。与lastSeenAt、lastFetchedAt分别保存。
- 保存UTC事件时间和首次显示采用的日期/时区；普通时区变化不重新格式化已冻结的日精度标签，防止跨时区显示日期跳动。源只有日期时按来源已知语义解析，不猜测用户当前时区。
- 网络更新写源日期证据，不修改本地首次发现。收藏状态同样属于本地用户状态，不能被图源刷新覆盖。
- 展示快照至少保存日期、标签、证据版本、来源与资格。新候选只有更早或相同日期且更明确时替换；更晚源日期保留为原始证据用于诊断，不覆盖展示。
- 新作排序优先基于本地发现事件/未查看状态，与来源上架日期分离。刚收录旧作仍可能是“新发现”，但不能因为今日发现就标为今日上架。
- 重试、分页、重复来源、备份导入及进程重启均不得生成新的“首次发现”。没有本地历史时只能如实记录当前首次观察，不能反推发布日期。

## 7. HTML样本与验证

原型所有日期、总章数、封面和来源可信状态都是本地示意，不是对漫画柜、MangaDex或其他真实源的实际评级。演示模型dateSources按虚构sourceKey区分字段，workDates保存不会后移的日期快照，实际生产注册表/磁盘持久化尚未实现。

- 初始平行天堂：示意可信上架2017-03-18、最新章节2026-09-17，漫画柜版本已收藏。
- 文字图源样本：不提供日期；总章数可已知，或另一版本显示未知。
- 变异体少女：模拟所有日期写为今日的不可信来源，展示首次发现2026-09-18，最新章节日期待核实。
- 「加入同名作品」产生新作品，记录当前模拟日期为首次发现。
- 「模拟次日刷新」使模拟时钟增加一天，并注入旧章节整体漂移的负例。可看到不可信章节日期被拦截，作品首次发现不变；重复刷新也不后移。两个设备独立。

模型测试执行日期选择、首次观察防覆盖、向前校正、字段独立、跨日证据及负例降级；浏览器测试执行真实渲染和操作路径。原型比较样本数组是简化的同ID章节序列，正式实现必须使用章节自然键映射、版本化证据和事务。

正式实施另须测试：多源收藏聚合、隐藏收藏源、总章数完整性、目录重排/新章插入、未来日期/闰日/时区、仅年份、重启及备份、图源改版降级和错误更正；这些不能由HTML内存测试替代。

本轮原型验证结果：完整模型与浏览器测试18项全部通过（8模型、10浏览器），零失败或跳过；三个脚本语法检查通过。已检查双端网格及320px来源选择窗口截图。此证据仅适用于HTML原型，不代表正式应用已实现。
