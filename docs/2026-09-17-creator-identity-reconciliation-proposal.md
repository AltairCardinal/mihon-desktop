# 跨插件唯一作者：同名自动统一、异名合并

日期：2026-09-17。状态：最终交互基线已确认（`77a610534`），实施设计已冻结；GA-01与GA-02已完成批次验收，按用户要求暂停后续roadmap实施；尚未完成真机发布验收。交互见[功能设计](2026-09-17-global-author-functional-design.md)与[HTML 原型](prototypes/author-identity/index.html)。

本版本整体替代此前“来源 ID + 首次确认 + 同名不同人”的方案。旧方案可在 Git 历史查阅，不再作为实施约束。本期实施沿用该设计和原型；未完成全部批次验收前不向用户真实库发布中间迁移版。

## 1. 唯一的身份规则

**作者名称文本相同，系统就必须作为同一人处理，不区分插件、来源或站内作者 ID。合并功能只用于不同名称。**

- “冈本伦”在漫画柜、其他插件或只有文字署名的来源出现，自动进入同一个作者页、作品集合和关注目标，不需要证据、选择身份或首次确认。
- “冈本伦”“岡本倫”“Okamoto Lynn”是不同名称，默认分别建档。用户将它们合并后，三个名称成为同一个人的全局名称集合；任何插件未来使用任一名称都自动归入同一作者。
- 系统不提供“相同文本但不同人”的例外。现实人物是否重名不改变这一产品规则，原同名分离/否定关系不能继续阻断自动统一。
- 外部作者 ID 相同而名称不同，不触发统一；外部 ID 不同或缺失而名称相同，仍必须统一。来源只用于作品访问、署名出处、版本展示及筛选。
- 未出现过的有效名称自动建立作者；空白/缺失署名显示“作者未知”，不把“未知”作为共同姓名创建作者。

“同一文本”采用解析出的单个姓名 token 的精确比较：沿用署名分词器提取原始姓名及去除分隔符边缘空白，不追加大小写折叠、繁简转换、全半角转换、标点清洗或音译。比较器本身不改写输入。原始署名用于溯源；搜索可以宽松匹配，但搜索命中不能改变精确身份规则。多个作者的署名分别解析，不把整个作者列表当作一个人物。

全局范围是用户的作者库，跨该库全部插件。不同设备各自新建记录的 UUID 不保证相同；UUID 是存储引用，不是人物判定依据。

## 3. 数据模型与数据库约束

继续以 Creator 作为唯一人物实体，增加 **全局精确名称注册表** `author_archive_identity_names`（设计名）：

| 字段 | 语义 |
|---|---|
| name_text TEXT COLLATE BINARY PRIMARY KEY | 精确名称，在整个作者库唯一；键不含 sourceId、插件、站点或外部 ID |
| creator_id INTEGER NOT NULL | 指向名称所属的活跃根作者，外键引用既有作者表 |
| origin / created_at / last_modified_at | 名称产生及迁移记录，区分直接署名、历史回填、用户异名合并 |

主显示名和所有已接受别名都必须注册；主显示名必须属于该作者名称集合。多个名称允许指向一个作者，一个名称不允许指向多个作者。索引采用精确文本列，不能以名字哈希碰撞或 NOCASE 比较替代唯一性。

保留 `author_archive_aliases` 的历史说明和搜索能力，但身份解析的唯一权威是新名称表。不能把仅为搜索生成的标准化变体自动注册成别名；对现有 raw_alias 的迁移保留其原始文本，避免 normalized 唯一约束吞掉大小写等不同文本。备份也必须保存完整名称表，不能只从旧 aliases 重建而丢失变体。

Creator 增加 identity_revision 用于异名合并的乐观并发控制；整个姓名集合或相关关系变化时更新。portable key 永久保留供旧链接、关注和备份引用；被收敛的作者留 MERGED 重定向，不删除旧键。删除人物、别名编辑、拆分等既有入口必须维护同一唯一约束。

**不新增来源作者键表、站点身份 adapter、作者证据置信评分或待确认同名署名表。** 外部作者链接可作为既有元数据显示，但不参与判定，也不为作者识别新增 HTTP 请求。

## 4. 唯一的解析与写入链路

共享 repository 提供 `resolveOrCreateByExactName(name)` 和带作品角色的 `observeCreatorMentions(...)`。所有入口必须调用它，不能各自查询/创建作者。

1. 解析署名为单独原始姓名 token；空白 token 跳过。
2. 按 name_text 精确查询全局名称表，命中后沿重定向找到活跃根作者。
3. 未命中时在同一事务内创建 Creator 和名称注册；并发唯一约束失败则回滚该次创建并重新读取胜出的名称记录，不留下孤立人物。
4. 将作品署名与根作者绑定；重复观察使用作品自然键 + 角色 + 名称保持幂等。任何来源 ID 不进入姓名查找条件。
5. 当前缓存或旧作品绑定若指向同名旧身份，按同名收敛迁移到根身份；不能因旧绑定存在而继续产生多个人。
6. 返回 Resolved；缺少姓名返回 MissingName；存储/损坏错误返回可恢复错误状态，不能把存储失败包装为“请选择同名作者”。

漫画详情（含未收藏漫画）、书架刷新/索引、作者发现、备份导入、同步接收、手动新建/改名、别名管理必须共用上述约束。显示作者页不依赖源在线或作者 ID 可用；已有名称命中在本地完成。

发现服务可以用精确姓名或已合并别名确定**作者关系**；这不代表作品已经抓取成功或两个漫画是同一本。作品候选、章节及版本判断继续遵守原有作品模型，不把“同作者”升级为“同作品”。

## 5. 历史同名记录自动收敛

历史同名整理是升级/加载索引的一部分，不是用户手工任务。漫画柜三个“冈本伦”应在作者入口可用前成为一个作者；不再出现三个同名选项。

- 读取现有活跃作者主名和已接受的原始别名，按精确名称建立连通分量。共享一个名称的档案必须归为同一组；既有明确合并的不同名别名继续属于该组。
- 同名与已有别名的传递关系使用同一规则，不能靠两两顺序得到不同结果。未被显式接受的搜索候选名称不参加分组。
- 每组自动选定稳定的保留键：沿用已有根；有多个活跃根时使用 portable key 的稳定二进制排序。不是用来源或本地自增 ID 决定身份。异名添加别名保留发起作者为根及其主名，主名另由独立改名命令修改。
- 在一个外层事务内迁移该组全部关系、名称、关注和重定向；中途失败整组回滚。自动迁移完成前展示准备/重试状态，不暴露多个正式同名作者让用户选择。
- 自动收敛关注默认取启用并集，保留已有订阅范围，不新增通知渠道。检查频率是全局作者设置，不是作者属性；合并、改名和索引都不得改写全局值。
- 保存迁移前可恢复资料及每组完成标记，按组分批和断点续跑。重启、重新索引、导入旧备份都必须幂等，旧记录不能复活重复身份。
- 作者角色取有意义的并集，例如同一个人的原作/作画可并存，其他合作作者不受影响。不得通过最后一次写入覆盖角色。

旧“同名不同人”决定在新规则下不再有效：记录其历史以便回溯，但不能据此拒绝同名收敛。它不是待用户再次确认的门槛。错误/损坏的合并环、缺失引用需要修复或回滚；这属于数据完整性错误，不是人物歧义。

### GA-01 实现维护边界

精确名称迁移的持久化就绪标记与分量检查点用于避免每次作者读取扫描全库。新增数据的各写入入口仍须即时维护唯一约束，不能假定迁移完成后不再出现遗留增量或导入。旧作者的持续作品订阅须监听当前根并切换订阅，不能仅在首次打开时解析一次。

`author_archive_identity_migration_components.recovery_graph` 保存版本化、分量内的迁移前JSON资料，当前格式版本为1；固定字段由 `CreatorIdentityRecovery.kt` 与 `author_identity_recovery.sq` 显式定义，捕获和合并在同一事务内，成功后保留快照。覆盖作者/旧键、精确名称/别名、漫画/图源/规范作品关系、关注策略与范围、运行/检查点/发现/通知以及作者语言断言。失败回滚不得遗留半张关系图；未知快照格式不能被当作可恢复资料。该记录用于审计及受控恢复，不是通用备份格式，也不提供绕过同名唯一约束的一键撤销。

普通元数据写入继续遵守既有字段优先级及角色替换语义（例如BOTH可变为AUTHOR）；只有身份合并内核显式取角色并集。自动名称解析使用AUTOMATIC关系及NAME_EXACT依据，不能伪装成用户选择而阻挡后续更新。`identity_revision`表达真实身份/关系语义变化；重复解析、绑定或无变化写入不应增加版本。原始漫画及图源署名不因身份合并改写，不新增关系署名拼接格式。

## 6. 直接添加别名与主名称修改

作者详情「添加别名」窗口展示其他根作者，搜索、多选后点击「添加」直接提交，无合并预览或二次确认。保留当前作者为根和主显示名；所选身份的全部名字成为其别名，现有和未来任意来源的同名署名都会复用。

共享命令 `AddCreatorAliases` 参数包括发起作者、选中身份、选择窗口读取的 expected revisions 和幂等键。窗口显示候选时记录版本；提交重新校验根、名称占用、相关版本和选择范围。资料变化时拒绝写入，在原窗口刷新候选、保留有效选择，再次点击添加；不把内部校验快照呈现为预览页面。

事务内复用合并内核，迁移全部名称、作品关系和旧键重定向；关注取启用并集。取消无写入、失败整组回滚、重复调用幂等，未选人物不变。事务不得改写全局检查频率。

`UpdateCreatorDisplayName` 仍为独立名称修改命令，但作者详情入口改为点击已有别名：使用漫画详情署名链接的同款样式，弹窗「要把XXX设为该作者的显示名称吗」，确定后设置主显示名。UI不再提供修改名称按钮、自由文本或下拉编辑器；必须校验所选名称仍属于当前根的名称集合，原主名保留为别名。取消无写入，失败不改变数据；作品、关注、根键和全局频率保持不变。成功后焦点转到主名称标题，取消回到原别名。通用名称注册能力不通过此入口暴露。

添加未占用的别名也须注册到全局名称表；占用名称必须通过明确的添加别名命令归集。移除别名/拆分需按不同名称整体迁移，不能让同一文本分别属于两人或某图源例外。原型实现主名修改与已有作者别名添加，不实现完整拆分器。

### GA-02 实现维护边界

`CreatorIdentityEditor` 是两端共享的窗口状态与命令调用入口；Android/Desktop复用各自既有页面和导航，只维护平台视图、焦点及生命周期适配。候选只取活跃根并排除当前根，窗口记录当前及全组选中版本；显示过滤和刷新不得自动选择新候选。会话标识隔离迟到的加载结果，原子提交门闩避免订阅更新与点击并发时丢失操作。身份观察失败可以重试，恢复成功清除读取错误而不覆盖窗口内命令错误。

`author_archive_identity_commands`保存幂等键、请求指纹、结果根与合并前恢复资料。请求重放先核对指纹，不能用同一键提交不同操作；名称/版本校验、完整关系合并及凭据写入同一事务，失败不留下部分合并或凭据。26到27升级新增该表及关注变化版本触发器，文件数据库重开后仍可识别重复请求。这里是设备本地操作记录，不是线上别名协议或通用撤销器；备份是否携带的边界由GA-04明确。

主名操作只选择当前已有精确名称。旧按漫画及自由新名拆分不能安全表达名称整体迁移，页面说明当前限制且不写入；不提供新的拆分编辑器。`CreatorWorkArchiveFilter`仅组合作品查询、来源和既有语言过滤，完整计数来自原始归档；不按标题或作者合并作品。打开来源版本优先沿用已有本地漫画ID，缺少本地条目才复用平台现有保存流程；缺插件显示不可用标记但不阻断已有本地详情。

## 7. 来源、作品与关注

来源仍存在于漫画条目中，用于打开漫画、显示来源、筛选和可用状态；不是作者身份的一部分。卸载插件不删除作者、名称集合或关注。

作者统一不合并漫画条目、章节、下载或阅读进度。已确认的同一作品关系才可折叠成多个版本；标题相同、作者相同都不足以改变作品身份。多来源作品页点击任一已注册署名返回同一个根作者；关注/取消关注对这个作者统一生效。

### 全局作者检查频率

检查频率是一份全局作者偏好，不再存储在Creator/单个关注记录上。共享设置命令仅保存 `DAILY` / `WEEKLY` / `MONTHLY`（每天/每周/每月），默认每天。调度所有已关注作者时读取这一全局值；新作者以后被关注时同样适用。每月按日历月处理，不存成固定720小时。

入口仅在双端作者列表页右上角：Windows底栏「作者」、Android「浏览 → 作者」。作者详情没有检查频率设置。草稿与保存值分离，取消不写入，保存失败保持原值；成功反馈、焦点返回列表设置入口。频率保存不改变关注、名称或作品；添加别名、改名、迁移同名及新建作者不改全局值。

正式实现复用共享偏好和双端DI，不另建人物级频率表。原有单作者周期不再作为新调度器的读取来源；迁移缺失全局配置时统一默认每天，已有全局值不覆盖；旧每作者周期退出读取链。共享日历计算与检查点、退避的精确规则已确定于功能设计第12节，偏好进入设置备份但不实时同步；这些规则须由production验证，原型仅演示全局内存设置。两端原型独立，不实现跨设备设置同步。

## 8. 备份、同步与失败处理

- 备份扩展保存精确名称表、合并/自动收敛记录与旧键重定向，沿用现有贡献器及事务恢复；具体版本号在生产实施时按当时最新格式分配，不硬编码旧提案的 v5。
- 导入旧备份时按本规则重新收敛同名，再恢复作品和关注；保留旧键映射。新格式必须做引用、环和唯一性校验，损坏时拒绝相应事务，不部分写入。
- 删除旧方案中“关注同步开启就禁止本地同名统一/姓名关联”的产品限制。同名自动统一始终是本地不变量，同步开关不改变姓名含义。
- 现有同步解析按 portable key 及本地重定向工作，它本身不等于姓名合并决定已经跨设备传播。接收端需先按精确名称解析/收敛 descriptor，保留远端键到本地根的重定向，再应用关注；缺少姓名和已知键时挂起待补全，不猜人或创建重复身份。
- 本期不在线传播不同名称合并、主名选择或全局周期，别名集合仅随明确备份恢复迁移；未来传播需要独立协议及兼容测试。不得塞进display name或假装FOLLOWING已覆盖。本期GA-05必须验证现有关注同步与本地合并的旧键映射、同名归根、因果取消和兼容错误，不能用禁止本地统一规避责任。
- HTML 两端是独立内存，不演示在线同步，无同步禁用场景。不在本轮部署同步服务或修改协议。

## 9. Production 接线与验证契约

| 接线点 | 必须验证的行为 |
|---|---|
| CreatorRepository / SQL 名称索引 | 同名跨插件唯一；不同 ID/缺 ID 无影响；并发同名创建仅一根且无孤立记录 |
| ManageCreatorIdentity / 双端详情 | 同名直达作者页；未收藏作品同样可解析；不出现同名选择框 |
| CreatorLibraryIndexer / 发现服务 | 刷新、重建、重启不再产生重复；异名默认独立，已合并别名自动命中 |
| merge 内核 / 关注 | 全组事务、幂等、角色并集、旧键链、未选名字不变、选择版本校验；关注取并集，不改全局频率 |
| 作者设置 / 双端入口 | 列表页三种全局频率保存与取消；对全部现有/未来作者生效，不改变关注；另一设备独立 |
| 主名切换 | 点击已有别名后确认/取消；校验名称归属，旧主名保留为别名；根及作品/关注/全局频率不变 |
| 别名管理 / 拆分 | 一个精确名称只能归属一个根；不能重建同名不同人或图源例外 |
| 备份 / 同步接收 | 旧数据收敛、新数据往返、混合版本错误提示、键重定向、关注不丢失 |
| Android / Desktop UI、DI、导航 | 共用精确姓名契约；合并入口/结果/失败反馈接入真实 production |

先写使旧行为正确失败的 focused tests，再最小实现、重构。共享契约必须覆盖“冈本伦”同名自动、“岡本倫”/“Okamoto Lynn”异名独立、异名合并后任意插件未来复用、大小写及标点不自动折叠、多个作者 token、空白署名、名字更新和并发创建。名字更新重新解析该署名，不能因站点 ID 未变自动替两个名字建立别名。

正式批次统一为GA-01名称唯一性/迁移、GA-02双端命令与交互、GA-03全局调度、GA-04备份恢复、GA-05现有关注同步兼容、GA-06正式验收；依赖及检查清单只在Roadmap维护。数据迁移和跨模块边界须独立审查。此前A/B/C粗分与站点取证工期作废，不把HTML测试当作production证据。
