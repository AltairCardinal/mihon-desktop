# 同步空间：默认无密码与遗忘密码风险提示

日期：2026-09-28。状态：用户已确认产品方向；本轮交付完整改动方案与 HTML 交互 DEMO，具体交互待用户审阅。**生产功能尚未按本文修改或发布。**

审阅入口：[Windows / Android 并列 DEMO](prototypes/multi-device-sync/password-review.html)。该文件转到 `index.html?review=password`；普通入口和模拟授权流程继续保留；新入口仅跳转到本地样本的创建步骤，不代表真实授权。

## 1. 决策、目的与范围

优先保证普通用户在更换或丢失全部设备后，仍能通过自己的 GitHub 账号读取同步数据。新建同步空间默认不设置额外同步密码；有额外隐私需求的用户主动选择密码保护，并在提交前明确了解遗忘后果。

GitHub 私有仓库的账号与访问控制，不等于 Mihon 对同步内容的客户端加密。无同步密码时，只要用户仍有权访问原空间，就无需额外秘密来读取同步内容；拥有仓库读取权限的人也能读取内容。密码保护面向所有希望把“读取仓库”和“读取同步内容”分开的人，不仅适用于共享账号。它不隔离同一账号使用者的仓库修改、删除权限，也不替代 GitHub 账号安全。

本轮只交付本设计、更新后的既有双端原型及原型测试。后续生产实现范围为共享首次配置 UI、帮助页、密码选择的提交防护、两端接入与对应验证；不重做日常同步、GitHub 授权、专用仓库初始化或数据合并。

不纳入：恢复码/恢复文件、密钥托管服务、可信联系人、修改或关闭既有空间密码、数据重加密迁移、删除/改名/重建远端空间。也不把“默认无密码”解释成自动解密已有空间。

## 3. 用户操作与文案

### 3.1 创建同步空间：默认不设置密码

入口：书架 → 同步 → 完成 GitHub 授权与目标检查 → 发现可以初始化的新空间。标题统一为 **创建同步空间**；创建的是 Mihon 同步空间，不在本页改变仓库创建/安装权限流程。

- 说明：“同步数据保存在你的 GitHub 私有空间。未设置同步密码时，新设备登录同一账号并获得访问权限即可同步。”该条件在打开开关后仍成立，不以常驻文案误示已加密空间也无需密码。
- 边界：“未设置同步密码时，内容不额外加密；拥有此空间读取权限的人可以读取同步内容。”
- 开关：“设置同步密码（可选）”，默认关闭。关闭时隐藏密码框、显隐按钮、风险确认和警告卡。
- 主按钮：“创建并开启同步”。点击直接使用已有无密码初始化及合并流程，不再弹一次确认。

账号权限丢失、仓库删除、远端数据损坏仍可能阻止恢复；“无同步密码”只消除额外密码带来的锁定风险，不承诺同步可以替代独立备份。

### 3.2 主动设置密码

打开开关后，在同页显示密码输入框、显示/隐藏按钮、持续可见的风险卡和默认未选中的“我已了解遗忘密码的后果”。警告卡位于输入区附近、确认与提交之前，使用图标、标题、正文及主题语义颜色，不仅依赖颜色或短暂 Toast。

警告正文：

> **请先保存密码，遗忘可能无法恢复数据**
>
> 同步密码不同于 GitHub 登录密码。本版本不提供找回或重置。
>
> 若遗忘密码，且所有设备都失去解锁能力，将无法恢复远端加密数据；重新登录 GitHub 无效。
>
> 本地现有内容不会因此删除。

帮助页进一步说明密码管理器、已解锁设备和独立备份的可用范围。创建页的开关始终允许用户在提交前退回无密码选择。

主按钮改为“设置密码并开启同步”；密码为空、格式校验不通过或尚未确认后果时不得执行。仍沿用现有 UTF-8 长度及字符校验，不静默删前后空格、不把不合格密码解释为无密码。确认只绑定本次选择，修改密码后撤销确认；切换显隐不撤销确认。

关闭密码开关立即清除密码草稿、错误、显隐状态及确认；再次打开不恢复它们。提交密码保护时不增加第二个密码框或第二个模态确认，以免重复要求用户确认同一后果。

### 3.3 已有空间

- 已有无密码空间：按既有流程直接合并，不显示创建页和风险确认。
- 已有加密空间：保持“输入同步密码”、显隐和“连接同步空间”，空密码禁止提交；错误留在当前页。没有关闭密码开关、不提供跳过或覆盖空间。
- 新增“忘记同步密码？”文本入口，进入同一面板内的帮助页。演示正确密码仍为 `mihon-demo`，应用外显式标注，不能当作生产默认密码。

### 3.4 忘记同步密码：提供准确帮助

页面标题：“忘记同步密码”。固定说明本版本没有密码找回/重置；GitHub 登录只恢复访问权限，不能解开已有加密数据。呈现用户当前可以尝试的事情：

1. 检查曾使用的密码管理器或保存记录，找回当时设置的同步密码。
2. 如果还有能正常同步的设备，保留其应用数据与连接，并备份本地内容。它可以继续使用，但当前版本没有从该设备重设密码的入口。
3. 如已无可解锁设备，检查独立备份；备份仅能恢复其中包含的数据，并不解锁原空间。
4. 如果密码和全部解锁材料均已丢失，应用无法解密远端旧数据。不要以断开、卸载或删除空间作为找回方法。

来自输入页时提供“返回输入密码”；来自设置页时提供“返回设置”。不显示“发送找回邮件”“通过 GitHub 重置”“导入恢复码”等尚未实现的按钮，也不以“帮助”之名删除或替换远端内容。

### 3.5 同步设置

保留现有连接检查、重新授权、设备名、同步频率、断开及更换空间。密码状态只读：

| 状态 | 展示 | 动作 |
| --- | --- | --- |
| 未设置 | “同步密码：未设置”；“内容不额外加密，由 GitHub 私有空间的访问权限保护。” | 不提供暗示可随时开启加密的开关 |
| 已设置 | “同步密码：已设置”；“新设备需要同步密码。本版本不提供找回或重置。” | “忘记同步密码？”进入帮助页，返回设置 |
| 状态未知/不支持 | 保留原有状态不可用或格式错误 | 不把异常标成未设置 |

## 4. 状态、返回、焦点和副作用契约

所有者：每端独立的面板会话与创建草稿。草稿至少区分 `passwordEnabled`、`password`、`passwordVisible`、`riskAcknowledged`；已提交的空间模式是另一份业务状态，不能用已经清空的输入框反推它。

| 操作 | 结果 |
| --- | --- |
| 首次进入可初始化新空间 | 默认无密码，草稿/确认为空，不自动聚焦隐藏输入 |
| 主动开启密码 | 展示输入、警告和确认；焦点保持在有效控件，不跳到另一设备 |
| 编辑密码 | 原样保存本端会话草稿，撤销风险确认；不因重绘丢失 IME、光标、选区 |
| 切换显隐 | 保留输入节点、选区和焦点；密码值、风险确认不变 |
| 关闭开关 | 清理全部密码草稿，回到无密码主按钮 |
| 进入帮助 | 清除输入密码；不触发解锁、初始化、断开或同步 |
| 帮助页返回或 Escape | 回原输入页/设置页；不同时关闭整个面板 |
| 创建页返回离开、关闭按钮、遮罩或关闭面板 | 清除未提交草稿；再进入默认关闭。关闭不撤销已提交的后台初始化/合并 |
| 主题、尺寸或另一端状态变化 | 保留本端草稿、确认、滚动及焦点；不能隐式开启或关闭密码 |
| 开始提交 | 冻结所选模式、保护材料与操作身份，禁止重复提交；清掉 UI 原始密码 |
| 初始化失败或响应结果未知 | 先用既有状态核对/重试，保持原提交模式；不能因为 UI 密码已清空而退为明文 |
| 必须重新输入密码的失败 | 明确回密码输入状态，重做本次确认；不能默默提交无密码 |
| 成功 | 自动进入已有合并流程，设置状态来源于已创建/读取的空间；后台完成不抢页面 |

面板仍沿用既有最大宽高、内部滚动和平台外壳。Tab/Shift+Tab 限定本端面板，背景不可交互；关闭后还焦到书架同步入口。帮助返回应还焦到有效的来源控件。新组件使用主题语义颜色，深浅主题均可读；320px Android 和 200% 字号下信息及全部操作可通过内部滚动到达。

## 5. 固定验收

下表为实现前冻结的 PROJECT_POLICY；HTML_ADAPTER 只验证原型真实事件及状态。生产测试须执行真实共享组件、controller 和 onboarding，不能用原型通过替代。

| ID | 用户操作 / 异常 | 必须结果 |
| --- | --- | --- |
| P1 | 两端进入新建页 | 默认关闭、无密码输入、正确说明；直接创建得到未设置密码状态 |
| P2 | 开启密码，空输入或未确认 → 提交 | 按钮禁用且事件处理防护有效，不创建不合并 |
| P3 | 输入有效密码 → 确认后果 → 提交 | 创建密码空间并自动合并；只提交一次，设置状态为已设置 |
| P4 | 编辑密码/切显隐/关开开关 | 编辑撤销确认；显隐保留值和选区；关开清空且不自动确认 |
| P5 | 未提交时关闭/返回后重进 | 密码、显隐、错误及确认清空，默认无密码；两端互不影响 |
| P6 | 主题变化或另一端重绘 | 输入值、节点焦点/选区、确认及本端导航不被清空或抢走 |
| P7 | 已有无密码 / 已有加密 | 前者直接合并；后者空/错密码不能绕过，正确密码才合并 |
| P8 | 解锁页 → 忘记密码 → 返回/Escape；设置 → 帮助 → 返回 | 返回原位置，一次只退一层；不泄漏旧密码，不改变连接 |
| P9 | 提交加密创建 → 失败 → 重试 | 保留保护模式，不覆盖已有空间、不退为明文；后台完成不抢页面 |
| P10 | 深浅主题、320px 手机、200% 字号 | 警告可读，内容不横溢，确认/提交/关闭/返回均可达；键盘圈定与还焦成立 |
| P11 | 单端切换/编辑/提交；另一端仍在编辑 | 未操作端草稿、确认、导航和焦点独立；真实点击 wiring 损坏会使测试失败 |
| P12 | 从审阅入口、普通入口和本地授权进入 | 都能走通对应流程；明确本地模拟，不请求真实服务，不产生凭据 |

## 7. HTML 适配与审阅说明

原型的密码开关、确认、帮助返回、关闭清理、模式捕获和设备隔离是真实浏览器交互；创建、错误、合并及解锁来自既有本地场景。原型不会保存用户真实密码，也不执行远端写入、真实派生或恢复。演示密码仅使用虚构内容；不要在原型输入个人密码。

专用审阅链接仅为应用外 HTML_ADAPTER：两端直接打开已完成模拟授权的新空间页，减少审阅前置点击；正常 `index.html` 继续保持原场景和完整本地授权演示。通过应用外场景选择器可切换“已有同步空间 · 未设密码”“已有同步空间 · 密码 mihon-demo”“同步空间创建失败”。

两端信息、默认选择与操作结果一致，差异仅来自现有外壳和视口。视觉来源为既有原型、[Desktop UI 规范](design/mihon-desktop-ui/README.md)及共享 `SyncPanelContent`，候选浏览器截图只用于审阅，不声明原生像素一致。

## 8. 恢复方式研究与后续边界

独立恢复码、恢复文件、可信联系人或托管密钥可以让用户在没有已解锁设备时恢复，但必须事先建立不依赖遗忘密码的第二条解密路径。普通备份则只能恢复备份覆盖的数据。

- [Proton 恢复说明](https://proton.me/support/set-account-recovery-methods)：区分账号密码重置与加密数据恢复，邮件/短信重置不能单独恢复旧加密数据。
- [Proton 恢复短语](https://proton.me/support/recovery-phrase)：预先启用并保存的恢复短语可以恢复数据。
- [Bitwarden 紧急访问](https://bitwarden.com/help/emergency-access/)：预先把用户数据密钥加密给可信联系人，再通过授权流程访问。
