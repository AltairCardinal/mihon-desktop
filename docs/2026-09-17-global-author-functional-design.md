# 跨插件唯一作者 · 功能与交互设计

日期：2026-09-17。范围：作者身份归集与跨插件作者页的产品设计，以及本地 HTML 交互原型。产品 Kotlin、数据库迁移、真实插件访问和同步协议尚未实施。

技术实现约束见[技术方案](2026-09-17-creator-identity-reconciliation-proposal.md)。本文件定义用户可见行为；[双端 HTML 原型](prototypes/author-identity/index.html)用于审阅这些行为。原型可演示不代表正式应用已经修复。

## 1. 产品目标与不可变规则

1. 一个已确认的人跨插件只有一个作者页、一个关注状态。图源内作者名称、编号和作品署名都可关联到此人，不能按插件各建一个正式作者。
2. 姓名相同只是候选依据；真实同名不同人保持独立。名字、作品相似或普通搜索命中均不能直接触发归集。
3. 用户确认有明确范围：确认一个稳定来源作者，可复用于该标识后续作品；仅确认文字署名，影响本次选定作品，不能扩展到所有未来同名作品。
4. 已确认作者直接进入作者页；新署名缺少证据时进入待确认，不再制造新的正式同名档案。
5. 归集的是作者档案及关系，不合并漫画条目、章节、阅读记录和下载文件。跨源作品版本按既有已确认作品关系展示；标题相同不等于同一作品。
6. 关联、归集、关注状态在当前作者库中生效。双端原型的数据分别保存在各自内存，不演示跨设备同步已经实现。

## 2. 信息架构与入口

| 入口 | Windows | Android | 反馈 |
|---|---|---|---|
| 作者列表 | 底栏「作者」 | 底栏「浏览」→「作者」页签 | 已关注/其他作者及待处理提示；不增加 Android 作者底栏 |
| 漫画作者署名 | 漫画详情作者按钮 | 同左 | 已确认直达作者；未确认打开关联面板；多个历史档案展示可区分摘要 |
| 关联其他来源 | 作者详情操作区 | 同左，窄屏可换行 | 显示来源、署名、代表作品和依据 |
| 整理作者 | 历史重复提示/作者管理入口 | 同左 | 选择要归集的档案，检查范围后确认 |
| 待确认署名 | 作者页待确认区域/作者列表提示 | 同左 | 多选具体作品，关联或保持独立 |

作者页内容依次为：名称与别名、关注按钮、来源数量/作品数量、关联其他来源/整理作者、作品列表与来源筛选、已关联来源、待确认事项。数据为空时保留关联入口，显示“还没有已确认的作品”。

列表中的真实同名作者必须用代表作品、来源及关注状态区分；不要求用户阅读内部 ID。历史待整理提示不把整个作者系统挡在强制弹窗之后，可以返回或稍后处理。

## 3. 作者页与作品展示

- 标题显示用户选定的主要名称，别名在副标题/别名区显示；“冈本伦”和“Okamoto Lynn”可以属于同一个作者。
- 作品卡显示作品名、来源和可用状态。已确认同一作品的多个来源以版本区分；来源筛选只改变列表，不改变人物身份、关注或归集结果。
- 从漫画柜或 MangaDex 的已关联作品点击署名，应回到同一个作者页，并显示同一个关注状态。
- 关注立即生效并反馈“已关注”；取消关注显示确认，说明取消的是此人在所有已关联来源上的作者关注，而不是删除作品或取消漫画收藏。取消对话框不改变状态。
- 来源被卸载/暂不可用时，该来源条目显示状态及受限操作；作者、其他来源作品和关注保留。不能把图源异常展示成“作者不存在”。
- 原有别名管理、拆分等生产能力保留。此次原型仅实现与本次身份归集直接相关的路径，不能以未演示为理由在生产实现中删除既有能力。

## 4. 漫画署名点击的状态规则

| 状态 | 页面行为 | 允许操作 |
|---|---|---|
| 已确认 | 直接进入唯一作者页 | 查看作品、关注、关联其他来源 |
| 多个历史同名档案 | 显示各档案的代表作品/来源/关注摘要 | 查看档案、整理作者、取消 |
| 有候选但未确认 | 标明“确认这位作者”，展示候选依据 | 关联已有作者、搜索、创建另一位作者、稍后处理 |
| 无候选 | 显示当前署名、来源和作品 | 搜索已有作者、创建作者、返回 |
| 正在核验 | 保留范围与原信息，显示进度 | 取消；禁止重复提交 |
| 核验失败 | 解释“暂时无法核对来源，现有关联未改变” | 重试、返回；不能当作没有作者 |
| 存在矛盾 | 展示冲突的档案/作品 | 返回重新选择、保持独立；禁止静默覆盖 |

当用户只是查看候选或返回时，不建立正式身份、不改变既有绑定。生产系统保存观察记录属于内部取证，不应呈现为已关联成功。

## 5. 历史同名档案归集

用户路径：漫画详情 → 点击作者 → 整理作者 → 选择档案 → 归集预览 → 确认 → 统一作者页。

选择页展示每个历史档案的代表作品、来源、关注状态，默认不把未核验范围偷偷纳入。对可以解释为同人的演示样本可预选，但所有预选必须可见、可取消；至少两份档案才能归集。零选择、只选一份时提交不可用并给出原因。

归集预览必须包含：

- 要整理的档案与受影响作品清单，不只显示“3 个同名作者”。
- 保留的作者档案及显示名；默认值可修改，不按本地内部编号让用户做选择。
- 归集后的作品数量及来源版本数量。合作作者保持独立，未核验作品提示需要先检查。
- 关注结果和有差异的检查/通知设置。不能无提示提高检查频率或扩大通知范围；生产提交只使用用户看过并确认的预览。
- “归集前保留恢复资料；归集不会修改阅读记录。归集后不能一键恢复原来的全部档案”说明。原型明确标注恢复资料为模拟，不能显示真实备份已生成。

确认时禁止重复点击。成功返回保留的作者页，显示“已整理 X 个作者档案，保留 Y 部作品”；旧作者入口和旧来源署名进入相同页面，不再显示相同的历史重复提示。失败保持原档案和全部选择，不显示部分成功。

预览期间内容发生变化时阻止提交，提示“作者资料已更新，请重新查看本次范围”；刷新预览后，仍有效的选择可保留，新增记录不能自动加入本次选择。取消预览回选择页；关闭整个面板回到原页面。

## 6. 关联其他插件的作者

用户路径：全局作者页 → 关联其他来源 → 查看候选 → 预览 → 确认关联。

候选卡展示来源名、该来源的署名、代表作品和为什么建议关联。展开依据只展示用户能理解的内容，例如“来源作者页将这些作品列在同一位作者下”“名称也写作岡本倫”。内部 UUID、置信分数、数据库字段不进入产品文案。

首个真实设计样本：漫画柜的冈本伦与 MangaDex 的 Okamoto Lynn。即使两站证据充分，也需要用户首次确认关联；确认后，来源的稳定作者标识继续复用到同一个人，无需逐部重复确认。

预览列出新增加的来源和作品、与现有已确认作品的版本关系，以及关注结果。明确提醒：“只关联已选来源作者；不会把所有同名作品加入。”确认后显示成功反馈，来源列表可直接进入其漫画，再从署名回到同一作者页。

“不是这位作者”先说明将保持独立，确认后该建议从此作者的待确认列表中移除，但不删除漫画。需要另建作者时，给出名称、代表作品和范围确认；不得把“不是这位”隐式等同于立刻创建一个人物。

## 7. 只有文字署名的来源

文字来源缺少稳定作者编号，提供“本次选择的作品”关联，不提供“此来源所有同名作品永远属于此人”的开关。

待确认列表支持多选、全选当前待处理集合、取消选择，并明确显示已选数量；零选择时确认按钮禁用。每项显示作品名、来源、署名及可用的依据。预览只列本次勾选项，提交后只移动这些项，剩余仍待确认。

列表已处理完时显示完成空状态。新加入的同名署名仍需核验，不因为上次勾选过同名作品自动归入；这一规则通过应用外“新增文字署名”或对应场景重新演示。

## 8. 关注与同步的首版边界

全局作者的关注跨其所有已关联插件统一，不按插件重复关注；来源筛选只是展示设置。示例中的设备彼此独立，Windows 关注不应自动改变 Android，以免误演示身份同步已实现。

当前同步 v1 尚不支持传播身份合并决定。因此首版在作者关注同步已开启时，新的归集/来源关联可预览但不提交；保留既有作者和关注的查看能力。入口提前显示：“当前作者关注同步尚不支持整理作者，可查看本次范围，暂时无法保存。”提供返回，不自动关闭同步，也不把“关闭同步”放成必须点击的主按钮。

该限制是当前版本的交付边界，不是跨插件身份模型本身的限制。以后在线同步协议完成后可以移除；原型只展示明确的受限状态，不修改同步设置或协议。

## 9. 交互细节与双端一致性

- Windows 与 Android 使用现有 Mihon 深浅主题、Material 图标及导航位置。Windows 对话框可适度加宽；Android 面板适配 320px，内容滚动，主要按钮可达，无横向溢出。
- 同样的数据与操作结果保持一致；差异仅在外壳、导航位置与排版。原型两端用相同初始样本，但后续操作互不影响。
- 弹窗有明确标题；打开时焦点进入弹窗，Tab/Shift+Tab 在内部循环，Escape 取消当前对话框会话，关闭后焦点回触发按钮。需要保留选择并回到上一步时使用「返回选择」。点击遮罩等价于取消，不执行写入。
- 输入、勾选和滚动属于当前页面会话；另一端操作、主题切换不能抢走焦点。返回预览前一页保留有效选择；关闭整个会话后，临时成功通知不在重开时回放。
- 结果文案描述用户可见变化；禁止只出现“执行成功”而不说明归集/关联了什么。失败显示原状态保留与下一步，不展示堆栈或技术错误码。
- 不可用的提交按钮同时显示原因，不能只通过颜色表示。按钮有明确可访问名称，勾选使用可访问复选框，键盘可完成主要路径。

## 10. 固定演示样本

| 样本 | 用途 |
|---|---|
| 三个历史“冈本伦”档案 | 分别关联《平行天堂》《极黑的布伦希尔德》《变异体少女》，演示旧数据如何归集；并非已取得真机数据库快照 |
| MangaDex 的 Okamoto Lynn | 演示跨插件关联；Parallel Paradise 的作品对应关系在场景中预置为已确认，因此展示为另一来源版本 |
| 文字图源（演示） | 无稳定作者 ID，演示有界批量确认，数据为虚构样本 |
| 冈本伦（同名演示人物） | 不同人反例，代表作品明确为虚构样本，不能混入真实冈本伦的作品归集 |

仅三个历史档案归集时为 3 部作品；加入对应 MangaDex 版本后仍为 3 部作品、4 个来源版本。原型其他附加样本以目录 README 的最终清单为准，不据样本推断实际图源当前全部作品数。

## 11. 演示控制与状态边界

应用外工具栏必须清楚标为演示工具，提供目标设备、场景、显示场景、重置及深浅主题。选定设备的场景只改变该设备；全局主题可同时改变外观，但不重建业务数据。复位与刷新不会触及用户真实应用。

需要覆盖的场景：历史重复、已统一作者、待关联 MangaDex、文字署名待确认、同名不同人、核验中/失败与重试、空状态、提交失败、预览过期、关注同步限制、来源不可用。场景切换不作为产品按钮嵌入作者页，避免用户误以为正式应用提供“制造失败”等操作。

原型使用浏览器页内内存，刷新恢复初始样本；没有 localStorage 持久化承诺、真实 HTTP 抓取、账号、真实备份文件、下载或安装。所有外部来源证据以本地面板展示，不触发网络请求。副作用和假数据边界在演示工具栏及 README 说明，产品页面不塞入实现术语。

## 12. 审阅顺序与完成标准

推荐先在 Windows 完成历史归集，再关联 MangaDex，从两个来源的漫画署名返回同一作者；然后在 Android 独立重复流程，确认 Windows 操作没有改变它。最后检查文字署名多选、不同人、失败/过期/同步限制与窄屏。

以下是设计验收项，不能用作生产功能已完成的标记：

- [ ] 《平行天堂》→ 作者 → 三个可区分档案 → 整理预览 → 取消：原档案与关注不变。
- [ ] 同路径确认归集 → 一位作者、完整作品集合、旧入口重定向；没有重复创建记录。
- [ ] 作者页 → 关联 MangaDex → 查看依据与确认范围 → 两个来源进入相同作者页并共享关注。
- [ ] 待确认文字署名 → 勾选部分作品 → 预览确认 → 仅选中项进入作者作品，未选项保留。
- [ ] 同名不同人 → 保持独立 → 不加入当前作者；另建作者需要明确确认。
- [ ] 提交失败/预览过期 → 未产生部分归集，可返回或刷新后继续。
- [ ] 关注同步受限/来源不可用 → 保留既有作者与数据，不能绕过受限提交。
- [ ] 深浅主题、320px、键盘与双端隔离 → 无溢出、无抢焦点、无页面错误、无远端请求。

实际原型操作与验证命令、测试结果见[原型 README](prototypes/author-identity/README.md)。生产实现仍需技术方案中的共享数据库、HTTP、DI、备份迁移、双端正式构建和真机验收，不能被 HTML 通过结果替代。

原型以固定人物样本实现上述主要确认闭环；任意人物搜索、自由创建作者、别名编辑、拆分纠正及真实证据冲突处置属于完整产品设计，未在此次样本原型中实现。候选空状态仅演示其他来源暂无候选，不代替整个作者库为空的生产验收。
