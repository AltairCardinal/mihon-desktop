## 3. 统一数学解释：充分支持集

固定事实版本v、setting与已观察知识K，令Ω(K)为一致完整输入集合，完整计划为Γ(X)。
稳定目标认证要求 `S_t(K)={π_t Γ(X): X∈Ω(K)}` 是单元素集合。
两个候选都只用已知条件证明某些信息不能改变完整target unit，再删除其取证需求，
因此得到的是充分支持集，不是已经求出的最小或必要支持集。

## 4. D 的生产实现：只枚举真实可达的入口

认证入口枚举位于 `ReaderPairingCertification.kt`。通用分支（first≠0且非isolated target）改为：

```kotlin
for (opening in if (first == 1) listOf(true) else listOf(true, false)) {
    add(ReaderPairingScanCursor(first, opening))
    if (first > 1 && pages[first - 1] !in settings.forcedSinglePages &&
        pages[first] !in settings.forcedSinglePages
    ) {
        add(ReaderPairingScanCursor(first, opening, first))
    }
}
```

证明（与第四轮一致，落到代码级）：

- 真实step0只能是单页0→index1/openingtrue，或pair0,1→index2/openingfalse；index0不新建reservation。
  故到达index1的真实正规状态只能是openingtrue且未预留，openingfalse的index1入口不可达，删除。
- 预留入口 `(first, opening, first)` 表示“前一页已输出单页并为first预留”。
  预留只能由index=first−1那一步创建，而那一步只有在`allowed(first−1)`为真时才输出单页并预留first。
  forced任一端点使`allowed()`硬禁止，first=1时index0不新建预留，故这些预留入口不可达，删除。
- 未被forced夹住的first>1仍保留预留入口；其余入口、first==0、isolated target、向左扩大与既有R1 guard原样保留。

生产级TDD（`ReaderPairingReachableEntryPruneTest`）：

- 红：实现前，20页/默认容量16/force p2/target p5 的见证为 NeedFacts(edge5,6)，强转 Certified 抛 ClassCastException。
- 绿：实现后为 Certified `[p4 RIGHT,p5 LEFT]`、certain=true、reason=null，与完整oracle逐槽相等，
  且 `isCurrent` 为真；见证本身断言 edge(3,4)=15、edge(4,5)=0、edge(5,6)=NotAnalyzed，
  并断言 `ChapterPairingRecord.isValidFor(20)` 为真（合法持久记录）。
- 反向守卫：无forced边界时同一状态仍请求 edge(5,6)，证明没有过度剪枝。

D 不改变任何既有契约：`:domain:jvmTest` 全部919项（含 `ReaderPairingCertificationResearchTest` 34项）在只有D时全绿。

## 5. C 的候选实现与本轮新发现的缺陷（未进生产）

C 按第四轮的设计实现为隔离候选（`run.py` 的 `candidate_c` 补丁，与研究轮完全一致）：
扫描层新增默认关闭的 `knownLaterNoMatch` 提示，认证层用 owner 的纯查询接入：

```kotlin
val hintedLater = if (knownLaterNoMatch?.invoke(pages[i + 1], pages[i + 2]) == true) {
    val observed = distance(pages[i + 1], pages[i + 2])
    if (observed == null) return false
    observed
} else {
    null
}
val nearDistance = distance(pages[i], pages[i + 1])
val laterDistance = hintedLater ?: distance(pages[i + 1], pages[i + 2])
```

提示命中时跳过 near 边读取，于是 near 边的两种事实都不再进入认证：

- near 边**缺失**（NotAnalyzed）→ 不再产生 NeedFact：这是收益（目标不再等待一个不能改变答案的事实）。
- near 边**可重试失败**（RetryableFailure）→ 不再产生 failure：这是缺陷。

实测证据（把研究C补丁接入生产后，既有契约测试 `ReaderPairingCertificationResearchTest` 有3项失败）：

| 既有契约测试 | 期望 | C候选下的实际 |
|---|---|---|
| new locations renew only resource failures and retain original scalar authority | RetryableBlocked(RESOURCE)，失败页在 `failures` 中 | Certified（失败被隐藏） |
| evicted sample recovery failure blocks a missing edge while retaining confirmed side | 目标因缺失边停在 NeedFacts | 目标直接认证（不再等待） |
| sixteen observed control pages cannot certify an unseen prefix reset | 待取事实含 EDGE_SAMPLES(113,114) | 该near边需求消失，仍因 ORIGINAL_ANALYSIS(113) 停在 NeedFacts |

第1、2项是真实的契约破坏：一条可重试的读取失败被静默忽略，认证在既有产品语义要求“阻断”的地方给出了证书。
第3项只是取证需求变小，认证仍然拒绝签发，核心性质（未见前缀不得被认证）未被破坏。

**为什么研究轮没看到**：338状态矩阵里C族的失败用例把失败注入 later 边（page3），
later 边是 RetryableFailure 时提示根本不会命中，所以矩阵里 near 边的失败从未被触发。
缺陷只在“near 边自身失败、later 边已算出且无匹配”的组合下出现，而这不在固定域内。

**修复方案（本轮未落地，规格已确定）**：提示必须同时保证被跳过的 near 边没有可重试失败。
扫描层的提示回调需要同时拿到 near 与 later 两对页（例如改为四参数回调），
认证层实现为：later 边为 Computed(score==null) **且** near 边不是 RetryableFailure 时才允许跳过。
这样失败记账完全保留，near 边“只是缺失”时的收益不受影响；
由于固定域不含 near 边失败，修复不改变本报告的任何测量数字。

**C 的代价（已测量）**：单独立时 owner 边查询 644→878（+234，+36%），提示查询322次、命中88次（27.3%）；
与D合并时提示查询降为202次、命中16次（7.9%），净查询644→590（-54）。
即：在D之后，C 的边际收益只有16项新增认证与16项需求减少，却要付出186次额外owner查询。
本报告不把C计入交付收益。

已交付的D，逐案读集变化：48项-6键、24项-3键、266项不变。

- D不仅减少需求条目，还直接减少owner边查询（-240，-37.3%）：被删入口本来要读取真实存在的边。
