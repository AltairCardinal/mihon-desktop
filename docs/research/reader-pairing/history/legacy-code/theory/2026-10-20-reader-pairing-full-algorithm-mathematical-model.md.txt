# 双页匹配完整问题：用户要求、信息边界与算法改进的数学模型

日期：2026-10-20。用途：交给新会话独立分析整个双页匹配算法，不局限于CP1的“认证轮次≤9”。

**这是问题定义与研究交接，不是算法最优性证明、产品验收或实施授权。当前要求不变；下面的候选算法与规则变化均尚未批准。**

## 1. 先回答“有没有可能有更好的数学解答”

有研究空间，但须区分四种“更好”：

1. 输出不变，证明和计算更省：例如更精确的局部证书、可组合状态摘要、增量维护。
2. 输出不变，需要读的图片更少或取得必要信息更早：例如自适应事实查询、正常解码复用、正确失效的派生索引。
3. 取得同样信息后，工作调度和呈现更及时：减少重复工作，不等待无关慢任务。
4. 改变配对策略，改善识别质量或信息局部性：须证明满足用户要求，并明确输出变化；不能自行用新规则替换现行产品语义。

数学分析应找可证明的改进与下界，不能预先断言某个缓存、动态规划或全局最优匹配一定解决全部问题。计算再快也不能替代尚未取得的决定性信息。

## 2. 用户要求：作为建模的最高优先级

来源：[父设计第1节](2026-10-12-reader-pairing-determinism-design.md)。该节记录的是用户澄清后的要求，不能恢复更早已撤回的过严或过松解释。

### U1：不同读序与重开得到同一配对

同一章节原始内容、设置和有效手动配对意图下，顺读、倒读、直接跳页、快速往返、退出重开，应得到相同的配对成员及物理槽位。

这不只是“最后事实收齐时收敛相同”：冷进入与热进入的第一次真实呈现也须一致。不得由先看到谁、先解码谁、哪个holder先画、缓存先命中谁，决定最终成员。

### U2：正常体验没有可感知的新增等待

以实际打开、翻页体验和同条件耗时对照验收；允许在正常读取、解码和预取期间完成必要分析，但全部成本必须计入。

**用户没有要求“目标图片一解码好就绝不能等待任何必要分析”。** 那是历史过严解释，已被澄清。也不能反过来把“无可感知”偷换成只报平均值，或把分析移到Ready前便不计时。

“可感知”没有在本文被任意换算成一个通用毫秒常数；应区分用户体验目标、现有阶段门禁和新方案需要验证的性能分布。

### U3：后台识别不能移动已露出的图片

保护范围包括当前页、手势中短暂露出的邻屏，以及一对中先画出的单侧。后台事实迟到后，不能换伙伴、换左右槽位、移动已露出图片；等到idle再移动也不符合要求。

不能用永久冻结第一次猜测来满足稳定，因为这会破坏U1；也不能将“只画过一侧”写回为永久单页、丢弃伙伴。

### U4：既有能力不能作为代价被删除或降级

- 普通双页阅读及自动跨页识别继续可用；不能用关闭自动识别、固定奇偶配对、普遍增加永久单页来绕开问题。
- 一张真实宽图应完整呈现，不能困在半槽、拆掉或跳过。
- 保留已有开篇选择、有效手动调整及其保存／失败恢复语义。
- 保留逐页Loading／Ready／Error、重试、缩放和既有方向处理。
- 不吞页、不重复呈现造成错误导航、不把未实际读到的伙伴标成已读。
- 不要求用户新增预处理步骤或反复手动修正，才算自动功能成功。

### U5：平台、内容与生命周期一致性

Android与Desktop使用同一配对语义。平台解码API可以不同，但不能在各自adapter中另造规则。

内容替换、重试、章节清单变化、旋转／阅读方向或手动意图变化，要正确失效相关派生事实与显示权限；保持其他无关页面正常使用。用户显式改设置属于新输入，不应与“相同输入下后台事实到达造成搬图”混为一谈。

## 3. 三类条件必须分开

| 类别 | 本文如何对待 |
|---|---|
| 用户要求U1～U5 | 不作为自动放宽项，不让新会话先要求用户在一致性、延迟和稳定性间取舍 |
| 现行产品规则 | 路线A必须保持；路线B可以提出替代，但要列变化、理由和反例，等待用户／主审裁定 |
| 现有实现机制与参数 | 可以研究更好的算法；任何实际改动仍遵守当前计划、TDD、资源与验收约束 |

当前的canonical扫描、局部入口枚举、LRU、4路准入、4页投机窗口和轮次计数，不是用户要求本身。**区分它们不等于本文批准改变它们。**

## 4. 基本数学对象

### 4.1 章节输入与版本

设章节源页序列 `P=(p0,…,p(n−1))`，各页有稳定源页身份；不允许因分组变化重新编号。

输入版本 `v` 包含或引用：源页列表版本、每页编码内容身份、分析算法版本、EXIF／用户旋转、阅读方向、自动开关、开篇模式，以及有效手动意图。临时手动调整须遵循既有明确会话语义；尚未加载的手动记录不能被默认为“没有手动意图”。

完整输入 `X_v` 还包含由这些原图确定的全部相关特征。目标页和导航轨迹不属于全局配对规则的业务输入，但可以影响取证顺序。

### 4.2 不要混淆三种“跨页／双页”

1. 一个编码文件本身是宽图：通常占完整显示区域。
2. 两个相邻纵图文件实际构成连续跨页画面：自动证据应帮助它们成为伙伴。
3. 两个普通纵页没有跨页连续性，但依照阅读布局规则作为一屏的普通双页。

“边缘不匹配”不等于“这两页永远不能组成普通双页”。只优化连续边缘匹配，不能代替完整阅读分区。

### 4.3 输出：路径上的单点／相邻对分区，加物理槽位

可用二元变量 `x_i` 表示是否把 `p_i,p_(i+1)` 配成一对，其中 `0≤i<n−1`；令两端虚拟变量 `x_(-1)=x_(n−1)=0`。

基本合法性：

```text
x_i ∈ {0,1}
x_(i−1) + x_i ≤ 1                 每页不能属于两对
y_i = 1 − x_(i−1) − x_i           y_i=1表示该页为单页单元
```

再按源顺序得到完整分区 `Γ(X_v)=(U0,…,Um)`：每页恰出现一次；单元只含一页或两个相邻页；不跨章、不倒置源顺序。

真实宽图和有效强制单页禁止相邻配对边；有效手动对要求对应边。互相冲突或失效的手动记录要先按现有规则处理，不能假设所有用户记录天然构成可行约束，也不能偷偷丢弃它们来使数学模型有解。

输出还包括 `slot(U,p) ∈ {LEFT, RIGHT, FULL}` 及所需的开篇／边界上下文。相同成员不同槽位仍可能违反U1/U3；单页不总是居中，真实宽图与普通孤页不能混为一类。

### 4.4 识别质量与确定性是不同目标

令潜在作者版式为 `G`。通常系统没有完整真值标签，页侧留白、颜色和边缘连续性都是启发式。

- 确定性要求：同一 `X_v` 的规则输出唯一，与访问历史无关。
- 识别质量要求：输出尽量符合 `G`，保留用户手动修正能力。

不能以“算法唯一”证明“识别正确”，也不能在没有标注／评价依据时宣布某个权重函数更接近作者版式。

## 5. 现行规则摘要：用于路线A的等价性参照

当前唯一完整计划由 `SharedDualPageRules.canonicalPlan` 使用 `ReaderCanonicalPairingScan` 生成，认证器也复用同一扫描步骤。

- 几何、章节边界、有效手动／开篇意图，以及槽位兼容的页侧证据共同限制相邻边。
- 相互重叠的可行候选比较手动优先级、页侧强度和相邻边缘距离；现行策略是局部顺序扫描与确定的同分裁决，**不能直接当成全局总分最大匹配**。
- 放弃当前可采用的边、选择下一对时存在原子预留；开篇状态与预留会影响后续单元和槽位。一个局部禁止边是否真正重置全部左侧影响，需要证明，不能看见宽图或LEFT／RIGHT就自行截断。
- 没有可靠特殊证据时，仍按确定边界与既有普通配对规则推进。未知和读取失败不是永久单页边界。
- 当前页侧分析从方向归一、未裁剪和未加滤镜的图像取固定样本，输出LEFT／RIGHT／已分析UNKNOWN；边缘分析有独立固定采样及白／黑／低方差排除规则。数值和算法入口见第13节。

这些是当前策略，不是用户已经认可所有启发式为全局最优。路线A以其完整事实输出为oracle；路线B必须另提明确的、可审阅的新语义，不能混用两种oracle求绿。

## 6. 部分信息、可能世界与正确的提前显示

### 6.1 状态类型

时刻 `s` 的可用知识为 `K_s`，至少区分：

- 尚未读取／分析；
- 已分析但页侧UNKNOWN；
- 边缘已计算但无匹配，和边缘尚未计算；
- 暂时失败／资源暂停／取消，可恢复；
- 带有效内容身份的结果；
- 标量仍在但恢复边缘所需原始样本已淘汰。

知识的可靠性与缓存驻留是两个维度。样本淘汰不一定删除既有标量结论；Computed也不意味着所需的一切边缘都已存在。内容或设置更新会使旧结果失效，不能跨版本假设知识单调增长。

### 6.2 安全提前显示的定义

`Ω(K_s)` 表示所有与已观察信息一致、符合原图／采样规则且物理上可实现的完整输入。不能把互相不可能共存的页侧和边缘值任意组合，借此制造下界或假歧义。

令 `π_t Γ(X)` 为目标页所属单元、成员顺序及物理槽位。对当前输入版本，理想的稳定证书条件是：

```text
{ π_t Γ(X) : X ∈ Ω(K_s) } 是单元素集合
```

即所有仍可能的完整输入都给出同一目标呈现。准备露出的邻屏也要满足相应条件；只证明当前anchor而放任邻屏猜测，仍会违反U3。

这个条件只要求目标投影确定，不要求所有可能世界的全章分区都相同。候选算法应尽量只证明必要局部结论，而不是默认先分析全章。

工程证书可以使用安全的近似，但必须证明可靠：所有被认证结果都满足上述不变性。近似过于保守可能造成不必要取证，正是可以优化的方向之一。

### 6.3 已知的信息边界，不能误读为全面不可行

考虑源页 `[O,A,B,C,D]`，冷跳B；已观察信息中B相同、A尚未取得。

- 世界X：A为普通纵页，现行输出可为 `[O] [A,B] [C,D]`，RTL下B在左。
- 世界Y：A为真实宽图，现行输出可为 `[O] [A] [B,C] [D]`，RTL下B在右。

在不能区分X/Y时，立即给B一个确定槽位、以后永不改，又要求与相应热缓存输出一致，不能普遍同时成立。即使宽高已知，未知竞争边也可能构造类似问题；具体反例须用实际规则验证。

这不是要求用户放弃U1～U3，也不是证明所有改进不存在。用户允许正常加载期间取得必要信息，研究重点是：最少需要什么信息、能否廉价前置、哪些证书比现实现更精确、实际剩余等待能否低于可感知程度。

须区分：健康本地路径可能已有header；旧下载无索引、在线冷跳、断网、预取未赶上不能一律当成同一初始信息。没有实证不能假设A永远缺尺寸，也不能假设所有关键像素早已可用。

## 7. 取证与调度：带成本的自适应查询问题

把动作 `a` 视为取得信息／可绘制资源的操作，例如读取header、取边缘样本、复用正常解码、构造方向性edge、验证缓存身份。每个动作有输入前置、产生的事实、时长、IO字节、CPU、解码内存和可取消性。

同一实际读取可以被多个消费者共享，一次解码可同时产生几何／页侧／边缘样本；不能将它们计成互相独立的等成本查询，也不能漏记为了验证缓存而新增的完整读取。

查询策略 `A(K_s, currentTarget, workload)` 可以目标优先、自适应，但最终 `Γ` 不得依赖策略和访问顺序。研究目标是以低成本使目标证书成立并提供正确显示资源。

至少分开以下变量：

| 对象 | 作用 |
|---|---|
| 真实缺失工作 | 能改变或阻止目标证明的必要工作 |
| 投机工作 | 预测后续缺口，当前尚非真实依赖；可以提升 |
| 已挂载／普通显示消费者 | 有独立显示与资源所有权，不能随旧投机一并取消 |
| 上层准入与待消费completion | 均占有界名额，完成通知不等于所有资源已释放 |
| 编码读取／native decode／GPU与UI | 不同资源瓶颈，不能只用一个“并发4”代替全部模型 |

必须保留：真实需要优先；一项有效事实完成后及时接纳和补位；不等无关慢投机；已运行不可抢占任务真实退出前继续计占用；新位置不能被无人需要的旧排队工作挤占。

当前研究参数含4路必需准入、4页lookahead、15秒位置期限、32MiB对象计量和可选16页等；它们不是普遍数学常数，且实际字节计量仍有工程缺口。本文不授权改变参数或宣称计量已完整。

任意快翻、任意网络停顿、任意任务时长下的统一低延迟保证不能被默认为成立。若一个证明需要有限完成时间、特定设备负载或输入分布，必须写出前提和失效场景，不能悄悄排除用户的冷跳与快翻。

## 8. 呈现、导航与进度：输出不是只有一组配对边

把运行时看作三个单向层：内容事实 → 逻辑计划／证书 → 有限期呈现权限与原生绘制。绘制历史不能反向修改逻辑分区。

### P1：曝光稳定

一次有效曝光要关联输入版本、源页身份、单元／槽位及帧权限。相同输入下，后台事实到达不能改变已曝光页面的伙伴或槽位。缩放状态、手势中的邻屏和图片lease也不能被列表换key隐式销毁。

保留一个旧ticket但直接重排pager列表，不构成稳定性证明；旧帧与新计划混用还可能重复出现伙伴或跳页。先猜后永久锁定、先猜后idle纠正、裁掉未画伙伴，均不能作为完整方案。

### P2：源页导航

跳页以用户指定源页定位，不用易变的组下标。前进／后退以当前有效单元边界生成源页意图；不同版本计划与active frame的边界不能混用。

释放邻屏只能释放资源／权限，不能从章节分区删除未画伙伴。宽图伙伴若尚未锁定却被新事实识别，应完整、可达地呈现，不得困在半屏或被略过；这属于必须覆盖的生命周期案例，不是允许已曝光结果任意变化。

### P3：进度真实性

设 `Drawn(ticket)` 为真实画过的页，`Progress(event)` 为一次有效用户停稳事件可提交的页集合，必须满足：

`Progress(event) ⊆ Drawn(event.ticket)`

且ticket内容／位置仍有效，事件符合已有进度策略。预取完成、被编入同一对、邻屏瞬间露出、手势取消都不能直接创造已读事件；也不能把“画过”等同“用户已读”。

### P4：显式改变输入与恢复

有效手动修改、方向变化、内容重试／替换形成新上下文，需原子切换或沿既有反馈恢复。不能以“U3要求稳定”为由拒绝用户明确修改，也不能借“新版本”标签掩盖相同内容下后台识别造成的自动搬图。

## 9. 优化目标：多目标且有硬约束

先满足U1～U5和可靠证书，再评价以下成本向量，而非用任意加权总分抵消正确性：

```text
(首次正确像素延迟、完整目标单元延迟、连续翻页尾延迟、
 额外读取次数/字节、解码次数、认证CPU工作、总CPU工作、
 峰值内存、后台干扰、失效与取消后的剩余工作)
```

从用户打开／跳页／翻页意图开始计时，记录编码读取、解码、事实可用、证书成立、正确首像素和完整画面的事件。工作会重叠，宜用资源约束事件图的关键路径分析，不能简单相加并重复计算重叠时间。

用同图、同设置、同产物条件的基线对照；分别报告冷／热、旧下载无索引、索引损坏、在线慢邻页、快翻、重开。统计有效样本分母、失败、p50／p95／最大值；全程成本不能藏在Ready之前或后台预处理之中。

若预处理成本为 `C_pre`，共服务M次请求，总成本至少按 `C_pre + Σ C_request` 记账，并另报首次无索引体验。平均摊销改善不能掩盖第一次冷跳仍不可用。

当前P9的15%／100ms收益和16ms逐页退化护栏是阶段性对照要求，不是本文证明的普遍感知阈值。≤9调度循环也不是算法质量的唯一成本量；详见[轮次问题模型](2026-10-20-reader-cp1-round-bound-mathematical-problem.md)。

## 10. 两条研究路线与可比较的算法家族

### 路线A：保持现行完整事实输出

约束：对所有合法完整输入X，`Γ_new(X)=Γ_current(X)`，包括成员、槽位、手动／开篇语义。允许改变证明、查询、缓存和调度方式，但不能用不同配对结果降低取证成本。

优先研究：

1. **更精确的可能状态／局部证书。** 当前认证器枚举有限入口，向左扩展至结果一致。哪些入口实际可达，哪些只是安全过近似？怎样携带准确开篇、前邻宽图、预留和手动边界摘要，减少假歧义而保持可靠？
2. **扫描状态的可组合摘要。** 将区间看作对入口状态的转移／关系，研究组合是否满足结合律，能否用于增量树或分段缓存。必须先证明状态充分、状态数边界、前瞻边依赖和手动重叠处理；不能只凭“有限状态”直接宣布O(log n)。
3. **动态维护与输出下界。** 更新一个早期边界可能使很长后缀的普通配对相位改变。若必须显式输出K个变化单元，就要计入至少相应输出成本；目标查询或惰性表示可能更便宜，但pager最终消费成本仍要计入。
4. **依赖验证与增量计算。** 完整输入未变时复用认证；输入改变时只重算必要部分。验证本身的时间、内存、负向事实和内容失效都要记账，不能只报告认证调用下降。
5. **自适应取证。** 对尚有不同目标输出的可能世界，优先取得能消歧且成本低的事实。信息增益／成本是待评价策略，未经分布和证明不能声称贪心最优。

### 路线B：提出新的唯一配对规则，待裁定

可以研究路径上的受约束匹配、带有限状态的动态规划等。示意目标可为对合法分区最大化一组有明确优先级的质量指标，并使用稳定同分裁决。

例如在确实具有局部可加代价、无额外全局约束时，可讨论“最后一页单独／最后两页成对”的DP；若包含开篇、槽位和预留等状态，应先扩展状态再证明。**这不是当前局部扫描的已证明等价改写。**

每个提案必须给出：

- 与现行规则输出不同的最小具体例子；为什么新结果对阅读更好、需要何种评价依据。
- 手动、宽图、页侧、边缘冲突和同分时的完整优先级；不能用普通总分覆盖明确手动意图。
- 未知信息下的证书、首次展示及最坏依赖范围。全局最优不天然具有局部可认证性，也不天然低延迟。
- U1～U5及原故障场景的保持理由；需要用户确认的语义变化单列。

路线B允许提出替代自动策略，不允许自动关闭能力、普遍固定奇偶、增加永久单页、要求用户逐章修正，或引入未经授权的OCR／机器学习／特定文件名规则作为默认答案。

## 11. 新会话应优先证明的命题

1. **表示与状态充分性：** 当前策略需要哪些最小状态？是否存在精确、可组合、内容身份可失效的摘要？几何／手动禁止边在何种条件下是真正的重置边界？
2. **证书可靠性与精确度：** 目标成员及槽位不变性的充分／必要条件是什么？当前入口过近似具体多读了什么？证明不能只比较最终全章输出。
3. **取证下界：** 构造两个物理可实现、已观测信息相同而目标输出不同的输入；说明至少要读取哪些额外信息。不能把所有未知变量当互相独立后给出虚假下界。
4. **工作量上界：** 分开首次建索引、单目标查询、单事实更新、显式输出K个变化单元、冷重开／热重开和失效恢复；给最坏与摊销界及前提。
5. **在线策略与前台保证：** 声明任务时长、可用信息、共享资源和负载假设，证明什么时候可以不等慢投机；不能承诺抢占不可抢占native工作。
6. **跨平台数值一致性：** 相同原图如何获得等价样本？阈值附近、alpha、旋转、色彩和tile有何影响？数值采样不同引起的结果变化不能归咎于“数学上确定”。
7. **语义改进的评价：** 如果不保持现行oracle，新的质量目标是什么，证据是什么，哪些约束仍是硬要求？

若得出“不可能同时满足”，须准确列出冲突所需的额外假设；不能把严格零等待的不可能性偷换成用户按真实体验验收的要求整体不可行。

| 内容替换、重试、旋转／方向改变、同路径同大小等元数据变化 | 缓存错误命中、旧证书／旧帧越权 |
| 真实目标已足够但无关投机挂起；投机转真实另测 | 整批屏障、以类别混淆掩盖等待 |
| 缓存淘汰、无索引旧下载、索引损坏、在线限速／失败 | 只证明热缓存、失败永久当否定事实 |

原事故证据有页码／日志边界，见父设计第2节；不要把所有转圈或用户记忆中的编号一概宣称已定因。

验证应分层：数学证明／反例 → 真实共享规则契约 → 真实平台呈现、导航与进度 → 同型性能对照及用户体验。前三层的通过不能自动替代最后一层。
