## 3. 统一数学解释：充分支持集

固定事实版本v、setting与已观察知识K，令Ω(K)为一致完整输入集合，完整计划为Γ(X)。
稳定目标认证要求 `S_t(K)={π_t Γ(X): X∈Ω(K)}` 是单元素集合。
本轮用已知条件证明某些信息不能改变完整target unit，再删除其取证需求。
得到的是充分支持集，不是已经求出的最小或必要支持集。
临时计划Γ_now(K)依UNKNOWN/null默认值产生，不能替代全completion稳定证书或授权slot曝光。

## 4. C：已有无匹配证据决定比较顺序

[真实laterWins](../domain/src/commonMain/kotlin/mihon/domain/reader/ReaderCanonicalPairingScan.kt#L88)先比较强度，仅等强自动情形读取near和later距离。
其最终条件为 `later != null && (near == null || later < near)`。
若已知later是Computed(null)，结果恒false，near未知、负数或NaN都不影响此布尔值。
这不依赖真实score非负；与R3 near=0的数值下界命题不同。
它也不省略强度判断所需的几何、side或manual事实。

隔离scan添加默认关闭的可选`knownLaterNoMatch` hint；只有隔离certifier的owner-backed实例接入。
owner.edgeAnalysis纯查询返回Computed且score==null才提示true；NotAnalyzed和RetryableFailure均不命中。
hint本身不登记Unknown或failure读集键，避免提示探测制造额外取证。
命中后仍通过原distance getter重读later：

```kotlin
val hintedLater = if (knownLaterNoMatch?.invoke(laterA, laterB) == true) {
    val observed = distance(laterA, laterB)
    if (observed == null) return false
    observed
} else null
val nearDistance = distance(nearA, nearB)
val laterDistance = hintedLater ?: distance(laterA, laterB)
return laterDistance != null && (nearDistance == null || laterDistance < nearDistance)
```

真正getter负责记录edge证据、缺失需求或失败；hint不是证据。
若hint过时而getter给有限值，就按该值继续原比较；getter缺失/失败的null伴随Need/RetryableBlocked，不能提前认证。
公开canonicalPlan未打开hint，任意callback的原行为保留，near=0/later=-1仍选择later。
5项直接合同覆盖真/假hint、getter给有限值/负值/null/NaN组合与默认公开负值接口。
它们不模拟线程交错；owner没有新锁或原子快照保证，调用侧串行及既有版本检查仍是前提。
额外hint带来一次owner查询，即使不命中也有CPU成本；不能说所有输入更快或所有读集都更小。

C主见证：19页、默认capacity16、RTL/AUTO/automatic=true、target=p1，索引均从0开始。
portrait 256×384，纵向7像素条纹灰度70/180；SHIFTED加5，INVERTED反转条纹，均经真实sampling和评分。
p1=SHIFTED，p2=TEXTURE，p3=INVERTED，其余GRAY；所有side分析Computed UNKNOWN。
接受序列 `p2,p3,p0,p4,…,p18,p1`，先保留edge(2,3)=Computed(null)，再逐出raw p2/p3；edge(1,2)从未计算。
baseline NeedFacts(edge1,2)，C Certified `[p1 RIGHT,p2 LEFT]`、certain=true、reason=null，与完整oracle相同。
读集12→11，决定性edge(2,3)仍保留；明确断言dependentPageIds含非目标端点p3。
每个依赖页逐一改变contentVersion均使isCurrent=false，因此包括p3；setting.manualRevision改变也拒旧。

## 5. D：压缩结构不可达入口

[认证入口枚举](../domain/src/commonMain/kotlin/mihon/domain/reader/ReaderPairingCertification.kt#L355)保守覆盖可能的opening/reservation与skip-left。
D不改变scan、距离比较或目标函数，只收紧入口集合：

- generic、非isolatedSpread分支的first==1：保留正规`(1,true,-1)`，原skip-left`(2,false,-1)`仍按既有forced guard决定保留。
- first>1且forced包含first前页或当前页：保留正规opening=true/false，删除reservedStart=first两个入口。
- 其余入口、first==0、isolated target、向左扩大与R1既有guard原样保留。

证明：真实step0只能singleton0→index1/openingtrue，或pair0,1→index2/openingfalse；index0不能新建reservation。
故到达index1的真实正规状态只能是openingtrue且未预留；skip-left代表另一种真实可能，不能直接删除。
一般first>1时，新reservation=first只能由前一步index=first−1的canPair=true且未输出pair创建。
forced任一端点使该canPair硬禁止，因此相应reserved入口不可达；真实未预留openingfalse仍可能到达，必须保留。
在现有scan及缺失事实/依赖机制可靠前提下，真实入口R仍包含于剪枝后枚举E′；沿单调step归纳不遗漏目标轨迹。
first单页后自然产生的后继入口仍在，D不删除这些真实路径。
这只支持入口局部可靠性，不背书整个certifier、readset、并发或UI生命周期。
本矩阵的first==1均有FORCE0/WIDE0边界，未直接实验无边界first==1子情形；其skip-left保留依据源码核对与可达性推导，不列为直接实验覆盖。

D关键见证：20页、默认capacity16、force p2、target=p5→first=3、RTL/FIRST_PAIR/automatic=true。
ChapterPairingRecord真实isValidFor(20)=true；p3=TEXTURE，p4/p5=SHIFTED，其余GRAY，全portrait。
接受序列 `p3,p4,p5,p0,p1,p2,p7,…,p19,p6`。
edge(3,4)=15、edge(4,5)=0保留，p5 raw已逐出，edge(5,6)=NotAnalyzed。
真实requiredSamples只返回p5，p6样本已在；所有相关scalar分析仍Computed。
完整真实step0输出pair0,1并置opening=false，forced p2单页后到first3仍opening=false，夹具直接断言这条轨迹。
实际step3因15>0选择later并原子预留4，随后输出pair4,5；幽灵reserved3入口才会走到缺edge5,6的路径。
baseline需edge5,6；D Certified `[p4 RIGHT,p5 LEFT]`、certain=true、reason=null，读集16→10。
C也独立解决该见证：其幽灵路径可使用已有更后later=null；这解释两项收益重叠，不代表组合运行。

## 7. 推荐、代价与可推翻条件

优先考虑D作为生产focused TDD候选：不增加owner查询，证明依赖真实可达状态，仍须覆盖回退入口和合法record接线。
C是按已有证据选择比较顺序，可作为独立后续候选；必须保留默认关闭接口和权威getter重读，测量hint命中率及额外查询成本。
本轮保持原输出并缩小需求，没有更换配对质量目标或测量用户收益。
尚未验证真实调度、IO字节、解码次数、CPU分布、Session/Memo、平台wiring及曝光/进度链路。
充分支持集可以指导通用求值器，但不是已经求得最优取证策略。
同一未知事实在不同分支的相关性必须保留，否则会产生假歧义；精确表达可能增加分支、CPU与读集维护成本。
稳定完整plan缓存已有多目标O(1)查询，不能强迫baseline反复扫描制造收益。
因此不据此宣称整体替换扫描更优，本轮没有实现新的符号求解器。

下列任一反例会推翻或缩窄推荐：

- D删除的入口在真实完整scan轨迹中可达，或改变target完整reason/slot/certainty。
- C仅凭hint认证、权威getter缺失/失败仍Certified，或later有限/负数控制被null提示覆盖。
- 决定性edge端点内容改变后仍isCurrent，或默认公开callback负值行为变化。
- 实际owner并发调用破坏串行前提，或额外hint成本抵消少取证收益。

下一步应先选择一个候选进入真实production红绿TDD与集成接线，而不是直接以本研究patch交付用户。
