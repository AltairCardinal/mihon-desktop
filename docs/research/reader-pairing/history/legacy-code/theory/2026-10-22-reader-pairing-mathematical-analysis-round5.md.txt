## 3. E：重试独立证书，不合并失败路径依赖

[研究wrapper](../scripts/reader-pairing-math/PairingConfluenceExperiment.kt#L89)先以lookbehind2调用真实certifyCapturing。
只有baseline返回NeedFacts，才在相同串行owner、identity、headers与settings下新建readset并用lookbehind3独立重试。
每次真实certify调用都会新建scan、manualCache、路径memo及事实收集器。
lookbehind3仅将初始左边界多移一页；重试内部仍保留既有unit不一致时继续向左扩展的逻辑。因此预算是最多额外一次认证调用，不是固定只额外扫描一页或一个窗口。
仅重试得到Certified才采用其trace和读集；否则返回baseline原对象、原trace和原readset。
RetryableBlocked及已经Certified不重试，不新增对外需求/失败或改写continuation字段。

```text
baseline = certify(newReadSet(), initialLookbehind=2)
if baseline is not NeedFacts: return baseline
retry = certify(newReadSet(), initialLookbehind=3)
if retry is Certified: return retry
return baseline
```

设E_l为窗口左端l的保守入口集合，R_l为真实轨迹可能入口。
此前有限入口认证可靠的前提是R_l⊆E_l，且每个被采用unit的事实/依赖读取正确。
左移一页后使用既有扫描和认证机制重新求证，而不是只从旧候选里删除有Need的分支。
新入口扫描可以在到达旧左端前合流，排除旧左端上无法由它产生的reservation或skip-left状态。
若新尝试得到完整unit唯一的证书，它在既有认证机制前提下可单独使用，无需继承已弃尝试的pending需求。
没有证明更宽窗口总会减少歧义或总能认证；N对照恰好展示重试仍不足。
回退返回同一对象的断言覆盖需求、失败、continuation、scanSteps及读集的精确保留。
采用retry时断言读集中没有非Computed edge，防止baseline pending edge泄漏；两者必要几何/side依赖可以不同。

## 8. 成本、被否证初稿与下一步

222次baseline合计1606个真实scan step，42次retry额外298步，合计1904步。
成功见证A为3+3步、B为8+8步；N/AUTO失败重试为8+10步，再回原结果。
这些是算法路径计数，不含owner供数、完整oracle构造、readset分配、manual处理每步复杂度或平台调度成本。
本轮没有CPU/IO/解码/用户延迟测量，不能用20个Need减少推导总提速；稳定全计划缓存仍有O(1)多目标查询优势。
候选E可先作为受条件约束的production focused TDD对象，不能无门槛给每次Need增加成本。
还需真实部分事实分布、重试成功率/额外查询成本、版本稳定性、Memo与曝光/进度接线证据。

本轮两个早期初稿仅经源码/语义核对即否证，没有为它们运行矩阵：
纯auto target5把targetPair距离设0的初稿，扩大入口仍存在到目标pair未预留的路径，需要missing竞争边；也可能与R3零下界收益重叠。
改为manualStart4的初稿同样不成立：allowed3会因相邻manual4直接false，reserved3也不能绕过canPair，原baseline已排除所谓ghost pair3,4。
最终采用章首同步和更早manual1，同目标正距离6及R4-CD基线明确分离。

能推翻或缩窄推荐的证据包括：更宽入口遗漏真实轨迹；新证书仍带已弃pending依赖；fallback改变原失败/需求；同K歧义被错误认证；manual或内容改变后仍isCurrent；实际重试成本抵消少取证收益。
支持驱动求值器是后续方向，必须保留同一未知量跨分支的相关性；不能把本轮独立重试称为已经求得最小支持集或全局最优取证。
