# 一次性自主研究委托

请把本包作为一个有硬合同、历史负结果和匿名原生成本锚点的算法研究任务。
你可以自主决定研究顺序、算法、工具、证明路线和实验投入；无需向委托人逐题确认。
我们需要足够广、足够深、可复现且能指导采用的成果，并接受有证据的否定结论。

## 研究对象与本轮重点

有序对象系统在部分事实、有限原始见证、异步工作、版本变更和发布授权下回答单元查询。
之前已发现并修正“多次尝试只记录选中尝试的缓存依赖”缺陷，也已保留低分配的等价算子。
完整信息增量树在部分负载上快，但缺少盈利的部分信息消费者；更强认证可以少取事实，
却还没有完整采用成本证据。缓存、预取、公平与防抖都有明显反转区域。

不要只优化旧 Python 的复制开销、重复发现已知缺陷，或只展示认证器内部快多少。
优先找出：如何在真实约束下让更强证明省掉物理工作；如何把维护成本从请求关键路径移走；
如何形成精确而便宜的部分信息摘要；如何在变化、共享、失败和取消下仍能可靠发布。

## 数量与深度

- 覆盖 `QUESTIONS.md` 的 **120 个主课题**、`COMBINATIONS.md` 的 **30 个组合**，
  每题至少两条实质不同路线；共用实现可以，但必须逐题说明不同结论和证据。
- 每题达到 D2：可检查的推导/反例，或能执行的原型、测试及相关成本；一段概览不算完成。
- 目标至少 **24 个不同机制达到 D3**，来自至少 8 个研究族：强基线、必要消融、
  三个串行独立测量进程、完整成本、敏感性和最坏退化。
- 目标至少 **12 个机制达到 D4**，来自至少 6 族：在耦合链路中检验采用、发布、
  取消、失效及回收，覆盖未参与调参的负载，并给可审计的采用边界。
- 深入至少 6 类范式，并自行提出不少于 **12 个不重复的新假设**，不要把参数微调计为新方向。
- 深度不足、反例推翻、参数缺失和资源触顶均据实保留。若可靠候选不足以达到数量目标，
  给出逐项淘汰证据和剩余缺口，禁止制造候选或把未运行项目填写为完成。

D2/D3/D4 的具体成果标准见 `EXPERIMENT_CONTRACT.md`。
建议按 **24–48 小时有效研究预算**规划工作；这是容量建议，没有最低运行时长要求。
禁止 sleep、无意义循环、重复同一个证据、制造巨量文字来凑时长。达到全部证据门槛可以提前交付。
平台或额度先耗尽时，一次性提交真实进度、可恢复状态和准确继续命令，不能声称已做完。

## 自主范围

可以在 `research_out/` 实现标准库原型、精确小域 oracle、求解器编码、符号模型、统计实验和
受控编译对照。可借助已可用工具，但不要为运行依赖静默使用凭据、外部付费服务或上传本包。
先检查执行环境；默认最多 2 个 CPU 密集 worker、内存预算 2 GiB，计时实验全部串行。
更大实验先用小规模找复杂度与价值，再在环境既有容量内有界扩大；记录实际资源上限。

不要请求业务源码、具体业务名称、账号、用户数据或自然负载频率。缺少的参数用符号、区间和
公开标为 synthetic 的场景；说明怎样测量才能决定采用。没有实测服务时间时，任何等待收益
都只能是条件结论。不能把虚拟时间换算为真实毫秒，也不能把当前线程分配当作总内存。

## 三条路线分开

- **L0**：保持全部公开观察；包括单元、槽、顺序、原因、确定性、需求与失败顺序、
  起点、步数、依赖、预算/生命周期等被声明为可观察的合同。内部缓存支撑可以更完整。
- **L1**：更早认证或改变取证/调度；保持同一完整世界的规范单元和失败合同，
  单独报告改变的需求/时序，给可靠证书与完整物理账本。
- **L2**：改变规则、接口或一致性约定；单列迁移、质量、公平、稳定性与裁定缺口，
  不冒充 L0/L1 的等价优化，不未经真值证明就宣称“更好”。

## 交付方式

只需一次最终交付：整合报告、150 题覆盖表、新假设、候选与 oracle、证明/最小反例、
测试、有效和无效原始数据、独立进程元数据、强基线对照、采用矩阵和干净环境复现入口。
按 `DELIVERY_TEMPLATE.md` 组织，并给一段供下一实现者直接执行的匿名交接指令。
若推导揭示本包不一致，保留最小反例，明确哪一层有问题；不要修改冻结规则来掩盖矛盾。
研究顺序由你选择，完成程度由证据决定。
