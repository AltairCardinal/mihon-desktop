# 给下一实现者的交接指令（最终版）

只实现下面列出的少量候选，**不要默认启用其余机制**。每项写明所需接口、必须验证的合同和完整收益指标。
历史版本：`NEXT_IMPLEMENTER_R9.md`（R9）、`results/raw/final/NEXT_IMPLEMENTER_fixround_before_final.md`（修复轮）。
当前矩阵：`research_out/ADOPTION_MATRIX.csv`（priority 列）。所有数字来自虚拟服务模型与本机 Python 层，不是原生预测。

## P0 必需接口（后面所有候选的前提）

1. **会话级 close（异步三段）**
   - 接口：`Session.close()` 或等价协议；每个候选提供释放钩子。
   - 合同：请求、逻辑关闭、物理排空分别记时。逻辑关闭时拒绝新意图与新工作、取消全部任务、撤销发布与证书、拒绝请求；
     被取消的运行中任务**一直占槽并计账，直到真实退出**；退出时的完成被丢弃、不接纳；只有最后一个任务真实退出后才关闭 owner、清空存储、
     调用释放钩子；重复关闭只应答（closing / closed）；不得直接清空任务表或占槽计数。
   - 验收：`research_out/tests/test_final_boundaries.py::CloseDrain`（反例：q=1、service=4，prefetch@0、close@1、probe@2、退出@4 → 排空完成于 t=4）。
   - 注意：包内 `Owner.close()` 之后未取消任务的 `finish()` 会抛 TypeError，所以 owner 必须在排空完成后才关闭。
2. **确认绑定发布句柄（bound_confirm）**
   - 接口：`confirm(target, handle)`；`handle` 是 `publish` 成功时的句柄，随回调令牌下发；重签产生新句柄并重新下发。
   - 合同：无句柄 → `unbound`；旧句柄、rebind 或关闭之后的句柄 → `stale_callback`；过期后重发同一单元，旧回调的确认数必须为 0。
     两阶段迁移：先双写并统计无句柄调用，降到 0 再拒绝；不提供"只有一个实例时自动绑定"的兼容捷径。
   - 指标：误确认数（开发 expiry 流 128→0）、迁移期被拒的旧式调用数；墙钟约持平（0.98–1.0）。
3. **强证明预算合同 BC-2**
   - 接口：`certify(..., mode='S', budget)` 的计费与停止语义；共享结构必须可回滚。
   - 合同：同一计量单位；建树、更新、查询、表填充全部计入本次调用；越限立即停止且不发证，走 L0；停止调用回滚共享结构
     （多次小预算不能累积成证明）；证书复用不计费。
   - 验收：`research_out/tests/test_budget_contract.py`（10 项）。

## P1 推荐采用

4. **增量撤销 inc_revoke（与 bound 确认组合）**——等价优化
   - 接口：owner 每次原子写入报告它可能改变的读键；守卫/epoch 变化时全量回退。
   - 合同：每个事件后的全部公开观察（published、confirmed、publish/confirm 返回值）与全量重验相同，覆盖设置变化、rebind、关闭和过期交错。
     本研究只做了有界随机搜索（约 21 万个事件 0 差异）与证明草图，建议原生实现补一份形式化论证。
   - 完整收益指标：发布读校验数（84 778→2 411）、墙钟（完整配置 0.157）、反向索引条目（211–669，关闭后为 0）、物理工作不变。
   - 反转：每次写入都是守卫变化时，退化为全量重验加索引维护。
   - 缺少的原生量：写入组合中守卫变化与项目写入的比例、每个支撑键上的当前发布数。
5. **D04 差值区间 memo（INTERVAL，替换比较签名）**——等价优化（owner 内部）
   - 合同：公开结果逐字段等于新建的 corrected owner；边界写错的变异体必须被拒（`tests/test_fixQ1.py`）。
   - 指标：引擎运行次数（链式抖动 392→245 等）、墙钟（owner 层约持平）；随机抖动无收益；驻留与 owner 相同。
   - 缺少的原生量：秩值抖动中相邻序不变的比例。

## P2 条件候选（默认关闭）

6. **gated_shadow：修正版运行器 + bound 确认 + 树路线**
   - 接口：bound 确认；证明尝试身份；已首发目标的再意图处理与物理镜像；异步 close；BC-2。
   - 合同：物理调度与 incumbent 逐事件相同（引理 S1）；每个目标的延迟不超过 incumbent；过期发布可重新取得；关闭后 L0 证书镜像为 0；
     **q_u > 0 且只有一条串行证明 lane**（到期时间才是唯一的尝试身份；q_u ≤ 0 在构造时拒绝）。
   - 启用条件：存在空闲计算 lane，且一次证明时间 q 小于 L0 仍需的串行服务时间（容量受限时约 k·service）；不要用"q < 单次 service"做门限。
   - 完整收益指标：虚拟延迟（冻结留出 −0.5%～−2.7%，开发网格 −8.5%）；物理获取不变（0 节省）；增加强证明计算（16 936 次评估/98 格）、
     lane 占用 170u、墙钟 +6.7%（完整配置 1.067）。没有原生提速证据。
   - 反转：证明与请求处理共用 lane（延迟 +75%）；gate 通过率或胜出率为 0。
   - 缺少的原生量：q 与 service 的分布、lane 空闲率、自然 gate 通过率与胜出率、L0 剩余串行服务步数。
   - 未验证的变体：fresh exact 路线（开发网格便宜，留出未验证），不要作为默认。
