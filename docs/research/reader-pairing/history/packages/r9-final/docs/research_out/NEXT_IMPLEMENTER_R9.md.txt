# 给下一实现者的匿名交接指令

目标：在不改变冻结分组规则与公开观察合同的前提下，采纳已证明安全的改动，并只在可观测门控与已测参数下启用条件机制。

## 立即可做（L0，无语义变化）
1. **raw 见证先派生后驱逐**（对照 NATIVE_OWNER.pseudo）：接纳一个见证时，先用所有当前驻留的相邻见证派生两方向秩，再驱逐到容量。
   验收：raw 容量 1 时相邻两个见证依次接纳必须派生出一个秩（`research_out/tests/test_wpT.py::test_P2...` 反映包内模型的反例）。
   注意：若原生 raw 上限计入这一瞬时位，比较对象是 evict-first 用 r+1。
2. **确认绑定到发布句柄**：确认回调必须携带它所针对的发布/证书句柄；句柄不是当前发布时只释放资源、不确认。
   验收：发布→支撑变化→重发→旧回调，确认数为 0（WP-H `bound_confirm`）。
3. **发布撤销增量化**：维护"支撑键 → 当前发布句柄"的反向索引，写入时只重验受影响的发布；守卫/epoch 变化时全量回退。
   验收：与全量重验逐事件相同（WP-H `inc_revoke`）。

## 条件启用（L1）
4. **强证明只以 shadow 方式接入**：L0 判决为 need_facts 且 gate 通过时（只有 RANK 需求、目标前 [0,t+3] 的分析全部已接纳），
   在**独立计算 lane** 运行强证明（关系树，β 域，nonneg 秩域）；成功则发布但**不取消、不改变任何物理任务**；发布过期时由 L0 结果刷新。
   必测参数：一次强证明的真实计算时间 q 与一次见证服务时间 s 的分位；判据 q < s；监控 gate 通过率与胜出率，零胜出时关闭。
   拒绝默认的原因：与请求处理共用计算 lane 时延迟可 +75%（gated_proof_first）。
5. **value 复用 + incarnation 授权**：只有生产者书面保证"同身份+同版本 ⇒ 同内容"时，跨知识丢失型 rebind 复用派生值；
   证书、发布、确认、location 永不跨 incarnation 迁移。
6. **压缩策略支撑**（投影支撑）只能用于 memo 校验，绝不能作为证书/发布支撑；发布支撑必须是证书实际读值。

## 不做
- 取消式竞速、阻塞式 proof-first、在线自适应 gate、portfolio 升级、分层/反向剪枝精确搜索、L2 规则替换（详见 REPORT §1、§6）。

## 交接校验
`research_out/candidates/wpT_checker.py`：任何强证书可用独立精确 DP（n≤7 再加世界枚举）复核，并扰动支撑范围 [0,t+3] 之外的事实验证不变。
