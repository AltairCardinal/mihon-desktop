# 研究报告：有序对象局部分组的部分信息认证

本报告是一次完整的自主研究结果。所有新增代码在 `research/` 下，原参考文件（`reference.py`、`protocol.py`、`test_*.py`、`fixtures/`）未修改，原 17 项测试仍全部通过。

**证据等级记号**（全文统一使用）：
- 〔证〕已证明：给出带前提的证明；
- 〔域〕有限域已验证：在写明范围、种子的有限实例上穷举或对照；
- 〔条〕有条件成立：依赖写明的未给定参数或宿主前提；
- 〔待〕尚待验证：本包无法实验；
- 〔否〕已被反例否定。

所有实验实例都是**抽象扩展域**（直接指定标签和标量）。表中的比例是构造域频率，不代表真实负载。golden 中只有 G002/G005/G006 来自原生成映射。全文不把步数换算成毫秒。

## 0. 核心结论

### 0.1 当前算法的主要瓶颈

1. **"触及即阻塞"，而不是窗口太小。** 参考认证器会把入口路径上读到的每个未知事实都当作阻塞（这是代码结构上的事实〔证〕）。它在多大比例上造成损失，本包只能在构造域中给出，掩码概率是人为设定的，不代表真实负载。在合法、非负秩构造域的 2400 个实例中〔域〕E1：
   - 参考返回 `need_facts` 864 例，其中 186 例（21.5%）在可能世界意义下目标结果已经唯一；
   - 分支认证可以认证其中 180 例；
   - 不扩窗的 C-SL 认证 1513 例，扩窗后为 1521 例：扩窗只多 8 例（占 C-SL 可认证数的 0.5%，占 oracle 唯一数 1528 的 0.5%）；
   - H-G 扩窗重试只多认证 3 例。

2. **有效性校验按全局身份比较。** 任何无关对象的内容变化都会使所有证书失效。同一版本内，读集中某个未知项变为已知，同样会触发失效。每张证书的快照和校验量随 n 线性增长：n=256 时平均为 270 个比较单位，作用域化后为 17.7。〔证〕+〔域〕E3。

3. **有一部分等待不可约，而且在 H11 下无法靠规则替换消除。**
   - 在 E1 构造域中，参考 `need_facts` 的 78.5% 确实还没有被可能世界确定〔域〕。这是构造域比例，不是真实负载比例。
   - 抽象扩展域中：目标与段首距离为 d 的均匀窄对象段里，任何可靠认证器的证书都必须包含 ⌈d/2⌉ 个对象的状态，其中最远的一个距目标 d−1〔证〕〔域 d≤40〕。这类长均匀段在生成域中是否出现、频率如何，尚未验证（PROBLEM §3.3，见 §6 第 7 项）。
   - 替代规则：设规则 (A2) 在均匀段内只依赖段内相对位置与两端上下文类型，不用绝对奇偶；(A3) 每段至多 c 个单对象。则存在依赖距离 Ω(L/c) 处事实的目标〔证〕。当 c=o(L)，即不普遍隔离时，这排除了有界窗口规则；若允许每段 Θ(L) 个单对象，这一界不给出结论（§3.3）。

4. **最大的单项风险不是性能，而是 header 的权威性。**
   - 参考在分析未计算时用 header 几何签发证书。
   - 如果宿主中 header 几何可能被后到的分析推翻（分支 β），在 E9 构造域中 994 张参考证书里有 479 张在同一版本内不稳定，构成 H2 风险。
   - 可以以 β 模式运行 C-SL 以保持可靠，代价是可认证数从 1052 降到 541。
   - 这一分支必须先在宿主上判定（§6 第 1 项）。〔证〕反例 +〔域〕E9。

## 1. 建立的理解

### 1.1 形式化

**扫描器状态**：σ = (i, o, r)。其中 i 是游标位置，o ∈ {T,F} 表示是否尚未发出过配对（opening），r ∈ {T,F} 表示 i 是否被原子预留。`step(σ)` 是事实的确定函数，产出（单元或⊥，σ′）：
- 配对时 σ′ = (i+2, F, ·)；
- 单对象时 σ′ = (i+1, o, i>0 ∧ allowed(i))。

**一步读取窗口**（引理 L1）：step(i) 读取
- 对象 i−1…i+3 的状态/方向；
- 左向的指定连接链（合法域中链长为 1）；
- 边 (i,i+1)、(i+1,i+2)；
- 全局 n 和 settings。

**目标结果**：F_t(X) = complete_plan(X) 中含 t 的单元，包括成员、顺序、槽、原因和 certain。

**知识**：
- K 中每个对象分析处于 未知/已计算/失败/陈旧（几何或变换不匹配）；
- header 有效或无；
- 每条边处于 未知/已计算（含已知空值）/失败。
- 边证据只在两端分析有效时可见；端点有 WIDE 时边为已知空值。

**可能世界模型**（分支 α，默认）：
- 有效分析精确；
- 否则有效且变换匹配的 header 固定占用状态，方向自由；
- 否则状态 ∈ {NARROW, WIDE}，方向 ∈ {A, B, UNKNOWN}；
- 两端都为 NARROW 的未知边取值 ∈ {空} ∪ ℝ（非负接口下为 ℝ≥0）。

**稳定认证**：|{F_t(X) : X ∈ Ω(K)}| = 1。

### 1.2 允许的操作与信息边界

- 认证器只能读 K，不能读世界。
- 取证动作把一个事实从世界揭示到 K：分析揭示状态和方向；秩需要两端分析在轮初已有效。
- 失败是 K 的状态，不是世界值。
- 同一版本内 K 只会精化（或在驱逐时丢失）；跨版本不单调。

### 1.3 代码与文字的矛盾、张力及分支假设

| 编号 | 观察 | 处理 |
|---|---|---|
| T1 | 文字说"有效已计算分析优先于 header"。`certify` 在分析未计算时用 header 几何认证，并且可以签发证书。若 header 几何不权威（分支 β），之后到达的分析可能推翻已签发证书，而且发生在同一内容版本内，构成 H2 风险。最小反例：5 个窄对象，automatic=False，对象 2 分析未知、header 为 NARROW，认证 {1,2}；分析到达后为 WIDE，结果变为 {2}（`test_branch_beta_header_contradiction_is_detected`）。 | 分两支。α：header 几何权威，参考可靠〔域〕E1 零不可靠。β：参考在 E9 构造域中有 **479/994** 张证书不稳定；C-SL 以 `header_authoritative=False` 运行仍然可靠，可认证 541 例（α 下为 1052）。 |
| T2 | H5 要求"无关对象可继续使用"，但读集中的 `identity` 是整个对象列表。 | 参考偏保守但不违反安全性；D3 修正这一点。 |
| T3 | `resolved()` 读取分析时不记录需求，用于短路。因此已认证结果的读集里可能有未知项，字节相等校验在知识精化时会误失效。 | D3 的精化容忍。 |
| T4 | 陈旧分析（变换不匹配）的方向和边状态仍被 `side()`/`edge()` 使用。只因为同一对象的 `dimension()` 总是先读并记录需求才无害，这是依赖读取顺序的隐式耦合。 | 新原型把陈旧分析整体视为未知。宿主修改读取顺序时须重查〔待〕。 |
| T5 | `isolated` 分支扩窗到 first<target 时只用两个入口，入口集不完整。 | 不可达：孤立目标在两种 opening 下原因优先级相同（ONLY/WIDE/FIRST/ISOLATE 均先于 OPENING），候选总是一致，扩窗分支是死代码。新原型对 first<target 改用通用入口集。 |
| T6 | 可能世界定义只关心值，失败在值域上等同未知；H4 却要求不得吞掉失败。 | 路线 A 采用"基线优先"组合（§3.1.5）。只对值唯一但被失败阻塞的情况另列合同变更路线 B′。 |

### 1.4 关键引理（后文所有证明共用）

**L1 局部性〔证〕**
- step(i) 只读 §1.1 列出的窗口，左向指定连接链在合法域中长度为 1。
- 因此 F_t 只依赖对象 ≤ t+3、边 ≤ (t+1,t+2) 及其左侧事实。
- 证明：逐函数检查 `_Scan`：`allowed(i+1)` 读 i+2 的状态，`manual(i+2)` 的有效性读 i+3；`later_wins(i)` 只读边 i、i+1；原因计算读 i−1…i+1。
- 〔域〕`test_locality_horizon_lemma` 在 120 个接口域实例上比较截断与全枚举，结果相同。

**L2 入口完备性〔证〕**
- first=0 时可达状态只有 (0,T,F)。
- first=1 时只有 (1,T,F)，以及 (2,F,F)（后者仅当 0、1 都不是硬隔离）。
- first≥2 时为 (first, o, F)、(first, o, T)（需 first−1 与 first 都不是硬隔离）、(first+1, F, F)。
- 证明：到达 first 的最后一步，要么是位置 first−1 的单对象（o 不变；预留需要 i>0 且 allowed），要么是 (first−2, first−1) 的配对（o=F），要么是 (first−1, first) 的配对（落在 first+1）。
- 预留只能在本位置产生，配对后携带的旧预留值都小于新游标。参考的结构入口与此一致。

**L3 比较不相交（新发现）〔证〕〔域〕**
- 在任一扫描路径上，被实际执行到秩比较阶段的 `later_wins(i)` 使用边对 (e_i, e_{i+1})，且不同比较使用的边对两两不相交；比较从不发生在 i=0。
- 证明：
  - 秩比较只在 can_pair(i) 为真、i 未被预留、且两强度相等且非负时发生。
  - 若后者胜且 i>0，则 i+1 被预留，在 i+1 不再比较。
  - 若后者不胜，则发出配对 (i,i+1)，下一次比较最早在 i+2。
  - 单对象原因 RANK_BOUNDARY 重算的是同一比较。
  - i=0 时有两种可配对方式：(a) AUTO 开局，需要 side(1)=trailing，这使 allowed(1) 为假；(b) manual(0) 为真（指定连接 0 或 opening=PAIR），此时 allowed(1) 因 manual(0) 为假。两种情况下 strength(1)=−1，都不发生比较。
- 〔域〕`test_lemma_r_on_complete_worlds`：1500 个完整世界（含接口域重叠连接），其中 >100 条路径发生比较，无一违例。
- **推论**：
  1. 秩值之间不存在跨步相关，每次比较只有三种结果：后者胜、不胜，或空值情形落入二者之一。
  2. 逐步局部枚举在秩维度上**没有精度损失**；C-SL 相对精确 oracle 的损失只来自对象事实（状态/方向）的跨步相关。
  3. H-C（非负下界支配）和 H-E（已知空值）都是这一局部三值比较规则的特例，无需单独机制。

**L4 秩代表网格〔证〕**
- 设已知值排序为 v1<…<vm，未知边数为 k。网格 G 在每个开区间（含两端外侧）放 k 个点并包含全部 vi。
- 则任一实值补全都存在一个保持全部大小关系与相等关系、且已知值不动的保序映射，把它映到 G^k；因此目标结果集合不变。
- 非负接口下，下方区间改为 [0, v1)，放 k+1 个点（含 0）。
- 由 L3，逐步局部枚举只需"本步两条边"的公共网格（k=2）。
- 测试：
  - `test_rank_grid_covers_dense_sampling`：80 个实例 × 300 个随机实数补全，无一产生网格集合之外的结果。
  - 原先设计的"每区间 1 点"变异检验**没有**被抓到，追查后正是 L3 的推论（1 点已足够），于是改用"去掉空值选项"作为变异，可以被抓到（`test_grid_without_null_is_caught`）。

- "更细的秩表示"由 L3 证明不必要；
- H-C 和 H-E 被 C4 吸收，不单列；
- 区间摘要树（H-B）未重复研究，部分事实下的安全摘要由 C12 的前向状态集给出一种形式。

## 3. 深入方案

### 3.1 D1：C-SL 分支认证（附 C-PW 精确对照）

#### 3.1.1 针对的冗余，与已有研究的区别

参考在窗口内对**全部结构入口**执行确定扫描，把未知值暂时当作"非 WIDE / UNKNOWN / 空"，只要读到任一未知或失败就整体放弃。冗余有两类：

- **(a) 证明无关的未知**：某未知事实的所有取值都导致同一目标结果，却阻塞了认证；
- **(b) 不可达入口路径上的未知**：入口集是保守超集，不可达入口读到的未知也会阻塞。

与历史机制的区别：

| 历史机制 | 区别 |
|---|---|
| H-E/H-C | 只处理单一比较的两种特例；C1 对每一步的每个读取事实统一做局部全取值分支，由 L3 证明这对秩维度已经精确 |
| H-G | 是一次独立重试、读集独立。C1 在**同一次**认证中逐格扩窗，按状态记忆，每格新增 O(1) 次展开，且对参考与 H-G 有严格支配（§3.1.3） |
| H-D | 方向同步的局部特判，C1 不需要特判 |

E1 的分解说明 (a) 是主因：不扩窗的 C-SL 已能认证 1513/1528 个唯一实例，扩窗只再增加 8 个。

#### 3.1.2 前提与原型

前提：分支 α，或以 `header_authoritative=False` 运行以适配 β；扫描函数确定（参考 `_Scan` 原样复用，不重写规则）。

```text
C-SL(K, t):
  first ← (t 已知 WIDE 或硬隔离) ? t : max(0, t−2)
  memo ← {}                                   # 键：σ，值：展开结果，与窗口无关
  loop:
    E ← L2 的结构入口(first)
    剔除需要 allowed(first−1)[∧ later_wins(first−1)] 而在任何局部取值下都不成立的入口
    U ← ∅；按位置小根堆处理状态 σ：
       若 σ.i > t：U ∪= {⊥}；continue
       对 expand(σ) 中每个 (u, σ′)：         # expand：对本步读到的未知做 DFS，取值域
           若 t ∈ u：U ∪= {u}                 #   对象：{N,W}×{A,B,U}；秩：{空}∪本步两边公共网格
           否则 push σ′                        # 状态按 (i,o,r) 合并
       若 |U| > 1：break                      # 本窗口无法认证
    若 U = {u} 且 u ≠ ⊥：return certified(u, support, extra_failures)
    若 first = 0：return need_facts(分支过的未知)
    first ← first − 1
```

可执行原型：`research/branching.py::certify_sl`。C-PW（`certify_pw`）对每个入口做路径敏感的惰性 DFS（同一路径上的事实只赋值一次），first=0 时恰为可能世界 oracle。

#### 3.1.3 正确性论证

**定理 1（C-SL 可靠性）〔证〕**

前提：α（或 β 模式）、L1、L2、L4。

结论：C-SL 签发 u ⇒ ∀X∈Ω(K)：F_t(X)=u。

证明：
1. 任取 X∈Ω(K)。X 的真实扫描到达 first 或 first+1 时的状态 σ_X 属于 L2 入口集，且满足它的前置条件，所以没有被剔除。
2. 对 σ_X 之后的每一步，X 在该步所读事实上的取值，要么与 K 的已知值一致，要么落在 DFS 的取值域里。秩取值经 L4 的保序映射落入本步公共网格，比较结果不变。
3. 因此 X 的转移 (u, σ′) 出现在 expand(σ) 中。
4. 按状态合并只并集、不丢元素。由此归纳，X 的目标单元 ∈ U。
5. 记忆正确：expand(σ) 只依赖 K 与 σ，与窗口无关。

**定理 2（对参考与 H-G 的支配）〔证〕〔域〕**

结论：参考 `certify(K,t,L)` 以任何 L 签发 u ⇒ C-SL 签发 u。

证明要点：
1. 参考在窗口 f 签发，意味着该窗口全部入口路径上读到的事实都已知。
2. 无需求即意味着：维度有效（分析有效或 header 有效）；方向来自已计算分析，且同一对象的 `dimension()` 必先读，所以分析有效；秩可见且两端有效。
3. `resolved()` 读到的未知只出现在短路已决定结果的位置（`resolved(i+1)==leading` 时 `resolved(i)` 的取值不影响结果）。
4. 因此在 C-SL 中这些路径不发生分支，转移相同。C-SL 的入口集 ⊆ 参考入口集。
5. 参考的边界规则（`not allowed(first−1)`）对应 C-SL 的前置条件剔除。
6. C-SL 从 t−2 向左扩窗必然经过 f，所以在 f 或更早签发；由定理 1，签发的必为同一 u。
7. H-G 是 L=3 的参考，因此同样被支配。
8. 补充：L∈{0,1} 时参考可能在 f>t−2 的窗口签发，而 C-SL 不访问这些窗口。此时参考签发需要 allowed(f−1) 已知为假（否则入口含 (f+1,F) 与预留态，会读到 t 或越过 t），C-SL 从 t−2 出发的路径在 f 处汇入同一组入口，所以结论不变。
   - 独立评审对 L∈{0,1,2,3,5} 共约 74k 张参考证书做了模糊检查，支配违例为 0。

〔域〕E1：4800 例中 `dominance_violations` 全部为 0。

**定理 3（C-PW 在 first=0 时精确）〔证〕**
- 入口唯一；DFS 的每个叶子对应"在已读事实上取定值"的世界柱集。
- 扫描结果只依赖已读事实，所以柱集内 F_t 恒定；全部柱集覆盖 Ω(K)（取值域完整，见 L4）。
- 〔域〕E1 中 C-PW 恰好认证全部 1528/1522 个 oracle 唯一实例。

**认证与失效机制**：证书携带 `support`，即认证窗口内读到的事实键。其中值未知、经分支处理的读项不是证明依赖，因为证书对它们的任意取值都成立。有效性校验由 D3 负责（§3.2）。

#### 3.1.4 成本

- **状态数**：每个窗口最多 4·(t−first+2) 个状态。记忆使所有窗口合计最多 4·(t+2) 次展开。
- **单次展开**：叶子数 ≤ Π(本步读取的未知事实的取值数)。对象 ≤6，秩 ≤ 1+|G_local|，其中 |G_local| ≤ 2+3·2 = 8。一步最多读 5 个对象和 2 条边，所以在合法域（指定连接链长 1）中，理论最坏是与 n 无关的常数 B ≤ 6⁵·9²；接口域中重叠指定连接链可以任意长，manual() 向左读的对象数不受此界约束。实际取决于窗口内未知数。
- **最坏总量**：O(t·B) 时间，O(t·B) 临时记忆，输出 O(|support|) ≤ O(t)。
- **建表**：无预处理。
- **验证**：O(|support|)（D3）。
- **实测**（E1 合法域，单位为执行的 step 次数，包含 DFS 重算）：

| 指标 | 参考 | H-G | 包装 C-SL |
|---|---|---|---|
| 全部实例平均（p90 / 最大） | 1.89（4/12） | 2.41（6/18） | 6.02（14/197） |
| need_facts 实例平均 | — | 2.99 | 13.0 |
| 其中被采纳的平均 | — | — | 7.0 |
| 其中未采纳的平均 | — | — | 14.6 |

  未采纳的实例绝大多数是真正未定的实例，这部分工作是在证明"尚不能认证"。C-PW 最大 8443 步，因此不部署。

#### 3.1.5 失败合同（H4）

`certify_contract`：
- 参考 `blocked` 或 `certified` 时**原样返回**；
- 只有参考为 `need_facts`（参考路径没有读到失败）时才运行 C-SL；
- 只采纳 C-SL 签发的证书。

C-SL 在探索中**新读到**的失败写入 `extra_failures`，不改变 status。这是显式策略：额外试探发现的失败要上报，但不改变"参考路径失败才阻塞"的原合同。E1 中这类情况 0 例（合法域）/2 例（接口域）。

H-E 的最小反例（近边失败、后边已知空值）由 `test_wrapper_never_swallows_reference_failures` 守住；变异"包装不先跑参考"会把 blocked 改成 certified，`test_wrapper_without_baseline_is_caught` 能抓到。

#### 3.1.6 适用负载、退化与反例

- **适用**：窗口内有少量与结果无关的未知，例如远端方向、被短路的比较、被已知 WIDE 截断的边。
- **退化**：
  - 未知很多且确实相关时，C-SL 会一直扩窗到 first=0 才判定 need，工作 O(t·B)；
  - 可用 `extension='budget'` 截断：不扩窗时认证 1513 例（扩窗 1521 例），平均 5.9 步（扩窗 6.8 步）。
- **精度损失的反例**：原始 C-SL 比 oracle 少 7 例（合法域，1521 vs 1528）/3 例（接口域，1519 vs 1522），全部来自对象事实的跨步相关，即同一未知对象在相邻两步被独立取值。修复需要路径敏感，代价指数级；也可以用滑动窗口内的精确 DP（状态 = σ × 窗口内未知对象赋值），O(n·6⁵)〔待〕，收益上限约为 oracle 唯一数的 0.5%。
- **能推翻它的反例**：任何 C-SL 签发、而 oracle 不唯一的实例。本次 E1（4800）、测试（>1000）以及 golden 7 例中都没有。

### 3.2 D3：作用域化、精化容忍的有效性（C7+C8，C9 有条件）

**冗余**：
- `first_changed_read` 比较的是整个身份列表（O(n)）且要求每个读项字节相等；
- 每张证书的快照同样为 O(n)。

**原型**：`research/validity.py`。快照包含三部分：
- 全局上下文（generation、order_revision、n、完整 settings，包括 revision）；
- 每个被读位置的身份（id、content_version、rotation、orientation）；
- 类型化读值。

校验规则：
- 旧值为未知、失败或 None 时，新值可以是任意值（精化）；
- `dimension:` 读项只比较扫描实际消费的部分：几何有效性、占用状态、变换（扫描只通过这些使用维度）。因此 header 支撑的维度被尺寸不同、但状态相同的分析精化时不失效。这是独立评审发现原生成器让 header 与分析几何逐字节相同之后补上的规则，并新增事件类与测试验证；
- 旧值已知时，新值必须相等；
- 驱逐（已知→未知）只在 `allow_eviction=True` 时容忍，默认关闭。

C1 的证书经 `support_snapshot` 映射到同一词汇表；`certify_contract` 采纳证书时附带 `snapshot` 字段。

**定理 4（作用域校验可靠）〔证〕**

前提：
- 参考 `certify` 的输出只经由 `record()` 读取事实，此外只读 n、settings 和被读位置身份中的 rotation/orientation（代码检查，见 T4）；
- 证书对其未知读值的任意取值都成立（参考：仅 `resolved()` 短路与 header 回退两处，见定理 2 证明；C1：定理 1）。

结论：若上下文、被读位置身份不变，且所有已知读值不变，则在新的知识下证书仍然成立。

证明要点：
- 已知读值不变时，扫描在这些路径上的转移不变。
- 未知读值即使变为任意值，结果也相同。
- 未读位置不进入任何转移。
- 规则修订、代次和顺序修订属于全局上下文，必然触发失效。

H5 要求的"替换依赖对象 / 同位置新身份"由位置身份守住，包括只有 header 证据、分析未知时的替换（`test_same_position_new_identity_with_header_only_evidence`）。变异"去掉位置身份"会漏掉这种情况，`test_scoped_validation_without_identity_is_caught` 能抓到。

**驱逐容忍的前提 P_ver（〔条〕）**：
- 未知分析记录不带算法版本，"见证被淘汰"和"算法版本升级、等待重算"无法区分。
- 只有当算法版本变化体现在证据记录之外（上下文或位置身份）时，驱逐容忍才安全。
- 没有 P_ver 时必须关闭。

**成本**：
- 快照与校验 O(|读集|)，参考为 O(n+|读集|)；
- 无建表；
- 额外存储为负收益，即节省存储。

**E3**：种子 31，1200 张参考证书，n=4..12。每个保留决定都做了安全核对：未截断时用精确 oracle，截断时用 300 个随机世界做反证。

### 3.3 D2：下界与替代规则的局部性障碍

**定理 5（Ω(d) 证书下界）〔证〕〔域 d≤40〕**（抽象扩展域；该族在生成域中的可实现性与频率未验证，见 §6 第 7 项）

族 LB_d：
- n=d+4 个 NARROW 对象，automatic=False，opening=AUTO，无约束；
- 目标 t=1+d。

结论：
1. 对象 1 为 NARROW 和 WIDE 的两个世界给出不同的目标单元，所以对象 1 未知时任何可靠认证器都不得签发（C-SL、C-PW 都正确给出 need）。
2. 对每个奇数 j∈[1, t−1]，只把对象 j 翻成 WIDE 的世界 X^(j) 与原世界只差一个事实，但目标单元不同。

证明：原配对为 (1,2),(3,4),…；翻转 j 后，j 之后从 j+1 重新配对。目标伙伴的奇偶性由 (t−1) 变为 (t−j−1)，两者奇偶不同当且仅当 j 为奇数。

推论：
- 任何证书（使目标唯一的事实集合）必须包含这 ⌈(t−1)/2⌉ 个对象的状态。
- 冷启动至少需要这么多次取证。
- 任何固定窗口认证器都不完备。
- 证书的失效面必然跨越 [1, t]。

E4 以 `complete_plan` 逐一核对了 d=1..40 的单点翻转（`single_flip_pivotal_items` 恰为奇数位置）。在完整知识下，参考读键数与步数随 d 线性增长（d=10/20/40 时读键 28/48/88、步数 36/76/156），C-SL 也是线性（步数 19/39/79，支撑 14/24/44）。

**定理 6（H11 下替代规则的局部性障碍）〔证〕**

前提：
- R 是任意确定分组规则，WIDE 对象不得参与配对（H3）；
- (A2) 段相对性：一个 NARROW 极大段内部的分组只取决于段长和两端上下文类型（序列端点或 WIDE），与段的绝对位置无关。这比"平移等变"更强，是对 H11"不固定奇偶"的一种形式化；
- (A3) 每段至多 c 个单对象。

结论：存在目标，其单元依赖距离 ≥ ℓ/2 处的单个事实，其中 ℓ ≥ (L−3c)/(3c+1)。当 c=o(L) 时这是 Ω(L/c)，无界；若规则允许每段 Θ(L) 个单对象，此界退化为常数，不给出结论。

证明：
1. 设段占据位置 a…b（b=a+L−1），a−1 与 b+1 为 WIDE。考虑三种配置：
   - 配置 0：原样；
   - 配置 1：对象 a 改为 WIDE，段变为 a+1…b；
   - 配置 2：对象 b 改为 WIDE，段变为 a…b−1。
2. 配置 1 和 2 的段长同为 L−1，上下文类型相同，由 A2，二者的分组是彼此平移一格的同一模式。
3. 三种配置合计至多 3c 个单对象。所以存在一个长度 ℓ ≥ (L−3c)/(3c+1) 的区间 J，它在三种配置中都不含单对象，所有对象都两两配对。
4. 在无单对象区间内，配对按奇偶交替，相位定义良好。
5. 由第 2 步，J 上配置 1 与配置 2 的相位不同，所以至少一个与配置 0 不同。
6. 取 J 中点处的目标（ℓ≥3 时伙伴落在 J 内）。相位改变即伙伴改变，而这一改变只由对象 a 或 b 单个事实引起，它们距目标 ≥ ℓ/2。

意义（均以 c=o(L) 为前提）：
- 参考的长程依赖与 H11 约束相容，任何满足 A2/A3 的规则都有同类依赖；
- 路线 B 无法在 A2、A3 下得到有界窗口认证；
- 想降低用户等待，只能从取证规划、共享工作和提前取得相位决定事实入手。

更直接的论证（同样成立）：若规则在 A2 下的局部半径有界，那么在长均匀段内部，每个位置看到的局部输入相同，决策必然相同。而"每个位置都与右邻配对"不可能对相邻位置同时成立，所以只能全部单对象，与 c=o(L) 矛盾。

### 3.4 D4：证明支撑与资源的交互

**D4a：KEEP vs CANCEL**（E7，合成协议切片，〔域·合成〕）

场景：C1 或任何换支撑的方案，在事实 b 的取证任务运行中使证书不再依赖 b；之后另一消费者又需要 b。

在容量 2/3 × 三个异步事件（b 完成、b 被再次请求、无关任务 c 请求）的全部 6 种排列上执行 `protocol.run_event_trace`，共 12 条交错 × 2 策略。容量 1 被排除：此时 b 的首个请求就是 `full`，b 从未在途，问题不成立。拒绝计数不含 cancel 操作自身的确认；KEEP 只有在 b 的完成确实已被接纳时，才把再次请求计为知识命中。

| 策略 | b 的任务启动数 | 有重复工作的交错 | 拒绝（cancelling/full） | 峰值占用 |
|---|---|---|---|---|
| CANCEL（离开支撑即取消） | 24 | 12/12 | 6 | 2 |
| KEEP（不取消，完成即接纳） | 12 | 0/12 | 0 | 2 |

- 逐条配对比较（启动数、拒绝数、峰值占用）时，KEEP 从不劣于 CANCEL。这个场景假定 b 之后一定会被再次需要，所以结论在相当程度上由场景构造决定；它真正说明的是：在不可抢占模型下，取消不能换回任何容量。
- 机制：不可抢占任务被取消后仍占名额直到实际完成（H7），取消不释放任何容量；而被取消的同身份请求在退出前不能复用（`cancelling`），违背 H6 的复用意图。
- 这与 H-G 在宿主集成中出现的"在途工作复用失败"相符，是一种可能的机制。由于这只是玩具模型，这里只作推测，未在宿主上验证〔待〕。

D_proof/D_work/D_publish 的映射建议：
- D_proof = support 中的已知事实 + 位置身份 + 上下文；
- D_work 只增不减，直到任务自然结束；
- D_publish = 已认证单元 + 版本。
- 支撑集收缩只改变"是否仍需等待"，不改变"是否持有任务"。

限制：切片没有排队态。若宿主有可抢占的排队任务，取消排队任务可能占优〔待〕。

**D4b：需求选择**（E2/E2H）

冷启动：分析全部未知，header 部分已知；每轮并行取得认证器给出的需求，秩需要两端分析在轮初有效。

easy：240 世界，种子 23，n=3..6，header 70%。下界在 210 个世界上精确求得（另 30 个因 oracle 截断未解，不计入超额）。

| 指标（easy） | 参考 | H-G | 包装（参考需求） | 包装（引擎需求） |
|---|---|---|---|---|
| 总轮数 | 186 | 186 | **170（−8.6%）** | 149（−19.9%） |
| 总取证 | 279 | 279 | **262（−6.1%）** | 358（+28.3%） |
| 距下界超额（210 个已解世界合计） | 43 | 43 | **27** | 95 |
| 平均内存步数 | 3.7 | 5.0 | 26.0 | 26.8 |

hard：160 世界，种子 29，n=4..7，header 20%，automatic 开，少方向标签。下界在 79 个世界上精确求得。

| 指标（hard） | 参考 | H-G | 包装（参考需求） | 包装（引擎需求） |
|---|---|---|---|---|
| 总轮数 | 309 | 309 | **289（−6.5%）** | 187（−39.5%） |
| 总取证 | 496 | 496 | **470（−5.2%）** | 658（+32.7%） |
| 距下界超额（79 个已解世界合计） | 43 | 43 | **29** | 97 |
| 平均内存步数（p90 / 最大） | 6.9（13/95） | 10.4（20/152） | 142（302/1325） | 118（304/627） |

在 hard 冷启动下，C-SL 的内存工作显著上升，平均 142 步、最大 1325 步：窗口内未知对象很多时，逐步枚举的常数 B 暴露出来。这是 §3.1.4 中最坏界在实例上的体现。

结论〔条〕：
- 沿用参考窗口需求、由 C-SL 提前认证，轮数与取证同时下降，并接近穷举下界；
- 改用 C-SL 的分支需求能进一步减少轮数，但会多取证；
- 取舍取决于"每轮延迟 / 每次取证成本 / 每步内存工作"的比例，本包没有给出这些参数；
- 下界由穷举最小证书得到（`min_certificate`）。

## 4. 淘汰记录与下界

| 思路 | 结论 | 反例或原因 |
|---|---|---|
| 未知当作已知空值 | 〔否〕 | 近边已知空值、后边未知时会错签 {2,3}，真实可能是 {1,2}（`test_unknown_rank_as_null_is_caught`；随机 rank_focus 域也能抓到）。默认生成器几乎不触发秩比较，这本身是覆盖缺口，已加入 rank_focus 生成器 |
| 秩网格去掉空值选项 | 〔否〕 | 近边已知空值、后边未知时漏掉"后边为空"的世界（`test_grid_without_null_is_caught`） |
| 去掉"配对越过 first"的入口 | 〔否〕 | 变异在随机接口域中产生错签（`test_missing_paired_entry_is_caught`） |
| 固定窗口完备认证 | 〔否〕 | 定理 5 |
| 绝对奇偶 / 局部极大匹配类替代规则 | 〔否〕（受 H11 约束） | 定理 6；绝对奇偶被 H11 明文禁止，局部极大在均匀段中普遍隔离 |
| 独立扩窗重试 H-G 作为主要方向 | 〔否〕（被支配） | 定理 2；E1 只多 3 例，而 C1 多 180 例 |
| C-PW 部署 | 〔否〕（成本） | 最坏指数级（E1 最大 8443 步），收益只比 C-SL 多约 0.4% |
| 支撑收缩时取消在途任务 | 〔否〕（合成切片内） | E7 |
| "每区间 1 点网格不足"（本研究最初的假设） | 〔否〕 | L3 证明 1 点已足够，变异检验因此失败；保留为发现 |
| 按被读位置±1 局部化设置成员资格 | 〔否〕（缺少证明） | `allowed()` 不读事实也会查询成员资格 |
| 推测性发布 / 永久锁定猜测 | 〔否〕 | 违反 H2，CONTRACTS 明文禁止 |

**不可消除的等待与成本**：
- 构造域中 need_facts 的 78.5% 真正未定〔域〕；
- 均匀段中 ⌈d/2⌉ 个事实必须取得〔证〕；
- 规则替换无法消除这种长程依赖〔证〕；
- 只能通过提前取得或共享取得来隐藏。

## 6. 回到宿主系统的下一步最小验证

1. **分支 α/β 判定**（最高优先级）：核对 header 几何与分析几何在原生成映射中是否恒等。
   - 若否，参考自身存在 H2 风险（T1），C1 必须以 β 模式运行。
   - 最小核对：在宿主中找"分析未知、header 有效"的已发布单元，再看分析到达后的单元。
2. **C1 核心差分**：在冻结原实现的 1,806 组差分域上运行 `certify_contract`。
   - 判据：采纳的证书单元与原实现完整计划逐组一致；
   - 判据：blocked/certified 原样返回；
   - 重点复核非默认旋转/方向（本包差分域未覆盖）。
3. **读集完整性审计**（定理 4 的前提）：在宿主认证路径上对所有输入读取插桩，确认没有 `record()` 之外的隐式输入（包括设置成员资格、缓存层）。
4. **P_ver**：确认算法版本变化在证据记录之外是否可见，决定能否开启驱逐容忍。
5. **协议层**：
   - 宿主是否有排队态、可抢占任务；
   - 支撑收缩时现行代码是否会取消或降级在途任务；
   - 需求标签降级是否会被当作新身份。
6. **成本参数**：在宿主上分别计量
   - 一次 C-SL 展开的成本；
   - 一次取证（分析/秩）的成本；
   - 一轮的固定延迟。

   有了这些才能把 E2 的轮数/取证变化换算成延迟。本报告不做换算。
7. **生成域可实现性**：定理 5、6 的族需要长段 NARROW 且无方向标签的输入，生成域中这类输入是否出现、出现频率如何，〔待〕。
