# 约束分层与验收合同

本文件区分研究必须保留的性质、等价路线必须保留的规则、可替换机制以及未确定假设。参考程序不是完整需求的替代品。

## H：硬性质

| 编号 | 性质 | 应能击败错误实现的检查 |
|---|---|---|
| H1 | 同一完整输入及有效外部约束，访问顺序、缓存状态、完成顺序与重新进入不能决定最终分组或槽标签 | 同输入的不同事件排列与冷/热状态比较；不仅检查最终收敛 |
| H2 | 已对外观察的单元在同一输入版本下不能因迟到事实被换成员或换槽 | 先发布部分成员/相邻单元，再到达新事实；禁止用永久锁住猜测代替证明 |
| H3 | 每个源对象恰出现一次；稳定身份、源顺序及目标定位保持；完整占用对象不能被切分、遗失或不可达 | 边界、连续完整占用、单对象序列、连接被解除 |
| H4 | 缺失、已知空值及可重试失败分开；必须报告的失败不得被优化吞掉 | 决定性失败、被短路查询上的已知失败、恢复失败与已知标量并存 |
| H5 | 内容/规则/约束版本变化必须使相关事实、证书和发布权限失效；无关对象可继续使用 | 替换依赖对象、同位置新身份、规则修订、延迟旧完成 |
| H6 | 在途共享任务按身份复用；可选任务变成必需时不能无故重复开启同一工作 | 任务已执行后提升消费者，检查工作句柄与实际开启计数 |
| H7 | 资源名额有界；完成待接纳仍可能占额；不可抢占任务实际退出前不能假装释放 | 完成未消费、取消未退出、饱和时入场 |
| H8 | 足够事实完成后应及时接纳并补位；不得形成等待无关慢任务的整批屏障 | 一个必需任务完成、另一个无关任务长时间挂起 |
| H9 | 后台完成、编组或短暂观察不能凭空产生“已确认消费” | 已确认消费集合是有效观察集合的子集，并须满足单独确认事件规则 |
| H10 | 显式新输入允许切换结果；不能给后台迟到事实虚构新版本以逃避H2 | 同版本补全与真实内容/规则变更分开 |
| H11 | 不要求新增人工预处理，不通过关闭既有自动能力、固定奇偶或普遍隔离对象满足稳定性 | 冷请求、无索引状态和替代规则的功能完整性 |
| H12 | 成本全程记账；不得以内部步数减少替代实际等待改善 | 冷/热分开，记录预处理、验证、失效、被拒尝试和共享工作 |

H4 的具体错误分类及作用域以参考接口为基础。若主张“与结果无关的失败本应被忽略”，可提出合同变更路线，但不能把它算作已保持原合同的优化。额外试探发现的失败是否上报也必须显式说明，不能混同原路径已观察的失败。

H6 不禁止正常失效后的重新工作：身份/版本变化、任务已终止或资源不再有效时，须按新的有效性判定处理。

## S：等价路线的语义

- 保留完整单元的成员、顺序、槽、原因和确定性。
- 保留合法外部指定连接与硬隔离的优先级、初始模式和同分规则。
- 保留相位与原子预留的效果；不能把局部截取的起点自动当作序列起点。
- 不把边的无有效秩理解为相邻对象永远不可组成普通单元。
- 通用数值接口与内建非负生成器分开。依赖非负性的优化只能在已保证该前提的接口启用。
- 认证采用的读集必须足以验证它实际使用的证据。被放弃尝试的未完成需求不能伪装成已取得的证据。
- 依赖集合可以替换而非仅缩小；下游对该集合的消费必须重新验证。

`reference.py` 是这组局部规则的具体基线。它的保守等待不属于不允许改动的结果语义。

## M：可研究替换的机制

以下不是普遍常数或硬需求：起始窗口大小、保守入口集合、是否重试、缓存容量与淘汰策略、索引结构、取证先后、任务并发参数、内部统计字段及摘要树实现。

可以改变它们，但必须计入新的内存、建表、校验、失效和额外工作成本，并证明 H/S 保持。一次重试不等于固定增加一个扫描步骤；窗口初始扩大一格后，内部算法仍可能继续扩展。

## A：未给定的参数与假设

没有默认保证：真实输入分布、任务时长上界、失败独立性、缓存命中率、无限资源、始终存在索引、原始见证永不淘汰、全部标量组合均可实现、所有回调数值非负。

若研究需要其中某项，请使用带前提的定理、参数化成本或分支分析。不能静默选择最有利条件，也不必因缺少参数停止整个研究。

## 证明依赖、资源需求与发布权限

三类集合分别记为：

- `D_proof`：决定证书是否仍有效的事实和版本；
- `D_work`：当前仍需执行、恢复或持有的物理工作及资源；
- `D_publish`：对外发布所需的有效成员与权限。

它们可能交叠，但不是定义上相等。当前消费方可能通过 `D_proof` 触发资源接纳；改变证明支撑集会改变操作行为。研究时必须给出三者的映射和版本检查条件。

不能仅删除依赖对象以减少工作，那可能丢失内容替换的检测；也不能盲目把新旧读集合并，那可能重新引入未完成事实、扩大失效面或抵消收益。具体方案需证明。

## 验证分层

| 层 | 本包如何支持 | 接受什么结论 |
|---|---|---|
| 数学 | 定义、状态与反例义务 | 带明确前提的命题、下界、复杂度 |
| 可执行核心 | 参考模型与有限测试 | 具体输入范围内的行为、操作计数 |
| 合成协议 | 事件状态机与协议测试 | 被显式建模的事件合同 |
| 真实核心差分 | 交付者在本地执行，摘要随包记录 | 明确差分域内与冻结原实现对齐 |
| 完整运行环境 | 未包含 | 不能宣称真实资源、时序、跨环境或体验已经验收 |

测试必须可以因有意义的错误而失败。仅检查文本或符号存在不能证明行为；部分测试重用参考实现时，不能当作独立正确性oracle。
