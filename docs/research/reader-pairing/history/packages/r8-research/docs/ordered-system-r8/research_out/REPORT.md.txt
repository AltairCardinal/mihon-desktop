> 范围：`RESEARCH_QUESTIONS.md` 48 个主课题、`COMBINATION_CHALLENGES.md` 12 个组合挑战、7 个新假设。
> 逐题证据索引：`coverage.csv`（67 行）；逐题正文：`sections/core.md`、`sections/hosts.md`、`sections/protocol.md`、
> `sections/new_hypotheses.md`；证明与反例：`proofs/PROOFS.md`、`proofs/hosts.md`、`proofs/protocol.md`；
> 正式计时表：`results/formal/TABLES.md`（全部由原始 JSONL 生成）；复现：`REPRODUCE.md`。
> 证据层标注：core / virtual_host / protocol / simulated（单位 u 或计数，未标定）/ local_measured（本机 Python 3.13、2 vCPU）/
> historical（包内 BASELINE_EVIDENCE，未混入本轮数据）。

## 0. 先说结论：真正得到了什么、没有得到什么

**得到的（按价值排序）**

1. **冻结虚拟宿主有一个 L0 正确性缺陷（C5）。** 记忆只保存被采纳尝试的读集，而 need_facts 与"采纳重试"的策略判决还依赖
   另一个尝试；两个最小夹具（`fixtures/host_traces/c5_*.json`）让 `Config.current()`/`strict()` 返回与 `certify_strategy`
   不同的公开判决（一个是该认证却仍报 need_facts，一个是 `first/steps` 不同）。修复（按尝试缓存或并集支撑）在正式计时中为冻结宿主的
   0.923×（15 个场景范围 0.836–1.072），存储读键约 1.6×。包内自带差分测试覆盖不到这一路径。
2. **冻结认证器依赖一个未声明的"头部权威"前提 α（NH-1）。** 若分析结果可以与有效头部的 state 不同（β），参考在 391 个随机小案例中
   认证的 278 个里有 106 个并不唯一；宿主族的轨迹生成器本身就产生了 29/207 次与有效头部 state 相矛盾的分析事件。β 安全的关系树仍能认证 179 个且 0 错签。
3. **扫描规则是一个窗口为 [i−1, i+3] 的有限状态转换器（定理 T-1，引理 L-M/L-W/L-M2）。** 手动连接链的奇偶是前向递推，
   因而任何区间的摘要是一个 10 元（可证明可并为 5 元）函数；同时证明了**不存在固定半径**的充分入口状态（定理 A1，构造在 G0 中可实现）。
   由此得到计划维护的线段树（B2）：每次更新 ≤5 个叶，查询 O(log n)，对相位链对手稳健。
4. **部分信息的早认证（L1）可以做到"几乎精确且可靠"，但在纯计算宿主里要付时间。** 独立叶关系树（过近似）与共享赋值 DP（精确）
   在 3 589 个小案例上对世界 oracle 0 错签、DP 0 漏签；随机部分知识上比参考策略多认证约 3.7%，在无关变化轨迹上多 27%（148→188），11 条冻结轨迹合计 1 470 个请求多出 66 个证书（4.5%）。
   正式计时中它使虚拟宿主慢 1.16–1.66×（主要是镜像拷贝与 diff）；接在 owner-method/逐位置修订宿主上，每次额外认证 0.8–130 ms。
   是否值得取决于一次取证轮次的真实延迟（REPORT §6 的盈亏式）。
5. **宿主成本的主体是更新路径，不是认证。** 认证只占宿主时间 1–13%（长链 69%）。冻结 `replace` 为决定"是否推进修订"要做两次整案
   `typed()`（n=256 时占 replace 约 62%）。**无条件推进修订（NH-2）判决不变**，正式三进程计时下为冻结宿主的 0.39–0.68×
   （11 个场景全部更快、三进程范围窄）。宿主族的 owner-method delta API 更进一步（0.03–0.43×），但那主要是 Python 深拷贝表示效应（N15）。
6. **（模拟层）见证级共享工作最划算。** 一个原始见证同时服务分析与两条相邻秩：取证 −46%（sweep），联合服务再使轮次 −28%；
   预取只在顺序访问有利，随机跳转使取证 ×2.7。
7. **大量方向被具体证据否定**：按设置特化的扫描（无收益）、决策 DAG（编译成本高于收益且随知识失效）、树判歧义后的 CEGAR/精确 DP 升级
   （139 次 0 次成功）、渐进特征用于秩比较（2 000/2 000 需要全精度）、最小支撑（重认证太便宜）、细粒度失效（C1/C2 在便宜更新下无稳定收益）、
   证书共享（C4）、最大权匹配编码（N01 重现）。

**没有得到的**

- 没有任何真实获取/派生/队列/端到端时延；所有这类结论都是模拟层的计数或无量纲 u，只给参数化盈亏条件。
- L2 替代规则（H5 的局部极大规则）只完成结构与成本比较，没有外部质量真值，属于待裁定方案。
- 生成域只刻画了秩子过程（rotation 0、h≥50）；侧向标签/状态的联合可实现集仍未知，相关下界只在扩展域成立。
- 部分信息下的**精确**区间摘要（带边界赋值）只做了设计与规模估计，没有实现。
- 协议层结论来自合成状态机与有界穷举（≤3 任务、深度 ≤7），不是原生调度器。

**接下来最值得做的**：(1) 在真实宿主上采用 C5 修复与 NH-2（或 owner-method 写屏障）；(2) 测出一次取证轮次与一次见证获取的真实成本，
用 §6 的盈亏式决定是否部署关系早认证与见证级共享；(3) 在合同里明确 α（或改用 β 安全认证）和数值接口（int/double，NH-6）。

## 2. 八个研究族小结（逐题见 sections/*.md 与 coverage.csv）

- **A 语义与下界**：A1 无固定半径（定理）+ m 位合并；A2 区间摘要常数大小（完整信息）；A3 最小支撑比参考读集小 38%；
  A4 给出 G0 中距离 n−3 的真实依赖和小案例上的自适应下界；A5 计划只依赖相邻严格序与 null；A6（协议族）同上下文可靠证书两两相等或不相交。
- **B 增量与复用**：B1–B3 树/重同步/线性三种维护（正式计时 §4）；B4 尝试级复用随 C5 修复保留、步骤级复用被否定；B5 联合认证只有 L1 价值；B6 只对可预测访问有用。
- **C 依赖与缓存**：C5 缺陷与修复；C1/C2 在便宜更新下无稳定收益；C3 类型标记身份元组 + 有界驻留（正式计时 §4）；C4 否定；C6 只在重建成本极偏斜时有效（正式 0.486×）。
- **D 信息获取与共享工作**：D2 见证共享最划算；D1/NH-3 少取证但多轮次；D3 仅顺序访问；D4 动态批 + 逐项接纳；D5 同 incarnation 复活；D6 强证明很少值得。
- **E 数值与见证**：E1 G0 秩序列构造性可实现；E2 相邻 double 代表（v±1 方案错签，N03 固定为回归）；E3 标签互换等变性，仅 automatic=False 可复用；
  E4/NH-6 int/double 接口给出不同计划；E5 渐进界对比较无用、对早判 null 有用；E6 独立叶抽象近乎精确。
- **F 计算范式**：F1 转换器有用、特化无用；F2 路径 DP 精确而最大权匹配不是规则；F3/F4 否定；F5 前沿缓存；F6 组合门控中 portfolio 是伪赢家。
- **G 协议**：incarnation 票据（epoch 标签在调用方复用时不安全）、取消意图与退出分离、逐完成接纳、发布权限占用表 + "目标在单元内"检查。
- **H 因果与负载**：H1 维护成本主体是整案比较；H2 相图与性能反例缩减器；H3 k 竞争比下界；H4 宿主投影字段的判别力不足；H5 L2 规则；H6 收益上限与决策表。

## 4. D3 候选：正式三进程结果

方法：`bench/formal_all.sh` 串行执行；每个候选 1 次预热 + 3 次测量 × 3 个独立进程（记录 PID/UTC），配置顺序轮换；

### 6.3 NH-2 的最坏情况

设计的最坏负载：只有 no-op replace，且每个请求的证明是递减链最后一项（n=256 时 764 个读键），使 always_bump 每次都要做完整读值校验
（`results/worst_always_bump.json`，单进程 5 次中位）：n=16 / 64 / 256 时 always_bump 为 49.9 / 213.0 / 861.0 ms，冻结宿主为
76.9 / 356.4 / 1 701.1 ms——即使在最坏负载下仍是 0.51–0.65×，因为整案 typed 比较比 764 个 typed 读值校验更贵。
在整案比较廉价（例如已有可信内容哈希/owner 修订）的宿主里，这一关系可能反转，故去留为"整案比较昂贵时保留"。

## 7. 覆盖区别与不能外推的结论

- 核心层（core）结论只对冻结 `_Scan` 语义成立；关系认证还依赖 α 与所选秩域。
- 虚拟宿主（virtual_host）的时间是 Python 表示的时间；深拷贝/typed 的比例在其他运行时会不同（N15）。NH-2 的**安全性**是普适的，
  **收益**取决于宿主比较整案的代价。
- 协议结论（protocol）来自合成状态机与有界穷举，环境前提（可信 incarnation、所有写入经过 owner）是假设。
- 模拟（simulated）的取证/轮次计数来自合成世界生成器；采样频率不是真实频率。
- 匿名宿主投影夹具只覆盖状态/槽/确定性/选定失败（H4 证明它看不见原因、需求顺序、steps、依赖项的变化）。

## 8. 给下一实现者的移植/验收清单

1. 记忆支撑：按尝试缓存（或并集），用 `fixtures/host_traces/c5_*.json` 做回归。
2. 修订维护：要么无条件推进（NH-2），要么 owner-method 写屏障（每个可见写入口都推进，逐入口漏戳变异必须失败）。
3. 合同：声明头部权威 α（或使用 header_authority=False 的认证）；声明秩的数值接口（double 规范化或拒绝大整数）。
4. 若部署 L1 早认证：只在 L0 判决为 need_facts 时运行；不改写 blocked；额外证书不进记忆；与 owner-method 更新共用脏位置；
   用世界 oracle 小案例回归（`tests/test_core_research.py`）。
5. 若维护完整计划：TreePlan（对手稳健）或 ResyncPlan（典型输入更快）+ 传播长度上限后回退到树。
6. 协议：incarnation 票据由 owner 发放；取消不释放不可抢占任务的槽；发布用占用表 + 目标在单元内检查；确认只来自显式事件。
7. 安全回退：任何候选出现判决不一致时回退到冻结参考的 `certify_strategy` 并清空记忆。
