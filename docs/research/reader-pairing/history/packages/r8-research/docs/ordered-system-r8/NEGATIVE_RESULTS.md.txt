# 已知负结果、陷阱与重开条件

本文件区分确定缺陷、有限成本负结果和未证明假设。它不禁止有新机制的新研究，但反例不能靠换名称绕过。

| 编号 | 已知边界 | 当前可接受结论 | 重开所需证据 |
|---|---|---|---|
| N01 | 参考策略具有相位、原子预留和同分规则 | 不能直接换成最大化秩总和的匹配并声称等价 | 规则双向等价证明，或作为 L2 明列输出差异 |
| N02 | 没有固定局部半径或“一个隔离就重置所有历史”的普遍证明 | 不能把固定窗口当所有输入的充分状态 | A1/A2 的充分性证明及长区分后缀检验；这是研究义务，不是所有局部方案均不可能的定理 |
| N03 | 大浮点 `v-1` 可以仍等于 v | 旧比较代表曾漏掉严格小于分支并错签 | 使用实际数值域可实现的严格代表或符号顺序，经过序列化后再核对完整 oracle |
| N04 | Python 任意精度整数与只接受有限 Double 的接口不同 | 能在一种接口表达不表示另一种可输入 | 分别列域和覆盖证明；不能拿不能序列化/不能输入的内部对象作现实世界见证 |
| N05 | 扩展域的独立标量不必都由共同见证产生 | 过近似唯一可保守签，过近似歧义不能证明生成域歧义 | 具体原始见证或充分可实现性证明 |
| N06 | 比较代表、完整起点探针等能减少旧分支器成本，但额外证明整体未稳定胜过当前快速路径 | 局部机制有效不等于值得默认启动 | 新门控/复用/成本条件；需重测旧亏损区域及真正减少的物理工作 |
| N07 | 已认证未知精化降低部分重算却提高热路径成本，部分边精化没有有效接纳例 | 无稳定总体收益，已移出当前实现 | 实质不同的支持模型或命中条件，完整维护与失败/已知变化验证 |
| N08 | 变更戳只在所有可见写入口被覆盖时安全 | 直接改可变映射绕过版本可产生假命中 | 所有权封闭或完备写屏障，逐入口漏戳变异，饱和/关闭/重绑回退 |
| N09 | raw 见证驱逐未必移除有效标量，缺一条邻边又可能需要见证 | 不能把驱逐一概当失知，也不能凭残留标量推断所有邻边 | 明确事实、原始驻留与任务工作三种生命周期 |
| N10 | 旧合成发布表只按target记录，元数据真变化后未正确切换身份空间 | 曾出现模型发布冲突；不能用成功发布的 wrong=0 宣称 H2/H5 全部通过 | 正确的完整上下文/权限模型及交错回归，不虚构版本 |
| N11 | 只加跨target重叠检查会漏掉同target完全不相交替换 | “没有成员重叠”不是可以替换的理由 | 同target稳定与跨target相容两种守卫同时验证；当前协议包含此回归 |
| N12 | 协议使用可信单调epoch限制输入，不会自动识别同epoch重新贴标的新内容 | 环境前提不是通用 ABA 解决方案 | 建模可信 incarnation 来源、票据及旧完成判定；说明违反前提的行为 |
| N13 | 预算仅在外层检查会让内部扫描多执行 | 一次 attempt 前检查才支持严格操作上限 | 0/1/差一步/恰好完成测试，并区分执行步、准入尝试和拒绝 |
| N14 | 相同seed但策略改变随机数消耗，会得到不同失败/事件 | 旧非公平比较不能作收益证据 | 固定外生事件、按稳定物理身份和attempt键定失败，逐公共键核对 |
| N15 | Python参考中的深复制和包装可造成很大表示差异 | 十余倍表示加速不代表其他实现同样获益 | 与当前强基线比较，原型成本与其他运行时成本分层 |
| N16 | 新维护计数在全关配置也存在 | 同代码消融未独立量出相对历史实现的新增维护成本 | H1 的因子账本或受控历史对照，不假定免费 |
| N17 | finish、consume、资源归还、认证、发布、有效确认不等价 | 简化为一个done会破坏容量、稳定发布或确认合同 | 显式状态与逐事件断言，特别检查取消未退出和完成未接纳 |
| N18 | 原型计时包含终态cleanup而工作计数曾在cleanup前取快照 | 自定义无close轨迹漏记一次清理调用，现已修复并回归 | 维护账本与计时边界一致；幂等cleanup调用次数和实际释放次数仍要区分 |

N06/N07 是特定轨迹和当前机制下的负收益，不是永远不可能获益的定理。N02 是禁止偷用未证明前提，不是封杀所有区间摘要。N10 的冲突来自完整上下文真实变化后的模型缺口，不是同一完整输入迟到事实改变答案的直接反例。

任何重开条目必须说出：旧失败原因是什么、新机制改变了哪个原因、为何不会仅仅把同一成本移到别处。缺少这三项就应视为重复探索。
