# 对手式验证矩阵

这里定义研究者须扩展执行的工作族，**不是宣称交付包已经运行了整张矩阵**。已运行范围见 `MODEL_API.md`、`RUNNING.md` 和 `PACKAGE_VALIDATION.md`。先用小域缩减反例，再按候选风险扩展；不要求无目的笛卡尔积。

| 编号 | 工作族 | 必须覆盖的变化 | 主要应抓出的错误 |
|---|---|---|---|
| W01 | 极小边界与目标一致性 | n=1/2/3、首尾目标、连续完整占用、同单元不同入口、全部目标排列 | 丢对象、槽错位、错误单元投影或覆盖 |
| W02 | 长影响链 | 重复局部模式、早期一个事实变化、逐渐加长的区分后缀 | 固定半径、局部起点重置、错误收敛 |
| W03 | 规则与预留 | 两方向、初始模式、合法指定连接链、硬隔离、同分 | 普通最大权匹配替代了确定规则、优先级变化 |
| W04 | 知识精化 | unknown→computed-null、unknown→known-value、unknown→failed、不同观察顺序 | 未知被当空值、未经证明提前签发、证书标签变化 |
| W05 | 失败与恢复 | 资源失败/读取失败、已知值与失败并存、清失败、重试、短路遇到旧失败 | 吞失败、永久负缓存、错误需求顺序或失败作用域 |
| W06 | 完整身份变化 | 同位置新对象、内容版本、变换、方向、规则/约束修订、重排和恢复 | 仅凭位置/数字/哈希复用旧证据或发布权限 |
| W07 | 工作集与访问 | 重复目标、邻近、往返、随机跳转、目标数刚超缓存容量、扫描污染 | 热命中专用技巧、跨目标 thrashing、隐藏准备成本 |
| W08 | 在途工作与容量 | C=1/2/4、消费者提升、取消未退出、完成未接纳、旧完成、重复完成 | 假释放、重复开启、整批屏障、越额或饥饿 |
| W09 | 可实现域关系 | 共同原始见证派生、方向性关系、关联标签/秩、扩展域独立标量 | 用不可能世界证明下界、排除实际世界的剪枝 |
| W10 | 数值与序列化 | null、±0、相邻有限浮点、大正负、有限极值、严格JSON往返 | `v-1==v`、错误代表、不可序列化符号世界、舍入偷换 |
| W11 | 驻留与知识分离 | raw 见证淘汰但标量仍有效、某邻边缺失、不同原始缓存容量、关闭 | 驱逐即失知、无见证凭空补边、误清可靠标量 |
| W12 | 稳定发布与确认 | 同target不相交替换、跨target成员/槽冲突、迟到事实、真实新版本 | 只检查相交、只检查同target、把准备当确认、虚构版本 |
| W13 | 成本偏斜与漂移 | 获取/派生/认证各自便宜或昂贵，一慢多快、突发、漂移、相关失败 | 只看步数/命中率、预取拖慢前台、偷看未来 |
| W14 | 操作预算与计数 | 0/1/恰好完成/差一步预算、计数近饱和、取消检查、epoch复用 | cap多一步、未完成当完成、溢出后假命中、错误ABA结论 |
| W15 | 空间和长期成本 | n跨分块/缓存阈值、长生命周期、密集依赖、高扇出更新、反复关闭 | 只限条目不限字节、旧快照泄漏、维护比重算还贵 |
| W16 | 交错与进展 | 请求/完成/接纳/取消/发布/新上下文的合法事件交错 | 单次最终一致掩盖中途错签、无关慢任务阻塞、失效后不进展 |

M（memo容量）、R（原始见证驻留容量）与 C（物理并发槽）是不同参数，不能用一个容量同时替代。某阈值若只存在于外部集成而虚拟模型未实现，应作为待移植检查登记，不能称包内已覆盖。

## 变异验证最低集合

对候选所涉及层选择有判别力的变异，不需要为未实现层制造假测试。最终前列候选应至少能击败相关的以下错误：

1. 删除某个可见写入口的修订更新。
2. 将 unknown 与 computed-null 合并。
3. 忽略设置、顺序或 incarnation 中一个必要守卫。
4. 将同一数字版本的新实例误作原 owner。
5. 将窗口局部起点当作序列起点。
6. 吞掉短路路径上应保留的失败或改变需求优先级。
7. 从证明支持中删掉被剪入口或探针读取。
8. 预算检查从执行前挪到执行后。
9. 取消意图或 finish 立即释放仍占用的资源。
10. 同target单元完全不相交就允许替换，或跨target不检查冲突。
11. 将后台准备、完成或发布直接写入有效确认历史。
12. 策略读取未来轨迹或按策略随机数消耗顺序生成失败。

记录变异后的真实失败、失败原因及恢复后的结果。测试无法杀死相关变异时，补测试或缩小证据主张；不能只把变量命名改成“mutant”而从未运行。

## 反例缩减

缩减必须保持目标命题的前提：合法外部约束、生成域可实现性、共同已知事实、失败作用域、版本与资源限制。输出最小或局部最小证据，并写出采用的缩减顺序与仍不能删除的部分；不要把非法约束或已改变上下文的实例当作同版本反例。
