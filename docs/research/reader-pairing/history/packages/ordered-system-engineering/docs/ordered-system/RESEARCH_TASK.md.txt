# 自主研究任务

## 本轮委托：把更强证明转成较低总成本

上一轮已发现局部分支认证和作用域化校验，但一个具体实现为少量新增认证付出了大量枚举、
集合和校验开销。新探索正在尝试预计算作用域与复用每步网格，性能尚未独立验收。
请阅读 `ENGINEERING.md`、`COST_MODEL.md`、`prior/NOTES.md` 和 `evidence/`，不要从
“未知即等待”或“更大窗口”重新开始，也不要把旧实现的负结果当成一般不可能定理。

本轮重点是：能否在不改变语义的情况下改变表示/求解方式，使完整请求的计算、分配、取证和
等待更经济。认证数量增加只是中间指标，不能抵消不安全发布或错误合同变化。

自主探索不同算法家族，尤其注意以下尚未解决的问题；它们是问题而非指定实现：

1. 能否把局部事实枚举编译成更紧凑的状态/决策/转移关系？跨窗口和跨目标能共享什么，
   已知比较与未知比较的表示是否必须构造完整事实赋值？
2. 哪些证明支持可以增量维护？作用域一次构建、多次校验的摊销边界是什么？
   身份、设置、知识精化、算法版本和失败如何进入可靠的有效性判定？
3. 当不同事实的获取成本不同、可共享或不可抢占时，下一步取什么证据最经济？
   怎样避免为实际上不可能认证的请求支付大量证明失败成本？
4. 是否有比现有完整输入规则更适合在线稳定输出的规则？该路线必须单列目标、性质和最小
   语义差异，遵守 H1–H12；需要合同变化的不能算等价优化，也不能声称已获批准。

先形成去重候选池，再选最有希望的少数深入验证。允许推翻上述分类，不以实现数量充当成果。
不要在未证明的 header 权威性、自然负载分布、无限容量或免费取证前提上签发无条件结论。

### 固定比较与交付

- 先跑测试及 `benchmark.py --quick`；基线、生成种子和错误案例保留。新增算法通过候选接口
  接入，不能直接改掉参考规则使测试“更容易通过”。
- 完整信息用冻结规则做语义对照；部分信息用合法世界/状态论证。对关键测试加入明确错误的
  变体，证明它可以击败漏入口、漏失败、漏身份或错签，而不只验证帮助函数。
- 测同一请求从校验到必要重算/合法发布的总成本，并分别报告作用域建表、热校验、被拒尝试、
  超预算、回退和模拟取证。模型事件、历史底层时间、本机重测必须分栏，不能拼成用户时延。
- 报告冷/热、短/长、低/高缺失、元数据稀疏/密集、失败与失效场景，展示负收益和退化。
  如果只在某个可检测成本比下有效，给出条件和参数敏感性。
- 复杂度要覆盖准备、分支传播、集合复制/合并、输出、校验与维护，不能仅数 scan step。
  用可重现预算限制探索；预算耗尽不代表证明成立。
- 构造域比例不是自然频率。若没有实际取证或发布测量，给条件成本/模型结果，不能宣称真实体验
  改善。原型性能也不能跨语言/环境直接对比历史绝对时间。
- 一次性交付代码、反例、论证、原始结果、候选总表、淘汰理由和回到宿主后的最小验证清单。
  区分已证明、有限域验证、有条件、未验证和被否定；可以交付否定结论，不为阳性结果改分母。

以下是通用研究与交付要求，仍然适用。

你获得的是完整的匿名问题包。请作为独立算法研究者，自主选择研究顺序与技术路线，在一次任务中完成探索、反证、验证和结论。不要等待提供者逐轮选择方向，也不要把讨论停在建议清单。

## 目标与自主权

寻找足够广泛、机制不同的优化点，以及可能优于当前方案的算法替代。优先给出可验证的实质收益，不以点子数量充当成果。

你可以质疑当前抽象是否充分、否定既有候选、重建状态表示、提出新的算法家族。`RESEARCH_HISTORY.md` 只用于避免重复，并不规定正确方向。没有义务认可它的推荐或继续扩窗。

必须保留硬性质。需要改变参考输出或错误合同的方案单列为替代语义路线，不能自行宣布已获准用于真实系统。

## 一次任务内自行完成的阶段

### 1. 建立自己的理解

阅读问题、约束和程序，运行现有测试。写出状态、输入、输出、允许的操作及信息边界。检查代码与文字是否矛盾；若有矛盾，以明确分支假设继续分析，指出各结论适用哪个分支。

缺少分布、成本或生成域参数时，使用符号参数、上下界或分场景分析。不要编造实际数据，不因一项缺失就停止其他独立工作。

### 2. 广泛探索并去重

形成候选池，寻找彼此不同的冗余或信息瓶颈。可考虑但不限于：精确状态/关系、增量与持久化结构、可组合摘要、证明支持选择、查询规划、负向信息、共享任务、缓存层次、替代目标和不可能性边界。

这些类别不是必须全部实现的清单。允许发现更好的分类。不要把不同命名、不同参数或相同剪枝的包装计作多个独立算法。

### 3. 反证优先，再深入验证

对候选主动寻找最小反例，尤其是相位、预留、指定连接重叠、已知空值、失败、版本变化、淘汰、事件乱序与发布稳定。

从候选池选择最有希望的3至5条深入论证；若有效方向不足，说明原因，不凑数。可修改或新增本包的实验文件，但保留原参考与基准测试以便对照。

对每个保留方案交付：

1. 所针对的冗余及与已有研究的实质区别；
2. 成立前提、伪代码或可执行原型；
3. 正确性、认证可靠性和失效机制的论证；
4. 最坏与摊销成本，包含建表、验证、输出和额外存储；
5. 适用负载、退化场景和能推翻它的反例；
6. 与统一基线的可复现实验，或明确写出为何暂时不能实验。

### 4. 独立检查与整合

检查结论是否把数值不变偷换成协议不变、把有限测试偷换成证明、把构造域频率偷换成真实收益。组合方案必须测边际收益与交互，不能相加单项数字。

保留原有测试并增加针对新假设的对抗用例。至少用一个明确错误的变体检验关键测试能否发现错误，避免只有与实现同构的断言。

## 实验边界

- 本包可离线运行，不需要账户、真实资料或访问原始系统。
- 优先小规模穷举、固定随机种子和最小反例，预估规模后再扩大；不要无界枚举。
- 完整事实参考函数可以作为语义回归oracle，但部分信息认证的普遍正确性还需独立可能世界/状态论证。
- 直接指定的标量实例与生成域实例分开报告；穷举范围、合法性过滤、种子和失败数必须保留。
- 合成协议不能代替未提供的宿主运行时。对未执行的层级标记“未验证”。
- 没有真实计时就报告工作量与条件性成本，不输出虚构的毫秒或加速倍率。

## 最终交付

请一次性提供：

1. **核心结论**：最值得采用/继续验证的方向，以及当前算法的主要瓶颈。
2. **候选总表**：去重后的机制、前提、潜在收益、额外成本、证据等级、是否改变语义。
3. **深入方案**：选中的方案及证明、原型、反例搜索和实验结果。
4. **淘汰记录与下界**：哪些思路失败、具体反例是什么、哪些等待或成本不可消除。
5. **可复现材料**：代码、命令、种子、规模、结果；区分参考文件与新增文件。
6. **下一步最小验证**：回到宿主系统后需要核对的接口和风险，不依赖任何业务名称。

将结论分为“已证明”“有限域已验证”“有条件成立”“尚待验证”“已被反例否定”。给出最有根据的推荐，也明确推荐会在哪些证据下被推翻。

任务结束时应有可供评审的完整结果，不以反问提供者或仅提出后续计划结束。
