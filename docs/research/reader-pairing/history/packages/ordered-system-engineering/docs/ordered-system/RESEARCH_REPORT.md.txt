## 0. 核心结论

### 0.1 主要瓶颈（按完整请求成本）

1. **当前实现的计算成本几乎全部是表示开销，而不是证明本身。** 对 `reference.certify` 做剖析〔实〕：48 个目标的一次扫描中约 92% 的时间花在 `deepcopy`（`_Input` 构造时整份复制输入，每个读取再复制一次），扫描规则本身很便宜。基线校验 `reads_current` 同样每次复制整份输入、比较整份身份。
2. **扩窗/分支的"证明失败成本"来自集合复制，而不是分支本身。** 旧 C-SL 在每个状态上累积其下游全部读集，长缺失输入时为 O(t²) 集合复制〔实〕：n=256、20% 分散缺失时一次调用约 1.4 s、tracemalloc 峰值约 28,800 KiB，最后仍是 need_facts。这与〔历〕中 branch/scale 随 n 增长到约 30 ms、52 MB 的成本形态一致（不同实现，不作数值比较）。
3. **编译核心之后，会话请求的下一个瓶颈是每次请求都重建整份输入字典（O(n)）**，它在任何校验之前发生〔实〕：n=512 时约 4.4 ms/次，而指纹校验约 61 µs、戳检查不到 1 µs。这一项在候选接口内无法消除（`Session.request` 先建 `case` 再调用候选），需要宿主侧改动。
4. **在本包的构造域里，大多数"需要事实"的请求确实不可认证，BX 的主要作用是便宜地确认这一点。** 这是构造域比例（掩码概率为人为设定），不是自然频率。
   - 抽象域 2300 个实例中，BX 对每个不唯一实例都给出了**精确驳倒**（1014/1014），没有一个扩窗到底或超预算〔域〕。
   - 会话场景中 BX 的尝试次数、采纳与驳倒见 §3.3.6〔实〕。

## 1. 建立的理解

### 1.1 完整请求的成本结构

会话中一次请求的路径（`runtime.Session.request`）：

```
构建当前知识 case（O(n)）→ 若有缓存则校验 → 否则重算认证 → 需求映射到物理任务
→ 任务完成/接纳（模拟服务）→ 再请求 → 合法发布
```

对冻结核心的剖析〔实〕：

| 组成 | 冻结实现 | 来源 |
|---|---|---|
| `certify` | 每次 `_Input` 深拷贝整份 case；每个读取再深拷贝一次值；结尾再深拷贝整个读集 | `reference.py` 第 36、247、324 行 |
| `reads_current` | 再构造 `_Input`（整份深拷贝），比较整个身份列表 | 第 375–397 行 |
| 会话 | 每次请求无论命中与否都先建 `case` | `runtime.py` 第 70 行 |

### 1.2 新发现的代码与文字张力

| 编号 | 观察 | 处理 |
|---|---|---|
| T7 | `Session.request` 在校验前总是构建完整 `case`，所以任何候选的热路径都有 O(n) 下限。 | 候选接口内无法消除；以 D2b（戳）单独建模宿主侧改动。 |
| T8 | 生成器的 header 与分析几何来自同一 `geometry_fact`，所以生成域 α 成立是**构造出来的**。 | 生成域内 α 模式结果不证明宿主 α；β 模式全程并跑。 |
| T9 | `benchmark.py` 的 hot/mixed 计时包含预观察采样（12 个对象约 6 ms），墙钟主要是采样而非认证。 | 另列重算/校验时间；扩展基准把正确性核对移出计时区。 |
| T10 | `runtime` 的 `metadata` 保守撤销该对象分析与相邻边；同值重复确认也会触发重算。 | 按模型合同执行，各策略一致。 |

## 3. 深入方案

### 3.1 D1：编译核心 `lowcost/fastcore.py`

**针对的冗余**：§1.1 的深拷贝与类型化快照。与 H-B/H-I 不同，它不改变证明，只改变表示，因此可以做逐字段等价。

**原型**：
- `Index` 惰性解析：每个位置至多一次，结果为元组；边索引在第一次读边时 O(E) 建一次，"后出现者胜"与参考相同；不做复制。
- `certify` 与参考的窗口循环逐行对应，复用 `reference._Scan` 原样。四个读回调返回与参考相同的值，同时把读取记成 `(键, 指纹)`。
- 输出与参考相同的全部字段，外加 `proof`。

**正确性论证**〔证〕：
1. 参考 `certify` 的结果只取决于四个回调（dimension/side/resolved/rank）的返回值序列、`n` 和规范化 settings。
2. `fastcore` 的回调对每个输入返回相同值。逐项核对：
   - `_fact` 规范化映射为固定字段顺序的元组；
   - `_geometry` 映射为 `_geometry_t`；
   - 边证据按 `_Input.edge` 的分支顺序计算；
   - 失败与需求以相同顺序写入相同字典。
3. 窗口循环、记忆、入口集与输出构造逐行相同，所以 `_Scan` 的执行轨迹相同，结果相同。
4. 错误情形保持一致：方向非法、id 重复、目标/回看越界、closed、访问到非法分析状态时都抛 `ValueError`。

〔域〕`lowcost/verify.py`：
- 扩展域 20,000 组（含旋转、陈旧、失败、接口域重叠连接、回看 0–3）；
- 生成域 4,953 组（含 observe/fail/evict/invalidate 事件序列、8 种方向、4 种旋转、WIDE 对象）；
- golden 92 组（两种 case 的全部目标）；
- 不一致 0。
- 变异"删除预留入口"被差分抓到（`Mutants.test_missing_reserved_entry_in_core_is_caught`）。

**成本**：
- 时间 O(参考 step 数 × 每步常数读) + O(被读位置) 解析 + O(E) 边索引（仅在读边时）；无深拷贝。
- 存储：证明为 O(\|读\|) 个小元组。
- 实测〔实〕（`TABLES.md`"单请求重验成本"）：n=48 时一次认证约 0.29 ms，参考约 6.3 ms；n=512 时约 0.44 ms，参考约 16 ms（本机噪声较大，同表比较）。

**退化**：
- 不再产出参考的类型化 `reads` 字典。依赖它的下游必须改用 `proof`（D2）。
- 独立评审找到的边界差异已修正并补回归测试：缺 `reason` 的失败分析（KeyError 推迟到使用时）、缺 `first` 的边记录（certify 路径急切建边索引，与参考一样在构造时报错）、失败字典按原迭代顺序合并（含键冲突时后者胜）。
- 仍保留的差异：未知分析状态在解析时报错（参考在访问时）；只在访问同一位置时出现，所以两者对同一请求同时报错或同时不报错。
- 校验（不是认证）跳过 id 唯一性检查以保持 O(\|读\|)，因此输入 id 唯一是校验的前提，与外部约束合法性一样属于调用方预检。

### 3.2 D2：指纹证明 `lowcost/proof.py`（及 D2b 戳）

**规则**：证明 = (上下文 = generation、order_revision、n、规范化 settings 含 revision；被读位置身份 = id、content_version、rotation、orientation；读指纹)。
- 挂起（need_facts/blocked）：所有指纹必须相等（严格），保证缓存的等待结论在任何被读证据变化时重算。
- 认证：旧值无值（未知/失败分析、未知/失败边、缺 header、无效维度）的读可以精化；有效维度只允许扫描不消费的字段变化；其余必须相等。
- 驱逐（已知→未知）不容忍。

**可靠性**〔证〕：
1. 由 D1，核心结果是 (上下文, 被读位置身份, 读指纹) 的函数。
2. 读集完整（编译核心）：所有事实访问都经过被记录的 `analysis/header/dimension/edge`；`ident` 只用于被读位置；边证据由端点分析派生，校验时重新派生。
3. 读集完整（BX 证书）：证明必须覆盖证书依赖的**全部**事实，包括：
   - 目标的占用状态（决定用哪组入口）；
   - 认证窗口**所有**入口的前置检查读取，**包括被剪枝的入口**；
   - 每个从存活入口可达的状态的展开读取；
   - α 模式下每个被读对象的 header（α 可以在分析陈旧时用 header 定状态）。
   **独立评审发现初版漏了被剪枝入口的读取和"陈旧分析 + header"的 header**，两者都可构造出过期证书仍被接受的反例：左侧对象由 WIDE 变 NARROW 后单元改变，但旧证明仍通过。已修正并加入回归测试与"只收存活入口"的变异测试。
4. 认证结果对其无值读的任意取值都成立：参考路径上无值读只出现在 `resolved()` 的已决短路与 header 回退两处；BX 窗口证书由定理 1 保证，锚点 0 探针证书由定理 3 保证。
4. 由此，上下文、身份、有值读都不变时，在新知识下证书仍成立。

**变异检验**：
- 去掉位置身份 → 漏掉"同位置换身份"（`test_proof_without_identity_is_caught`）；
- 把挂起证明当作作用域化 → 缓存的 need_facts 在未知→已知后被复用（`test_tolerant_pending_proof_is_caught`）。

**摊销**：
- 作用域在认证时顺带建成：读取本来就要发生，没有单独的建表遍历。
- 每次校验 O(\|位置\|+\|读\|)，若有秩读再加 O(E) 边索引。
- 实测〔实〕：n=12…512 时 19.5–61 µs，参考 0.46–8.7 ms。

**D2b 位置变更戳**（`lowcost/stamps.py`，宿主侧模型）：
- 知识层每次变更证据时给受影响位置加戳。命中时只比较证明位置的戳，不变则有效，否则回退到建 case + 指纹校验。
- 前提 P_stamp：每个通过 `case()` 可见的证据变化都会给受影响位置加戳；每个上下文变化（settings、generation、顺序修订）都会加全局戳。**只有所有变更都经过该类的方法时才成立**：直接改字典的代码（如 `runtime.Session` 的 metadata 处理）会绕过它，使快路径失效。
- `Stamps` 测试在 40 条随机事件序列（含 settings 与代次变化）上逐位置比较 `case()` 证据，抓到过两个缺陷：
  - 我第一版原型中 `observe(i)` 会清除 i 的失败，从而改变相邻边的失败证据，但只在秩变化时才给邻居加戳；
  - 独立评审指出全局戳从不递增，settings/代次变化时快路径会接受指纹校验拒绝的证明。
- 两者修正后漏戳为 0；位置有损与全局有损两种变异都会被抓到。
- 收益〔实〕：单请求重验从"建 case 4.4 ms + 校验"变为戳检查约 0.7 µs（n=512）。这只是条件性建模，候选接口内不可测。

### 3.3 D3：BX 分支认证 `lowcost/branch.py`

#### 3.3.1 针对的冗余，与已有研究的区别

| 问题 | 旧 C-SL / C-PW | BX |
|---|---|---|
| 未知秩 | 值网格（每个未知秩约 9 个值） | **比较级**：每个未知秩至多 2 个代表值，覆盖其所在唯一比较的两种结果（引理 R） |
| 跨窗口 | 每个状态累积下游全部读集、分支与失败（O(t²) 集合复制） | 每个状态只记"可达目标单元集合"，第二个不同单元即截断为 AMBIG；支撑只为认证窗口遍历一次 |
| 每个分支 | 新建 `_Scan` 与 View | 一个可复用扫描，清空 manual_cache |
| 不可认证请求 | 扩窗到 0 后才结束 | **先驳倒**：两个真实世界给出不同单元即停止 |
| 预算 | 无 | 确定性操作预算，计入被分支中止的尝试 |
| 精确认证 | C-PW 无界 | 锚点 0 的路径敏感探针，在上限内完成即为精确证书 |

#### 3.3.2 原型

```text
BX(K, t):
  first ← 起始窗口（同参考）
  1. probe(anchor = first−1, cap)：锚点左侧未知固定为默认世界（一条路径，带检查点），
     锚点右侧未知惰性路径敏感分支；找到两个不同单元 → 精确驳倒，返回 need_facts/refuted。
     若锚点 = 0 且在上限内完成且唯一 → 精确证书。
  2. 窗口证明（C-SL 语义，比较级秩代表）：
       reach(σ) = σ 可达目标单元集合（≥2 个即 AMBIG），按位置自后向前记忆；
       唯一单元 → 只遍历认证窗口一次收集支撑，签发证书。
  3. 第一次窗口歧义时：S 个随机完整世界（惰性抽值的具体扫描），两个不同单元 → 驳倒。
  4. 扩窗 first−1（每扩一格只展开新状态）。
  5. first = 0 仍歧义：锚点 0 的完整探针（上限内）→ 驳倒 / 精确证书 / need_facts。
  预算耗尽 → need_facts/budget，绝不签发。
```

接入会话（`lowcost/candidates.py::build_bx`）：
- 先跑 `fastcore`；blocked 和 certified 原样返回；
- need_facts 时才跑 BX，只采纳 BX 证书；
- BX 新读到的失败写入 `extra_failures`，不改变状态；
- 挂起结论的证明对两阶段读到的一切取严格指纹。

β 模式（`build_bx_beta`）先移除不能代替缺失分析的 header，再进入同一流程。

#### 3.3.3 正确性

**引理 R′（比较代表完备）〔证〕**

设一步中 `later_wins(i)` 的比较为 `b ≠ 空 ∧ (a = 空 ∨ b < a)`，a、b 为边 i、i+1 的秩。由引理 R（上一轮已证，本轮复用），同一路径上该比较是这两条边唯一被消费的地方，且只消费比较的布尔结果。代表值集合如下：

- a 未知、b 已知为 x：{空 → 真，x → 假}；
- a 未知、b 尚未知：{空, 1}，随后 b 相对 a 的取值分支：a 为空 → {空 → 假，0 → 真}；a = v → {空 → 假，v−1 或非负时 v/2 → 真}；
- 非负前提下 v ≤ 0 时"真"不可实现，只保留 {空}。

这些代表覆盖每个实值世界在该比较上的结果，且只用合法值（非负时 ≥ 0）。因为值不在别处被消费，按代表分支与按全部实值分支得到相同的步结果集合。

**定理 1（窗口证明可靠）〔证〕**：同上一轮 C-SL 定理（入口完备 L2 + 逐步局部全取值），把秩网格替换为引理 R′ 的代表。另外，"只记可达单元集合并截断"不丢失任何单元：AMBIG 只会让窗口不认证，这是保守方向。

**定理 2（驳倒精确）〔证〕**：
1. 探针与随机样本的每片叶子都是对**被读事实**的一个赋值：锚点左侧取默认值，其余取分支或抽样值，秩取合法代表，WIDE 端点的边强制为空。
2. 扫描结果只依赖被读事实，所以存在与之一致的完整世界 X ∈ Ω(K)。
3. 两片叶子给出不同单元，就是两个合法世界给出不同 F_t，所以确实不可认证。

**定理 3（锚点 0 探针的精确证书）〔证〕**：锚点 0 时没有固定值；路径敏感 DFS 在上限内穷尽所有叶子，每个读取事实都取完整的结果代表（状态 2、方向 3、秩按 R′）。叶子覆盖 Ω(K)，全部给出同一单元即为证书。

**定理 4（支配）**〔论证 + 域〕：BX 的入口集与参考略有不同：孤立目标扩窗时用通用入口，α 下陈旧分析让位于 header。所以这里给的是论证而不是完整证明；`verify.json` 与独立评审 89,059 个参考已认证实例中支配违例为 0。
- 参考签发 u ⇒ BX 签发 u（同上一轮定理 2 的论证，BX 的入口集与已知值读取与参考一致）；
- 旧 C-SL 签发 u ⇒ BX 签发 u（同一窗口证明，比较级代表不弱于网格）。

〔域〕`verify.json` 6 个配置共 2300 个 oracle 核对实例，覆盖 α/β、有符号/非负、合法/接口域、默认/秩聚焦生成器：

| 指标 | 结果 |
|---|---|
| oracle 唯一 | 1286 |
| BX 认证 | **1286**（等于 oracle） |
| 参考认证 | 1119 |
| 旧 C-SL 认证 | 1283 |
| 错签 | 0 |
| 驳倒 | 1014（等于全部不唯一实例） |
| 错误驳倒 | 0 |
| 超预算 / 扩窗到底 | 0 / 0 |
| 支配违例 | 0 |
| 总步数 | BX 12,107；旧 C-SL 21,920 |

截断跳过 276 例（oracle 超过 30,000 个世界），已计入。

**变异检验**：
- "未知秩只取空"被可靠性检查抓到；
- "把窗口歧义当驳倒"在一个需要扩窗的完整知识实例上产生错误驳倒，被抓到；
- "包装不先跑参考"会吞掉失败，被抓到。

#### 3.3.4 成本

**单次调用**：
- 窗口证明：每个窗口最多 4·(t−first+2) 个状态；跨窗口共享，每个状态展开一次。
- 单次展开叶子数 ≤ Π(本步未知事实的取值数)：对象 ≤ 6，秩 ≤ 2。合法域每步至多 5 个对象、2 条边，常数 B ≤ 6⁵·2²，与 n 无关；接口域重叠连接链不受此界约束。
- 可达集合记忆每状态 O(1)。
- 支撑收集一次，O(认证窗口状态数)。
- 近窗探针：O(锚点) 默认路径 + 窗口区域分支，上限 cap = (锚点+1) + 8·(t−锚点+4)。
- 随机样本：S·O(t)，默认 S=4。
- 总量受操作预算约束，默认 4000 step。

**实测**〔实〕（`TABLES.md`"长输入证明失败成本"，单次调用的最小墙钟 / tracemalloc 峰值）：

| 族 | n | 编译核心 | 旧 C-SL | BX |
|---|---|---|---|---|
| 20% 分散缺失 | 256 | 0.89 ms / 23 KiB / need | 1405 ms / 28,762 KiB / need | 8.4 ms / 160 KiB / 精确驳倒 |
| 近目标缺失 | 256 | 0.82 ms / 23 KiB / need | 304 ms / 16,307 KiB / need | 6.7 ms / 178 KiB / 精确驳倒 |
| 20% 分散缺失 | 512 | 1.67 ms / 60 KiB / need | 未跑（无预算） | 65 ms / 738 KiB / **认证** |

- 相对旧 C-SL，降两个数量级。
- 相对只做保守判定的编译核心，BX 多花 5–10 倍时间，换来驳倒或证书。
- n=512 时 BX 签发了编译核心给不出的证书，代价 2,320 步，接近默认预算 4,000。在更长的输入上预算会成为限制。

#### 3.3.5 失效与能推翻它的反例

- **长且确实歧义、但歧义只来自远左侧**：近窗探针用默认值固定左侧，找不到第二个单元；随机样本可能也找不到。此时 BX 扩窗到 0，在锚点 0 探针的上限内结束或超预算，返回 need_facts，不会错签。成本上限就是预算。
- **α 不成立**：α 模式证书可能被后到分析推翻（上一轮已给出反例）。必须用 β 模式；β 模式代价是更多取证与轮次（36 个会话场景合计取证 +8.7%、轮次 +30%，相对基线，见 §3.3.6）。
- **能推翻定理的反例**：任何 BX 签发而 oracle 不唯一，或驳倒而 oracle 唯一的实例。本次 2300 + 测试中的约 1000 个实例都没有。

### 3.4 D4：下一步取什么证据（`lowcost/acq_study.py`）

驳倒给出两个真实世界及它们不同的事实集合（枢轴）。任何把二者区分开的证书都必须学到至少一个枢轴，所以枢轴是这一对世界的必要命中集。由此检验三种取证策略：参考需求、全部枢轴、只取最便宜的一个枢轴。

抽象域冷启动：200 个世界，种子 97，n=3..7；分析全部未知，header 部分已知；一轮内并行取证，秩需要端点分析在轮初有效。145 个世界精确求得最小证书下界，合计 229 次取证（〔模〕，`results/acq.json`）：

| 策略 | 轮次 | 分析 | 秩 | 全部认证 | 超出下界（145 个已解世界） |
|---|---|---|---|---|---|
| REF（参考认证 + 参考需求） | 285 | 392 | 54 | 200 | 62 |
| **BX_REF（BX 认证 + 参考需求）** | **263（−7.7%）** | **367（−6.4%）** | 53 | 200 | **45** |
| BX_PIVOT（驳倒后取全部枢轴） | 324（+13.7%） | 383 | 56 | 200 | 56 |
| BX_PIVOT1（每轮只取一个最便宜枢轴） | 403（+41%） | 361 | 51 | 200 | 36 |

取 J = 分析 + cR·秩 + L·轮次（cA=1），在 cR ∈ {0.5, 1, 4}、L ∈ {0, 1, 10} 的网格上（`TABLES.md`）：
- L = 0 时 BX_PIVOT1 最省（总取证比 BX_REF 少约 2%）；
- L ≥ 1 时 BX_REF 最优；
- BX_PIVOT1 对 BX_REF 的盈亏点约为 L ≈ 0.06·cA：多 140 轮，只少 8 次取证。

结论：
- **"BX 认证 + 参考需求"在这个模型里对参考严格更好**：轮次与取证同时下降，超出下界的取证从 62 降到 45〔模〕。
- **枢轴驱动取证被否定**〔否，本域〕，除非轮次几乎免费。原因是枢轴只保证区分**一对**世界，取到之后常常还有别的世界对存在，于是多出轮次。
- 避免为不可认证请求付费的办法是精确驳倒（D3）：它把"证明失败"的计算降到 O(t) 量级，并且不改变需求，所以不增加取证。

### 3.5 D5：在线稳定的替代规则（`lowcost/alt_rules.py`）

- **发布锚定**：第一个被请求的目标锚定其所在段的配对相位。同一完整输入（6 个窄对象），访问顺序 [1,0,2,…] 得到 {0},{1,2},{3,4},{5}，顺序 [2,0,1,…] 得到 {0,1},{2,3},{4,5}。最终分组取决于访问顺序，违反 H1〔证〕。
- **绝对奇偶**：常数局部性，但正是 H11 明文禁止的"固定奇偶"〔否〕。
- 上一轮定理 6：顺序无关、段相对、每段 o(L) 个单对象的规则都有 Ω(L) 局部半径。结合以上两个反例，本轮没有找到同时满足 H1–H12 且在线局部的替代规则，因此**不提出路线 B**。这是"在这些前提下无解"的结论，不是一般不可能定理：放宽 A2/A3 的规则未被排除〔待〕。

## 4. 淘汰记录与下界

| 思路 | 结论 | 证据 |
|---|---|---|
| 未知秩当作已知空值（单一代表） | 〔否〕 | 秩聚焦生成器上产生错签（变异测试） |
| 窗口歧义即视为不可认证 | 〔否〕 | 完整知识、需扩窗的实例上错误驳倒（变异测试） |
| 跨窗口按状态累积读集（旧 C-SL） | 〔否〕（成本） | O(t²) 集合复制；n=256 时约 1.4 s、峰值约 28,800 KiB〔实〕 |
| 在每个扩窗点倍增锚点的路径敏感探针（本轮早期版本） | 〔否〕（成本） | n=256 时探针占 33,786/37,059 步；改为近窗一次 + 随机样本 + 锚点 0 一次 |
| 每个分支从位置 0 重跑探针（本轮早期版本） | 〔否〕（成本） | 改为在分支处检查点重启 |
| 只在秩变化时给邻居加戳（本轮早期版本） | 〔否〕 | `Stamps` 真实性测试抓到边失败证据变化漏戳 |
| 全局戳从不递增（本轮早期版本） | 〔否〕 | 独立评审：settings/代次变化时快路径会接受指纹校验拒绝的证明；已加全局变更接口与变异测试 |
| BX 证书只收存活入口的前置读取、α 只在分析未计算时收 header（本轮早期版本） | 〔否〕（**可靠性缺陷**） | 独立评审给出两个过期证书仍通过校验的反例；修正后加入回归测试、"只收存活入口"变异测试、未读位置变更模糊测试 |
| 驳倒枢轴驱动取证 | 〔否〕（本域） | §3.4 |
| 发布锚定规则 / 绝对奇偶 | 〔否〕 | H1 反例 / H11 |

**不可消除的成本**：
- 会话在候选接口内的 O(n) 输入构建（T7）；
- 确实不可认证的请求至少要一次驳倒，成本 ≥ O(t) 具体扫描：要构造合法世界必须给出从起点到目标的完整路径；
- 上一轮定理 5 的 ⌈d/2⌉ 证书下界仍然适用于长均匀段，它限制的是需要的事实，而不是表示的成本。

## 6. 回到宿主后的最小验证清单

1. **α/β 判定**（决定 BX 与 header 相关路径用哪种模式）：宿主中有效 header 的占用分类能否在同一内容版本内被后到分析推翻。
2. **核心差分**：在冻结原实现的 1,806 组差分域上逐字段对比 `fastcore.certify`，包括 needs 顺序和 steps。重点核对非默认旋转/方向与失败枚举。
3. **读集完整性审计**：宿主认证路径上是否有未被 `proof` 记录的输入，如设置成员资格、缓存层、外部回调。
4. **下游消费者**：谁在读参考 `reads` 的类型化内容；它们能否改为消费 `proof`。
5. **戳前提 P_stamp**：宿主知识层的所有证据变更点（包括失败清除、元数据确认、驱逐、重绑定）是否都能给受影响位置加戳；用 `Stamps` 测试的方法在宿主事件流上回放核对。
6. **BX 预算与上限**：在宿主真实输入长度下标定 `budget`、近窗探针上限与样本数 S；记录超预算比例。超预算不签发，但会付出成本。
7. **成本参数**：宿主上一次展开、一次取证（分析/秩）、一轮的固定延迟。没有这些，不能把 E2/E3 的轮次与取证变化换算成等待。
8. **协议层**：BX 采纳后需求集合变化时，在途任务按身份复用、不取消（上一轮 KEEP 结论在合成切片内成立），不可抢占任务实际退出前不释放名额。
