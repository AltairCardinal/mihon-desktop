# 问题定义

## 1. 研究对象

给定有限有序对象序列 `I=(i0,…,i(n−1))`。系统按固定语义把它划分为单对象单元或相邻二对象单元；每个成员还带一个槽标签和必要的结果标签。输入事实逐步到达，可能失败、失效或被移出原始见证缓存。

系统需要在不必取得所有事实的情况下，为指定目标确定其最终单元；在保证正确的同时减少必要等待、重复工作和资源成本。查询目标及访问顺序可以影响取证过程，不能改变同一完整输入的结果。

本问题同时包含：确定性规划、部分信息认证、增量失效、资源协议及稳定发布。它不要求把所有层合并成一个复杂求解器。

## 2. 输入、输出与约束

### 2.1 输入版本

上下文版本 `v` 至少区分：对象清单与稳定身份、对象内容版本、特征算法版本、变换、方向模式、规则设置和外部约束修订。

输入可包括：

- 每对象的两个几何尺度及离散变换；几何可能未知。
- 每对象的方向性标签 `A / B / NEUTRAL`；已知 `NEUTRAL` 与未分析不同。
- 每有向相邻候选边的秩或已知无有效秩；内建特征过程产生非负秩，但通用回调接口的扩展域可以更宽。
- 硬隔离集合、被指定的相邻连接、初始模式、自动规则开关和对象顺序的方向解释。

完整输入 `X_v` 包含确定这些事实的潜在原始见证。内容身份是版本管理约定，不意味着算法能够从一个身份标记反推出未知事实。

正常输入的外部约束必须先通过调用方合法性检查。互相重叠的指定连接、越界引用或冲突不能被默默删去。参考程序提供低层接口，没有完整实现该预检；其接口域测试可以传入非法约束以观察既有分支，但不能计入正常输入收益。

### 2.2 分区与完整目标结果

令 `x_j∈{0,1}` 表示连接相邻对象 `i_j,i_(j+1)`，令边界虚拟量 `x_(-1)=x_(n−1)=0`。必须满足：

```text
x_(j−1) + x_j ≤ 1
y_j = 1 − x_(j−1) − x_j
```

每个对象恰好出现一次；单元仅包含一个对象或两个相邻对象；源顺序和身份保持。硬隔离与完整占用对象禁止相邻连接；合法指定连接按明确优先级执行。

参考完整计划记为 `Γ(X_v)`。目标投影 `F_t(X_v)=π_t Γ(X_v)` 包含：

1. 单元成员和成员顺序；
2. 每成员的槽标签 `A / B / ALL`；
3. 完整占用或单对象原因等语义标签；
4. 参考接口规定的确定性标记。

只比较成员集合不够。成员相同而槽、原因或确定性不同，不能自动算作等价。

### 2.3 参考策略的性质

现策略按顺序扫描，受初始相位、前瞻竞争和原子预留状态影响。候选比较具有确定的优先级和同分规则。它不等于“最大化所有被选边的秩之和”，也不保证仅凭固定长度窗口即可决定任意目标。

精确分支以 `reference.py` 为可执行定义；该文件中的策略是等价研究的参照，而不是全部用户目标本身。区间摘要是否充分、禁止边是否重置全部前缀影响，都需要证明。

## 3. 部分知识

### 3.1 事实状态

每类事实至少区分以下状态：

| 状态 | 含义 |
|---|---|
| 未观测 | 尚不能据此作肯定或否定结论 |
| 已知值 | 当前版本下已取得有效结果 |
| 已知空值 | 已完成判定，结果是无有效秩或无方向偏好 |
| 可重试失败 | 当前取证失败，带失败类别及身份；不等于已知空值 |
| 已失效 | 结果不再匹配当前上下文，不能继续作为证据 |

知识可靠性与见证驻留分开建模。原始见证被淘汰后，已经确定且版本仍有效的标量可以继续存在；但缺失的另一条边未必能仅靠该标量恢复。

同一上下文内可以累积知识；跨版本不能假设知识单调增加。已知事实也不保证当前持有相应的物理资源。

### 3.2 可能世界与证书

`Ω(K,v)` 是与当前知识 `K`、版本和生成规则一致的完整输入集合。稳定目标认证要求：

```text
{ F_t(X) : X ∈ Ω(K,v) } 只有一个元素
```

证书是这个不变性的有限证明记录，并带能够验证有效性的依赖。工程认证器可以保守：真实答案已唯一时仍等待；但不能在存在不同答案时签发。

该定义只针对结果确定性。它不自行豁免失败传播、资源身份、发布权限和运行协议。跳过一个不影响数值结果的查询，仍可能改变必须处理的失败。

### 3.3 可实现域与扩展域

必须区分三个集合：

1. **生成域**：事实由共享潜在见证经确定映射产生，存在相关性；由原实现处理合成见证得到的少量匿名导出实例，可证明某些组合确实可实现。
2. **抽象扩展域**：测试中可以直接指定标签和标量。这方便寻找规则反例，但未必每个组合都可由见证产生。
3. **当前知识对应域**：只允许补全当前未知部分，不能修改已经观察到的事实、缓存中可见见证或版本约束。

如果在更大的保守域上证明性质，则在其子域上仍成立；若在扩展域发现反例或估算收益，必须检查它能否映射回生成域。尤其不能用不可能共同出现的标签和边值证明信息下界。

本包不提供原始特征提取器的完整生成域刻画。有关生成域可实现性的普遍结论是待证明义务，而不是可以默认满足的假设。可以研究参数化生成器，但须把其范围与已验证实例分开。

## 4. 在线状态与动作

一个适用的系统状态描述为：

```text
S = (v, K, R, J, C, P, H)
```

- `v`：当前输入与规则版本；
- `K`：有效观察知识及失败；
- `R`：驻留的原始见证、派生值和资源占用；
- `J`：排队、执行、完成待接纳的任务及消费者；
- `C`：证书、读集及复用索引；
- `P`：当前可对外发布的单元与权限；
- `H`：已经被实际观察及有效确认的历史。

动作可以取得元数据、取得原始见证、派生多个事实、执行认证、验证依赖、复用任务、发布单元或使旧状态失效。一项实际工作可服务多个消费者，不能把共享工作按每条逻辑事实重复收费。

事实在异步完成时必须先验证身份，再接纳；完成通知不必等于资源已经归还。取消不可抢占任务时，取消意图与任务真正终止是两个事件。

`protocol.py` 仅实现这里若干硬协议的合成状态机。它不表示整个真实资源调度器已经实现，也不提供实际任务时长或负载分布。

## 5. 不可互相补偿的目标

先满足 `CONTRACTS.md` 中的硬性质，再比较成本向量：

```text
(首次正确结果延迟, 完整目标就绪延迟, 连续请求尾延迟,
 实际读取次数与数据量, 派生计算次数, 认证工作,
 依赖验证工作, 峰值驻留量, 后台干扰, 失效后的剩余工作)
```

延迟从请求意图开始计算，不能把成本藏在准备完成之前或移到无统计的预处理阶段。并行工作有重叠，应以受资源约束的事件图或实际时间线分析关键路径，不能简单相加所有动作时长。

预处理至少计为 `C_pre + Σ C_request`；显式输出 `k` 个变化单元时计入输出成本；复制快照、构造依赖、缓存校验和内存占用均不能省略。

没有统一给定的毫秒阈值，也没有默认输入分布、失败率或无限网络保证。需要概率或有界任务时长的结论必须列出条件。有限状态域内的命中比例不是真实工作负载频率。

## 6. 两种合法研究路线

### 路线 A：等价改进

对所有合法完整输入保持 `Γ_new(X)=Γ_reference(X)`，并满足运行协议。可以改变状态表示、查询次序、依赖组织、缓存、增量算法和调度；不要求内部执行轨迹逐步相同。

部分信息时允许比参考算法更早可靠认证，或减少不必要需求；不能以“原来要等”为由禁止改进，也不能以“最终答案相同”为由跳过失败和身份合同。

### 路线 B：替代规则

允许提出新的确定分组规则或目标函数。必须列出：最小输出差异、新目标的根据、全部优先级、信息依赖范围、语义迁移成本及仍保持的硬性质。

一个规则有唯一最优解，并不证明它更符合未提供的外部真值。缺少标注时，可以证明结构性质和成本，但不能宣称识别质量更好。

替代规则属于待裁定方案，不能伪装成语义等价的优化。

## 7. 下界与反例的正确用法

若两个可实现完整输入在所有可观察状态上相同，却有不同的目标投影，则只凭这些观察不能稳定认证。必须给出两者的具体补全、共同知识和不同结果。

这不意味着整个任务不可行：必要信息可以与已有工作共享、提前取得，或以更低成本取得。也不能把严格零等待的不可能性，当成全部体验目标不可能的证明。

对任意优化，优先寻找最小反例：状态充分性、相位与预留、失败短路、版本更新、缓存淘汰、事件乱序、旧任务提升与发布后迟到信息。区分“反例已成立”“需要更强前提”“暂未找到反例”。
