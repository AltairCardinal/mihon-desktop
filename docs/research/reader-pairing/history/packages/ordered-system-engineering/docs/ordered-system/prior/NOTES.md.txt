# 上一轮探索代码：范围与已知问题

这三个模块保留上一轮已修正的探索程序：`model.py`、`branching.py`、`validity.py`。
导入前缀已适配本包；它们不是宿主中后来硬化版本的逐行移植。

- `certify_sl`：局部分支、状态合并与跨窗口可达结果记忆。候选思想是在所有允许补全给出同一
  unit 时提前认证，而不是触及未知即等待。
- `certify_pw`：路径敏感枚举，用作小域精确对照；不可默认用于大规模部署或完整基准。
- `certify_contract`：保留失败合同的组合。β 请求必须先移除不权威 header；不能直接透传 α 证书。
- 局部有效性原型：区分 scope 存储和完整输入读取成本。作用域本身若每次重建也会有分配代价。

已经发现并修过的问题：β 包装绕过、抛出分支的失败尝试漏计、只缓存展开却重复传播旧窗口、
校验前构造完整输入。不要重复引入它们，也不要只看某一个 step 计数就声称整个调用线性。

该探索版本没有完整的生产操作预算，不得在未知数很多的长输入上无界运行。默认 quick 基准
不调用这类无预算枚举。新算法应提供真实可终止的预算接口，不能靠外层计时后才发现超额。

与历史实测候选不同：实测版本采用更保守的入口与失败处理，并有不同的运行时、对象表示和缓存
生命周期。此目录的 Python 耗时不能复现历史实测绝对值；需在同一环境、同一策略合同下重新比较。

数学下界也有前提：长段证书依赖不意味着所有压缩表示都不可能更快；替代规则的局部性障碍依赖
段相对性与单对象数量限制，不能从某个附加假设下的下界推断所有替代策略都失败。
