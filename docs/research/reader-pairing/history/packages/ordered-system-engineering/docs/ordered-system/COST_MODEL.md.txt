# 成本、负载与采用判断

## 历史观测怎样使用

`evidence/observed_costs.json` 与 `evidence/raw_baseline.jsonl` 是匿名化的历史底层实测。
其配置 `base/scoped/branch/both` 分别表示扩窗基线、局部身份校验、额外分支认证、组合。
它们是同一候选内的策略配置；不是四个独立生产发布版本。

每个配置有 3 个独立进程，每进程 30 次重复。计时批次包含固定的多个构造状态，不能把整批耗时
当成一次普通请求，也不能把 90 条记录当成 90 个独立进程。历史复用阶段直接比较同一次 base
运行的结果读集，含 certified、need_facts 和 blocked；不是分别测量 branch 所选证书的生命周期。

这些观测支持“当时那种实现存在较高计算/分配成本”，但不能证明某算法思路无价值。它们没有
自然触发频率、实际取证节省或请求到首个合法发布的耗时；短批次线程 CPU 还受粗粒度计时限制。
累计分配不等于峰值内存。新本机实验与历史数据不能跨运行时直接比较绝对值。

## 最新实现进展

历史观测之后已出现“作用域预计算”和“每步网格复用”的实现探索，仍在迭代，尚未完成本次
独立验收。不要把旧的负成本结论自动套到这一版，也不要把未冻结/未验收的新测量当成采用证据。
如果数据中包含 provisional 观察，须单独展示，不能混入 confirmed 汇总或自然频率。

## 要优化什么

主要指标是完成一个合法请求所需的总工作和等待；证书数量和 scan step 是中间指标。
使用多目标或带约束优化，不任意挑选权重把退化藏进综合分数。

| 分量 | 至少记录 |
|---|---|
| 内存计算 | 输入/索引、展开、分支重跑、传播、排序、复制/合并、作用域、校验、回退 |
| 内存资源 | 持久条目、临时峰值、累计分配、缓存大小；不可测项 N/A |
| 物理工作 | 实际开始、复用、提升、取消、完成、接纳；不要用 needs 条目替代 |
| 等待 | 请求→合法发布；模拟时钟与本机墙钟分列 |
| 正确性 | 错签、不安全保留、旧完成发布、重复工作、必须报告的错误 |

## 参数化服务时间与敏感性

未提供真实服务时间分布。模型可以注入确定值、长尾或相关延迟，但必须标为 synthetic。
至少展示“取证便宜/昂贵、可避免失效稀疏/密集、缓存冷/热”的敏感性，不挑一个有利成本比当真实负载。
不要把历史计时与模拟服务时间相加成“已测用户时延”。允许报告参数条件下的界或盈亏曲线。

“少一次失效省多少”必须按实际会触发失效的请求条件测量，不能用混合域平均认证时间替代。
对比应包括校验及必要重算，固定元数据确认比例可用 0%、1%、5%、20%、100%，明确是构造轨迹。

## 同一环境下的新基准

先跑短基准，再在固定配置下比较候选。记录种子、输入摘要、配置、进程、源码/候选摘要、
冷/热的具体定义、预热和测量次数；所有输出结果要被消费。
每个候选的已采纳、被拒绝、超预算及回退尝试都计入。小规模全补全可验证唯一，随机补全只用于找反例。

可以排除不合法外部约束，但需保留它们的接口回归，分母不能悄悄改变。证据截断列为未穷尽。
无可靠精确区间时明确写“不足以确认收益”。原始数据和生成配置应随结果交付。

## 采用判断

- 等价路线必须保持完整结果语义、失败及发布合同；错误证书和不安全保留不可用性能收益抵消。
- 净收益需在预先声明的负载和成本条件下成立，给出绝对差、退化案例及分摊成本。
- 仅某些可检测条件下有收益，就给出可检验的启用条件；没有测到条件时不建议默认开启。
- 允许“当前实现不采用”或“只保留数学机制”。不允许把某个实现的负结果推广为一般不可能定理。
