# 修复轮 Q1：A04 / B01 / B05 / D04 / D05 的证明、反例与证明范围

所有数字来自 `results/raw/fix/Q1/` 下由 `bench/run_fixQ1_*.py` 生成的原始文件。冻结规则 `reference.py` 视为可信；
"exact DP" 指 `omega.certify_exact`（R9/R8 已对世界枚举核对）。

## A04-1　两种协议都满足 I1–I8（有界模型上的穷举，不是一般证明）

**模型**：`fixQ1_a04.small_case()`（n=6、目标 4、缺一条秩、两项服务）上的真实 `StrongSession` 加上 harness 级关闭协议。
事件字母 {P 证明结果到达, L L0 重认证, Fa, Fb 服务完成, X 全部取消, R rebind 失效, K 关闭, C 确认}，Fb 有三种隐藏结果
（正常 / 无 raw 见证 / 晚失败 = 分析 failed）。FL = 首个合法结果胜出；FP = 证明只在下一次服务完成处提交（两阶段）。

**穷举范围**：含 K 的 8 事件全部 40 320 种顺序 × 3 种 Fb × 2 协议；不含 K 的 7 事件全部 5 040 种顺序 × 3 × 2；
重复证明完成（多重集 {P,P,L,Fa,Fb,X,R,C} 的全部 20 160 种不同顺序）× 2 协议。相同时间戳 = 相邻事件的两种排列都被枚举。
**结论（只对该模型与该案例成立）**：违例 0（I1–I8）；不含 K 的顺序全部以"已发布"（Fb 正常/无见证）或"blocked 终态"
（晚失败）结束，两协议逐顺序结局相同；含 K 的顺序全部满足"关闭后不发布、不确认、运行中任务退出前不释放、全部退出后
owner 关闭、证书/发布清空"。
**变异体被杀**（说明不变量有判别力）：提交不复核支撑、关闭立即释放运行中槽位、关闭保留发布、去掉首胜守卫（在重复完成中
产生双发布 I8）。

**为什么 FP 不更安全**：FP 的提交点恰在一次服务完成之后，而这次完成往往改变证书支撑（派生出缺失的秩），所以 FP 比 FL
更依赖提交时复核（"提交不复核"变异在 FP 无关闭集合上 5 040/5 040 顺序违例，FL 196/5 040）。两协议的安全性都来自
`Session.publish` 的支撑复核 + epoch/guard，而不是来自阶段屏障。

## B01-1　ZDD 摘要与表摘要表示同一关系；合成充分

设块 b 的入口键集合为 K_b（来自 Lemma B-1 的边界接口：游标态、b−1…b+2 的 state/side、边 b 的秩选择、活序约束分量），
表路线存 R_b ⊆ K_b × K_{b+1}，ZDD 路线存同一 R_b 的特征族（入口字面量相对 b·B 编号、出口字面量相对 (b+1)·B 编号）。
`image(F, R)` 返回 {out(S) : S∈R, in(S)∈F}：递归按字面量全序同步下降；遇到出口字面量时恰当 F 含空集（入口部分完全匹配）
才保留——这是 ZDD 上"入口相等"的连接，等于表路线对 F 中每个键查表取并。`retag` 是保持全序的结构映射。
故两路线在每个块边界上的前沿相同，由 Theorem B-2（R9）等于 exact DP 前沿。**唯一性**：零抑制 + 唯一表 ⇒ 对固定字面量序，
同一族只有一个节点（规范）；不同块相对编号相同的关系是同一节点（`distinct_relations` 计数）。
**核对**：随机 150 例 1 844 次查询两路线与 exact DP 0 不一致；受限字母表上 **全部** n=3 部分案例（1 125 例、3 375 次）
对世界枚举 0 不一致，**全部** n=4（16 875 例、67 500 次）对 exact DP 0 不一致。

**最小跨界变量（经验，非证明）**：在每个边界遗忘一类变量（block=1，3 000 个随机例，三种剖面）：
state(b−1)、state(b)、state(b+1)、side(b)、side(b+1) 必要（改变目标单元集合的例数 82/309/87/144/62）；
state(b+2) 罕见必要（2/3 000）；秩选择 rk(b) 与序约束 lt 在 ext 域 3 000 例中不必要，但定向搜索 205 234 例（nonneg 域，
秩高度未知）各有 200 例必要；manual 位、side(b−1)、side(b+2) 在 3 000 例中从不必要——manual 位冗余与 R8 引理 L-M2 一致
（有证明），side(b−1)/side(b+2) 的冗余**没有证明**，只是未观察到。因此最小接口 = Lemma B-1 接口去掉 manual 位；
side(b−1)、side(b+2) 是否可删为开放问题。

## B05-1　两条反向路线都不删除合法补全

GOAL（R9）：剪掉的前沿元素只可能补全到 u0（树关系对"可达"过近似），故不会删掉单元 ≠ u0 的世界；结论用 `pruned>0`
补回 u0。MITM：任一合法世界 w 的运行在 m 处经过前沿键 f（exact DP 的完备性）；从目标向后，每一步的前驱键是在后继约束下
重算步 i 得到的，w 自身的赋值实例化了其中一个前驱，投影掉的变量只被后缀读取（位置 ≥ i+3、边 ≥ i+2）、序约束整体保留，
所以 w 的单元 u 在 m 处有与 f 相容（同游标态、公共变量一致、序约束联合可行）的后向键 ⇒ u 被保留。
**核对**：随机网格 54 例 × 3 种汇合距离与 exact DP 单元集合逐个相同（0 删除、0 多余），设计负载 12 例同样。

## D04-1　区间记忆对完整公开观察精确，并严格宽于签名记忆

冻结扫描只在 `later_wins(i)` 中读秩，且只以 `b is not None and (a is None or b < a)` 使用（a = r(i,i+1)，b = r(i+1,i+2)）。
因此一对相邻秩的全部决策内容是 null 标志与指示 [b<a] = [δ<0]（δ = b − a）。若非秩读值逐字相等、null 标志相同、
每个被读相邻对的 δ 留在原区间（(−∞,0) 或 [0,+∞)），则每一次尝试做出相同决策、按相同顺序读相同键、返回相同公开字段
（status、unit、needs、failures、first、steps、dependent_items）。SIG 额外冻结 [a<b]，这个位从未被读取。
**范围**：被检查的"相邻对"是支撑中相邻的两个秩键；若两键实际在不同的 later_wins 调用中被读（从未互相比较），
条件仍充分（更严），不影响正确性。
**核对**：分数 {1,2,3}、每边 ±0.5 的全部 n=3–5 链变化 3 996 个：区间接受 3 618、SIG 接受 3 276，区间接受的变化中
公开观察改变 0 个；8 种负载 × 8 条轨迹逐请求与新建 owner 比较 0 不一致；把区间边界写成 δ≤0 的变异体 681 次不一致。
**结果复用 ≠ 完整观察复用**：存在只保持规范单元、而 `dependent_items` 改变的值变化（最小例：n=5 全 1 链、目标 3、
边 2 +0.5，dependent_items [0..4]→[1..4]）；只为单元消费者服务的复用在这种变化下合法，但不能当作 L0 公开结果复用。

## D05-1　活序约束分量的界（证明）

自动模式下秩比较只发生在 `later_wins(i)`（边 i 与 i+1），且只在 `can_pair(i)` 时。若返回 True 且 i>0，
下一游标 reserved = i+1，步 i+1 直接成对、不比较，下一次比较在 i+3 或更后；若返回 False，(i,i+1) 成对，
下一次比较在 i+2 或更后，涉及边 i+2、i+3。所以两次比较只可能在开局（i=0 不能 reserve）共享一条边：
活分量至多 2 个约束 / 3 条边（开局），其余位置至多 1 个约束 / 2 条边，与 n、指定连接、隔离无关（它们只会去掉比较）。
**核对**：405 个案例（随机含开局/指定连接/隔离、长全未知秩链 n≤32 × 3 种开局 × 2 方向、指定连接、隔离、全未知状态）
观测到的最大值是 1 个约束 / 2 条边（开局的 2 约束上界未被触及）。
**复杂度的精确依赖**：exact DP 的步调用数 = Σ_i Σ_{f∈前沿_i} |explore 结果|，前沿大小 ≤ 10 · 6^{u} · 2 · c，
u = 窗口 [b−1, b+2] 中状态/侧未知的位置数（≤4），c = 活序约束分量的可行结果数（由 D05-1 有界）；所以代价对 n 线性、
对"窗口内未知事实数"指数，而不依赖链长。
