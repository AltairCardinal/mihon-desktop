# 输入字段与证据范围勘误（R10 修订）

原始输入文件一律不改。下面是对字段含义和证据范围的澄清；研究输出中所有受影响的引用都已逐项修改（见 `CHANGELOG.md`）。

## E1 N0 的 `proof_work`

- 含义：只统计额外的强证明工作（strongWork），**不包括普通认证**。
- 推论：`proof_work = 0` 只说明没有额外强证明，**不能推出“全部证明工作为 0”**。窗口内普通认证做了多少工作没有记录。
- 处理：`lab/n0_structure.py` 中的字段已改名为 `strong_proof_work_*`，普通认证工作标为 UNKNOWN。“N0 窗口内证明工作为 0”的说法已撤回。

## E2 N0 没有授权时刻

- 成员已经物化，不等于完整 unit 已经授权。N0 没有记录 C_i（unit 被授权的时刻）。
- 处理：撤回“N0 是 H1 的真实同类实例”和“H1 已在已测路线上成立”两句。N0 的真实计数仍然保留：变换调用 54/54、成员在意图前约 247–279 ms 已变换完成、意图到完整绘制 145.5/154.3 ms。但这些数字不能说明授权之后的时长是多少，也不能说明它在干预下会不会变。

## E3 R0 错误首槽的原因

- 已知原因：完整认证和 canonical 结果是正确的。错误出在发布/历史层：在结果还没有 Certified 时，就提前锁定了一个猜测结果。
- 处理：R0 的错误结果（目标 169 发布成 [169,170]）保留为失败证据；撤回“R0 是固定窗口截断导致错误的真实实例”。固定窗口不精确的结论只靠抽象构造独立成立：
  - 链族 [X,(Y|X),X×m] 的长依赖；
  - 长链族中固定回看窗口在 300 个目标里错误 74/55/30/10/4 次（回看 2/3/5/8/16）。
- R0 现在说明的是另一类风险：在 Certified 之前发布或锁定结果。这一类风险由 Q055/Q060 的协议模型覆盖。

## E4 “23 个支持对象”与“至少 6 轮”

- 正式数据中目标 169 的 `support_objects` 是认证所依赖的对象，**不等于** 意图时刻还未知的任务数。其中一部分事实可能已缓存，或已由之前的工作取得。
- 轮次下界成立需要三个定义：
  1. 意图时刻缺失的任务数 m_miss（包内没有记录）；
  2. 任务粒度：一次物化可同时产出方向分析与两侧边样本，边样本需要两个对象，所以“一个对象一个任务”只是假设；
  3. 轮次：一次 certify → need → 取得循环。4 路并发表示同时在途的任务不超过 4 个，不等于每轮能取得 4 个事实；而且在 C10 的逐个回退纪律下，下一轮的需求要等上一轮结果出来才知道。
- 修订后的表述：**若** m_miss 个任务都必须取得、每个任务服务时长相同、需求可以事先全部知道（允许投机），**则**轮次下界为 ⌈m_miss/4⌉。只有在 m_miss = 23 且一个对象恰好对应一个任务时，才得到“6 轮”。在逐个发现需求的纪律下，精确调度给出 m_miss+1 个服务时段（m ≤ 7 的小域已验证）。观测到的 20–29 轮与逐个回退的结构相容，但不能用来推出 m_miss。

## E5 摘要树结论的范围

“摘要树任何规模都不胜出”改为：**在已测的实现与负载下**摘要树不胜出。具体范围：

- Python 实现，叶大小 8，确定性检查点间隔 16；
- n = 48/176/1024 个对象，每次 20 个随机目标查询，或 20 次单点几何翻转加查询；
- 完整知识，3 个独立串行进程。

本轮没有证明更广的结论。另外，检查点需要完整的前缀知识，而有限入口认证在部分知识下也能工作，两者适用的输入域不同。

## E6 外部参照

旧的 20 000 例差分（`lab/gamma_xcheck.py`）依赖上一包的 `reference.py`（环境变量 R9_REFERENCE），而这个参照不随本包提供。因此这项差分只算**历史证据**，本包不能独立复现它。本包自带的中性检查见 `lab/gamma_ref2.py`：这是只依据语义参考重写的独立实现，不调用 `gamma.py` 的任何判定函数。另有手算黄金例。两者见 `tests/test_revision.py`。
