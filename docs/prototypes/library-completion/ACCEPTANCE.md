# 书架完整 Roadmap：交互审核清单

本清单对应 [产品 roadmap](../../roadmap/2026-09-28-desktop-library-completion-roadmap.md) 的全部 19 项需求。勾选表示审核者认可本地 HTML 中的交互，不代表 Kotlin 产品实现、数据迁移或原生设备验收完成。每个场景从外层工具栏重新加载，避免前一场景的筛选、选择或设置影响结果。

## 审核方法

打开 [并列 DEMO](index.html)。外层工具用于选择目标端、加载样本、模拟故障/时间/设备条件；iframe 内是拟议产品操作。先按 Windows 流程审核，再对 Android 检查相同业务结果。Windows 的 Ctrl 操作仅在 Windows 端适用；Android 使用长按和选择模式。

以下是固定验收目标。条目保持未勾选，供用户审核；自动测试的实际结果另记在 [README](README.md)，不能据此自动勾选用户意见。

## A. 展示、封面、评分和分类（L01–L06）

- [ ] **A01 / L01**：加载大书架 → 分别切紧凑网格、舒适网格、仅封面、列表 → 拖动内容右侧滚动条可到末尾并返回顶部，不启动更新。
- [ ] **A02 / L01**：在分类 A 滚到中部 → 切分类 B 滚动 → 切回 A → 恢复 A 的浏览位置；进入详情再返回也保持位置。
- [ ] **A03 / L02**：打开漫画详情 → 替换自定义封面 → 返回书架 → 四种布局均显示自定义封面；详情与书架一致。
- [ ] **A04 / L02**：已有自定义封面 → 模拟源封面版本变化 → 自定义封面仍优先；删除自定义封面后显示最新源封面。同地址版本改变能看出变化。
- [ ] **A05 / L03**：有未读章节的作品 → 显示页关闭未读角标、保留继续阅读按钮 → 角标消失而按钮仍在，点击进入该书未读章节预览。
- [ ] **A06 / L03**：全已读作品没有虚假的继续入口；多选时继续按钮遵循选择动作，不误入阅读器。
- [ ] **A07 / L04**：加载追踪评分样本 → 按评分排序 → AniList 百分制与十分制服务统一成十分制比较，多服务按规范化均值排序，无评分有明确展示。
- [ ] **A08 / L05**：单追踪服务样本 → 筛选显示“已追踪”；多服务样本 → 显示可读服务名，不显示内部数字 ID。
- [ ] **A09 / L05**：仅设置一个追踪筛选 → 顶栏提示筛选生效；连续点击经历不指定、包含、排除，结果随状态变化，清除后提示消失。
- [ ] **A10 / L06**：唯一自定义分类 → 分类标签仍可见；唯一系统默认分类 → 不强加无意义标签；显示设置关闭分类标签后遵循开关。
- [ ] **A11**：深浅主题切换 → Windows 网格封面保持 7:10、Android 保持 2:3；列表采用独立小封面，不拉伸成网格。

## B. 统一筛选／排序／显示面板（I04）

- [ ] **B01**：书架顶栏打开“筛选、排序与显示” → 同一模态含三个标签；关闭后重新打开默认“筛选”。
- [ ] **B02**：再次点击当前底栏“书架” → 打开同一面板，不重置分类、查询或滚动；已有面板不叠加。详情前台时不误开根书架面板。
- [ ] **B03**：筛选页逐个操作下载、未读、已开始、书签、完结、周期及追踪条件 → 三态文字清晰；结果即时生效，组合条件和搜索共同作用。
- [ ] **B04**：启用全局仅下载场景 → 下载筛选强制包含且不可改；解除全局条件后恢复正常编辑。
- [ ] **B05**：排序页检查标题、章节数、最近阅读、最近更新、未读数、最新章节、获取时间、加入时间、追踪评分、随机，共 10 项；适用项目可切升降序。
- [ ] **B06**：重复点击随机排序 → 再次重排，而不是显示无意义的升降序；其他偏好和选择保持。
- [ ] **B07**：显示页切换四布局，分别调横向和纵向列数 0–10 → 0 为自动；旋转/改变宽高后消费对应列设置。
- [ ] **B08**：依次开关下载数、未读数、本地、语言角标，继续阅读、分类标签、分类数量 → 只改变对应展示，关闭面板后保留。
- [ ] **B09**：面板三页分别滚动再来回切页 → 各页位置在本次会话内保留；操作即时保存，无“应用”才能生效的隐藏草稿。
- [ ] **B10**：注入下一次偏好保存失败 → 修改选项 → 显示错误并恢复权威旧值；关闭重开不出现假成功值。
- [ ] **B11**：已有搜索和多选 → 重选书架开面板并筛掉部分已选漫画 → 隐藏选择仍保留；Escape 第一次关面板，第二次退出选择，第三次退出搜索。
- [ ] **B12**：面板内连续 Tab / Shift+Tab → 焦点留在面板、背景不可操作；关闭后回触发器，触发器不存在时有可用回退焦点。
- [ ] **B13**：面板打开时切深浅主题、调整窗口 → 设置、当前页、焦点和滚动保持；不抢另一设备或外层工具焦点。

## C. Windows 分类切换和多选（I01、I03）

- [ ] **C01 / I01**：鼠标位于 Windows 书架内容区 → Ctrl+滚轮向上／向下 → 切上一／下一分类，首尾不循环且不缩放页面；同向事件间隔小于 250ms 只切一次，停顿至少 250ms、反向或释放后再按 Ctrl 可再次切换；Ctrl+方向键不再切分类。
- [ ] **C02 / I01**：搜索输入框正在编辑、模态、详情页内 Ctrl+滚轮 → 不切分类；Alt/Shift 同时按下、横向滚动或输入法组合输入时也不消费；Android 不接入 Windows 的 Ctrl+滚轮分类。
- [ ] **C03 / I01**：已有查询、筛选、跨分类选择 → 切分类 → 均保留；载入该分类排序和浏览位置，分类名和数量反馈正确；更新中仍能切类，原任务范围不变，Ctrl+滚轮不触发顶部刷新。
- [ ] **C04 / I03**：标准 A–E 可见顺序 → 普通单击 B → 直接打开详情，无双击要求。已有选择时普通单击只增加／取消目标选择，保留其他选择并更新锚点，不打开详情；取消最后一项只退出多选并清除锚点，下一次普通单击才打开。
- [ ] **C05 / I03**：Ctrl 点 B → 仅 B；Ctrl 点 D → B、D；Ctrl 再点 D → 仅 B；最后一项取消后退出选择，不导航。
- [ ] **C06 / I03**：重置后 Ctrl 点 B → Shift 点 E → B/C/D/E；继续 Shift 点 C → B/C，证明锚点固定且范围能收缩。
- [ ] **C07 / I03**：承接 C06 → Ctrl 点 E → B/C/E、锚点 E；Ctrl+Shift 点 D → B/C/D/E，追加而不清其他选择。
- [ ] **C08 / I03**：从较后项向前 Shift → 反向闭区间包括两个端点；排序变化后范围按当前可见顺序计算。
- [ ] **C09 / I03**：分类 A 已选若干项 → 切分类 B 后 Shift 点目标 → 旧选择保留，不跨分类生成区间，只以目标重建锚点。
- [ ] **C10 / I03**：筛选隐藏原锚点 → Shift 点可见目标 → 当前可见选择替换成目标单项，隐藏旧选择保留；Ctrl+Shift 则追加。
- [ ] **C11 / I03**：有锚点时长按另一项 → 追加闭区间且保留锚点，松开不打开详情；无锚点时长按进入单项选择。
- [ ] **C12 / I03**：全选／反选只作用当前可见集合、保留隐藏选择并清锚点；之后 Shift 从目标单项重新建立范围。
- [ ] **C13 / I03**：右键、Alt 点击、滚动、面板控件不误多选；删除后的陈旧目标事件不复活实体；四种布局执行同一选择规则。
- [ ] **C14 / Android**：长按进入选择，选择模式普通点选切换；长按范围操作符合 Android 策略，两端在多选中普通单击均增减选择，Windows 的 Shift 替换范围与 Android 的追加范围仍各自保留。

## D. 顶部继续滚动刷新（I02）

- [ ] **D01**：内容中部向上滚至顶部 → 仅滚动，不立即更新；继续向上才出现“继续向上滚动，准备刷新当前分类”。
- [ ] **D02**：继续同段滚动达到第一阈值 → 显示“再次向上滚动，刷新『分类名』”；同段惯性不能直接确认。
- [ ] **D03**：提示出现至少 300ms、两段间隔至少 400ms，在 3 秒内再向上滚达到第二阈值 → 只启动一个当前分类任务，显示实际本地任务进度。
- [ ] **D04**：提示未提交时反向、离顶、等待 3 秒、切分类、改搜索／筛选、开模态、进入多选、窗口失焦或离页 → 清除提示，不启动任务。
- [ ] **D05**：Ctrl/Alt/Shift 滚轮、横向滚动、Home/PageUp、滚动条拖动、面板内部滚动 → 不触发刷新。
- [ ] **D06**：空库、加载中或加载错误 → 不武装；非空但不足一屏的分类仍能按两段操作刷新。
- [ ] **D07**：搜索只剩一本 → 按手势刷新 → 更新范围仍为当前完整分类；全库更新由显式按钮触发。
- [ ] **D08**：任务运行时继续滚动／再点刷新 → 不创建重复任务；任务结束且 800ms 无滚动后才能重新武装。

HTML 将浏览器 wheel 的像素／行／页单位归一化，第一／第二段采用 80／48 的适配单位。该操作可审核提示和状态转换，不能据此认定 Windows 触控板惯性、自然滚动和 125%/150%/200% DPI 原生验收通过。

## E. 分类与排序设置（S01、S02、S07）

- [ ] **E01 / S01**：设置 → 默认分类 → 每次询问／默认／自定义分类 → 添加新收藏时分别询问或放入目标；已有书不移动。
- [ ] **E02 / S01**：删除当前默认的自定义分类 → 后续收藏使用明确回退策略，不写入不存在分类。
- [ ] **E03 / S02**：设置 → 更新分类 → 默认分类 0 和自定义分类均可在“不指定／包含／排除”间切换；取消不保存，确认一次保存完整策略。
- [ ] **E04 / S02**：作品同时属于包含与排除分类 → 全库更新排除它；包含集为空时代表全部，仍执行排除。
- [ ] **E05 / S02**：当前分类被全库排除 → 当前分类刷新仍处理它，但仍应用漫画智能限制；查询／筛选不裁剪更新范围。
- [ ] **E06 / S02**：注入保存失败 → 包含与排除均保留旧值，不出现一半新策略。
- [ ] **E07 / S07**：开启按分类排序 → 两分类设不同排序 → 关闭 → 分类旧排序清理；重新开启不复活旧排序。显示布局仍是本端全局偏好。
- [ ] **E08 / S07**：注入重置失败后关闭 → 保持开启并提示；中断关闭后模拟重启 → 可恢复完成或明确重试，不假装成功；恢复期间不重复提交。

## F. 章节变化及更新容错（L07、L08）

- [ ] **F01 / L07**：加载“成功／失败／成功”更新样本 → 全库刷新 → 最后一本仍处理，摘要准确区分成功、失败、跳过，失败也计入已处理进度。
- [ ] **F02 / L07**：打开更新详情 → 能看到作品名称和可理解的失败／跳过原因；重试失败项只重跑失败集合，已成功对象不重复请求。
- [ ] **F03 / L07**：失败后点普通刷新 → 创建新一轮完整候选；与“重试失败项”范围可区分。
- [ ] **F04 / L07**：运行中进入详情／返回 → 更新继续且进度恢复；取消 → 已完成保留、未处理数准确，晚到错误不覆盖取消状态。
- [ ] **F05 / L07**：中断后模拟重启／继续 → 只处理原任务未完成集合，不把后来新增收藏扩入；已取消收藏的对象安全跳过。
- [ ] **F06 / L07**：有确定工作集的旧记录 → 显式“继续旧更新”；无工作集的旧记录 → 明确不能恢复原范围，由用户重新发起，不伪装成全库恢复成功。
- [ ] **F07 / L08**：加载章节变化样本 → 更新 → 目录可见新增、改名、重排、移除和可识别 URL 替换；数量及更新信息同步变化。
- [ ] **F08 / L08**：更新前章节已读、书签、阅读页、下载和配对状态有样本 → 更新后对应状态保留；同 URL 保留身份，换 URL 依可识别章节号承接，不按相似标题随意合并。
- [ ] **F09 / L08**：异常空目录、畸形或不完整响应 → 不清空原目录，显示失败；单本提交失败不留下半份目录，也不影响其他作品。
- [ ] **F10 / L08**：目录移除下载章节 → 不自动删除用户已有下载；更新期间的阅读进度不能被旧快照覆盖。
- [ ] **F11 / L08**：模拟目录已提交但恢复记录尚未完成／文件副作用失败 → 重试不重复章节和下载任务，只补未完成阶段，错误可见。

上述目录、文件、恢复和事务均是可重复本地样本状态。审核可确认用户如何操作与看到结果，真实 SQLDelight、文件权限／冲突、源响应解析和崩溃窗口仍属于产品 roadmap 的强制验收。

## G. 周期、智能更新、元数据及设备条件（S03–S06）

- [ ] **G01 / S03**：设置周期可选关闭、6、12、24、48、72 小时及每周；选择 48／72 后关闭重开仍保留。
- [ ] **G02 / S03**：推进演示时间至到期 → 仅调度一次；模拟重启、睡眠唤醒与时钟回拨 → 不重复触发，不把等待设备的任务算作新周期已完成。
- [ ] **G03 / S04**：分别启用仅已追平、已开始、未完结、预计更新期 → 对应不符作品跳过并说明原因；组合设置按共同条件判定。
- [ ] **G04 / S04**：零章节作品不因“尚未开始”被一律跳过；本地／不支持更新的源按明确原因跳过。
- [ ] **G05 / S04**：手动当前分类和手动全库更新仍应用漫画智能限制；手动不会绕过所有规则。
- [ ] **G06 / S05**：启用 Wi-Fi／非计量／接通电源限制 → 到期且不满足时显示具体等待原因，满足后只续跑一次原任务。
- [ ] **G07 / S05**：所选条件为未知 → 等待，不默许；未选择的未知字段不阻断。无电池但确认接通外部电源满足供电条件。
- [ ] **G08 / S05**：自动任务中途模拟断网或拔电 → 在下一作品前等待、已完成保留，不算源失败；恢复条件继续原工作集。
- [ ] **G09 / S05**：同样设备受限时手动刷新／显式失败重试 → 绕过自动设备门槛，真实源模拟错误仍报错。
- [ ] **G10 / S06**：刷新作品信息默认关闭 → 只更新章节；开启后可见作品信息变化，受保护标题与自定义封面保留。
- [ ] **G11 / S03–S06**：任务运行中更改设置 → 已开始作品不被突然中断；后续调度读取新设置，自动任务边界重新判断设备条件。

## H. 双端与可访问性收口

- [ ] **H01**：只对 Windows 加载场景／改偏好／打开弹层 → Android 的导航、选择、滚动、焦点和通知不被重置。
- [ ] **H02**：Android 320px、Windows 窄窗口 → 操作可滚达，内容不横向溢出；长标题和更新原因可读。
- [ ] **H03**：切换 200% 字号 → 面板关闭、设置保存、确认／取消仍可操作，内容通过内部滚动到达。
- [ ] **H04**：批量删除／分类删除等危险动作有明确确认和结果；取消不改数据。场景工具的重置只影响所选演示端。
- [ ] **H05**：无联网、无账号、无真实文件删除；阅读器仅本地预览、同步入口仅保留上下文，均不冒充生产引擎。
- [ ] **H06**：浏览器刷新与“模拟重启”的状态保留边界在 README 中明确；故障恢复的反馈与失败后可用操作可理解。
