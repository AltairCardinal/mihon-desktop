## 使用与审核顺序

直接用 Chrome 打开 `index.html`。所有素材和脚本在本目录，无 CDN、账号或外网请求。应用外工具栏选择目标端和场景，加载后在对应设备内操作。Windows 未多选时单击打开，进入多选后单击增减选择；Ctrl 可进入或增减多选，Shift 选择范围。取消最后一项只退出多选，不打开作品；Escape／关闭选择栏也可退出。Android 保留长按及选择模式。

推荐分四轮审核，每轮约 10–15 分钟：

1. **书架操作**：基础 A–E → 统一面板 → Ctrl/Shift 选择 → Ctrl+滚轮切分类 → 千本快滚 → 顶部两段滚动刷新。
2. **展示和设置**：封面、未读角标与继续阅读、追踪评分、唯一分类 → 默认分类、更新包含/排除、分类排序关闭。
3. **更新结果**：部分失败 → 详情及重试 → 目录增删改与换链 → 空/畸形响应 → 取消、离页和模拟重启。
4. **策略和故障**：虚拟时间 → 智能规则 → 设备等待与恢复 → 作品信息更新 → 保存失败、关闭排序中断、旧任务和损坏记录。

详细步骤和边界见 [验收清单](ACCEPTANCE.md)。每个场景最好重新加载后开始，避免先前保存的筛选和设置影响判断。场景加载作用于外层选择的目标，主题和字号是审阅辅助控制。

常用场景和用途：

| 场景 | 重点操作 |
| --- | --- |
| 基础书架 A–E | 固定锚点选择、面板、分类切换；需要 A–E 顺序时使用标题升序并清除筛选 |
| 千本书架 | 四布局、滚动条和分类位置恢复 |
| 唯一默认／唯一自定义分类 | 分类标签显隐 |

| 自定义封面 | 替换、删除和源封面修订 |
| 部分更新失败 | 完成摘要、失败明细、恢复源后仅重试失败 |
| 目录增删改与换链 | 详情目录与已读、书签、页码、下载身份 |
| 空目录／畸形目录响应 | 失败可见且原目录不丢失 |
| 下次保存失败 | 下一次偏好操作失败回滚 |

| 自动更新等待 | 到期后设备不符等待，恢复条件续跑 |
| 旧更新待确认／更新记录损坏 | 明确恢复入口或错误，不默默扩张为全库更新 |

## 交互来源与适配边界

- **SOURCE**：复用仓库已提交 Mihon 原型的视觉语言和图标；默认深浅主题取 [组件事实表](../../design/mihon-desktop-ui/desktop-reference.md)。Windows 网格封面为 7:10，Android 为 2:3。列表封面独立处理。
- **PROJECT_POLICY**：行为以 [本次 roadmap](../../roadmap/2026-09-28-desktop-library-completion-roadmap.md) 为准，包括用户确认的“未多选单击打开，多选中单击增减，Ctrl 增减，Shift 范围”。旧原型或现有生产代码不覆盖这些新约定。
- **HTML_ADAPTER**：浏览器 DOM、CSS px、焦点和滚轮单位、本地样本、虚拟时钟、故障注入与模拟重启用于审核交互。它们不是 Compose dp、真实 Windows 原生事件或系统 API 的验收证据。

本目录自包含，不引用正在其他任务中修改的 `multi-device-sync` 运行脚本或样式。两端分别持有业务样本和偏好；导航、选择、滚动、通知与焦点不得互相覆盖。外层场景控件通过指定目标发送命令，不是产品设置。

**状态保留**：普通浏览器刷新会重新建立默认样本，不写浏览器持久存储；“模拟重新打开”保留所选端的内存快照，用于审阅设置和任务恢复，并返回书架、退出临时选择。多数场景重新建立该端样本；“下次保存失败”“分类排序关闭中断”“更新记录损坏”只注入当前样本故障，方便保留已有设置再检查失败。深浅主题和字号作用于两端，设备条件及虚拟时间仅作用于所选端。

“自动更新等待”样本同时设为 Wi-Fi 未知和未接通电源；需在外层把两个条件都恢复后才继续。修改外层某一字段只改变该字段，不会自动满足其他条件。恢复图源与记录可解除源故障、损坏记录以及加载/加载错误样本，不替代设备条件恢复。源封面变化优先作用于当前详情作品；在书架时作用于第一本样本。

“替换自定义封面”切换本地生成的封面样本和版本，供检查重复替换；它不打开系统文件选择器。删除后回到最新源封面。章节变化样本会展示保留的下载身份和配对标识，以便核对状态承接，这些是审阅样本而非实际磁盘路径。

顶部刷新在 HTML 中保留 80/48 的两段归一化阈值、提示至少 300ms、分段间隔至少 400ms、3 秒过期与 800ms 静默冷却。实际鼠标、触控板惯性、自然滚动、系统缩放和原生消费顺序仍须产品阶段验证。短列表可触发，空/加载/错误列表不可触发；刷新使用完整分类，不按可见搜索结果裁剪。

更新使用本地任务和章节模型，展示成功／失败／跳过、范围快照、取消、失败重试及有限恢复。模拟 SQL 事务、文件副作用、下载关联、设备状态和源响应只能证明演示模型及其界面接线；真实数据库并发、HTTP 解析、Windows 网络/电源检测、文件权限及进程崩溃恢复仍须 LC07–LC10 验收。完全退出应用后的后台系统服务不在方案内。

阅读器是章节与阅读位置的本地预览；同步只保留书架上下文入口，不在本轮重写同步协议或复制另一 DEMO 的完整授权流程。批量操作仅影响样本，不操作用户真实收藏或下载。

主代理独立审核使用 `contract-review.test.cjs`。四布局完整 Ctrl/Shift 序列、隐藏/跨分类选择、分类按键防抢、真实 `mouse.wheel` 两段更新、跨端焦点、实际计算字号翻倍与窄屏弹层通过初审。评分升降序、分类方向隔离、重复自定义封面替换和任意方向滚轮冷却四项初审失败，交原实施代理修复。字号检查曾因没有等待跨 iframe 消息而提前取值；修正测试的完成等待后通过，未改变产品验收标准。

2026-09-28 最终修复复验与完整套件合并执行一次：**37/37 通过，0 失败、0 跳过，45.77 秒**。其中模型 12 项、实施浏览器测试 17 项、主代理独立契约 8 项。四项初审失败已通过独立复验；补充发现的场景工具设备状态与真实等待条件不一致问题，先以真实 DOM 复现，再修复回读并纳入完整套件。四个运行脚本语法检查通过。

## Ctrl＋滚轮分类切换

用户改为 Ctrl＋滚轮后，移除 Ctrl＋左右方向键绑定。鼠标位于 Windows 书架内容区，向上切上一分类、向下切下一分类；首尾不循环，也不要求滚动到顶部。相同方向相邻事件间隔小于 250ms 只切一次；静默 250ms、反向或松开 Ctrl 后再次按下可继续切换。

仅实际消费该手势时阻止浏览器默认缩放；搜索输入框正在编辑、可编辑内容、输入法组合输入、弹层、详情和阅读器不切分类，Android 保持原交互。分类切换保留搜索、筛选、多选及分类各自滚动位置；更新运行中仍能切类，不改变更新工作集。Ctrl 滚轮不触发顶部刷新，无修饰键两段刷新保留。

此节覆盖前文历史验证中的旧分类按键规则；没有把 HTML 事件验证当作已完成原生 Windows 实现。

## 详情差异处理方式交互审阅
