# Mihon 双端原生界面同步演示

## 同步进度稳定展示审阅（2026-09-28）

打开[双端同步进度审阅](./index.html?progress=continuous)，会直接打开 Windows 与 Android 的同步面板。普通 `index.html` 仍从书架进入；应用外“进度审阅”可选场景，点击“显示在所选设备”或“双端显示进度”。单端检查可用 `device.html?progress=local-eta`。

本轮依据[同步进度显示方案](../../2026-09-28-sync-progress-display-design.md)实现 **HTML_ADAPTER**；SOURCE 是既有双端外壳、主题和同步入口，稳定阈值与信息层级属于 PROJECT_POLICY。没有修改 Kotlin、同步模型、ETA 算法或持久化，也没有真实请求、真实失败日志文件或系统调度。普通同步的演示确认量取本地模型已上传 `sent` 加已经应用的 `applied`，待人工决定不计入；这是本地模型成功返回的展示口径，不等同于生产持久回执。这不代表生产同步进度已完成修改。并行的密码安全审阅入口与本轮独立。

审阅步骤：

1. “正常连续演示”依次准备、接收、校验、合并、上传与核对，约 24 秒结束。主标题维持“同步中”；累计确认量独立于传输比例。“传输 100% 后核对”先显示当前范围 100%，3 秒后切为核对，不能冒充整轮成功。
2. “高频动作与新增数据”每 250ms 提供演示事实，主摘要最多每秒更新文字。普通动作稳定 800ms 才显示；2 秒内 3 次动作／方向／范围变化后合并为“正在交换数据”，相同事实稳定 2 秒才解除。旧范围比例立即失效，不跨范围拼接。
3. 切换“可信整体剩余”“仅局部／请求估算”和 10／60 秒无进展：整体 ETA 必须连续可信 2 秒才显示；10 秒无进展立即失效。局部 ETA 只在详情中，说明槽原位替换，默认只有一条主轨道；暂停、等待和终态不播放活动动画。
4. 点击“查看详情”，查看计数、当前请求、最近进展、队列与条目记录。详情可独立滚动；新事实不自动展开、不滚到底部、不抢另一端输入焦点。队列不是任务分母；未知显示“待统计”或“暂无法估算”。
5. “暂停与恢复”需手动继续，恢复先核对；“限流倒计时与重试”显示距离下一次尝试，15 秒后自动核对和继续。旧“交互场景”的待机恢复、网络等待、总量未知及首次合并复用同一张卡；暂停主操作控制当前合并任务。此 DEMO 合并没有另一个独立子任务队列，不虚构第二个暂停入口。
6. “部分完成与失败日志”区分下方待决定、待核对批次及无法还原项，未展开详情也可直接打开本地样本日志。“成功终态”“已是最新”冻结历时；后者由明确无工作样本触发，不能依据确认 0 条判断。已有取消确认、批处理、设置和授权继续使用原入口。
7. 普通书架 → 同步 → 立即同步也使用共享卡。结果归入说明槽，收起不补播临时通知，但保留本轮终态事实。首次配置完成仍回到已连接的同步页；旧合并成功页保留“查看同步”。

固定摘要槽：主状态／主操作、累计确认、稳定动作、单一轨道、固定“已用”和“整体剩余”、两行说明空间、详情入口。常规文字变化不增加摘要行数；窄屏或大字允许按配置重排并在面板内滚动。详情最大高度 300 CSS px、摘要内边距 16 CSS px 均为 HTML 适配值，不声明为 Compose 常量。减少动画遵从浏览器 `prefers-reduced-motion`；仅状态标题使用 polite 播报，逐秒数字不会朗读整卡。

自动化：`sync-progress-display.test.cjs` 以虚拟时钟覆盖 800ms／2秒阈值、范围失效、ETA 过期和终态；`sync-progress-layout.test.cjs` 点击真实双端 DOM，覆盖直达入口、暂停、详情隔离、日志、节点／滚动／焦点保持、320px及大字；`sync-progress.test.cjs` 保留已有恢复／网络／授权验收。首轮红测为展示函数缺少动作与 ETA、页面缺少共享卡，随后实现通过；最终 focused 9/9 通过（展示时钟2项、真实浏览器4项、旧恢复3项），受影响队列与通知2/2通过，四个脚本的 `node --check` 通过。独立审查后的累计恢复、队列分类、纯接收计数与 Android 窄屏问题均有红绿回归；主代理完成修复复验后统一执行整套回归。

收口验证：整套 DEMO 共 47 项，首次 44 项通过、3 项失败。其中插件宽屏入口漏载 `sync-progress.js` 已修复，并同步补齐复用外壳的权限原型入口；对应插件布局 1/1、权限浏览器 5/5 复验通过。其余 2 项是并行密码改动把“密码保护未开启”改为“同步密码／未设置”后，旧双端断言未更新，与进度功能无关；未修改该并行工作。为确认提交独立性，从暂存内容导出本轮原型后执行旧交互与进度浏览器复验，7/7 通过（含上述两项密码文案断言）；提交未混入并行密码修改。独立浏览器审阅覆盖固定几何、详情滚动和焦点、局部 ETA、传输完成与最终核对、部分失败和双主题；修复复验确认真实 320px Android 与大字无横向溢出。

本批次跨脚本、加载入口、样式、测试和 README，超过 8 个文件是同一双端展示组件接入与契约更新的内聚变更。主要风险为旧导航回归及定时器隔离；新增外壳使用方必须在 `sync-interactions.js` 之前加载 `sync-progress.js`。不以本地浏览器测试代替 Android/Desktop 发布验收。


## 2026-09-28：默认无密码与遗忘密码提示（用户已通过）

直接打开[本轮双端审阅入口](password-review.html)，Windows 和 Android 会进入新空间创建样本。入口跳过的只是本地模拟授权；原 [index.html](index.html) 保留原场景与完整模拟授权路径。完整变更方案、开发契约和固定验收见[同步密码与恢复边界设计](../../2026-09-28-sync-password-safety-design.md)，生产任务与验证门槛见[实施 roadmap](../../roadmap/2026-09-28-sync-password-safety-roadmap.md)。方案及本原型已获用户批准，**不代表 Android/Desktop 产品已更新**。

本节替代下文 09-18 的“空输入/非空输入直接切换创建按钮”交互说明；历史验证记录按原日期保留。

建议按以下顺序审阅，两端规则相同：

1. 创建页默认关闭“设置同步密码（可选）”，不出现密码输入框；“创建并开启同步”直接演示未加密空间的初始化及合并。
2. 开启可选密码，查看持续展示的遗忘风险卡。输入虚构密码，并确认“我已了解遗忘密码的后果”后，才能点击“设置密码并开启同步”。未输入或未确认不能继续；编辑密码会撤销确认。
3. 关闭再开启密码开关，或关闭面板后重进，密码和确认不会恢复。切换显隐保留输入与选区；切换深浅主题、操作另一端不应清空本端草稿或抢焦点。
4. 在应用外“交互场景”选择“已有同步空间 · 密码 mihon-demo”并显示场景，完成本地授权后点击“忘记同步密码？”。帮助页说明保存密码、已解锁设备、本地备份和当前无法找回的边界；返回原输入页，输入 `mihon-demo` 可继续。帮助页不提供假重置、恢复码或删除重建入口。
5. 合并完成后进入同步设置，检查密码只读状态及说明；密码已设置时可进入帮助再返回设置。既有空间不能在设置中开关密码。
6. 选择“同步空间创建失败”，以密码保护模式提交后重试；完成后仍显示已设置密码，不能因输入已清空而退为未加密。已有无密码样本仍直接合并。

GitHub 私库访问权限与客户端加密是不同保护：不设置同步密码时，拥有空间读取权限的人可以读取内容；设置密码后，新设备还需要密码。本原型不实现真实加密、不处理真实账号，不要输入个人密码。独立恢复码、密钥托管、修改/关闭已有密码和旧空间迁移不属于本轮方案。

创建选择与确认是每端面板会话草稿；关闭、离开未提交步骤或关闭密码开关会清除。已提交空间模式独立保留，用于本地失败重试样本。帮助页返回/Escape只返回来源页，关闭按钮/遮罩关闭整个面板。主题变化和另一端重绘不得清草稿、转移焦点或改变模式。布局沿用原型最大 560px 宽、720px 高的面板及内部滚动；这些是 HTML 映射，不代替 Compose 运行测量。

验证结果见[设计第 9 节](../../2026-09-28-sync-password-safety-design.md#9-本轮验证记录)：完整 DEMO 回归 42/42 通过、0 跳过；独立检查双端深浅主题、键盘焦点、320px 手机与 200% 字号。审查发现的禁用按钮外观与警告图标填充已修复并复验。完整回归后的静态说明澄清另做浏览器核验；不重复全套测试。完整回归命令仍为下文的 `node --test --test-concurrency=1 docs/prototypes/multi-device-sync/*.test.cjs`；本轮不运行 Gradle 或产品构建。

Android「获取已安装应用列表」权限提示的独立审阅入口见[插件列表权限 DEMO](../installed-apps-permission/index.html)及[说明](../installed-apps-permission/README.md)。该同级原型复用本目录外壳；本页继续保留同步及建议安装交互，不加载权限模拟脚本。

## 原型路径

- 默认左侧 Windows Desktop、右侧 Android 手机并列显示，网页背景及两端默认主题均为深色。窄窗口保持并列，通过预览区域横向滚动查看，避免把设备缩小到难以操作。
- 应用外「演示预览」工具条默认展开，可切换双端浅色/深色、全局离线状态和重置；选择“触发设备”后，模拟启动/定期同步及 120 项待处理作用于所选端。手动同步仍从各自书架顶栏进入。收起工具条后，操作两端不会重新展开它。
- Windows 使用 Mihon Desktop 外壳和六项底栏：书架、更新、历史、浏览、作者、更多；浏览页签按源码保留图源/插件，作者从独立底栏进入，迁移从更多进入。默认打开书架，同步从书架顶栏进入；更新底栏只打开漫画更新列表。
- Android 使用手机状态栏、Material TopAppBar、五项底栏：书架、更新、历史、浏览、更多。作者入口在浏览内的「图源 / 作者 / 插件 / 迁移」页签，不加入 Android 底栏。
- 从书架漫画卡片、更新条目或作者详情进入漫画详情；在详情中收藏、取消收藏和开始阅读。作者可从 Windows 作者页或 Android 浏览 → 作者列表进入详情并关注。
- 更新页面保留平台差异：Windows 使用 48×68 封面、卡片行和筛选/日历/全部已读/刷新动作；Android 使用 56dp 紧凑行、44×44 封面和筛选/日历/刷新动作。
- 书架顶栏的同步按钮打开高位底部面板，同步是书架的子功能。面板最多 560px 宽、720px 高，窄屏自动适配，列表内部滚动；可用关闭按钮、遮罩、Escape 或下滑抓手关闭。关闭后回到书架，不取消后台同步，完成时也不会抢占当前页面。
- 同步面板右上角齿轮进入同一面板内的设置子页面，宽高不变；左上返回或 Escape 回到同步列表并恢复滚动位置。启动/定期开关仅影响当前设备，修改立即生效。关闭按钮、遮罩或下滑会关闭整个同步面板；后台同步完成不会改变当前子页面。
- 同步按钮只有三种表达：后台异步更新时旋转；有需手动处理事项时显示数量（只计算取消收藏/关注，超过 99 显示 99+）；都没有时只保留普通同步图标。旋转与计数可同时出现。未上传队列、离线与上次失败在面板内说明，不增加顶栏状态。更新底栏仅显示漫画未读更新数，与同步数量独立。

## 大量待处理场景

打开应用外「演示预览」→「120 项待处理」，会替换当前示例数据并自动打开当前设备的同步面板。80 项取消收藏与 40 项取消关注均通过现有模型的收藏/关注、交换、取消与接收流程生成；不是静态占位行。条目标题、来源及确认/忽略操作完整可用，处理后数量立即减少。再次点击会重新建立 120 项场景，重置演示恢复普通数据。

标题与设置入口固定，列表内部滚动，优先展示待处理内容；书架顶栏超过 99 显示 99+，待确认数量在列表上方操作条显示。PC 与手机均不再显示标题下方独立的待处理摘要栏。设置返回保留滚动位置。本原型直接渲染 120 行，不代表已实现面向无限数据的分页或虚拟列表。

## 章节式批量处理

交互参考原版 `MangaToolbar.kt`、`MangaBottomActionMenu.kt`、`MangaScreen.kt` 与 `MangaScreenModel.toggleSelection/toggleAllSelection/invertSelection`：长按条目进入选择，选择中点击条目切换；再次长按可连续选中范围，桌面端也可 Shift 点击。另提供“多选”显式入口。条目列表的直接上方集中显示多选操作条：未选择时提供“多选”和“全部处理”菜单；选择时显示已选数量、退出、全选、反选，以及“保留所选”和“在此设备取消所选”，零选择时禁用操作。操作条在列表滚动时吸附于滚动区域顶部，同步面板标题不被选择模式替换，面板底部不再放置批量操作。全选覆盖整个待确认列表，不只当前可见区域。

列表上方操作条的“更多”提供“全部在此设备取消”和“全部保留在此设备”，无需逐项勾选。两者都会显示一次汇总确认，列出漫画与作者数量和后果；取消汇总框保留选择。执行复用已有确认/忽略模型，结果显示实际处理数，全部完成退出选择。关闭面板、切换设备及重置场景清除选择。

批量仅处理取消收藏/关注。其他分歧自动处理，不进入待确认列表。确认框保存本次操作 ID；后台新到达的条目不加入，已被远端新操作作废的条目跳过并反馈。选择状态随有效待确认项更新，避免误处理失效操作。确认只移除接收端收藏/关注，忽略保留接收端状态，两者均不反向恢复来源端。

## 建议演示顺序

1. 初始打开 Windows 书架 → 顶栏同步，电脑 B 会看到手机 A 发来的取消收藏待确认项；可确认或忽略本次取消。
2. 打开底栏更新，在一台设备（来源端）从更新条目或漫画详情操作收藏、阅读或关注，并点击书架 → 顶栏同步 →「立即同步」；直接在旁边另一台设备（接收端）点击「立即同步」查看结果。
3. 在右侧 Android 进入浏览 → 作者 → 作者详情关注；来源端先立即同步，再在左侧 Windows 作为接收端立即同步。Android 不会出现 Desktop 的独立作者底栏。
4. 从演示栏打开“自动处理分歧”场景，查看同步记录中的自动处理结果，无需选择本地或远端。
5. 阅读模式仍按设备独立保存。正在阅读时不跳页与下次采用最近位置的产品规则，通过“自动处理分歧”的记录展示；旧内存模型的阅读行为本轮未修复。
6. 在应用外工具条切换离线，继续收藏或阅读；恢复在线后先同步来源端，再同步接收端。待上传操作会保留到重试成功。

## 源码对照与边界

`preview.js` 提供并列容器及公共工具条，用同源 srcdoc iframe 隔离两端的视口、焦点与键盘事件，继续加载原有 `app.js`。双端复用同一个 `sync-model.js` 模型和内存操作日志；代理状态只把导航、选择、面板通知和定时器留在各自视图，收藏、阅读、待上传队列仍按设备 ID 隔离。重绘另一端不抢焦点、不接收尚未同步的操作。重置及大量待处理场景会终止两端现有定时器、重建视图，避免旧后台任务修改新场景。页面刷新丢失原同步演示状态；新增插件建议的折叠与忽略偏好例外，会按设备保存在浏览器本地。这不是跨浏览器通信。单端隔离验收保留 `device.html`，并列入口的共享状态、工具条和双端交换由 `parallel-preview.test.cjs` 覆盖。
