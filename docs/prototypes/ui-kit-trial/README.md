# Mihon UI 规范双端实验

打开 [双端并列入口](./index.html)，或单独打开 [单端入口](./device.html?platform=android)；单端参数可用 `platform=windows`。应用外工具栏可以切换深浅色，并链接到[旧同步 DEMO](../multi-device-sync/index.html)对照。本目录是本地 HTML 实验，不连接网络、数据库、下载器或真实同步任务；刷新会重置所有假数据。截图是候选视觉证据，未经人工确认为生产基准。

本实验只覆盖书架搜索和未读筛选、一本漫画的章节多选和下载移除确认、书架同步面板内的本机设置。底栏保留平台入口差异，但范围外页面明确禁用。Windows 有独立「作者」，Android 没有；从漫画卡片进入详情，两端都从书架顶栏进入同步面板。章节示例的其他漫画可用于检查下载状态隔离。

## 页面契约

基线：本机 `d379849b85` 加既有未提交工作树。HTML 实验不能充当 Kotlin production wiring 或原生 Compose 验收。

| 页面 / 类型 | 入口、容器与状态所有者 | 返回、关闭、焦点 | 副作用与边界 |
|---|---|---|---|
| 书架 / root | 各 iframe 自有顶栏、底栏和内存状态；标题、查询、筛选与漫画卡片 | 搜索开后输入聚焦；清空仍在搜索；关闭或 Escape 回书架 | 查询只查当前书架的标题；未读筛选即时生效；状态不跨刷新 |
| 漫画详情 / detail | 卡片进入；唯一详情顶栏、章节滚动列表；稳定书 ID 与章节 ID | 返回先取消多选，再回书架；显式多选预选首项；取消最后一项退出 | 移除操作只改当前漫画本设备的假下载标记；无真实文件或阅读行为 |
| 同步面板 / modal+settings | 书架同步按钮；面板内设置子页；当前 iframe 的两个布尔开关 | Escape 先设置返回面板，再关闭面板；关闭回到书架按钮；弹层入焦并圈定 Tab，背景 inert | 开关即时更新本机假状态；关闭不启动任务；遮罩关闭整个面板 |
| 移除下载 / modal | 已选择且至少一项已下载时可打开；按适用数量确认 | 取消、Escape 回原批量操作，保留选择；Tab 留在框内 | 只移除已下载的所选章节；确认后反馈实际数，未下载项跳过 |

内容区域自身滚动，顶栏和底栏由外壳提供；面板自身滚动。Android 与 Windows 的差异限制在状态栏、顶栏高度、底栏入口和设置摘要。消息由应用窗口的状态条提供。外部工具栏不进入设备 iframe，切主题时不传递导航或焦点状态。

## 规则映射与来源

| 决定 | 来源和规则 | 本次可验证的范围 |
|---|---|---|
| 页面、局部模式与弹层返回分层 | UI 包 `01-navigation.md` UI-01、UI-03、UI-04；本机旧 DEMO `README.md` 的书架同步面板路径 | 浏览器实际点击与 Escape，测试检查标题、返回和面板层级 |
| 查询 `null` 与空串分开，清空不关闭、无结果给解除限制动作 | UI 包 `02-content-actions.md` UI-11 与 `04-async-feedback.md` UI-18 | 标题查询、本地即时过滤；没有异步旧结果测试 |
| 选择稳定 ID、计数、取消最后一项、批量适用子集 | UI 包 UI-08、UI-09；本机 `MangaScreenModel.kt` 的选择接口及 `MangaDetailScreen.kt` 的章节批量操作 | 三个假章节；全选、取消、确认实际下载数；没有范围选择 |
| 弹层确认、副作用与本机开关 | UI 包 `03-dialogs-forms.md` UI-14、UI-15、UI-17；旧 DEMO `app.js` 的 `startup-setting`、`periodic-setting` 与面板返回 | 浏览器验证取消无副作用、Tab 圈定和本机隔离；无真实偏好存储 |
| 明暗主题、图标与平台导航差异 | UI 包 `05-visual-accessibility.md` UI-22、UI-25、UI-26；旧 DEMO `ui-view.js` 的主题 tokens、图标路径和平台 nav spec | 复用本地路径和 token；320px 与桌面宽无横向溢出，截图待人审 |

本包规范基于另一提交，`component-baseline.md` 也明示未核查本机工作树。因此上表的“规范来源”仅代表设计约束，不代表上游原版已满足。漫画名、封面占位、三条章节、默认已下载、显式多选预选首项、禁用范围外底栏、弹层 focus 细节和下载状态内存模型是本实验的**自主推断或简化**，不能算规范效果。平台入口和同步本机开关语义由本仓库现有 DEMO 与源码补足，不归功于 UI 包。

`NOT_IMPLEMENTED`：反选、范围选择、三态筛选、继续阅读 FAB、真实阅读、真实下载、真实同步、持久化、进程恢复、动态色、RTL、大字体与原生键盘/无障碍设备验证。UI-09、UI-12、UI-27 只覆盖表中部分条款，不能标作整类通过。HTML 页面也不复用 Compose 的 `AppBar`、`AdaptiveSheet` 或 Preference 组件，仅模拟其可审阅结构。

## 验证记录

先写 `trial.test.cjs`，首轮浏览器红灯 4/4：目标页面不存在。补页面后 4/4 绿。新增下载确认行为断言后，因原行只显示“已选”而红，补本地下载状态后 4/4 绿。独立验收指出描边图标、弹层焦点、零选择和跨漫画下载状态问题；新增浏览器断言先复现图标 `stroke-width: 0` 和弹层焦点留在背景按钮，随后修复，focused 5/5 绿。最后补混合已下载/未下载数量测试，并保留截图供独立审查。

运行时在当前 PowerShell 会话设置 `PLAYWRIGHT_CORE_PATH` 指向可用的 `playwright-core` 目录，然后执行：

```powershell
node --test docs/prototypes/ui-kit-trial/trial.test.cjs
node --check docs/prototypes/ui-kit-trial/trial.js
```

自动化实际驱动 Chrome 页面 DOM，检查搜索/筛选、选择/确认、面板返回、焦点圈定、设备隔离与两种视口尺寸。截图文件名标明主题和尺寸；截图只能证明当时的 HTML 像素，不能证明原生 Mihon 视觉一致。

## 主代理最终验收

完整浏览器测试 6/6 通过，0 失败、0 跳过；`trial.js` 和 `preview.js` 语法检查通过。独立查看双端书架和 320px 确认框截图。测试结果仅对应上述样本交互，不代表 UI-01–32 全部符合。

已知视觉偏差：实验封面为 3:4，本机 Android `MangaCover.Book` 为 2:3；保留作为规范执行效果的观察，不作为生产视觉基准。完整分析和首轮问题见[评估报告](../../design/mihon-ui-kit-evaluation/README.md)。
