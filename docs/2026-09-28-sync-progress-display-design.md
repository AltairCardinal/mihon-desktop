# 同步进度显示盘点与稳定呈现方案

日期：2026-09-28。源码基线：`dd4ac37264f03699b92ceb197d5846236b6e979c`。状态：**设计建议，尚未实施**。

## 1. 结论与范围

建议将同步界面收敛为 **固定摘要卡、一条主进度、按需展开的详情**。默认让用户看清三个问题：同步还在进行吗、已经安全完成多少、接下来需要我做什么。内部动作、不同口径的计数和诊断信息保留在详情中。

盘点覆盖 Android/Desktop 共用同步面板、首次合并、暂停/恢复/重试、终态、外围队列与消息、最近条目，以及 Android 前台通知。统计单位是**去重后的文案资源模板**，数字、文件路径、作品名称和组合后的句子不逐一算新文案；按钮、单位词和不可达分支分开解释。与多设备同步无关的追踪服务同步、图源章节刷新不在范围内。授权表单、仓库发现错误的全部修复说明不是运行进度，仅纳入其中的等待/加载提示。

本文件是本轮唯一交付文档，包含盘点、设计、映射和未来验收要求；不新增原型、生产组件、状态数据库、实施 roadmap 或构建产物。源码读取及资源提取用于文档核对，不作为产品行为测试。

## 2. 已观察到的结构与影响

以下是 `SOURCE` 源码事实；对用户观感的解释是基于这些结构的推断。本轮未录制真实同步过程，不声称已复现每种闪动。

| 位置 | 已观察到的事实 | 对显示的影响 |
|---|---|---|
| `SyncStageProgress` | 三行阶段列表后继续渲染动作、计数、耗时、ETA 等 | 同一任务同时存在多组状态标题，阅读层级不清晰 |
| ETA | 整体估算一行；局部估算两行；暂停/恢复等状态不渲染 ETA | 随可用样本增减，卡片行数发生变化 |
| 辅助数据 | 首次导入、接收校验数、检查数、累计确认数、新增数据提示均有独立显隐条件 | 字段出现/消失会推动下方按钮和内容 |
| 等待提示 | 无进展 10 秒、60 秒时加入说明；恢复进展后撤下；最近进展时间另占一行 | 普通短时等待被放大为多行持续变化的文字 |
| HTTP 正文 | 无总体字节分母、但有当前正文长度时，再添加一条正文进度条 | 同一卡片可能同时显示不定总进度与有定局部进度 |
| 日志 | `state.logs` 在进度卡内逐条展开；默认查询 5 条，可加载更多，最多 500 条 | 日志到达会增加高度，持续替换的标题也分散注意力 |
| 卡片外部 | 主状态、三行队列、运行卡、结果 notice、首次合并剩余量、批处理量分别渲染 | 同一事实可能重复出现；可用视口进一步被压缩 |
| 引擎 | 下载逐批切换传输/确认；上传准备、传输、确认可再次发生，恢复传输也会退回传输阶段 | 三阶段是当前工作范围的分类，不是整次同步的一次性三步流程 |
| 终态 | 成功、部分完成、失败、受阻、取消由独立终态分支渲染，并冻结历时 | 应保留这项已有保障，不能为了稳定高度继续显示活动动画 |

## 3. 设计依据与取舍

`SOURCE`：Android 官方文档区分有定与不定进度，有定进度表达实际可计算的完成比例，不定进度只表达工作仍在进行。[Android Developers：Progress indicators](https://developer.android.com/develop/ui/compose/components/progress)

`PROJECT_POLICY`：以下信息层级、显示节奏和占位规则是本方案建议值，不是 Material 官方规定。遵循[Desktop UI 规范](design/mihon-desktop-ui/README.md)和[组件事实表](design/mihon-desktop-ui/desktop-reference.md)，保留现有主题、BottomSheet、状态链路和平台行为。本轮没有 HTML 适配，故没有 `HTML_ADAPTER` 验收结论。

选择不做伪造的整轮百分比，不给准备/传输/确认各分配 1/3 权重。整轮工作量在发现远端变动、多轮追赶时可能继续增长，当前安全确认量、局部进度和可信 ETA 比一个不断回退的总百分比更准确。

## 4. 默认界面

### 4.1 信息布局

下图为布局示意，数字是假设样本，不是运行证据。主卡只保留固定信息槽；按同一窗口宽度和字号，运行中的可选文案不增加行数。

```text
┌──────────────────────────────────────┐
│ 同步中                         暂停  │  A 状态与唯一主操作
│ 本次已确认 1,280 条                   │  B 整轮安全确认量
│ 正在交换数据                         │  C 稳定的用户动作
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │  D 单条进度轨道
│ 已用 01:42        整体剩余：暂无法估算 │  E 时间，固定标签
│ 已完成的进度会保留                    │  F 一条说明，预留两行
│ 查看详情                           › │  G 固定位置的详情入口
└──────────────────────────────────────┘
```

此例 D 使用不定进度，不对应 B 的比例。若本轮上传总字节明确，C 可显示“正在上传 · 传输 64%”，D 才使用同一范围的有定值；这不是“整次同步已完成 64%”。

| 槽位 | 默认内容 | 显示规则 |
|---|---|---|
| A | 同步中／正在暂停／已暂停／等待网络／等待重试／同步完成／部分完成／同步需要处理／同步未完成／已取消 | 只表达整轮状态。运行时不随每个内部动作改变大标题。右侧主操作在固定区域原位更新 |
| B | 本次已确认 N 条 | 始终保留。可信数暂不可得时显示“本次已确认：正在核对”；不把未知显示成 0 |
| C | 正在准备／正在接收／正在合并／正在上传／正在核对；快速交替时“正在交换数据” | 仅一个动作槽，不堆叠旧动作。局部比例必须明确写“传输”等范围标签 |
| D | 一条线性进度轨道 | 整体有可靠分母才可表示整体，否则只表示 C 已标明的当前范围；范围不稳定时用不定进度 |
| E | 已用 mm:ss；整体剩余：估算中／约 N 秒／暂无法估算 | 两个常驻字段，未知值原位替换。局部 ETA 不占用“整体剩余”字段 |
| F | 正常为“已完成的进度会保留”；等待时替换为具体原因或下一步 | 常态预留两行文字空间，不轮播。只显示当前最高优先级说明 |
| G | 查看详情／收起详情 | 始终可见，数字不使按钮横向移动，展开状态不会因新进度重置 |

首次运行尚无安全确认数据时 B 使用“正在核对”；确认可可信地为 0 时显示“本次已确认 0 条”。不能为美观把 0 隐藏。

### 4.2 详情里的内容

“查看详情”展开同一面板内的受限滚动区域，不新开模态或自动抢焦点。用固定键值行展示：

- 当前方向与范围：本轮下载／本轮上传／首次合并；内部 scope/run ID 不向普通用户展示。
- 当前动作：保留完整的真实动作描述，更新数字与内容，不增加/删除行；短动作可以合并显示，不重放历史步骤。
- 本轮准备、传输、确认计数；本轮已接收并校验数；本地合并检查数。行在详情展开时确定顺序，尚未知显示“待统计”，当前不适用显示“—”，均不伪装为 0。
- 本轮传输比例、当前请求传输比例分别标注。HTTP“正文”改称“当前请求”，并说明只代表一个请求的数据传输。当前请求的百分比不显示在默认卡中，不再增加第二条活动进度条。
- 当前阶段剩余／当前请求剩余／最近进展；没有可信估算显示“暂无法估算”。同一行保留标签，不发生一行变两行。
- 待上传操作及收藏、关注、阅读记录分类。它们是排队数据，不等于本次任务分母。已有用户新增操作可能进入下一轮。
- 最近条目：沿用现有按需加载，不自动展开、不因条目到达滚动到底部。行键稳定，读取完整标题通过明确展开，避免跑马灯。

首次合并剩余量和“暂停后续处理／继续处理”留在详情中的“首次合并”块；人工决定批处理使用单独标为“处理已选事项”的块，保留其暂停/继续入口，不能与暂停整次同步合并成一个含义模糊的按钮。任一子任务暂停且妨碍继续时，F 必须说明并提供定位入口，不能只藏在详情。

结果 notice 中重复的上传/接收/待处理摘要归入同一结果区。批处理结果仍按其独立业务显示，不能因去重而丢失。待人工决定列表继续是主面板的独立内容区，失败日志也有默认可见的入口，不以“展开详情”作为处理错误的前提。

## 5. 从内部动作到用户动作

| 实际来源 | 主卡 C | 详情保留 | 为什么 |
|---|---|---|---|
| CHECKING、RECOVERING | 正在核对进度 | 核对已保存进度、恢复状态 | 不误导为从头开始；恢复状态优先于旧阶段 |
| IMPORTING、导入计数、上传制品准备 | 正在准备数据 | 首次合并、写入数、生成上传数据、准备数 | 内部写入与生成不是需要用户区分的多个主步骤 |
| 下载 TRANSFERRING | 正在接收数据 | 本轮下载计数、可用传输比例 | 将“获取同步数据”统一为简短动词 |
| 下载 CONFIRMING，尚未进入投影 | 正在校验数据 | 接收并校验数、确认数 | 未开始合并时不能提前写“正在合并” |
| 下载 CONFIRMING，投影已开始 | 正在合并数据 | 检查数、接收数、确认数及整批确认说明 | 检查数增加不等于合并成功 |
| 上传 TRANSFERRING | 正在上传数据 | 传输条数、字节比例、当前请求比例 | 上传完成不等于整次同步完成 |
| 上传 CONFIRMING | 正在核对结果 | 核对已保存数据、已确认数 | 必须等真实远端 ACK |
| 快速循环下载/校验/合并/上传，方向或范围频繁改变 | 正在交换数据 | 最新方向、动作与范围 | 主卡不重演每个细碎步骤，也不沿用旧范围百分比 |
| 发现新增数据 | 正在交换数据 | “发现新增数据，继续同步”及新范围 | 不把已完成重置成“又从 0 开始”；B 保持整轮累计 |

三阶段清单从默认卡移到详情，标签明确为“当前工作范围”。只依据当前阶段 ordinal 不能断言整次运行的早期工作已经永久完成；主界面不再使用会反复复位的三步勾选器。

## 6. 防闪动与进度真实性

### 6.1 稳定节奏

以下为初版建议参数，需以虚拟时钟行为测试和原生视觉检查验收：

1. 用户点击立即同步后立即给出“同步中”，关闭重复提交入口；不延迟点击反馈，也不强迫已完成任务多停留几秒。
2. 普通具体动作需连续稳定 **800ms** 才提升到主卡 C。在候选尚未稳定、旧动作已结束时，立即显示真实的上位文案“正在准备数据”或“正在交换数据”，不能为了最短停留时间继续宣称旧动作仍在执行。
3. 交换过程中，若 **2 秒内发生 3 次动作/方向/范围变化**，锁定主卡“正在交换数据”；直到同一具体动作及范围稳定 **2 秒**才解除。详情显示最新事实，不排队回放。
4. 主卡、进度轨道的 label 与数值由同一份展示快照原子更新。动作仍是上位文案、或者旧范围已失效时立即撤下旧的有定比例，使用原位不定轨道，绝不把新分子配旧分母。
5. 沿用生产事实推送最多每 250ms 一次、可见时每秒刷新历时的机制。文字数字最多每秒刷新一次即可；终态、暂停、恢复、授权/存储等阻塞状态立即呈现，不受普通动作节流影响。
6. 数字采用等宽数字特性并右对齐，为百分比和合理位数预留宽度；千分位、单位格式统一。文字只做原位替换；如使用淡入淡出，建议 120–160ms 且容器不重新测高，不做上下滑动或数字滚动。
7. 无进展达到 10 秒立即撤下旧 ETA。恢复后按现有有效样本条件重新估算；建议新 ETA 连续可信 2 秒后显示，避免“估算中↔约 N 秒”来回闪。推迟新估算可见不等于延长过期 ETA。
8. 面板收起停止视觉计时，不改变生产任务。重开先显示当前真实状态；按当前 run/scope 重建展示会话，不能先闪上一轮 ETA 或成功提示。

### 6.2 一条进度轨道的口径

- 有整轮可信总量时才能使用整轮比例；当前模型通常只能提供工作范围内的分母，默认不得拼造整轮百分比。
- 有当前范围的可信传输总字节时，可使用已去重有效字节比例；方向、范围或请求变化时不得跨范围插值。多轮频繁变化时主卡保持不定轨道，详细比例留给详情。
- 准备/确认阶段，只有稳定、可解释的同范围工作量才使用有定进度；整批确认从 0 跳到 N 是合法事实。缺少可分解中间量时使用不定轨道和“正在核对”，不伪造逐条进度。
- 字节已发送 100% 只代表传输完成。阶段完成但整轮未结束时，C 切换为“正在核对结果”，D 改为该阶段的真实模式，不显示整轮成功图标。
- 暂停/离线/系统等待/重试等待时停止不定动画；已知比例可保留为静态轨道。未知时保留中性轨道占位，不伪造 0%。终态轨道区域替换为静态结果标识，无加载语义。
- `confirmedThisRun` 未恢复时显示核对中；已有持久 `run.confirmedItems` 可用时按同一运行安全记录展示。不得用 `receivedItems`、`checkedFields`、日志条数或已传输字节补计安全确认数。

### 6.3 时间的固定口径

默认 E 永远标为“整体剩余”。可信 `wholeEtaSeconds` 才填数；仅有 `stageEtaSeconds` 或 `activeBodyEtaSeconds` 时，默认显示“暂无法估算”，对应估算进入详情的独立字段。这是对旧需求“局部 ETA 与整体未知提示同时展开”的呈现调整，保留信息与计算语义。

暂停等状态 E 原位显示“整体剩余：已暂停／等待网络／等待重试”，不倒数；F 显示自动重试倒计时，明确它表示**距离下一次尝试**，不是距离完成。ETA 为 0 但未终态时显示“整体剩余：正在收尾”，不拼成“预计还需约正在收尾”。

“已用”继续表示本次运行实际历时，包含暂停与等待；终态按持久结束时间冻结。不得为平滑更改估算算法、重试预算或引擎工作时序。

## 7. 状态与操作矩阵

显示优先级：**持久终态 → 用户暂停/等待/受阻 → 正在暂停或恢复 → 长等待提示 → 普通运行**。终态用持久结果解释，不被最后一个活动阶段覆盖。表中的文案为目标文案。

| 真实条件 | A / F | E 与轨道 | 操作与边界 |
|---|---|---|---|
| QUEUED | 等待同步 / 等待任务开始 | 整体剩余：等待开始；静态轨道 | 沿用现有可执行动作，不新增取消能力 |
| RUNNING + ACTIVE | 同步中 / 已完成的进度会保留 | 活动进度；整体估算或未知 | 暂停同步 |
| PAUSING | 正在暂停 / 正在保存进度 | 不展示 ETA；停止表示新增工作的动画 | 暂停按钮原位禁用并写“正在暂停”，不提前启用继续 |
| PAUSED_USER | 已暂停 / 已完成的进度会保留 | 原位“已暂停”；静态进度 | 继续同步 |
| WAITING_NETWORK | 等待网络 / 网络恢复后将按现有调度继续 | 原位“等待网络”；静态进度 | 不承诺应用关闭后始终常驻；不新增绕过调度的操作 |
| WAITING_SYSTEM | 等待继续 / 正在等待系统安排 | 原位“等待继续”；静态进度 | 沿用系统恢复策略，不预测恢复时间 |
| WAITING_RETRY | 等待重试 / N 秒（或分钟）后自动重试 | 原位“等待重试”；静态进度 | 按持久 nextRetryAt 倒计时，不虚构“立即重试”按钮 |
| WAITING_RETRY + rate_limit | 等待重试 / 服务暂时限制请求，N 秒后重试 | 同上 | 限流原因保留；不能因刷新重置倒计时 |
| RECOVERING | 正在核对进度 / 正在恢复已保存的进度 | 整体剩余：正在核对；不显示旧字节比例 | 核对完成前不宣称已重新上传 |
| 活动状态 10–59 秒无进展 | 同步中 / 正在等待当前步骤返回 | 整体剩余：暂无法估算 | 确认阶段在详情说明整批确认；不自动报错 |
| 活动状态 ≥60 秒无进展 | 同步中 / 已有一段时间没有新进展，可查看详情 | 同上 | 详情显示准确时长；不推断代理、网络或图源故障 |
| SUCCEEDED | 同步完成 / 本次数据已完成同步 | 冻结总历时，静态完成标识 | 沿用立即同步入口；保持本轮结果直到下次运行 |
| 成功且确实没有待同步数据 | 已是最新 / 没有需要同步的数据 | 同上 | 必须有真实无工作事实；不能仅据 confirmedItems=0 判定 |
| PARTIAL | 部分完成 / 分别说明待人工决定、待核对或无法还原 | 冻结历时，无 ETA | 重试同步；已有下方决定列表；有真实失败项时可直接打开失败日志 |
| FAILED | 同步未完成 / 进度已保留；仅实际耗尽时说明重试上限 | 冻结历时，无 ETA | 重试同步；不能把所有失败都概括为重试次数耗尽 |
| BLOCKED | 同步需要处理 / 展示服务端或本地已有的明确原因 | 冻结历时，无 ETA | 沿用重新连接、连接空间等现有修复入口；安全相关完整说明可阅读 |
| CANCELLED | 本次同步已取消 / 显示已有确认结果 | 冻结历时，无 ETA | 不由本方案新增任务取消按钮 |

F 只选一条最高优先级的原因，其他原因进详情。错误修复入口、无法还原项数和隐私风险说明不能只留一个含糊省略号。终态可一次性切换为结果布局；这属于有意义的状态改变，不属于运行中反复增减内容。

待核对批次涉及的“变动数”不是失败数；待手动决定不是失败；日志中的“已接收”不是安全确认。旧 SOURCE 失败说明代表上一次尝试的事实，不得据此要求安装图源，保留现有“重试并重新恢复已保存数据”的建议。

## 9. 复用与实施边界

1. **直接复用**现有 `SyncRuntime`、`SyncProgressFact`、`SyncRunSnapshot`、持久安全回执、ETA 计算和 `SyncPanelController` 的推送/时钟；不重做同步引擎和估算系统。
2. 两端本来就共享 `presentation-sync`。建议在该模块提取轻量展示映射及有界、会话级动作稳定器，供 MAIN/首次合并共同消费；不能 Android/Desktop 各写一套文案判断。普通映射可纯函数；节奏需可注入时钟，不能用持久数据库记录视觉防抖。
3. 追加到现有同步链路。新层只决定信息在哪显示、什么时候将普通动作提升到摘要；不改变生产状态、数据模型、确认条件、重试/暂停行为或事件格式。
4. 平台独立部分仅限已有容器、键盘/返回和失败日志打开方式，技术原因是平台窗口及文件访问 API 不同；没有新建独立同步 UI 状态机的技术或用户体验理由。
5. 本方案落地时需同步更新旧 ETA 需求的默认呈现条款，保留其计数/安全语义；旧三阶段正文可留作详情分类，不能悄悄删掉原验收来获得通过。
6. 无数据成功提示与泛化 FAILED 标题需真实运行事实驱动；若当前状态不足以可靠区分某子原因，使用通用事实文案，不为设计便利增加臆测信号。整轮 ETA 不可得也是合法状态。

### 动态内容：资源表之外的完整模板边界

| 来源 | 当前标题/内容 | 条件与目标去向 |
|---|---|---|
| 首次导入日志 | 首次合并 / 正在写入已保存的数据；首次合并 / 已写入已保存的数据 | 导入前/后更新同一条；进入详情最近条目 |
| 无法读取批次日志 | 同步数据 / 数据无法读取 | 接收失败；详情保留，不能把一条日志当作一部漫画失败 |
| 无可解析对象的批次日志 | 同步数据 / 已接收、已确认重复数据或已确认上传 | logBatch兜底；详情保留实际结果 |
| 对象日志标题 | 作品/作者的真实名称；缺失时为作者、漫画、阅读记录 | 动态名称不计为静态模板；章节优先关联作品名 |
| 对象日志说明 | 作者关注／收藏／阅读记录 × 已接收／已确认重复数据／已确认上传 | 三种操作与三种结果组合，共9种潜在组合；不是9种整轮阶段；放入详情 |
| 失败日志路径 | failureLog.path | 当前运行真实文件路径；不计入静态模板，详情可读完整路径，默认保留打开入口 |
| 历时格式 | mm:ss | 运行时递增，终态冻结；可超过59分钟，不按数字变化增加行 |
| 重试倒计时和ETA | 数字 + 已列的秒/分钟模板 | 不能把无限可能数值算作文案种类 |
| Android前台通知 | 同步 / 正在同步… | 复用A1的两个资源；本轮未发现阶段数字推送，不重复计数 |
| 工具栏 | 同步（图标语义）、正在同步…（busy语义）、待处理数字/99+ | 固定48dp入口，数字是人工待决定数量，不是任务百分比；保留此口径 |

首次授权的完整错误说明、密码字段与校验错误、设置开关、批量确认对话框以及列表选择动作不纳入“进度文案”总数；它们不应混入运行中的动作轮播。完整失败报告正文也不是主界面的进度文字，本方案仅调整报告入口和摘要，不改报告生成格式。
