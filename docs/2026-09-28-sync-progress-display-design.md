## 1. 结论与范围

同步界面收敛为 **固定摘要卡、一条主进度、按需展开的详情**。默认让用户看清三个问题：同步还在进行吗、已经安全完成多少、接下来需要我做什么。内部动作、不同口径的计数和诊断信息保留在详情中。

盘点覆盖 Android/Desktop 共用同步面板、首次合并、暂停/恢复/重试、终态、外围队列与消息、最近条目，以及 Android 前台通知。统计单位是**去重后的文案资源模板**，数字、文件路径、作品名称和组合后的句子不逐一算新文案；按钮、单位词和不可达分支分开解释。与多设备同步无关的追踪服务同步、图源章节刷新不在范围内。授权表单、仓库发现错误的全部修复说明不是运行进度，仅纳入其中的等待/加载提示。

本文件是产品显示行为的需求权威；roadmap 只组织实施顺序、边界与证据，不另写一套显示规则。本次更新不实施生产代码、不新增状态数据库、不生成发布产物。源码读取及资源核对不作为产品行为测试。

## 2. 已观察到的结构与影响

以下是 `SOURCE` 源码事实；对用户观感的解释是基于这些结构的推断。本轮未录制真实同步过程，不声称已复现每种闪动。

| 位置 | 已观察到的事实 | 对显示的影响 |
|---|---|---|
| `SyncStageProgress` | 三行阶段列表后继续渲染动作、计数、耗时、ETA 等 | 同一任务同时存在多组状态标题，阅读层级不清晰 |
| ETA | 整体估算一行；局部估算两行；暂停/恢复等状态不渲染 ETA | 随可用样本增减，卡片行数发生变化 |
| 辅助数据 | 首次导入、接收校验数、检查数、累计确认数、新增数据提示均有独立显隐条件 | 字段出现/消失会推动下方按钮和内容 |

| HTTP 正文 | 无总体字节分母、但有当前正文长度时，再添加一条正文进度条 | 同一卡片可能同时显示不定总进度与有定局部进度 |
| 日志 | `state.logs` 在进度卡内逐条展开；默认查询 5 条，可加载更多，最多 500 条 | 日志到达会增加高度，持续替换的标题也分散注意力 |
| 卡片外部 | 主状态、三行队列、运行卡、结果 notice、首次合并剩余量、批处理量分别渲染 | 同一事实可能重复出现；可用视口进一步被压缩 |
| 引擎 | 下载逐批切换传输/确认；上传准备、传输、确认可再次发生，恢复传输也会退回传输阶段 | 三阶段是当前工作范围的分类，不是整次同步的一次性三步流程 |

## 3. 设计依据与取舍

`SOURCE`：Android 官方文档区分有定与不定进度，有定进度表达实际可计算的完成比例，不定进度只表达工作仍在进行。[Android Developers：Progress indicators](https://developer.android.com/develop/ui/compose/components/progress)

`PROJECT_POLICY`：以下信息层级、显示节奏和占位规则是本项目冻结的目标，不是 Material 官方规定。遵循[Desktop UI 规范](design/mihon-desktop-ui/README.md)和[组件事实表](design/mihon-desktop-ui/desktop-reference.md)，保留现有主题、BottomSheet、状态链路和平台行为。`HTML_ADAPTER`：已通过的原型证明信息层级与交互方案获得认可，其模拟数据、CSS 尺寸和浏览器测试不能替代生产状态及原生验收。

选择不做伪造的整轮百分比，不给准备/传输/确认各分配 1/3 权重。整轮工作量在发现远端变动、多轮追赶时可能继续增长，当前安全确认量、局部进度和可信 ETA 比一个不断回退的总百分比更准确。

## 4. 默认界面

### 4.1 信息布局

下图为布局示意，数字是假设样本，不是运行证据。主卡只保留固定信息槽；按同一窗口宽度和字号，运行中的可选文案不增加行数。

```text
┌──────────────────────────────────────┐
│ 同步中                         暂停  │  A 状态与唯一主操作
│ 本次已确认 1,280 条                   │  B 整轮安全确认量
│ 正在交换数据                         │  C 稳定的用户动作
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │  D 单条进度轨道
│ 已用 01:42        整体剩余：暂无法估算 │  E 时间，固定标签
│ 已完成的进度会保留                    │  F 一条说明，预留两行
│ 查看详情                           › │  G 固定位置的详情入口
└──────────────────────────────────────┘
```

此例 D 使用不定进度，不对应 B 的比例。若本轮上传总字节明确，C 可显示“正在上传 · 传输 64%”，D 才使用同一范围的有定值；这不是“整次同步已完成 64%”。

| 槽位 | 默认内容 | 显示规则 |
|---|---|---|
| A | 同步中／正在暂停／已暂停／等待网络／等待重试／同步完成／部分完成／同步需要处理／同步未完成／已取消 | 只表达整轮状态。运行时不随每个内部动作改变大标题。右侧主操作在固定区域原位更新 |
| B | 本次已确认 N 条 | 始终保留。可信数暂不可得时显示“本次已确认：正在核对”；不把未知显示成 0 |
| C | 正在准备／正在接收／正在合并／正在上传／正在核对；快速交替时“正在交换数据” | 仅一个动作槽，不堆叠旧动作。局部比例必须明确写“传输”等范围标签 |
| D | 一条线性进度轨道 | 整体有可靠分母才可表示整体，否则只表示 C 已标明的当前范围；范围不稳定时用不定进度 |
| E | 已用 mm:ss；整体剩余：估算中／约 N 秒／暂无法估算 | 两个常驻字段，未知值原位替换。局部 ETA 不占用“整体剩余”字段 |
| F | 正常为“已完成的进度会保留”；等待时替换为具体原因或下一步 | 常态预留两行文字空间，不轮播。只显示当前最高优先级说明 |
| G | 查看详情／收起详情 | 始终可见，数字不使按钮横向移动，展开状态不会因新进度重置 |

首次运行尚无安全确认数据时 B 使用“正在核对”；确认可可信地为 0 时显示“本次已确认 0 条”。不能为美观把 0 隐藏。

### 4.2 详情里的内容

“查看详情”展开同一面板内的受限滚动区域，不新开模态或自动抢焦点。用固定键值行展示：

- 当前方向与范围：本轮下载／本轮上传／首次合并；内部 scope/run ID 不向普通用户展示。
- 当前动作：保留完整的真实动作描述，更新数字与内容，不增加/删除行；短动作可以合并显示，不重放历史步骤。
- 本轮准备、传输、确认计数；本轮已接收并校验数；本地合并检查数。行在详情展开时确定顺序，尚未知显示“待统计”，当前不适用显示“—”，均不伪装为 0。
- 本轮传输比例、当前请求传输比例分别标注。HTTP“正文”改称“当前请求”，并说明只代表一个请求的数据传输。当前请求的百分比不显示在默认卡中，不再增加第二条活动进度条。
- 当前阶段剩余／当前请求剩余／最近进展；没有可信估算显示“暂无法估算”。同一行保留标签，不发生一行变两行。
- 待上传操作及收藏、关注、阅读记录分类。它们是排队数据，不等于本次任务分母。已有用户新增操作可能进入下一轮。
- 最近条目：沿用现有按需加载，不自动展开、不因条目到达滚动到底部。行键稳定，读取完整标题通过明确展开，避免跑马灯。

首次合并剩余量和“暂停后续处理／继续处理”留在详情中的“首次合并”块；人工决定批处理使用单独标为“处理已选事项”的块，保留其暂停/继续入口，不能与暂停整次同步合并成一个含义模糊的按钮。任一子任务暂停且妨碍继续时，F 必须说明并提供定位入口，不能只藏在详情。

结果 notice 中重复的上传/接收/待处理摘要归入同一结果区。批处理结果仍按其独立业务显示，不能因去重而丢失。待人工决定列表继续是主面板的独立内容区，失败日志也有默认可见的入口，不以“展开详情”作为处理错误的前提。

## 5. 从内部动作到用户动作

| 实际来源 | 主卡 C | 详情保留 | 为什么 |
|---|---|---|---|
| CHECKING、RECOVERING | 正在核对进度 | 核对已保存进度、恢复状态 | 不误导为从头开始；恢复状态优先于旧阶段 |
| IMPORTING、导入计数、上传制品准备 | 正在准备数据 | 首次合并、写入数、生成上传数据、准备数 | 内部写入与生成不是需要用户区分的多个主步骤 |
| 下载 TRANSFERRING | 正在接收数据 | 本轮下载计数、可用传输比例 | 将“获取同步数据”统一为简短动词 |
| 下载 CONFIRMING，尚未进入投影 | 正在校验数据 | 接收并校验数、确认数 | 未开始合并时不能提前写“正在合并” |
| 下载 CONFIRMING，投影已开始 | 正在合并数据 | 检查数、接收数、确认数及整批确认说明 | 检查数增加不等于合并成功 |
| 上传 TRANSFERRING | 正在上传数据 | 传输条数、字节比例、当前请求比例 | 上传完成不等于整次同步完成 |
| 上传 CONFIRMING | 正在核对结果 | 核对已保存数据、已确认数 | 必须等真实远端 ACK |
| 快速循环下载/校验/合并/上传，方向或范围频繁改变 | 正在交换数据 | 最新方向、动作与范围 | 主卡不重演每个细碎步骤，也不沿用旧范围百分比 |
| 发现新增数据 | 正在交换数据 | “发现新增数据，继续同步”及新范围 | 不把已完成重置成“又从 0 开始”；B 保持整轮累计 |

三阶段清单从默认卡移到详情，标签明确为“当前工作范围”。只依据当前阶段 ordinal 不能断言整次运行的早期工作已经永久完成；主界面不再使用会反复复位的三步勾选器。

## 6. 防闪动与进度真实性

### 6.1 稳定节奏

以下为冻结参数，需以虚拟时钟行为测试和原生视觉检查验收：

1. 用户点击立即同步后立即给出“同步中”，关闭重复提交入口；不延迟点击反馈，也不强迫已完成任务多停留几秒。
2. 普通具体动作需连续稳定 **800ms** 才提升到主卡 C。在候选尚未稳定、旧动作已结束时，立即显示真实的上位文案“正在准备数据”或“正在交换数据”，不能为了最短停留时间继续宣称旧动作仍在执行。
3. 交换过程中，若 **2 秒内发生 3 次动作/方向/范围变化**，锁定主卡“正在交换数据”；直到同一具体动作及范围稳定 **2 秒**才解除。详情显示最新事实，不排队回放。
4. 主卡、进度轨道的 label 与数值由同一份展示快照原子更新。动作仍是上位文案、或者旧范围已失效时立即撤下旧的有定比例，使用原位不定轨道，绝不把新分子配旧分母。
5. 沿用生产事实推送最多每 250ms 一次、可见时每秒刷新历时的机制。文字数字最多每秒刷新一次即可；终态、暂停、恢复、授权/存储等阻塞状态立即呈现，不受普通动作节流影响。
6. 数字采用等宽数字特性并右对齐，为百分比和合理位数预留宽度；千分位、单位格式统一。文字只做原位替换；首版不增加淡入淡出、上下滑动或数字滚动动画。
7. 无进展达到 10 秒立即撤下旧 ETA。恢复后按现有有效样本条件重新估算；新 ETA 连续可信 2 秒后显示，避免“估算中↔约 N 秒”来回闪。推迟新估算可见不等于延长过期 ETA。
8. 面板收起停止视觉计时，不改变生产任务。重开先显示当前真实状态；按当前 run/scope 重建展示会话，不能先闪上一轮 ETA 或成功提示。

### 6.2 一条进度轨道的口径

- 有整轮可信总量时才能使用整轮比例；当前模型通常只能提供工作范围内的分母，默认不得拼造整轮百分比。
- 有当前范围的可信传输总字节时，可使用已去重有效字节比例；方向、范围或请求变化时不得跨范围插值。多轮频繁变化时主卡保持不定轨道，详细比例留给详情。
- 本次首版的准备/确认阶段在默认卡统一使用不定轨道，具体条目数放详情；有定主轨道只用于稳定且总字节可信的传输阶段。整批确认从 0 跳到 N 是合法事实，不伪造逐条进度。
- 字节已发送 100% 只代表传输完成。阶段完成但整轮未结束时，C 切换为“正在核对结果”，D 改为该阶段的真实模式，不显示整轮成功图标。
- 暂停/离线/系统等待/重试等待时停止不定动画；已知比例可保留为静态轨道。未知时保留中性轨道占位，不伪造 0%。终态轨道区域替换为静态结果标识，无加载语义。
- `confirmedThisRun` 未恢复时显示核对中；已有持久 `run.confirmedItems` 可用时按同一运行安全记录展示。不得用 `receivedItems`、`checkedFields`、日志条数或已传输字节补计安全确认数。

### 6.3 时间的固定口径

默认 E 永远标为“整体剩余”。可信 `wholeEtaSeconds` 才填数；仅有 `stageEtaSeconds` 或 `activeBodyEtaSeconds` 时，默认显示“暂无法估算”，对应估算进入详情的独立字段。这是对旧需求“局部 ETA 与整体未知提示同时展开”的呈现调整，保留信息与计算语义。

暂停等状态 E 原位显示“整体剩余：已暂停／等待网络／等待重试”，不倒数；F 显示自动重试倒计时，明确它表示**距离下一次尝试**，不是距离完成。ETA 为 0 但未终态时显示“整体剩余：正在收尾”，不拼成“预计还需约正在收尾”。

“已用”继续表示本次运行历时，包含暂停与等待；终态使用现有持久 `updatedAt-createdAt` 冻结，`updatedAt` 是最后更新时间，不能称作另有记录的精确结束时间。没有分段数据时不推算实际网络工作时间，不为平滑更改估算算法、重试预算或引擎工作时序。最近历史结果使用“上次历时”，整体剩余为“—”；当前待恢复的受阻或仍有待确认下载的部分完成运行，依据 controller 的真实 active/latest 选择区分当前与历史语境，不能只凭终态枚举推断。

## 7. 状态与操作矩阵

显示优先级：**持久终态 → 用户暂停/等待/受阻 → 正在暂停或恢复 → 长等待提示 → 普通运行**。终态用持久结果解释，不被最后一个活动阶段覆盖。表中的文案为目标文案。

| 真实条件 | A / F | E 与轨道 | 操作与边界 |
|---|---|---|---|
| QUEUED | 等待同步 / 等待任务开始 | 整体剩余：等待开始；静态轨道 | 沿用现有可执行动作，不新增取消能力 |
| RUNNING + ACTIVE | 同步中 / 已完成的进度会保留 | 活动进度；整体估算或未知 | 暂停同步 |
| PAUSING | 正在暂停 / 正在保存进度 | 不展示 ETA；停止表示新增工作的动画 | 暂停按钮原位禁用并写“正在暂停”，不提前启用继续 |
| PAUSED_USER | 已暂停 / 已完成的进度会保留 | 原位“已暂停”；静态进度 | 继续同步 |
| WAITING_NETWORK | 等待网络 / 网络恢复后将按现有调度继续 | 原位“等待网络”；静态进度 | 不承诺应用关闭后始终常驻；不新增绕过调度的操作 |
| WAITING_SYSTEM | 等待继续 / 正在等待系统安排 | 原位“等待继续”；静态进度 | 沿用系统恢复策略，不预测恢复时间 |
| WAITING_RETRY | 等待重试 / N 秒（或分钟）后自动重试 | 原位“等待重试”；静态进度 | 按持久 nextRetryAt 倒计时，不虚构“立即重试”按钮 |
| WAITING_RETRY + rate_limit | 等待重试 / 服务暂时限制请求，N 秒后重试 | 同上 | 限流原因保留；不能因刷新重置倒计时 |
| RECOVERING | 正在核对进度 / 正在恢复已保存的进度 | 整体剩余：正在核对；不显示旧字节比例 | 核对完成前不宣称已重新上传 |
| 活动状态 10–59 秒无进展 | 同步中 / 正在等待当前步骤返回 | 整体剩余：暂无法估算 | 确认阶段在详情说明整批确认；不自动报错 |
| 活动状态 ≥60 秒无进展 | 同步中 / 已有一段时间没有新进展，可查看详情 | 同上 | 详情显示准确时长；不推断代理、网络或图源故障 |
| SUCCEEDED | 同步完成 / 本次数据已完成同步 | 冻结总历时，静态完成标识 | 沿用立即同步入口；保持本轮结果直到下次运行 |
| 成功且确实没有待同步数据 | 已是最新 / 没有需要同步的数据 | 同上 | 必须有真实无工作事实；不能仅据 confirmedItems=0 判定 |
| PARTIAL | 部分完成 / 分别说明待人工决定、待核对或无法还原 | 冻结历时，无 ETA | 重试同步；已有下方决定列表；有真实失败项时可直接打开失败日志 |
| FAILED | 同步未完成 / 进度已保留；仅实际耗尽时说明重试上限 | 冻结历时，无 ETA | 重试同步；不能把所有失败都概括为重试次数耗尽 |
| BLOCKED | 同步需要处理 / 展示服务端或本地已有的明确原因 | 冻结历时，无 ETA | 沿用重新连接、连接空间等现有修复入口；安全相关完整说明可阅读 |
| CANCELLED | 本次同步已取消 / 显示已有确认结果 | 冻结历时，无 ETA | 不由本方案新增任务取消按钮 |

F 只选一条最高优先级的原因，其他原因进详情。错误修复入口、无法还原项数和隐私风险说明不能只留一个含糊省略号。终态可一次性切换为结果布局；这属于有意义的状态改变，不属于运行中反复增减内容。

待核对批次涉及的“变动数”不是失败数；待手动决定不是失败；日志中的“已接收”不是安全确认。旧 SOURCE 失败说明代表上一次尝试的事实，不得据此要求安装图源，保留现有“重试并重新恢复已保存数据”的建议。

## 9. 复用与实施边界

1. **直接复用**现有 `SyncRuntime`、`SyncProgressFact`、`SyncRunSnapshot`、持久安全回执、ETA 计算和 `SyncPanelController` 的推送/时钟；不重做同步引擎和估算系统。
2. 两端本来就共享 `presentation-sync`。建议在该模块提取轻量展示映射及有界、会话级动作稳定器，供 MAIN/首次合并共同消费；不能 Android/Desktop 各写一套文案判断。普通映射可纯函数；节奏需可注入时钟，不能用持久数据库记录视觉防抖。
3. 追加到现有同步链路。新层只决定信息在哪显示、什么时候将普通动作提升到摘要；不改变生产状态、数据模型、确认条件、重试/暂停行为或事件格式。
4. 平台独立部分仅限已有容器、键盘/返回和失败日志打开方式，技术原因是平台窗口及文件访问 API 不同；没有新建独立同步 UI 状态机的技术或用户体验理由。
5. 本方案落地时需同步更新旧 ETA 需求的默认呈现条款，保留其计数/安全语义；旧三阶段正文可留作详情分类，不能悄悄删掉原验收来获得通过。
6. 无数据成功提示与泛化 FAILED 标题需真实运行事实驱动；若当前状态不足以可靠区分某子原因，使用通用事实文案，不为设计便利增加臆测信号。整轮 ETA 不可得也是合法状态。

## 13. 开发接口与数据字典（冻结）

### 13.1 复用链路和修改位置

生产链路继续为 `SyncRuntime / SyncRunStore → SyncPanelController.state → SyncPanelContent → AndroidSyncPanel / DesktopSyncPanel`。只在 `presentation-sync/src/commonMain/kotlin/mihon/presentation/sync/` 增加共享展示投影与会话稳定器，并由现有 MAIN 与 SETUP/MERGING 消费。推荐文件名 `SyncProgressPresentation.kt`、`SyncProgressSummary.kt`；这是待新增文件，不是现存实现。

投影输入为同一份 `SyncPanelState`、展示会话及注入的单调时钟；输出为不可变 `SyncProgressPresentation`，含身份、状态、主操作、确认量、动作、轨道、历时、整体 ETA、说明、详情和终态问题摘要。输出文字用资源键及参数表达，不在数据层生成中文。普通可组合函数只渲染投影并发出现有 action，不另行判断阶段、累加计数或启动同步。

会话所有者放在 `SyncPanelContent` 的页面分发之前，避免 MAIN/SETUP 切页重置稳定器；不放进全局单例、数据库或平台 wrapper。数据层只在现有恢复/订阅 wiring 被集成测试证明有缺口时局部修复，不借此增加迁移、同步事件或新的后台服务。

| 展示字段 | SOURCE 输入 | 确定的转换与缺省 |
|---|---|---|
| 运行身份 | `run.spaceId / generation / runId`；`attemptId` | 三元组隔离运行；attempt 改变时清短期估算和动作候选，保留同一运行的安全确认量。详情折叠状态不因同一运行重试丢失 |
| 当前范围 | `progress.scope / direction / stage` | 仅接受 scope 等于 runId 或以 `runId:` 开头的事实；不匹配即忽略，不能显示别轮数据。scope 只作内部键 |
| 运行状态 | `run.state`、`progress.hold`、`run.phase` | 先持久终态、再持久暂停/等待、再 PAUSING/RECOVERING，最后普通活动；PAUSING/RECOVERING 是 hold，不伪造为 `SyncRunState` 枚举 |
| 本次已确认 | 活动期有效 `progress.confirmedThisRun`；终态 `run.confirmedItems` | 保留 nullable；活动期 null 不从接收/检查数补值。可复用 controller 重建的安全值；仅持久值明确大于 0 时可作已知下界，0 且尚未核对仍显示核对中。终态持久值优先；UI 不以 max 缓存掩盖生产计数错误 |
| 本轮阶段条数 | `completedItems / totalItems` 与对应 stage | 仅代表当前范围当前阶段。详情可以保留同 scope/direction 已观察到的三个阶段值；未观察过显示待统计。最多缓存三阶段，换 scope/direction 清除；恢复事实不能伪造未观察到的阶段历史 |
| 接收、检查与导入 | `receivedItems / receivedTotalItems / checkedFields / importCompletedItems / importTotalItems` | 各自独立行；检查单位为项，事件单位为条。无有效事实时待统计；不适用为 —；已知 0 正常显示 |

| 当前请求比例 | `activeBodyBytes / activeBodyTotal` | 只在详情；分母 >0、值合法才显示，换请求以最新事实为准，不插值；不生成第二条活动轨道 |

### 13.2 原型与生产不可直接照搬的部分

- 原型 `sent + applied` 只是本地模型的演示确认量。生产只能使用安全确认字段，不从上传/下载数量相加推导，也不能靠演示计时器增加确认数。
- 原型覆盖快速切换、范围变化、局部估算、无进展、暂停恢复、限流、部分完成、成功及“已是最新”。这些是输入场景，不是生产的新状态机或真实失败文件。
- 当前生产没有显式、持久的“本轮确实无工作”标记。**本次生产首版所有 SUCCEEDED 默认显示“同步完成”**；原型“已是最新”仅表达将来具备该证据时的语义，不要求为此扩展协议/数据库。不用四个计数恰好为 0 代替明确证据。P14 的本轮通过条件是零条成功仍如实成功、零条 PARTIAL 绝不显示最新。
- HTML 首次合并只有一个模拟任务；生产已存在 `PauseImport/ResumeImport` 和 `PauseBulk/ResumeBulk`，必须保留独立控制，不能照抄 DEMO 把所有暂停绑到 PauseSync。
- HTML 的 300px 详情上限、16px 内边距不是原生常量。原生沿用现有 12dp 卡圆角、18dp 卡内边距、24dp MAIN 水平边距；SETUP 原有 0dp 外边距保留。根据剩余高度限制详情，不把 HTML 大块留白机械移植到 Compose。

## 14. 稳定器、生命周期及更新算法（冻结）

推荐 `SyncProgressDisplaySession` 只保留当前身份、至多三个阶段计数、一个动作候选、最多三个最近变化时间、ETA 可信起点、最近展示时间和最新待展示快照；空间复杂度 O(1)，日志仍由现有 controller 提供。阈值集中为常量：动作 800ms、频繁变化窗口 2000ms/3 次、解除锁定 2000ms、整体 ETA 连续可信 2000ms、普通数字刷新 1000ms。动画首版无需淡入淡出；减少动态效果时使用静态轨道并保留状态文本。

一次事件按以下顺序处理，测试必须覆盖同帧变化：

1. 校验运行身份及 scope。身份变化先清旧快照、计数缓存和候选；新运行默认收起详情、滚动归顶。重复同一事实不算动作变化。
2. 计算持久状态/hold 优先级。终态立即清活动动画、局部和整体 ETA，使用持久结束时间；暂停/等待立即清 ETA 可信起点；恢复清旧比例及缓存，不回放离开期间的动作。
3. 动作键为 `(scope, direction, stage, run.phase, mergingReceivedData)` 中实际影响用户动作的部分；计数、字节和 ETA 数值变化不算换动作。准备候选用“正在准备数据”，其余候选用“正在交换数据”。800ms 前不显示具体动作；2 秒闭区间内累计 3 次有效键变化后锁定上位文案，稳定 2 秒再解除。
4. 任何 scope/direction/stage/attempt 变化立即使旧传输比例和 ETA 失效；即使普通数字尚在节流期也立即清除，不留下旧分母。只有具体传输动作稳定后才把同快照比例与标签一起提升到摘要。
5. ETA 有效性要求 ACTIVE、非恢复、非终态、当前事实整体值非负、无进展年龄已知且 <10 秒。首次可信连续 2 秒后显示；可信期间值改变不重置 2 秒。scope/direction/stage/attempt 改变、null、非法值或达到 10 秒均立即撤销并重新计时。仅局部 ETA 时主卡直接显示暂无法估算；首次正在等整体可信窗口显示估算中。
6. 原子生成七槽内容、主操作和轨道。普通计数更新可合并到每秒一次；暂停、等待、恢复、终态、明确错误及过期值撤销绕过节流。在固定布局下不能用 AnimatedVisibility 增删摘要行。
7. 没有新事实也要在可见期间到达 800ms/2 秒/10 秒边界时求值，采用可取消的最近截止时间唤醒，并复用 controller 的每秒时钟更新历时。不能只靠下一次网络回调才解除候选，不能新建第二个永久轮询循环。所有计时器在面板不可见时取消；生产订阅和持久化不受影响。

主卡停留期间，MAIN↔SETUP/SETTINGS 来回、主题或尺寸变化保留当前运行的详情展开与滚动；新运行或空间身份变化清除；Close→Open 是新面板会话，详情默认收起，先取当前真实状态再开始候选窗口。关闭不停止同步、不发 Pause/Cancel。运行已经终态时重开立即显示持久结果，不为进入动画临时显示同步中。新事实不得清空待决定列表选择或抢占输入焦点。

## 15. 操作、布局与文案的可实施契约

### 15.1 主操作与非主操作

| 条件 | 卡片右上操作 | production wiring |
|---|---|---|
| RUNNING/ACTIVE | 暂停同步 | `PauseSync`；点击后真实 hold 为 PAUSING 才显示正在暂停，不能 UI 直接改 PAUSED_USER；可有本地一次点击防重入 |
| PAUSING | 正在暂停，禁用 | 不再派发动作，等 runtime 的保存/停止结果 |
| PAUSED_USER | 继续同步 | `ResumeSync`；真实恢复完成前显示核对，不直接强写 RUNNING |
| QUEUED、RECOVERING、网络/系统/重试等待、无 run 占位 | 当前等待说明，禁用 | 不新增取消/立即重试入口；不改 nextRetryAt |
| FAILED、PARTIAL | 重试同步 | `RetrySync`，由 controller 现有允许状态检查决定 |
| BLOCKED+授权问题 | 重新连接 GitHub | `Authorize`；保护现有浏览器认领和失败反馈 |
| BLOCKED+存储/无效数据且既有条件允许 | 连接同步空间 | `BeginSetup`；不能对所有 BLOCKED 一律重新授权 |
| BLOCKED+其他原因 | 查看原因 | 本地展开完整说明并定位，不新建虚假修复 action；保留原有合法修复入口 |
| SUCCEEDED、CANCELLED | 立即同步 | `Synchronize`；沿用连接/初始化约束 |

详情的首次合并块直接绑定 `PauseImport/ResumeImport`，独立显示 `importRemaining/importPaused`。批处理块标明“处理已选事项”，继续绑定 `PauseBulk/ResumeBulk`，不会暂停同步运行。子任务暂停时 F 写明对象，并提供“查看处理进度”定位；卡片主操作仍只控制整轮运行。

`SyncFailureLogStatus.Ready` 且 runId 匹配终态时，在默认结果区显示失败数和“打开失败日志”，调用原 `onOpenFailureLog(path)`；完整路径在详情可复制/阅读，不把文件路径塞进主摘要。SaveFailed 时保留失败摘要及“日志保存失败”，不渲染可点击的假路径；平台打开失败沿用既有通知。公开仓库隐私风险保留完整可读说明，不能裁到两行后没有全文入口。

### 15.2 信息归位和几何验收

- 有运行卡时，旧 `SyncStatusHeader` 中重复运行文案及外部 `SyncQueueSummary` 不再重复渲染；保留面板标题、设置、关闭。队列进入详情。无运行卡时原有空闲倒计时与排队摘要继续可见。
- 同一 exchange 的 notice 数字归入结果/详情，不另堆一条运行摘要；不能拿缺 runId 的旧 notice 覆盖持久终态。`notice.bulk` 和 setupCompleted 是独立反馈，沿用当前可见会话生命周期和 DismissNotice，不因去重吞掉。
- SETUP/MERGING 移除重复的合并标题/加载指示器，使用同一七槽卡；授权、发现、创建仍是原设置步骤，不强行放进同步阶段。首次合并结束后的路由、取消确认、历史入口不改变。
- 详情顺序固定：当前范围/动作 → 三阶段条目 → 接收与检查 → 范围/请求比例 → 局部 ETA 与最近进展 → 队列 → 首次合并/批处理 → 最近条目。长期不适用的独立子任务块可不出现，不能把可选项留在默认摘要造成跳动。
- 标准字号下标题、确认量、动作、轨道、时间、两行说明、详情触发器各有稳定槽位。由宽度/字号决定一行或两行时间，不能由内容碰巧溢出决定。数字支持等宽字形但不为预留位数截断大数字。
- 外层内容必须能滚动到卡片末尾与待决定列表；不要继续把无限高摘要和有 weight 的列表塞进无法滚动的 Column，导致列表高度变 0。复用稳定 key 和现有 LazyListState；详情可在有界高度内滚动，列表不放入无限高度的嵌套 LazyColumn。原生截图记录实际布局约束。
- 对固定 viewport/fontScale/locale：运行中切换动作、计数位数、整体/局部 ETA、等待说明时，卡片下沿、主操作和详情触发器坐标差不超过 1dp；详情显式展开、新运行/终态或用户调整布局配置允许有意重排。200% 字体下先保证完整可读和可操作，不以裁切达成坐标断言。
- 焦点、选择和滚动不因新事实变更；日志行使用稳定 key，不自动滚到底。收起详情时若焦点在详情内部，返回触发按钮；点击别处不能被计时重绘拉回。只对状态标题的有效变化做一次 polite 播报，数字不作为整卡 live region。

### 15.3 资源与失败原因

继续使用 Moko。新增/改义字符串同步维护 base 与 zh-rCN，其他语言依项目回退；不批量翻译或删除仍被别处使用的旧资源。新增类别至少包含：稳定动作“正在交换数据”、核对中确认量、固定整体剩余标签、详情展开/收起、当前请求替代正文的产品术语、等待开始/继续、处理已选事项及查看原因。沿用已有数量/时长复数和格式函数，不直接拼接英文单位。

第 11 节 130 项是实现前盘点，不因迁移而改写历史数量。落实去向：C1/C3 局部/C4 局部/C8 最近条目/A1 队列进入详情；C2 进入动作与说明；C5/C6 在固定说明槽；C7/C9 进入结果及原因全文；C10/A3 保留真实操作；A2 保留授权等待，仅合并步骤复用卡。`FAILED` 默认“同步未完成”，仅 `stopReason == retry_exhausted` 显示耗尽说明。不存在具体原因时使用通用事实，不推断网络代理、图源或凭据故障。

## 18. 生产实现维护入口（2026-09-30）

共享实现位于`presentation-sync`的`SyncProgressPresentation.kt`与`SyncPanelContent.kt`。`SyncProgressDisplaySession`仅保存有界展示观察，输入来自现有controller事实；不写数据库、不生成业务进度、不启动同步或重试。MAIN与首次合并复用同一面板会话及摘要；空间/generation/run切换、关闭重开按第14节重置。生产使用单调时钟及最近deadline更新展示，隐藏/卸载取消视觉定时，业务runtime继续独立运行。

## 19. 真机终态恢复补充契约（2026-09-30）

用户已授权执行[终态恢复及 DEBUG roadmap](roadmap/2026-09-30-sync-terminal-recovery-debug-roadmap.md)。该补充解决历史结果与连接状态组合造成的主操作死路，继续复用共享面板、当前连接流程和数据库查询；诊断不得改变业务结果。实际实现及测试仍以[本轮证据](evidence/sync-terminal-recovery-debug-2026-09-30.md)为准，未通过项不能称为已完成。

- 历史取消/完成与当前连接分开判断。已连接可启动新的合法运行并保留旧记录；未连接或持久停用时主卡提供“连接同步空间”；格式不兼容时提供原原因入口，不跳过兼容守卫。首次合并、授权、密码、安全确认及暂停所有权沿原链路执行。
- 历史摘要用“上次结果”“上次已确认”“上次历时”，动作槽说明确认结果保留，不重复取消标题。当前可恢复的运行保留现有语境及合法操作；检查失败提供重试检查，不能无限灰色等待。七槽尺寸及静态终态轨道保持。
- 诊断复用同一 production Runtime/Controller/SQL 查询，明确原始启用字段、解码结果、面板投影以及 active/latest 选择。无法读取与真实停用分别表示；前后身份或状态变化时明确“不一致”并允许再采集，不能把跨身份字段组合成有效快照。
- 仅导出版本、状态、计数、时间和会话内关联别名；不导出账号、仓库地址、令牌、密码、密钥、授权链接、作品/事件内容或完整数据库。现有失败日志包含作品与地址，不能代替该脱敏报告。
- 诊断只保留最近128条内存元数据转换；导出最多256KiB并说明截断。用户显式开启诊断会话后，私有缓存只保存随机盐与上一快照的关联摘要，用HMAC别名关联跨进程采样，最长24小时或结束时清理；不开启时明确只保证本进程关联。诊断失败应提供反馈并保持原任务、连接、确认记录及偏好不变。
- 面板关闭/重开、前后台与冷启动先采样，再核对是否真正漏刷新或晚到覆盖。只有实际运行证据支持时才改生命周期、终态写入或取消释放；不能由长历时、定时job存在或重开看到相同历史直接推断挂起。

本轮补充已完成真机与双平台原生验收、TDD及独立审查，结果随修复roadmap聚合提交收口；原进度计划其他人工验收状态保留。诊断runSource来自真实active/latest查询，loaded面板另比对其连接/运行消费；采样不一致或读取失败时为UNKNOWN，不能把未知当NONE。进度fallback的hold不代表执行者存活，需结合active/coordinator/owner事实。最终诊断会话已结束，后续需要关联跨进程取证时应显式另开会话。
